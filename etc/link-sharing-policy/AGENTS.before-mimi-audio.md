Claude Code 와 Codex 가 함께 읽는 파일이다. 새 세션에서 배경지식이 필요하면 여기부터 본다.

**여기는 지도만 둔다.** 이 파일은 `C:\dev` 밑에서 일할 때마다 통째로 context 에 들어간다.
절차와 함정 상세는 그 프로젝트 폴더의 `AGENTS.md` 나 `C:\dev\docs\` 에 두고,

## Claude 업데이트 후 실행 오류와 ADB

Claude가 0x80070020으로 안 켜지거나 ADB를 사용하려면 `G:/내 드라이브/에이전트/etc/claude-adb-repair/diagnosis.md`를 먼저 읽는다.
2026-09-11 이전 Claude 실행 환경에 남은 adb.exe를 직접 확인했다. ADB 서버는 Claude 안에서 시작하지 않는다. Windows 로그인 작업 `ADB Independent Server`가 독립 실행한다. ADB 사용 전과 서버 종료·업데이트 후에는 `Start-ScheduledTask -TaskName 'ADB Independent Server'`로 독립 서버를 먼저 시작하고 `C:/dev/etc/claude-adb-repair/adb-start.json`의 성공 결과와 서버 생존을 확인한다.
재부팅 후 검증 결과는 `C:/dev/etc/claude-adb-repair/after-reboot.json`에 있다.

- 버전 1.62.1, 크로미움 151. 이미 받아둔 브라우저를 쓰므로 따로 내려받을 필요 없다

공개 HTTP, 인앱 브라우저, 또는 위 ESM 라이브러리를 직접 import한 Node 스크립트를 사용한다.
백그라운드 프로세스를 `Start-Process` 로 띄워야 하면 `-WindowStyle Hidden` 을 지정한다.

로그인이 필요한 화면은 Playwright 로 하지 마라. 빈 브라우저라 세션이 없다.

## 브라우저 탭 정리

작업하려고 연 탭은 **그 작업이 끝날 때 닫는다.** 크롬이든 인앱 브라우저든 마찬가지다.
탭과 창이 많으면 컴퓨터가 눈에 띄게 느려진다.

- 내가 연 것만 닫는다. 원래 떠 있던 탭은 사람이 보던 것일 수 있으니 그대로 둔다
- 확인하려고 띄운 개발 서버도 확인이 끝나면 내린다
- 여러 건을 도는 루프는 **한 건 끝날 때마다** 닫는다. 마지막에 몰아서 치우려다 놓친다
- 막혀서 그만둘 때도 닫고 나간다. 실패한 탭이 제일 잘 남는다

## 인스타 열람에는 속도 제한을 걸지 않는다

**읽기는 아무리 많이 해도 막히지 않는다.** 프로필 열람, 게시물 보기, 하이라이트 열기,
소개글 링크 따라가기는 전부 읽기다. 여기에 계정당 대기 시간, 시간당 상한, 하루 상한을 넣지 마라.
조사 루프에 그런 제한을 걸면 며칠이면 끝날 전수 조사가 몇 주로 늘어난다.

- 조사 루프 설계에 "인스타 시간당 N개" 같은 항목을 만들지 않는다. 이미 있으면 뺀다
- 계정 하나를 다 보면 바로 다음 계정으로 넘어간다. 사이에 쉬지 않는다
- 다만 **탭은 계정 하나 끝날 때마다 닫는다.** 이건 차단이 아니라 컴퓨터 속도 문제다

**제한이 실제로 있는 쪽은 쓰기다.** DM 보내기, 팔로우, 좋아요, 댓글, 스토리 반응은
횟수 제한과 스팸 판정을 받는다. 조사 루프는 이 동작을 아예 하지 않으므로 해당이 없다.

로그인 화면이나 캡차가 뜨면 그건 속도 때문이 아니라 세션이 풀린 것이다.

## Codex Chrome 확장 연결 확인

Chrome 작업 전에 현재 도구의 브라우저·탭 목록을 읽고, 사용자가 보여준 URL·탭 제목·탭 그룹과 대조한다. 일치하는 탭이 속한 browser ID를 명시해서 선택하고, 화면에서 서비스 로그인 계정을 확인한 뒤 입력한다. `chrome` 별칭, 프로필 표시 이름, 과거 browser/tab ID만으로 대상을 확정하지 않는다.

- Chrome 프로필, 서비스 로그인 계정, ChatGPT 확장 연결은 각각 별도로 확인한다. Claude의 `select_browser` 절차를 Codex에 그대로 적용하지 않고 현재 도구가 제공하는 API를 사용한다.
- 시간 초과는 확장 비활성화·로그아웃·다른 프로필 사용의 증거가 아니다. 현재 도구 연결 오류로 기록하고, 브라우저 목록 재조회와 실제 browser ID 재선택으로 확인한다. 목록 자체가 실패하면 프로필은 미확인 상태다.
- 사용자가 확장 활성화 화면을 제공했다면 그 증거를 인정한다. 확인 없이 재설치·권한 확대·프로필 변경을 요구하지 않는다. `native pipe closed before response`는 도구 통신 오류로 구분한다.
- 2026-09-09 채용 작업: 정상 조회 당시 Chrome browser ID `2`, 표시 이름 `프로필 1`에 사람인·잡코리아와 사용자의 채용 등록 탭이 함께 있었다. 이는 당시 관찰값이며 다음 세션에서 고정값으로 재사용하지 않는다. 이후 시간 초과만으로 다른 프로필 또는 확장 꺼짐을 단정할 수 없다.

## 세션이 여럿이면 크롬 프로필을 나눠 쓴다

**로그인은 크롬 프로필 단위다.** 인스타 계정 전환은 탭이 아니라 그 프로필 전체에 걸린다.
그래서 에이전트 A가 계정 A로 일하는 중에 에이전트 B가 계정 B로 전환하면 **A 쪽도 B로 바뀐다.**
A는 그걸 모른 채 계속 돌아서 엉뚱한 계정으로 DM을 보내거나 글을 올린다. **오류는 안 난다.**
인스타가 제일 잘 물지만 로그인이 걸린 곳은 다 마찬가지다.

- **계정을 전환하기 전에 지금 어느 계정인지부터 본다.** 내가 쓰려던 계정이 아니면
  다른 세션이 쓰는 중일 수 있다. 확인 없이 전환하지 마라
- 다른 세션이 다른 계정으로 붙어 있으면 **크롬 프로필을 따로 쓴다.**
  `list_connected_browsers` 로 붙어 있는 크롬 목록을 보고 `select_browser` 로 다른 것을 고른다.
  이 PC의 쇼츠 작업은 사용자가 이미 만들어 둔 기존 Chrome 프로필 두 개(`내 Chrome`, `새 Chrome 프로필`) 중
  사용 중이지 않은 것을 고른다. **새 프로필을 만들거나 기존 프로필을 복제하지 않는다.**

  ```bash
  "/c/Program Files/Google/Chrome/Application/chrome.exe" --profile-directory="Profile 2" &
  ```

- **애매한 게 정상이다.** 다른 에이전트가 일을 끝내고 멈춰 있는데 탭만 남은 경우가 많아서,
  탭만 보고는 지금 쓰는 중인지 알 수 없다. 애매하면 프로필을 나누는 쪽으로 간다.
  프로필 하나 더 여는 비용보다 엉뚱한 계정으로 나간 DM 한 통이 훨씬 비싸다
- 프로필을 못 나눠서 전환을 했으면, 끝나고 **원래 계정으로 되돌려 둔다**
