# 노션

- **무엇에 쓰나**: 회의록, 기획 문서, 진행 상황, 제품별 논의를 읽고 쓴다
- **제어층**: L1 (Notion MCP). 막히면 L3 으로 브라우저에서 연다
- **못 하는 것**: 상대 날짜 필터("최근 7일")를 만들지 못한다. 아래 함정을 보라

---

## 어디에 무엇이 있나

먼저 드라이브 `정보/노션.md` 를 연다. 주요 페이지 주소와 구조가 거기 있다.
회의록은 웰니스박스 워크스페이스의 `회의록` 아래에 날짜별로 쌓인다.
지난 미팅 내용을 찾을 일이 제일 많다.

## 읽기

페이지 주소를 알면 바로 가져온다. 페이지 안의 표와 하위 페이지까지 같이 온다.

```
notion-fetch { id: "<페이지 URL 또는 ID>" }
```

주소를 모르면 검색부터 한다. 질문 하나에 호출 하나다. 여러 개를 한 번에 묻지 마라.

```
notion-search { query: "비아트리스 미팅", query_type: "internal" }
```

데이터베이스를 뒤지려면 먼저 `notion-fetch` 로 그 DB 를 열어 `collection://` 로 시작하는
데이터 소스 주소를 받고, 그걸 `data_source_url` 로 넘긴다.

## 쓰기

페이지를 새로 만들거나 기존 페이지에 붙일 수 있다.
**사람이 쓰던 페이지를 통째로 갈아엎지 마라.** 덧붙이거나 새 하위 페이지를 만든다.

회의록을 정리해 올릴 때는 기존 회의록 하나를 먼저 열어 **형식을 그대로 따른다.**
표 안에 넣을 내용을 본문으로 풀어 쓰거나 그 반대로 하면 사람이 다시 고친다.

## 알려진 함정

- **상대 날짜 필터를 만들지 못한다.** "최근 일주일" 같은 조건을 넣으면 **오류 없이 0건**으로 돌아온다.
  빈손으로 온 걸 "그런 문서가 없다" 로 착각하기 딱 좋다. 날짜는 `2026-08-13` 처럼 절대값으로 준다
- 첨부 파일은 본문에 `file://` 로 인코딩돼 들어온다. 파일 이름은 보이지만 내용은 안 온다.
  내용을 봐야 하면 브라우저(L3)로 열어서 받는다
- 검색이 못 찾는다고 없는 게 아니다. 페이지 제목이 애매하면 상위 페이지를 열어 목차로 내려간다
- `replace_content` 로 페이지를 통째로 다시 쓸 때는 **하위 페이지 `<page url=...>제목</page>` 태그를 새 본문에 전부 넣는다.**
  빠뜨리면 그 하위 페이지가 지워진다(기본은 오류로 막히지만 `allow_deleting_content` 를 켜면 진짜 지워진다).
  쓰기 전에 fetch 로 지금 본문을 받아 하위 페이지 목록부터 세고, 쓴 뒤에 다시 fetch 해서 절 단위로 있는지 센다
- 다른 페이지의 첨부 파일을 옮겨 붙이려면 그 페이지 fetch 결과의 `<file src="file://...">` 태그를 그대로 복사해
  `insert_content` 에 넣는다. 같은 첨부를 가리키는 새 블록이 생기고 파일을 다시 올릴 필요가 없다 (260904 확인)

## 인증이 끊겼을 때

MCP 가 인증을 요구하면 세션에서 못 푼다. 사람에게 claude.ai 커넥터 설정에서
노션을 다시 연결해 달라고 말하고, 그동안은 L3 으로 브라우저에서 읽는다.
크롬에는 이미 로그인돼 있다.
