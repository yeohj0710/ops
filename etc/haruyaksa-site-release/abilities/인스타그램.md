# 인스타그램

- **무엇에 쓰나**: 계정 지표 실측, DM 확인, 릴스 업로드, 인플루언서 조사
- **제어층**: L3 (로그인된 크롬)
- **못 하는 것**: 계정 만들기, 비밀번호 직접 입력

---

## 계정을 만지기 전에 지금 어느 계정인지 본다

**로그인은 크롬 프로필 단위다.** 계정 전환은 탭이 아니라 그 프로필 전체에 걸린다.
다른 세션이 다른 계정으로 일하는 중에 내가 전환하면 **그쪽도 같이 바뀌고, 그 세션은 모른 채
엉뚱한 계정으로 DM 을 보낸다. 오류는 안 난다.**

프로필은 용도로 갈라 쓴다.

| 프로필 | 무엇이 들어 있나 | 무엇에 쓰나 |
| --- | --- | --- |
| `사용자 이름1` | 회사 공식 계정 | 사람의 DM 발송, ops 업무 전반 |
| `새 Chrome 프로필` | 콘텐츠 계정과 반응 계정 | 쇼츠 업로드, 릴스 반응 |
| `내 Chrome` | 대체 | 위가 사용 중일 때 |

**deviceId 와 "Browser 1/2" 이름은 붙는 순서에 따라 바뀐다.** 이름으로 가리지 마라.
무엇이 로그인돼 있는지로 가린다.

다른 계정으로 붙어 있으면 전환하지 말고 프로필을 나눈다.
`list_connected_browsers` 로 목록을 보고 `select_browser` 로 고른다.
**새 프로필을 만들거나 복제하지 마라.** 로그인 세션은 복사되지 않는다.

## 지표 뽑기

**로그인된 크롬을 쓰지 않는다.** 셸에서 전용 프로필로 크롬을 띄우는 수집기가 따로 있다.

```text
node "<OPS>/manuals/insta-metrics/scripts/ig-harvest.mjs" --check
```

로그인이 없어도 릴스 조회수와 팔로워가 나온다(260831 실측). 조사 트래픽이 섭외 DM 계정에
안 쌓이는 게 이 길의 핵심이다. 그 계정이 잠기면 시딩 업무가 통째로 선다.
자세한 절차는 `manuals/insta-metrics/MANUAL.md` 에 있다.

조회수는 두 군데서 나온다. **피드 API 의 `play_count`** 와 **릴스 탭 화면 표기**다.
둘은 5% 안팎 다르니 한 산출물에 섞어 설명하지 마라. 게시물(격자) 탭에는 조회수가 아예 없다.

## DM 을 읽었으면 되돌린다

**모든 DM 확인에 걸리는 규칙이다.** 사람은 안 읽은 표시로 무엇이 새로 왔는지 안다.

1. **방을 하나라도 열기 전에 안 읽은 방 목록을 먼저 적는다.** 열고 나면 알 방법이 없다
2. 다 읽고 그 방들을 **전부** 안 읽음으로 되돌린다. 방 줄에서 오른쪽 클릭하면 메뉴가 뜬다
3. 되돌린 뒤 개수를 다시 세어 맞는지 본다

DM 목록은 가상 스크롤이라 화면에 보이는 것만 DOM 에 있다. 내리면서 모은다.

**답장은 초안만 쓰고 보내지 않는다.**

## 업로드

업로드 전에 URL 이 아니라 **Create 화면에 표시된 계정명**을 확인한다.
자르기 화면에서 원본을 고르고 9:16 세로 미리보기를 확인한다.

쇼츠 업무에서 인스타 게시 계정은 `@haruyaksa` 하나다. Create/Reels 화면에 `haruyaksa`가
표시되지 않으면 공유 버튼을 누르지 말고 계정을 전환한 뒤 업로드 화면을 다시 연다.
프로필 URL이나 Chrome 프로필 이름은 계정 확인 증거로 쓰지 않는다.

인스타는 한 업무 호출에 릴스 한 편만 게시한다. 미게시 영상이 여러 편이어도 다음 호출로 남긴다.
게시한 릴스의 최종 URL을 확보한 뒤 세 계정의 좋아요·저장·서로 공유를 먼저 처리하고,
그 다음 매뉴얼에 정한 SNS Supporter 조회수 주문을 처리한다. 두 후처리를 확인하기 전에는
업무를 완료로 보고하지 않는다.

**크롬 창이 숨어 있으면 동영상이 안 붙는다.** 창이 최소화됐거나 완전히 가려 있으면
크롬이 그 탭의 미디어 로딩을 멈춰서 업로더가 그 자리에 영영 서 있는다.
클릭과 DOM 은 숨은 탭에서도 되고 **동영상만** 안 된다. 창을 앞으로 끌어낸다.

### 영상과 이미지는 난이도가 다르다 (260831 실측)

**막히는 건 동영상 하나뿐이다. 이미지 캐러셀은 배경 탭에서 그냥 된다.**

| 무엇 | 릴스(mp4) | 카드뉴스(png 여러 장) |
| --- | --- | --- |
| 배경 탭에서 미디어가 붙나 | 안 붙는다. 팝업을 띄워 가림을 풀어야 한다 | **붙는다.** 13ms |
| 캡션 | 팝업에서 넣으면 빈 채로 나간다. 게시 뒤 수정으로 다시 넣는다 | **게시 화면에서 한 번에 들어간다** |
| 자르기 옵션 | 원본 / 1:1 / 9:16 / 16:9 | 원본 / 1:1 / **4:5** / 16:9 |

**캐러셀은 파일 input 이 `multiple` 이라 `DataTransfer` 하나에 다 담아 한 번에 넣는다.**
한 장씩 여러 번 넣는 길을 찾지 마라. 이름순이 곧 장 순서고 10장이 상한이다.

파일을 페이지로 넘기는 로컬 서버는 `manuals/shorts-pipeline/scripts/insta-file-server.mjs` 하나로
영상과 이미지를 다 다룬다. 절차는 `manuals/card-news/MANUAL.md` 의 U1~U5 에 있다.

## 알려진 함정

- **새 화면에 들어온 직후 첫 클릭은 페이지에 도달하지 않는다.** 좌표는 맞는데 클릭이 0건이다.
  **스크롤을 한 번 굴리면 그때부터 먹는다.** 새 화면에서는 스크롤 → 좌표 다시 재기 → 클릭 순서로 한다
- **계정 전환을 좌표로 누르지 마라. 바로 아래가 로그아웃이다 (260831 실측).**
  사이드바 `더 보기` 메뉴의 항목 수가 **계정마다 다르다.** 비즈니스 계정에는 `프로페셔널 대시보드` 가
  더 있어서 아래 항목이 통째로 밀린다. 다른 계정에서 잰 좌표를 그대로 쓰면 `계정 전환` 대신
  `로그아웃` 이 눌린다. 실제로 그렇게 로그아웃됐다.
  **DOM 에서 글자로 찾아 그 요소를 `.click()` 한다.**
  ```js
  [...document.querySelectorAll('*')]
    .filter(x => x.children.length === 0 && x.textContent.trim() === '계정 전환')[0]
    .closest('[role="button"],button,div[tabindex]').click();
  ```
  로그아웃됐어도 당황할 것 없다. 계정 선택 화면에 세션이 남아 있어 이름을 누르면 비밀번호 없이 들어간다.
  거기서도 좌표 클릭이 안 먹으니 같은 방법으로 `.click()` 한다
- 조사 트래픽을 발송 계정에 쌓지 마라. 스팸 판정을 받으면 정작 섭외 DM 이 막힌다
- 파일 업로드는 `컴퓨터에서 선택`으로 열린 파일 선택 창에 `setFiles`로 절대 경로를 먼저 넘긴다.
  G 드라이브 mp4 직접 입력이 확인됐다(260904). 예전 `file_upload`가 경로를 거부하거나 파일 선택이
  실패할 때만 `manuals/shorts-pipeline/scripts/insta-file-server.mjs`를 쓴다
- **Codex 쪽 크롬 런타임은 `evaluate` 가 읽기 전용이다.** `window.X = ...` 대입,
  `new Image()`, `document.createElement()`, 캔버스 저장이 안 먹는다. 값을 돌려받는 `fetch` 는 된다.
  **여기서 멈추지 마라.** 대량 수집은 셸에서 `playwright` 로 전용 프로필을 띄우면 제약이 없어진다
  (`manuals/insta-metrics/scripts/ig-harvest.mjs`). 셸이 없으면 아무것도 안 심고 결과만
  돌려주는 모양으로 바꿔 열두 개씩 끊어 부른다 (`scripts/harvest-batch.js`).
  공개 게시물 커버는 화면의 `currentSrc` 를 내부 변수로 얻은 뒤, URL 을 출력하지 않고
  Node 의 `fetch` 로 지정한 경로에 직접 저장한다. `<img>` 에 `downloadMedia` 를 쓰면
  파일 저장 대신 CDN 이미지 탭으로 넘어간다
