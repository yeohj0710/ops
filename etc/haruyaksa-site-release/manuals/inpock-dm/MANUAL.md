# 인포크링크 DM 자동화 세팅

- **부르는 말**: 인포크 세팅해줘, DM 자동화 세팅, 댓글 자동화, 자료형 릴스 세팅
- **미리 허가**: 인포크링크 자동화 규칙 저장과 켜기
- **런너**: claude
- **제어층**: L3 (로그인된 크롬)
- **한 번에 걸리는 시간**: 15~25분

---

## 무엇을 만드는 업무인가

자료형 릴스에 "댓글에 ○○ 남겨주시면 정리한 자료 보내드려요" 를 걸어두고,
댓글이 달리면 **공개 답글 + DM** 이 자동으로 나가게 세팅한다.
팔로우한 사람에게만 자료를 주는 구조라 팔로워가 늘어난다.

## 쉬운 설명

### 쓰는 상황

약사님 인스타그램에 자료형 릴스를 올렸습니다. "댓글에 '자료' 라고 남겨주시면 정리본 보내드려요" 를 걸어서 팔로워를 늘리고 싶을 때 씁니다.

### 시키는 말

Claude 나 Codex 새 세션에 이렇게 말하면 됩니다.

> G드라이브 에이전트 폴더 참고해서 인포크링크 DM 자동화 세팅 업무 해줘

어느 계정에, 어떤 단어를 댓글로 받을지, 어떤 자료 링크를 보낼지를 같이 알려주면 됩니다.
세팅이 끝난 컴퓨터에서는 "인포크 세팅해줘" 로 줄여도 됩니다.

### 진행 순서

1. 이미 로그인해 둔 크롬으로 인포크링크 관리자 화면에 들어갑니다.
2. 성적이 잘 나온 기존 세팅을 복제해서 시작합니다. 처음부터 만들면 빠뜨리는 칸이 생깁니다.
3. 네 단계를 채웁니다. 댓글에 공개 답글을 달지, 팔로워와 안 팔로우한 사람에게 다른 메시지를 보낼지, 어떤 단어가 달린 댓글에 반응할지, 어느 게시물에 걸지입니다.
4. DM 문구를 세 벌 씁니다. 모두에게 가는 것, 팔로워에게 가는 것, 아직 팔로우하지 않은 사람에게 가는 것입니다. 약사님마다 말투가 달라서 그 계정 글투에 맞춥니다.
5. 세팅한 내용을 채팅에 요약해서 찍어 줍니다. 켜기 전에 사람이 눈으로 확인합니다.

### 결과물

댓글이 달리면 공개 답글이 자동으로 달리고, 팔로우한 사람에게는 자료 링크가 DM 으로 갑니다. 아직 팔로우하지 않은 사람에게는 팔로우해달라는 안내가 먼저 갑니다.

### 되돌릴 수 없는 것

2단계에서 "팔로우 여부에 따라 다르게 보내기" 를 한 번 켜면 다시 끄지 못합니다. 누르기 전에 확인합니다.

## 어디로 바로 가나

클릭으로 헤매지 말고 주소로 간다.

| 무엇 | 주소 |
| --- | --- |
| DM 자동화 목록 | `https://link.inpock.co.kr/admin/manager/?tab=trigger` |
| 한 건 편집 | `https://link.inpock.co.kr/admin/manager/trigger/default/edit/?id=<번호>` |

홈(`/inpockhome`)의 `DM 자동화하기` 카드를 눌러도 같은 데로 간다.

## 지금 뭐가 걸려 있나는 API 로 본다

**읽기는 화면을 훑지 마라.** 로그인된 탭에서 fetch 하면 쿠키로 그냥 통한다. 화면보다 빠르고 정확하다.
쓰기는 하지 마라. 확인 전용이다.

```js
await (await fetch('https://link-rest.inpock.co.kr/managers/triggers',{credentials:'include'})).json()
```

| 무엇 | 주소 (GET) | 보는 것 |
| --- | --- | --- |
| 목록 | `link-rest.inpock.co.kr/managers/triggers` | `count`, 각 건의 `id`, `keywords`, `follow_type`, `is_active` |
| 한 건 전부 | `.../managers/triggers/<id>` | 답글 7줄, 세 탭 문구, 버튼 텍스트와 URL |
| 계정과 연동 | `.../managers/me` | `username`, `can_auto_reply`, `has_plan`, `followers_count` |
| 전체 일시정지 | `.../managers/global-pause` | `pause_triggers`, `pause_auto_reply`. **둘 다 false 여야 나간다** |

세 탭은 `default_template_group`(모든 고객), `follower_template_group`, `non_follower_template_group` 이다.
`follow_type` 이 `separate` 면 팔로우 분기가 켜진 것이다(260828 실측). 다른 값이면 안 켜진 것이니 화면에서 확인한다.

## 계정 확인이 먼저다

**화면 왼쪽 위에 지금 계정이 적혀 있다.** 세팅 전에 그걸 먼저 본다.
세 계정을 쓴다. `jessiyaksa`, `oyakstory`, `kimjejo_pharma`.
로그인 정보는 `자격증명/계정.md` 의 "약사, 인플루언서 계정" 표에 있다 (인포크는 인스타와 아이디, 비밀번호가 같다).

전환은 왼쪽 **아래**의 `로그아웃` 을 누른다(톱니바퀴가 아니다).
바로 로그아웃되지 않고 계정 전환 화면이 나온다 → 계정전환 → 셋 중 하나.

## 본보기: jessi_yaksa '다이소' 편

목록에서 성적이 압도적이다. **발송 806, 읽음 648, 클릭 320** (260820 실측).
그다음이 생리대 편 311/249/119 이고 나머지는 25/21/5, 50/41/22 수준이다.
**복제할 편은 매번 목록의 숫자를 보고 고른다.** 매뉴얼에 박힌 이름을 그대로 쓰지 마라.

> (광고❌, 협찬❌) 약사가 진짜 써보고 고른 내돈내산 제품만 추천 다이소 1,000원짜리에 3...

점 3개 → **수정** 으로 볼 수 있다.
**같은 계정에 새로 만들 때는 점 3개 → `복제` 가 가장 빠르다.** 키워드, 링크, 문구만 바꾼다.

## 실제 화면 구성 (실측)

편집 화면은 **4단계 + 다음**, 다음을 누르면 **DM 문구 화면**이 나온다.

**복제로 시작하면 단계가 거꾸로 나온다.** 복제 화면 주소는 `trigger/default/new/?from=quick&type=copy` 이고,
덜 채운 칸(게시물)이 맨 위에 펼쳐진 채 뜬다. 순서는 게시물 → 키워드 → 팔로우 분기 → 답글이다.
나머지 칸은 `(완료)` 로 접혀 있으니 열어서 확인만 하고 `다음` 을 누르면 된다.

### 1단계. 답글을 남겨볼까요?

댓글에 달리는 **공개 답글**이다. 선택지는 아니요 / 랜덤하게 / 정중하게 / 친근하게 / **직접** 다섯이다.
본보기는 `직접` 에 답글 7개를 넣고 랜덤으로 돌린다.

```
DM 공유드렸습니다🤍 확인 부탁드려요! (요청함도 확인해주세요🎁)
감사합니다💚 DM 확인 부탁드려요🔥
감사합니다☺️ DM 공유드렸으니 확인 부탁드려요! (요청함도 확인해주세요👍)
DM 전달 드렸습니다🔥 메세지 요청함도 확인 부탁드려요🙌
감사합니다☺️ DM 확인 부탁드려요!📬 (메세지 요청함도 확인 부탁드려요!)
감사합니다😍 DM 전달드렸으니 확인 부탁드려요🙌❤️
DM 전달드렸습니다 💌
```

`요청함도 확인해주세요` 를 넣는 이유는 이렇다. 안 팔로우한 사람에게 간 DM 은 요청함으로 들어가서
본인이 안 보면 모른다.

### 2단계. 팔로우 여부에 따라 다르게 보낼까요?

> **한번 설정하면 이후 수정이 불가능하다.** 화면에 그렇게 적혀 있다.

`팔로워/비팔로워 다르게 메시지를 전송할래요` 를 고른다. 본보기가 그렇게 되어 있다.
**잘못 고르면 그 건은 못 고치고 새로 만들어야 한다.** 누르기 전에 두 번 확인한다.

### 3단계. 어떤 댓글에 메시지를 보낼까요?

키워드다. 복제본에는 원본 키워드가 칩으로 남아 있으니 **칩의 X 를 눌러 지우고** 새 낱말을 넣는다.
입력칸에 치고 엔터를 누르면 칩이 된다. 사람이 준 낱말을 그대로 넣는다.

### 4단계. 어떤 게시물을 자동화할까요?

선택지가 둘이다.

- `자동화하려는 게시물을 직접 선택 할게요`: 이미 올라간 릴스를 그리드에서 고른다
- `다음에 생성되는 게시물을 자동화 할게요`: **아직 안 올린 릴스면 이걸 고른다.** 목록에 `NEXT 다음 게시물 자동화` 로 뜬다

릴스를 올리기 전에 세팅을 먼저 거는 경우가 많다. 그리드에서 못 찾겠으면 안 올라간 것이니 두 번째를 고른다.

### 다음 화면. DM 문구 (탭 셋)

아래 세 벌이 **표준 한 벌**이다. 계정을 안 가리고 그대로 쓴다.
자료 이름만 그 편에 맞게 갈아 끼우면 되고, 나머지 문장은 손대지 않는다.
(260828 에 kimjejo_pharma 세팅이 이 한 벌 그대로 들어갔다.)

**모든 고객**: 팔로우 확인용. 제일 먼저 나가는 DM.
```
댓글 남겨주셔서 감사합니다🫶
비밀 자료는 팔로워분들에게 보내드리고 있어요!
저를 팔로우해주셨다면 아래 버튼을 눌러주세요!
```
버튼: `팔로우했어요 🙌🏻`

**팔로워**: 버튼 누른 사람이 팔로워면 이게 간다. 메시지 종류는 `텍스트` / `이미지 캐러셀`.
```
감사해요! 비밀 정리 자료 전달드릴게요! 👇
```
버튼: `<자료 이름> 📩` ← **여기에 자료 링크를 넣는다**

자료 이름은 노션 페이지 제목을 줄여 쓴다. 260828 kimjejo_pharma 는 `스트레스 노화 차단 방법 7가지 📩` 였다.
문장 쪽에 자료 이름을 또 넣지 않는다. 버튼에 이름이 있으니 본문은 `비밀 정리 자료` 로 고정한다.

버튼은 미리보기 말풍선 안의 버튼을 **누르면** 아래에서 서랍이 올라온다.
서랍에 `버튼 텍스트` 와 `클릭 시 동작(URL)` 두 칸이 있고 `설정 완료` 로 닫는다.
창 세로가 짧으면 서랍이 화면 밖에 걸린다. 그때는 창을 키우거나 아래로 굴려서 본다.

**비팔로워**: 팔로우가 확인 안 되면 이게 간다.
```
앗, 팔로우 확인이 안 됐어요 😢
팔로우하셨다면 버튼을 다시 눌러주세요!
```
버튼: `팔로우 완료했어요 🙌🏻`

## 절차

1. **키워드와 자료 링크가 있는지 본다.** 없으면 시작할 때 한 번 묻는다
2. `admin/manager/?tab=trigger` 로 간다. **왼쪽 위 계정을 확인한다.** 다르면 로그아웃→계정전환
2-1. **목록이 다 뜰 때까지 8~10초 기다린다.** 처음엔 `총 0개` 로 뜬다. 이미 걸린 게 있는지 세고 시작한다
   (API 로 세면 기다릴 것도 없다. 위 "지금 뭐가 걸려 있나는 API 로 본다")
3. 같은 계정이면 본보기 편을 **점 3개 → 복제**. 다른 계정이면 `+ 자동화 추가하기`
4. 1단계 답글 7개를 넣는다(위 문구를 그 채널 말투로 다듬는다)
5. 2단계 `팔로워/비팔로워 다르게`. **되돌릴 수 없으니 확인하고 누른다**
6. 3단계 키워드, 4단계 릴스 선택
7. DM 문구 세 탭을 채운다. 팔로워 탭 버튼에 **자료 링크**를 넣는다
8. 저장하고 **목록에서 다시 열어 값이 남아 있는지 확인한다**
9. 세팅 내용을 채팅에 코드블록으로 찍는다

`<드라이브>/영상 편집/[공통] 유용한 소스/캡션 자동 생성/학습용 데이터/<사람> (@핸들)/프로필.html`

- **kimjejo_pharma**: 제조와 성분 이야기가 중심

## 알려진 함정

- **2단계 팔로우 분기는 한번 정하면 못 고친다.** 잘못 고르면 새로 만들어야 한다
- **로그아웃 버튼은 왼쪽 아래**다. 톱니바퀴가 아니다. 그리고 로그아웃이 곧 계정 전환 화면이다
- **계정을 먼저 확인한다.** 다 만들고 계정이 틀린 걸 알면 처음부터다
- 이 사이트는 SPA 라 `<a href>` 가 6개뿐이다. 링크를 찾지 말고 **주소로 바로 가거나 화면을 눌러라**
- 답글을 하나만 넣으면 같은 답글이 반복돼 스팸처럼 보인다. **여러 개 넣어 랜덤으로**
- 남의 돌아가는 편을 열어 보는 건 괜찮지만 **저장은 하지 마라.** 확인만 하고 나온다
- 키워드나 링크를 추측해서 넣지 마라
- **작업 탭이 활성 탭이 아니면 이 화면은 죽은 척한다.** 260820 에 여기서 한 시간을 썼다.
  `document.visibilityState` 가 `hidden` 이면 React 가 다시 그리지 않는다. 증상은 셋이다.
  버튼 설정 서랍이 열렸는데 화면 밖에 붙어 안 올라온다, 화면 캡처가 `Script injection timed out` 으로 죽는다,
  값을 넣어도 `__reactProps` 의 value 가 옛날 값 그대로다(그래서 `설정 완료` 가 계속 회색이다).
  **JS 로 값을 밀어 넣는 우회는 여기서 안 통한다.** 네이티브 setter 도 onChange 직접 호출도 상태에 안 붙는다.
  판정은 `document.visibilityState` 하나로 끝난다. `hidden` 이면 탭을 앞으로 보내고 다시 한다
- **다만 `hidden` 이라고 다 죽는 건 아니다(260828).** 탭이 배경인 채로 목록 클릭, 단계 펼치기,
  탭 전환, 하이드레이션이 전부 정상이었다. 화면 캡처도 됐다. 260820 증상은 버튼 설정 서랍 단계에
  몰려 있는 것으로 보인다. **읽고 확인하는 일은 배경 탭에서 그냥 해라.** 문구를 넣고 저장하는 단계에서만
  탭을 앞으로 세운다
- **화면은 값이 붙기 전에 기본값을 먼저 보여준다. 여기가 제일 위험하다(260828).**
  목록은 `총 0개 / 아직 자동화된 게시물이 없어요` 로 뜨고, 편집 화면은
  `남기지 않음`, `동일하게 전송`, `모든 댓글`, `직접 선택` 에 전부 `(완료)` 를 달고 뜬다.
  **8~10초 지나야 진짜 값으로 바뀐다.** 로딩 표시가 없어서 빈 계정으로 착각하기 딱 좋다.
  세팅이 있는 계정을 0개로 보고 새로 만들면 중복이 생기고, 기본값 상태에서 `다음` 을 눌러 저장하면
  걸어둔 설정이 통째로 날아간다. **읽기 전에 세고, 값이 뜬 걸 보고 나서 누른다**
- 지운 버튼은 사라지지 않고 `is_active:false` 로 남는다. API 에 버튼이 둘로 보여도
  화면과 실제 발송은 `is_active:true` 인 하나만 쓴다. **API 만 보고 중복이라고 판단하지 마라**
- 답글 스타일 칩이 `정중하게` 인데 7줄은 직접 고쳐 둔 건이 있다(kimjejo_pharma 260828).
  실제로 나가는 건 아래 7줄이니 그대로 두면 된다. **칩을 `직접` 으로 고쳐 놓겠다고 다시 누르지 마라.**
  칩을 바꾸면 7줄이 프리셋으로 초기화된다
- **다른 세션이 같은 크롬을 쓰면 내 탭이 계속 뒤로 밀리고 탭 그룹째 닫히기도 한다(260828).**
  Ctrl+9 로 마지막 탭을 잡는 것도 그 사이 남이 만든 탭에 걸려서 안 먹는다.
  이럴 때 화면을 붙잡고 씨름하지 말고 **확인은 위의 API 로 끝낸다**

## 묻는 건 이것 하나뿐

**키워드와 자료 링크.** 지어낼 수 없다. 안 줬으면 시작할 때 한 번 묻는다.

나머지는 묻지 않는다.
- 계정이 안 정해졌으면 **그 릴스가 올라간 계정**에 건다
- 문구는 본보기와 채널 프로필을 보고 정한다
- 세팅은 고칠 수 있다(팔로우 분기만 빼고). 완벽을 기다리지 말고 만들어 놓고 보고한다
