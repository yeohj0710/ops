# 프리랜서 급여 알프레드 등록

- **부르는 말**: 프리랜서 급여 등록해줘, 알프레드 급여 등록, 원고료 지급 처리해줘, 인플루언서 원고료 정산해줘, 편집자 편집비 정산해줘, 이번 달 사업소득 등록해줘, 혜움 급여입력 해줘, 3.3 떼고 지급 준비해줘
- **미리 허가**: 알프레드 급여카드 사업소득 행 등록, 드라이브 정산 폴더 생성과 파일 저장, 시딩 시트 정산자료와 지급 칸 갱신, 카톡 지급 요청문 초안 작성. 송금은 하지 않는다
- **런너**: claude
- **제어층**: L1 → L3
- **한 번에 걸리는 시간**: 40~60분

`<드라이브>` 는 `<OPS>/machine.json` 의 `drive_root` 다. 보통 `G:/내 드라이브`.

---

## 무엇을 만드는 업무인가

한 달치 프리랜서 지급을 **알프레드 급여카드 사업소득에 등록**하고, 대표가 그대로 송금할 수
있는 상태까지 만든다. 끝났을 때 넷이 남아 있어야 한다.

- 알프레드 그 달 급여카드 `사업` 탭에 이번 대상이 전부 올라간 상태
- 프로젝트 폴더에 그 달 `OO_혜움_급여입력_사업소득_YYMM.xlsx`
- 프로젝트 폴더에 갱신된 `OO_인플루언서_통장계좌_정리.xlsx` (세후 실지급액)
- 카톡에 올릴 지급 요청문 초안

**송금은 이 업무에 없다.** 등록과 요청문까지 하고 이체는 대표가 한다.

## 실행 계약

호출하면 대상 명단 뽑기부터 알프레드 등록과 요청문 작성까지 한 번에 간다.
명단만 만들고 멈추지 않는다. 한 사람이 막혀도 나머지는 계속 등록하고 막힌 사람만 사유를 적는다.
**송금과 이체 비밀번호만 사람에게 넘긴다.**

## 이 업무가 다루는 두 갈래

돈 나가는 사유는 둘인데 끝나는 자리는 같다. 둘 다 알프레드 `사업` 탭이다.

| 갈래 | 누구 | 금액을 어디서 읽나 |
| --- | --- | --- |
| 인플루언서 원고료 | 시딩 확정자 중 업로드까지 끝난 사람 | 시딩 시트의 합의 단가 |
| 편집자 편집비 | 사업자등록 없는 개인 편집자 | 검수 완료 편수 곱하기 편당 단가 |

**셋째 갈래는 여기서 처리하지 않는다.** 사업자등록이 있는 편집자다.
세금계산서를 청구로 발행받아 매입 증빙으로 처리한다. 알프레드 급여카드에 넣지 마라.
2026-07 기준 엄성미님(모먼트플로우)이 여기 해당한다. 편당 공급가액 15,000원에 부가세 10% 별도다.

## 준비물

- **크롬에 알프레드 로그인.** `https://app.alfred.kr/` 이다. 계정은 드라이브 `자격증명/계정.md`
- 대상별 **통장사본과 신분증사본.** 없으면 그 사람은 이번 달에서 뺀다
- 대상별 **주민등록번호와 계좌.** 프로젝트 폴더에만 둔다
- 편집자 건이면 그 달 **검수 완료 편수**

파일 이름의 `혜움` 은 알프레드를 가리킨다. 같은 것이다. 이름을 바꾸면 지난달 것과 안 맞으니 그대로 쓴다.

## 절차

1. **대상 명단을 만든다 (L1)**

   **인플루언서 갈래.** 시딩 시트 `인플루언서` 탭을 gviz CSV 로 통째로 받는다. 화면을 훑지 마라.

   ```js
   const u = "https://docs.google.com/spreadsheets/d/" + ID
     + "/gviz/tq?tqx=out:csv&headers=2&sheet=" + encodeURIComponent("인플루언서");
   const t = await (await fetch(u, { credentials: "include" })).text();
   ```

   진행 단계 12칸에서 **`⑩업로드` 가 찍혔고 `⑫지급` 이 안 찍힌 행**이 이번 대상이다.
   금액은 그 행의 `④합의 단가` 를 읽는다. **열 문자를 외워 쓰지 마라.** 2행 헤더 이름으로 매핑한다.

   **편집자 갈래.** 편집자가 보내오는 편수는 **그 달치다.** 계약이 매월 말일 기준 정산이라
   "8월 31일 기준 총 29개" 는 8월에 한 29편이라는 뜻이다. 누적이 아니다.
   7월에도 "7월 31일 기준 총 17개" 로 왔고 그게 7월 한 달치였다.

   그래도 **드라이브에서 편수를 실측해 대조한다.** 이게 유일하게 믿을 수 있는 대조다.

   ```bash
   # 편집자 폴더를 최신 영상 파일 수정월로 갈라 센다. 영상 1편 = 폴더 1개
   # <드라이브>/영상 편집 아래를 훑고, 폴더 이름이 편집자 이름인 것만 본다
   ```

   260831 실측이다. 권성은님 폴더 45개가 7월 18편, 8월 27편으로 갈렸다.
   편집자가 말한 17편과 29편에 각각 맞는 규모다. 파일 수정 시각이 검수 완료 시점과
   정확히 같지는 않아서 **한두 편 차이는 정상이다.** 규모가 맞는지만 본다.

   **누적으로 넘겨짚지 마라.** 260831 에 내가 29편을 누적으로 읽고 7월 17편을 빼서
   12편으로 넣었다. 뺄셈이 435,000 빼기 255,000 으로 딱 떨어져서 맞는 줄 알았는데
   틀렸다. **뺄셈이 맞아떨어지는 것은 증거가 아니다.** 아무 두 숫자나 빼면 떨어진다.
   드라이브를 세어 보고서야 8월에만 27편이 있는 게 나왔다.

   노션 편집 진행도는 **편수 근거로 쓸 수 없다.** 약사 인플루언서 영상만 들어 있어서
   훨씬 적게 나온다. 권성은님은 노션에 4건인데 실제는 29편이었다.

   **지난달 카드는 그래도 연다.** 중복 등록이 아닌지 보는 용도다. 지난달과 이번 달
   금액이 같으면 같은 건을 두 번 넣은 것일 수 있다.

   결과를 `<OPS>/work/<taskId>/대상.json` 에 남긴다. 사람마다 갈래, 표시명, 세전금액, 근거 한 줄.
   **주민등록번호와 계좌는 여기 넣지 마라.**

2. **정산자료를 확인한다 (L1)**

   프로젝트 폴더의 `인플루언서 통장사본 및 신분증` 을 본다.
   사람마다 `OOO님_신분증사본.jpg` 와 `OOO님_통장사본.jpg` 두 장이 있어야 한다.

   **한 장이라도 없으면 그 사람만 이번 달에서 뺀다.** 뺀 사람을 보고에 적고 나머지는 계속 간다.
   **이게 보이면 성공**: 대상 인원수와 자료가 갖춰진 인원수가 같거나, 차이가 보고에 적혀 있다.

3. **통장계좌 정리표를 갱신한다 (L1)**

   `<프로젝트폴더>/OO_인플루언서_통장계좌_정리.xlsx` 다. 지난 회차 파일을 이어 쓴다.
   열은 이렇다.

   | 열 | 넣는 값 |
   | --- | --- |
   | 번호 | 순번 |
   | 계정 | 인스타 표기 그대로 |
   | 표시명 | 부르는 이름 |
   | 예금주 | 통장사본과 글자까지 같아야 한다 |
   | 은행 | 통장사본 그대로 |
   | 계좌번호 | 하이픈 포함 그대로 |
   | 금액 | **세후 실지급액** |
   | 금액 비고 | `세전 50,000원 - 원천징수 1,650원` 꼴 |
   | 비고 | 업로드일, 지급일 같은 것 |

   **금액 칸이 세후라는 것을 잊지 마라.** 여기만 세후고 알프레드는 세전이다.

4. **알프레드 급여입력 양식을 채운다 (L1)**

   양식은 알프레드가 준다. 5번 단계 화면의 `급여입력 양식 다운로드` 로 받는다.
   지난 회차 파일을 복사해 써도 된다.

   시트가 셋이다. `일용직`, `사업소득`, `기타소득`. **`사업소득` 시트만 쓴다.**

   | 열 | 넣는 값 |
   | --- | --- |
   | 번호 | 순번 |
   | 성명 | 필수. 신분증 이름 |
   | 주민등록번호 | 필수. 숫자만 또는 하이픈. 다른 문자는 안 된다 |
   | 소득구분 | `기타자영업(프리랜서)` |
   | 지급액 | 필수. **세전** |
   | 내/외국인구분 | 비우면 내국인 |
   | 세금공제여부 | `세금공제전` |

   `<프로젝트폴더>/OO_혜움_급여입력_사업소득_YYMM.xlsx` 로 저장한다.
   **양식의 행 위치나 머리글을 손대지 마라.** 시트에 경고가 박혀 있고 실제로 업로드가 깨진다.

5. **알프레드 급여카드에 올린다 (L3)**

   `https://app.alfred.kr/company/payroll` 을 이미 로그인된 크롬으로 연다.
   `입력가능` 아래 그 달 카드를 누른다. **주소의 숫자를 외워 쓰지 마라. 달마다 다르다**
   (26년 6월은 232610, 26년 8월은 244826이었다).
   지난 달을 확인만 할 때는 `완료` 목록에서 열면 되고, 그쪽 주소는 `payroll/2026-07-01/business`
   처럼 날짜 꼴이다.

   `사업` 탭을 누른다. **올리기 전에 지금 인원수와 합계를 적어 둔다.**
   탭 이름의 `사업(N명)` 과 표 맨 아래 합계다. 위쪽에 버튼이 셋 있다.

   | 버튼 | 언제 | 기존 행 |
   | --- | --- | --- |
   | 이전 급여 불러오기 | 전에 한 번이라도 지급한 사람일 때. **1순위다** | 그대로 두고 붙인다 |
   | 급여 대장 엑셀 업로드 | 처음 지급하는 사람이 여럿일 때 | 회차마다 확인한다 |
   | 행 추가 | 처음 지급하는 사람이 한둘일 때 | 그대로 두고 붙인다 |

   **`이전 급여 불러오기` 를 먼저 시도한다.** 귀속연월을 고르면 그 달에 지급한 사람이 뜨고,
   체크해서 `불러오기` 를 누르면 **주민등록번호까지 그대로 실려 온다.** 금액만 이번 달 값으로
   고치면 끝난다. 260831 에 이 길로 권성은님을 넣었다.

   **에이전트는 주민등록번호를 치지 않는다.** 불러오기로 안 되는 처음 지급자는
   엑셀 업로드로 가거나, 그 칸만 사람에게 넘긴다.

   **`임시 저장` 을 반드시 누른다.** 페이지 맨 아래에 있다. 화면에서 합계가 바뀌어도
   저장을 안 하면 새로고침에 통째로 사라진다. 260831 에 한 번 날렸다.

   **`계산 요청` 은 누르지 마라.** 그 달 급여카드 전체를 세무사에게 넘겨 `2. 계산중` 으로
   보내는 단계다. 근로소득까지 같이 넘어간다. 이 업무의 범위가 아니다.

   **이게 보이면 성공**: `임시 저장이 완료되었습니다` 가 뜨고, 탭 이름이 `사업(N명)` 으로 늘고,
   **새로고침한 뒤에도** 합계가 그대로다. 행마다 사업소득유형이 `기타자영업(프리랜서)`,
   세금공제 여부가 `세금공제전` 인지도 본다.

   숫자가 안 맞으면 그 행의 `이 행 삭제` 로 지운다. `전체 삭제` 는 남의 행까지 날린다.

6. **지급일을 맞춘다 (L3)**

   행마다 `지급일` 이 그 달 말일인지 본다. 다르면 고친다.
   실제 이체일(다음 달 10일)과 다른 것이 정상이다.

   **"돈이 9월에 나가는데 왜 8월 카드냐" 는 질문이 반드시 나온다.** 이 회사는 일한 달 기준으로
   넣는다. 260810 에 실측했다. 유현일님이 그날 "7월 31일 기준 17편" 으로 정산을 올렸고
   대표님이 그날 이체했는데, 알프레드에는 **7월 급여카드에 지급일 2026.07.31 로** 들어갔다.
   혜움이 그대로 받아 7월 카드를 완료 처리했다. 근로소득 카드도 같은 방식이다.
   26.07급여를 2026.08.10 에 이체했는데 7월 카드에 있다.

   그러니 8월 말일 기준으로 정산한 것은 이체가 9월 10일이어도 **8월 카드**다.
   다음 달 카드는 그 달이 시작해야 열린다. 8월 31일에는 9월 카드가 아예 없다.

7. **지급 요청문을 만든다 (L1)**

   카톡 업무방에 올릴 초안을 `<OPS>/work/<taskId>/지급요청.md` 에 쓴다. 이렇게 적는다.

   - 무슨 건 몇 명인지
   - 세전 합계와 세후 합계
   - 사람별 은행, 계좌, 세후 금액은 **통장계좌 정리표 경로로 넘긴다.** 본문에 계좌를 늘어놓지 않는다
   - 자료가 없어서 이번에 뺀 사람

   **보내지는 않는다.** 초안까지가 이 단계다.

8. **시트와 노션을 갱신한다 (L1)**

   시딩 시트 `⑪정산자료` 와 `⑫지급` 을 찍는다. **시트 쓰기는 codex 런너가 맡는다.**
   claude 런너면 붙여넣을 프롬프트를 만들어 사람에게 준다. 프롬프트 첫 줄에
   "2행 헤더를 먼저 읽어서 열 위치를 확인하고 시작하라" 를 넣는다.

   편집자 갈래는 노션을 고치지 않는다. 편수만 읽는 쪽이다.

9. **보고를 남긴다 (L1)**

   `<드라이브>/에이전트/보고/<날짜>-프리랜서급여.md` 다.
   대상 인원, 세전 합계, 세후 합계, 뺀 사람과 사유, 알프레드 등록 결과를 적는다.

## 알려진 함정

- **원천징수액을 손으로 계산하면 알프레드와 몇 원 어긋난다** → 알프레드는 소득세와
  지방소득세를 각각 10원 미만 절사한다. 255,000원이면 손계산 3.3% 는 8,415원인데
  알프레드는 7,650 더하기 760 으로 8,410원이다. **알프레드 값이 맞다.**
  카톡 요청문에도 알프레드 차인지급액을 적는다
- **편수를 누적으로 넘겨짚어 반으로 깎았다** → 260831 에 실제로 낸 사고다.
  "8월 31일 기준 총 29편" 을 계약 시작부터의 누적으로 읽고 7월 17편을 빼서 12편을 넣었다.
  435,000 빼기 255,000 이 180,000 으로 떨어지고 29 빼기 17 이 12로 떨어지니 맞는 줄 알았다.
  **뺄셈이 떨어지는 것은 아무 증거가 아니다.** 사용자가 물어봐서 드라이브를 세어 보니
  8월에만 27편이었다. 편수는 그 달치다. **문구만 보고 정하지 말고 드라이브에서 센다**
- **임시 저장을 안 누르면 통째로 사라진다** → 표에서 합계가 바뀌는 것은 화면일 뿐이다.
  페이지 맨 아래 `임시 저장` 을 누르고 **새로고침해서 남아 있는지 확인한다**
- **`계산 요청` 을 누르면 그 달 전체가 세무사에게 넘어간다** → 근로소득까지 같이 간다.
  사업소득 한 줄 넣으려고 누를 버튼이 아니다
- **세전과 세후를 바꿔 넣는 사고가 제일 잦다** → 알프레드는 세전, 이체는 세후다.
  50,000원이면 원천징수 1,650원, 실지급 48,350원이다. 두 숫자를 한 표에 같이 적어 두면 안 헷갈린다
- **사업자 편집자를 급여카드에 넣지 마라** → 사업자등록이 있으면 세금계산서 건이다.
  공급가액에 부가세 10%가 붙고 매입 증빙으로 간다. 급여카드에 넣으면 이중으로 잡힌다
- **급여카드 주소의 숫자가 달마다 바뀐다** → 지난 회차 주소를 그대로 열면 다른 달을 고친다.
  `company/payroll` 목록에서 `입력가능` 카드를 눌러 들어간다
- **완료된 달은 못 고친다** → 카드 상태가 `3. 완료` 면 읽기만 된다.
  놓친 건은 그 달에 못 넣고 다음 달로 넘긴다
- **양식을 변형하면 업로드가 조용히 깨진다** → 열을 늘리거나 머리글을 고치지 마라.
  주민등록번호에 공백이나 문자가 섞여도 깨진다
- **업로드 안 한 사람에게 먼저 지급하지 마라** → 시딩 조건이 업로드 확인 뒤 지급이다.
  `⑩업로드` 가 안 찍혔으면 대상이 아니다
- **편집자 편수의 월 경계가 애매하다** → 노션 편집 진행도에 `검수 완료일` 칸이 없다.
  `업로드일` 로 거르되 편집자가 보낸 정산 요청 편수와 대조한다. 다르면 사람에게 묻는다
- **외국인 인플루언서는 두 갈래로 갈린다** → 갈림목은 국적이 아니라 한국에 사느냐다.
  **외국인등록증과 한국 계좌가 둘 다 있으면** 세법상 거주자라 이 절차 그대로 3.3% 로 들어간다.
  한국인 등록과 다른 칸은 둘뿐이다. 주민등록번호 자리에 **외국인등록번호 13자리**,
  그리고 **내/외국인구분에 `외국인`** (한국인은 비운다).
  **둘 중 하나라도 없으면** 비거주자라 22% 원천징수 건이고 이 절차로 넣으면 안 된다.
  특히 **여권번호로 넣는 것은 금지다.** 여권번호를 쓴다는 건 한국에 안 산다는 뜻이라
  나중에 3.3 과 22 의 차액을 추징당한다. 그 사람은 빼고 보고에 적는다.
  분기표와 받을 자료는 노션 "해외 인플루언서 사례비 지급 관련 조사" 에 정리해 뒀다
  (https://app.notion.com/p/3cd3b1f9b9ae806c9529dea721addd53).
  22% 건의 해외송금 창구(센트비즈, PayPal 비즈니스)는 2026-08-31 기준 아직 개설 전이다
- **예금주와 신분증 이름이 다른 경우가 있다** → 가족 계좌를 준 것이다.
  본인 명의 계좌를 다시 받는다. 계약서가 본인 명의 계좌로 지급한다고 못박혀 있다
- **주민등록번호가 빈 행은 `임시 저장` 이 막는다 (260904 실측)** → "급여내역에 잘못된 정보가
  포함되어 있습니다. 붉은색 영역을 수정하신 후 저장해 주세요" 모달이 뜨고 **한 행도 저장되지 않는다.**
  처음 지급하는 사람을 `행 추가` 로 넣으면 주민등록번호 칸이 붉게 남는데 에이전트는 그 칸을 못 채운다.
  **일을 이렇게 가른다.** 에이전트가 나머지 칸(성명, 소득유형, 세금공제전, 지급액)을 다 채우고,
  **그 한 칸만 사람에게 부탁하고, 사람이 넣으면 에이전트가 이어서 `임시 저장` 을 누르고 새로고침으로 확인한다.**
  사람에게 저장까지 떠넘기지 마라. 260904 일동제약 출연진 2명을 이 순서로 끝냈다
- **저장 안 된 행은 새로고침 한 번에 통째로 사라진다 (260904 실측)** → 위 상황에서 행을 채워 두고
  탭 제목만 바꿔 사람에게 넘겼더니, 그 사이 탭이 새로고침되면서 두 행이 다 날아갔다.
  사람은 "알프레드에 안 되어 있다" 는 화면을 보게 된다. **채워 놓은 것은 저장돼야 존재한다.**
  사람 손이 필요한 칸이 있으면 **그 자리에서 부탁해 바로 받고 즉시 저장한다.** 대기 상태로 두지 마라.
  보험으로 같은 내용을 급여입력 엑셀(주민번호 빈칸)에도 남겨 두면 `급여 대장 엑셀 업로드` 로 되살릴 수 있다
- **알프레드 표는 Handsontable 이라 한글 타이핑이 셀에 안 들어간다 (260904 실측)** → `type` 으로 "전종열" 을
  쳐도 셀이 비어 있고 숫자만 들어간다. 되는 길은 이렇다. 셀을 고른 뒤 **F2** 로 편집기를 열고,
  `document.activeElement`(textarea.handsontableInput) 의 value 에 값을 넣고 `input` 이벤트를 쏜 다음 **Enter**.
  드롭다운 칸(사업소득유형)도 같은 방법으로 `기타자영업(프리랜서)` 를 넣으면 목록 첫 줄에 걸려 Enter 로 들어간다.
  숫자 칸은 그냥 타이핑해도 된다
- **셀은 좌표로 누르지 말고 td 에 mousedown 을 쏴서 고른다** → `행 추가` 뒤에 표가 한 줄 밀려서
  좌표로 누른 클릭이 윗줄에 들어갔고 전종열 행 이름을 유채민으로 덮어썼다.
  `.ht_master` 첫 번째 것의 `tbody tr` 에서 행을 찾아 그 td 에 `mousedown` `mouseup` `click` 을
  `dispatchEvent` 하면 배경 탭에서도 그 셀이 `td.current` 가 된다. 합계 줄은 맨 마지막 tr 이라
  새로 넣은 행은 뒤에서 두 번째다. `.ht_master` 가 여럿이면 드롭다운 목록이 열린 것이니 첫 번째만 본다
- **`이전 급여 불러오기` 대화상자는 `position: fixed` 오버레이라 `offsetParent` 로는 못 찾는다 (260904)** →
  `getBoundingClientRect()` 크기로 보이는지 판정한다. 안에 `귀속연월로 검색` 과 `사람 단위로 검색` 탭이 있고,
  사람 탭에는 placeholder 가 `성명 입력` 인 input(type 속성 없음)과 돋보기 버튼이 있다.
  **배경 탭에서는 검색이 안 돈다.** 귀속연월 탭은 `불러오는 중입니다.` 에서 멈추고, 사람 탭은 native setter 로
  이름을 넣고 Enter 와 돋보기 클릭을 쏴도 7월에 있는 권성은까지 `전체 0명` 으로 나왔다.
  화면 캡처도 `Script injection timed out` 으로 죽는다. 이 대화상자를 쓰려면 사람이 탭을 앞으로 세워야 한다.
  대신 **완료 카드를 직접 열어 읽는 것이 배경 탭에서도 된다.** `payroll/2026-06-01/business` 꼴이다
- **Handsontable 은 보이는 12줄만 그린다. 이름 전수 확인은 스크롤해서 모아야 한다 (260904 실측)** →
  처음 지급하는 사람인지 보려고 6월 카드(사업 33명)를 열었더니 12명만 잡혀서 없는 줄 알 뻔했다.
  `.ht_master .wtHolder` 를 200px 씩 내리면서 매번 이름을 `Set` 에 모으면 33명이 다 나온다.
  이렇게 확인해서 전종열, 김두영, 유채민 세 명은 전에 지급한 적이 없고 `이전 급여 불러오기` 로는
  주민등록번호를 못 실어 온다는 것을 확정했다

- 해외송금이 필요한 사람이 나왔을 때
