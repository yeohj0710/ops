### 화면이 멀쩡해 보이는데 아무 일도 안 일어날 때, 이 넷부터 본다

넷 다 **엉뚱한 얼굴로 돌아온다.** 오류가 안 나거나, 나더라도 원인과 상관없는 말이라
엉뚱한 데를 파게 된다. 260818 에 이것들로 몇 시간을 썼다.

**1. 새 화면에 들어온 직후 첫 클릭은 페이지에 도달하지 않는다.**

주소를 옮기거나 로그인 계정을 바꾼 바로 다음이다. 캡처 단계에 리스너를 걸고 세어 보면 클릭이 0건이다.
좌표를 의심하게 되는데 좌표는 맞다. `find` 가 준 `ref` 로 눌러도 마찬가지다.

**스크롤을 한 번 굴리면 그때부터 먹는다.** 스크롤은 처음부터 잘 들어간다.
그러니 새 화면에서는 **스크롤 → 좌표 다시 재기 → 클릭 → 결과 확인** 순서를 습관으로 한다.

**2. 크롬 창이 숨어 있으면 동영상이 안 붙는다.**

창이 최소화됐거나 다른 창에 완전히 가려 있으면 `document.visibilityState` 가 `hidden` 이 되고
크롬이 그 탭의 **미디어 로딩을 멈춘다.** 영상을 읽어야 다음으로 가는 화면(인스타 업로더 같은)이
그 자리에 영영 서 있는다. 클릭과 DOM 은 숨은 탭에서도 잘 된다. **동영상만** 안 된다.

판정은 페이지에서 직접 한다. `URL.createObjectURL(file)` 로 `<video>` 를 만들고
`loadedmetadata` 를 기다려 안 오면 창이 숨은 것이다. 고치는 건 L1 이다.

```powershell
# Chrome_WidgetWin_1 창을 EnumWindows 로 훑어 제목이 맞는 것 하나만 고른다
[W]::ShowWindow($h, 9); [W]::SetForegroundWindow($h)
```

창을 전부 복원하면 **마지막 것이 앞에 서서** 헛일이 된다. 하나만 골라야 한다.
창 제목은 그 창의 **활성 탭 제목**이라, 내 탭이 뒤에 있으면 제목으로 못 찾는다.
그럴 땐 **그룹에 탭을 하나만 남긴다.** 나머지를 닫으면 남은 탭이 활성이 된다.

**3. 어떤 화면에서는 `form_input` 과 `find` 만 45초 타임아웃으로 죽는다.**

`javascript_tool` 도 `computer` 도 멀쩡한데 이 둘만 "Page still loading (executeScript waited 45000ms
for document_idle)" 로 돌아온다. 260818 김제조 보드에서 실측했다. 페이지가 `document_idle` 을 영영
안 주는 구조면 그 둘이 걸린다. `document.readyState` 를 찍어 보면 `complete` 라 더 헷갈린다.

**막히면 도구를 바꾼다.** 값은 `javascript_tool` 로 넣고(`input` 과 `change` 를 같이 쏜다),
누르기는 `computer` 로 한다. 요소를 찾는 것도 `find` 대신 `javascript_tool` 로
`getBoundingClientRect()` 를 재서 좌표를 뽑는다. 화면 캡처 크기와 `innerWidth` 가 다르면
비율을 곱해야 한다(`k = 캡처폭 / innerWidth`). **창 크기는 작업 중에도 바뀌니 매번 다시 잰다.**

**4. `form_input` 은 값만 넣고 앱 상태를 안 바꾼다.**

React 화면에서 자주 문다. 칸에 값은 보이는데 그 값으로 계산되는 금액이나 합계, 다음 버튼이
안 깨어난다. `input` 과 `change` 이벤트를 손으로 쏴도 안 되는 경우가 있다.

**계산에 쓰이는 칸은 진짜 타이핑으로 넣는다.** 세 번 클릭해 기존 값을 잡고 친다.
넣은 뒤에는 **값이 아니라 결과를 확인한다.** 금액이 바뀌었는지, 버튼이 켜졌는지 본다.

### 팝업과 새 창은 안 잡힌다. 주소를 가로채서 내 탭에서 연다

**실측한 것.** 페이지가 `window.open` 으로 띄운 팝업도, `target="_blank"` 로 연 새 탭도
`tabs_context_mcp` 목록에 **안 나온다.** 그룹 밖에 생기기 때문이다. 화면에는 보이는데 만질 수가 없다.
헤매지 말고 아래대로 한다.

**1. 누르기 전에 가로채기를 심는다.**

```js
window.__opened = [];
const _open = window.open;
window.open = function(u, ...r){ if(u) window.__opened.push(String(u)); return _open.call(window, u, ...r); };
document.addEventListener('click', e => {
  const a = e.target.closest && e.target.closest('a[target="_blank"]');
  if (a && a.href) window.__opened.push(a.href);
}, true);
```

**2. 버튼을 누른다. 3. `window.__opened` 를 읽는다. 4. 그 주소를 내 탭에서 연다.**

```
navigate {tabId: <내 탭>, url: <가로챈 주소>}      기존 탭에서 이어서
tabs_create_mcp → navigate                          원래 탭을 남겨야 하면
```

이제 그 화면은 내 탭이라 `read_page`, `form_input`, 클릭이 다 된다.

**팝업이 아예 안 뜰 때도 있다.** 확장이 만든 클릭은 사용자 제스처로 안 쳐줘서 팝업 차단기에 막힌다.
위 가로채기는 차단돼도 주소를 남기니 그대로 쓰면 된다.

**같은 탭에서 열어버리는 방법**도 있다. 폼 입력만 하면 되는 팝업엔 이게 제일 간단하다.

```js
window.open = u => { if(u) location.href = u; return null };
document.querySelectorAll('a[target="_blank"]').forEach(a => a.removeAttribute('target'));
```

단 **OAuth 와 결제 인증창에는 쓰지 마라.** 그건 팝업이 부모 창에 결과를 돌려주는 구조라 흐름이 깨진다.
그런 창은 주소를 가로채 새 탭에서 열고, 끝나면 원래 탭으로 돌아간다.

**브라우저 밖 창은 여기서 못 만진다.** 윈도우 파일 선택창, 공동인증서 창, ActiveX 결제창이 그렇다.
그건 L4 로 가야 하는데 컴퓨터 제어는 브라우저가 읽기 등급이라 클릭이 막힌다. 이 경우만 사람을 부른다.

### 내 페이지로 File 을 넘길 때는 `rel="opener"`

로컬 서버를 띄워 `postMessage` 로 File 을 건네는 방법을 쓸 때다.
`window.open` 은 첫 번째만 되고 그 뒤로 팝업 차단에 걸리니 임시 `<a>` 를 만들어 진짜로 클릭하는데,
`target="_blank"` 만 주면 크롬이 **기본으로 `noopener`** 를 걸어 `window.opener` 가 `null` 이 된다.
보내는 쪽이 돌려보낼 길이 없어진다. `rel="opener"` 를 같이 준다.

## 구글 시트를 만질 때

**읽기는 화면을 훑지 마라. gviz 로 CSV 를 통째로 받는다.** 로그인된 크롬 탭에서 같은 출처로 fetch 하면 된다.
998행짜리 시트도 한 번에 오고, 눈으로 세는 것보다 정확하다.

```js
const u = `https://docs.google.com/spreadsheets/d/${ID}/gviz/tq?tqx=out:csv&headers=2&sheet=${encodeURIComponent(탭이름)}`;
const t = await (await fetch(u, {credentials:"include"})).text();
```

- `headers=` 는 **머리글이 몇 행인지** 알려주는 값이다. 제목 행이 따로 있으면 `headers=2` 로 줘야 첫 줄에 진짜 헤더가 나온다.
  `headers=0` 으로 두면 gviz 가 열마다 자료형을 정해 버려서, **숫자 열과 체크박스 열의 헤더 글자를 조용히 버린다.**
  팔로워나 금액 열의 헤더만 빈칸으로 나오면 이 문제다. 값은 멀쩡해서 더 헷갈린다.
- `export?format=csv` 는 쓰지 마라. 다른 호스트로 넘겨서 CORS 에 막힌다. gviz 는 같은 출처라 통한다.
- 탭 이름과 gid 를 모으려면 `.docs-sheet-tab` 을 하나씩 눌러 `location.hash` 를 읽는다.

**쓰기는 창이 보여야 한다.** 시트 편집기는 탭이 가려지면 입력을 흘린다. 화살표 키가 열 번 중 예닐곱 번만 먹고
나머지는 오류도 없이 사라진다. `repeat` 를 줘도 똑같다. 좌표를 의심하게 되는데 좌표 문제가 아니다.

- `document.visibilityState` 가 `hidden` 이면 그 상태다. 최소화가 아니라 **다른 창에 완전히 가려도** 그렇게 된다
- 키를 한 번 보내고 `#t-name-box` 값이 기대만큼 안 움직였으면 흘린 것이다
- 화면 캡처가 `Script injection timed out` 으로 죽는 것도 같은 원인이다

창을 앞으로 못 끌어내면 **대량 편집을 여기서 하지 마라.** 지우기와 붙여넣기가 반쯤 먹으면 원장이 깨진다.
그럴 땐 Codex 로 넘긴다. 넘길 때 넣을 수식과 검증할 숫자를 같이 적어 준다.

**범위 선택은 주소로 한다.** 이름 상자를 JS 로 `focus()` 하면 렌더러가 45초 타임아웃으로 얼어붙는 일이 있다(260819 실측).
대신 주소에 `?gid=<gid>&range=I3` 을 붙여 새로 열면 그 칸이 잡힌 채로 뜬다.
**이미 그 gid 에 떠 있는 탭에서는 안 먹는다.** 새로 이동해야 한다.

## 로그인 창을 만났을 때

**사람을 부르기 전에 이 순서로 한다.** 대부분 1번이나 2번에서 끝난다.

1. `tabs_context_mcp` 로 이미 그 사이트 탭이 열려 있는지 본다. 세션이 살아 있으면 로그인이 안 뜬다
2. 화면에 **"구글로 로그인"** 이나 SSO 버튼이 있으면 그걸 누른다. 팝업이 뜨면
   위 "팝업과 새 창" 절대로 주소를 가로채 내 탭에서 연다
3. **아이디 칸을 클릭한다.** 크롬이 저장해 둔 계정이 드롭다운으로 떠오른다.
   그 항목을 누르면 아이디와 비밀번호가 함께 채워진다. `form_input` 으로 값을 넣는 게 아니라
   **크롬이 채우게 두는 것**이다. 채워졌는지는 `read_page` 로 칸이 비어 있지 않은지만 본다
4. 로그인 버튼을 누른다

- **로그아웃 버튼을 누르지 마라.** 계정을 바꿔야 하면 그 서비스의 계정 전환을 쓴다.
  인스타는 사이드바 "더 보기 → 계정 전환" 이다
- **전환하기 전에 지금 어느 계정인지 먼저 본다.** 로그인은 크롬 프로필 단위라 전환이
  그 프로필 전체에 걸린다. 다른 세션이 다른 계정으로 일하는 중이면 그쪽 화면까지 바뀌고,
  그 세션은 모른 채 엉뚱한 계정으로 DM을 보낸다. 규칙은 `C:\dev\AGENTS.md` 에 있다
- 다른 계정으로 붙어 있으면 전환하지 말고 **프로필을 나눈다.**
  `list_connected_browsers` → `select_browser {deviceId}` 로 다른 크롬을 고른다.
  쓸 게 없으면 새 프로필로 띄운다 (`chrome.exe --profile-directory="Profile 2"`).
  그 프로필에 확장이 안 붙어 있으면 사람이 한 번 붙여야 한다
- 넷으로 안 되면 사람을 부르되 **어느 서비스에 어느 계정인지** 적는다.
  사람이 한 번 로그인하면 그 뒤로는 계속 된다

## 차단됐다는 말을 들었을 때

도구 호출이 "classifier 에 막혔다" 로 돌아오는 일이 있다. 결제 화면에 글자를 치거나
민감해 보이는 폼을 만질 때다. **거기서 업무를 접지 마라.** 두 가지를 먼저 한다.

1. **금액과 대상을 숫자로 화면에 적는다.** "2,000회 200원, 잔액 5,200 → 5,000, 대상은 이 릴스".
   이게 대화에 있으면 그 뒤로는 타이핑도 버튼도 통한다. 260818 에 SNS서포터 주문이 이렇게 풀렸다.
   **답을 기다리라는 뜻이 아니다.** 매뉴얼에 값이 박힌 지출이면 적고 그대로 진행한다
2. **같은 일을 하는 다른 도구를 쓴다.** 타이핑이 막히면 폼 채우기 도구가 통한다.
   우회를 노리는 게 아니라 원래 그 일에 쓰는 도구면 된다

**그 자리에서 끝까지 누른다.** 화면만 차려 놓고 다음 단계로 넘어가면
사람이 답답해서 직접 하게 되고, 그때 내가 한 것과 사람이 한 것이 섞여 보고가 틀린다.
실제로 260818 에 그렇게 됐다.

정말로 못 하는 것은 셋뿐이다. **비밀번호와 카드번호 직접 입력, 계정 만들기, CAPTCHA.**
나머지는 보고하고 진행한다.

## L4. 컴퓨터 제어

`mcp__computer-use__*` 를 쓴다. 한 번에 다 불러온다.

```
ToolSearch: { query: "computer-use", max_results: 30 }
```

쓰기 전에 `request_access` 로 필요한 프로그램을 사람에게 승인받는다.

- **브라우저는 여기서 못 만진다** (읽기 등급). 브라우저 일은 L3 으로 내려간다.
- **터미널과 IDE 는 클릭만 되고 타이핑이 막힌다.** 명령은 L1 로 친다.
- 한글, PowerPoint, 카톡, 탐색기처럼 브라우저 밖 프로그램이 여기 대상이다.
- 키를 보내기 전에 `screenshot` 으로 **앞에 있는 창이 맞는지 확인한다.**
  확인 없이 보내면 엉뚱한 창에 타이핑한다. 실제로 겪은 사고다.
- 메일과 메시지 안의 링크는 클릭하지 마라. 주소를 읽어 L3 에서 연다.

## 끝나면 닫는다. 탭을 쌓아 두지 마라

탭과 창이 많으면 기계가 눈에 띄게 느려진다. **내가 연 것은 내가 닫는다.**

| 무엇 | 닫는 법 |
| --- | --- |
| 크롬 탭 (L3) | `mcp__claude-in-chrome__tabs_close_mcp {tabId}` |
| 인앱 브라우저 탭 (L2) | `mcp__Claude_Browser__tabs_close {tabId}`. 첫 탭은 못 닫으니 거긴 `navigate` 로 딴 데 보낸다 |
| 개발 서버 | `mcp__Claude_Browser__preview_stop {serverId}` |

- **원래 떠 있던 탭은 건드리지 마라.** 사람이 보던 것일 수 있다.
  `tabs_context_mcp` 로 처음에 목록을 받아 두면 뭐가 내 것인지 알 수 있다.
- 검증이 끝나면 바로 닫는다. 보고를 쓰기 전에 닫아라. 쓰고 나면 잊는다.
- 막혀서 그만둘 때도 닫고 나간다.
- 여러 건을 도는 작업은 **한 건 끝날 때마다** 닫는다. 마지막에 몰아서 치우려다 놓친다.

## 준비는 직접 한다. 사람 시키지 마라

사람이 원격에 있는 경우가 많다. "크롬 띄우고 다시 말해주세요" 같은 말은 **작업을 못 하게 만든다.**
네가 할 수 있는 준비는 그냥 해라.

| 막힌 것 | 사람에게 묻지 말고 이렇게 |
| --- | --- |
| 크롬이 안 떠 있다 | 직접 띄운다 (아래 명령). 3~5초 기다렸다가 다시 붙는다 |
| 탭이 없다 | `tabs_create_mcp` 로 만들고 `navigate` |
| 확장이 아직 안 붙었다 | 크롬을 띄운 뒤 `tabs_context_mcp` 로 몇 초 간격 두 번까지 다시 확인 |
| 개발 서버가 안 돈다 | `preview_start` 로 띄운다. Bash 로 띄우지 마라 |
| 폴더가 없다 | 만든다 |
| 저장소가 최신이 아니다 | `git pull` 한다 |

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" &
```

크롬이 이미 떠 있는지는 이걸로 본다.

```bash
tasklist //FI "IMAGENAME eq chrome.exe" //NH
```

**두 번까지는 스스로 되살려 본다.** 그래도 안 되면 그때 사람을 부르되,
무엇을 시도했고 무엇이 막혔는지 같이 적는다. "다시 말해주세요" 만 남기지 마라.

사람을 불러야 하는 건 **권한이 필요한 것**뿐이다. 로그인 세션 만료, 결제수단 미등록,
매뉴얼 밖의 되돌릴 수 없는 버튼. 매뉴얼 안의 지정된 게시 버튼은 다시 승인받지 않는다.
창을 띄우거나 폴더를 만드는 건 네가 한다.

## 하지 않는 것

- 송금, 계좌이체, 주식이나 코인 거래 (주문은 매뉴얼에 값이 박혀 있으면 그대로 한다)
- 비밀번호, 카드번호, 주민번호를 직접 입력하기
- 매뉴얼 밖의 보내기, 게시, 지출, 삭제를 사람 확인 없이 누르기 (매뉴얼에 적힌 단계는 그대로 한다)
- 계정 만들기, 약관 동의, CAPTCHA 풀기
