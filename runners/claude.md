# Claude 런너, 제어층 대응표

매뉴얼은 "L3 으로 카페24 관리자를 연다" 처럼 **추상으로** 적혀 있다.
그걸 Claude 세션에서 실제로 어떤 도구로 하는지가 여기 있다.
도구가 바뀌면 **이 파일만** 고친다. 매뉴얼은 안 건드린다.

**10분 안에 끝나는 것.** 사람이 옆에서 보고 있는 작업, 판단이 섞인 작업, 확인이 필요한 작업.
한 시간 넘게 도는 대량 작업은 Codex 에게 넘긴다 (`--runner codex` 로 큐에 넣는다).

## L1. 명령어, API, 스크립트

`Bash` 도구. 이 기계는 Windows 이고 Bash 도구는 Git Bash(POSIX sh)다.
PowerShell 문법(`$env:`, here-string, 백틱 줄바꿈)은 여기서 안 통한다.

- 파일 읽기, 쓰기, 검색은 `Read` `Write` `Edit` `Grep` `Glob` 을 쓴다. `cat` `sed` `grep` 으로 대신하지 마라.
- **PowerShell 로 소스 파일을 고쳐 쓰지 마라.** CP949 왕복으로 한글이 `??` 로 깨지고 빌드가 죽는다.
  치환이 필요하면 node 스크립트로 한다.

## L2. 인앱 브라우저

`mcp__Claude_Browser__*`

- 열기: `preview_start` 에 `{url}` (외부 사이트) 또는 `{name}` (`.claude/launch.json` 의 개발 서버)
- 읽기: `read_page` (접근성 트리, ref 가 붙어 나온다) → 화면 캡처보다 이게 정확하다
- 확인: `read_console_messages` `read_network_requests` `preview_logs`
- 조작: `computer` (ref 로 클릭) `form_input`
- **개발 서버는 Bash 로 띄우지 마라.** `preview_start` 를 쓴다.

로그인이 필요한 화면은 여기서 안 된다. L3 으로 올린다.

## L3. 크롬 익스텐션 (로그인된 진짜 크롬)

`mcp__claude-in-chrome__*` 를 쓴다. 기본으로 안 떠 있으니 먼저 불러온다.

```
ToolSearch: select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__tabs_create_mcp
```

필요한 걸 **한 번에 다 부른다.** 하나씩 부르면 왕복만 낭비한다.
폼이 있으면 `form_input`, 오류를 봐야 하면 `read_console_messages` 를 같은 호출에 얹는다.

- 카페24 관리자, 인스타그램, Figma, 노션처럼 로그인 세션이 필요한 곳은 전부 여기.
- 파일 업로드는 `file_upload` 가 있는지 먼저 확인한다. 없으면 사람이 해야 한다.

### 브라우저 도구가 막히면 셸에서 자기 브라우저를 띄운다

여기 `javascript_tool` 은 대입까지 되지만 **Codex 쪽 브라우저는 읽기 전용이다.**
매뉴얼을 그 차이 위에 세우면 런너를 바꾸는 날 업무가 선다. 260830 에 인스타 지표 채우기가 그랬다.

수백 건짜리 수집은 브라우저 도구로 하지 말고 **L1 에서 `playwright` 로 전용 프로필을 띄운다.**
사람 크롬과 따로 놀고, 45초 제한도 없고, 중간에 끊겨도 이어 돈다.
본보기는 `manuals/insta-metrics/scripts/ig-harvest.mjs` 다.
**사람에게 코드를 붙여넣어 달라고 하지 마라.** 그건 실패 처리다.

### "확장이 연결 안 됨" 이 떠도 확장은 살아 있다. 다시 고르면 된다

**260827 실측.** 크롬은 46개 프로세스로 멀쩡히 떠 있는데 페이지를 만지는 도구만 전부 죽었다.

- `navigate` `javascript_tool` `get_page_text` → "Claude in Chrome is not connected" 또는 중간 끊김
- `tabs_context_mcp` `tabs_create_mcp` `tabs_close_mcp` → **정상**

**이 갈림이 곧 신호다.** 탭 관리는 되는데 페이지 조작만 죽었으면 확장이 빠진 게 아니라
**세션이 붙잡고 있던 브라우저 핸들이 끊긴 것**이다. 20초, 30초, 60초, 90초를 기다려도 안 낫는다.
"확장을 다시 설치하세요" 안내가 같이 오는데 **그 말을 따르지 마라. 설치는 멀쩡하다.**

**한 줄로 되살린다.**

```
mcp__claude-in-chrome__list_connected_browsers      → deviceId 를 받는다
mcp__claude-in-chrome__select_browser {deviceId}    → "Connected to browser" 가 오면 끝
```

붙고 나면 탭 그룹이 새로 생기니 `tabs_context_mcp` 로 탭을 다시 받아 이어서 한다.
`switch_browser` 는 쓰지 마라. 사람이 크롬에서 직접 눌러야 하는 것이라 원격이면 2분 기다리다 끝난다.

**예약 작업에서 특히 이걸 먼저 본다.** 사람이 없는 시간에 도는 작업이 "확장이 죽었다" 로
빈손 보고를 내는 원인이 이것이다. 재시도로는 절대 안 풀린다.

### 화면이 멀쩡해 보이는데 아무 일도 안 일어날 때, 이 다섯부터 본다

다섯 다 **엉뚱한 얼굴로 돌아온다.** 오류가 안 나거나, 나더라도 원인과 상관없는 말이라
엉뚱한 데를 파게 된다. 260818 에 이것들로 몇 시간을 썼다.

**1. 새 화면에 들어온 직후 첫 클릭은 페이지에 도달하지 않는다.**

주소를 옮기거나 로그인 계정을 바꾼 바로 다음이다. 캡처 단계에 리스너를 걸고 세어 보면 클릭이 0건이다.
좌표를 의심하게 되는데 좌표는 맞다. `find` 가 준 `ref` 로 눌러도 마찬가지다.

**스크롤을 한 번 굴리면 그때부터 먹는다.** 스크롤은 처음부터 잘 들어간다.
그러니 새 화면에서는 **스크롤 → 좌표 다시 재기 → 클릭 → 결과 확인** 순서를 습관으로 한다.

**2. 크롬 창이 숨어 있으면 동영상이 안 붙는다.**

창이 최소화됐거나 다른 창에 완전히 가려 있으면 `document.visibilityState` 가 `hidden` 이 되고
크롬이 그 탭의 **미디어 로딩을 멈춘다.** 영상을 읽어야 다음으로 가는 화면(인스타 업로더 같은)이
그 자리에 영영 서 있는다. 클릭과 DOM 은 숨은 탭에서도 잘 된다. **동영상만** 안 된다.

판정은 페이지에서 직접 한다. `URL.createObjectURL(file)` 로 `<video>` 를 만들고
`loadedmetadata` 를 기다려 안 오면 창이 숨은 것이다. 고치는 건 L1 이다.

```powershell
# Chrome_WidgetWin_1 창을 EnumWindows 로 훑어 제목이 맞는 것 하나만 고른다
[W]::ShowWindow($h, 9); [W]::SetForegroundWindow($h)
```

창을 전부 복원하면 **마지막 것이 앞에 서서** 헛일이 된다. 하나만 골라야 한다.
창 제목은 그 창의 **활성 탭 제목**이라, 내 탭이 뒤에 있으면 제목으로 못 찾는다.
그럴 땐 **그룹에 탭을 하나만 남긴다.** 나머지를 닫으면 남은 탭이 활성이 된다.

**3. 어떤 화면에서는 `form_input` 과 `find` 만 45초 타임아웃으로 죽는다.**

`javascript_tool` 도 `computer` 도 멀쩡한데 이 둘만 "Page still loading (executeScript waited 45000ms
for document_idle)" 로 돌아온다. 260818 김제조 보드에서 실측했다. 페이지가 `document_idle` 을 영영
안 주는 구조면 그 둘이 걸린다. `document.readyState` 를 찍어 보면 `complete` 라 더 헷갈린다.

**막히면 도구를 바꾼다.** 값은 `javascript_tool` 로 넣고(`input` 과 `change` 를 같이 쏜다),
누르기는 `computer` 로 한다. 요소를 찾는 것도 `find` 대신 `javascript_tool` 로
`getBoundingClientRect()` 를 재서 좌표를 뽑는다. 화면 캡처 크기와 `innerWidth` 가 다르면
비율을 곱해야 한다(`k = 캡처폭 / innerWidth`). **창 크기는 작업 중에도 바뀌니 매번 다시 잰다.**

**4. `form_input` 은 값만 넣고 앱 상태를 안 바꾼다.**

React 화면에서 자주 문다. 칸에 값은 보이는데 그 값으로 계산되는 금액이나 합계, 다음 버튼이
안 깨어난다. `input` 과 `change` 이벤트를 손으로 쏴도 안 되는 경우가 있다.

**계산에 쓰이는 칸은 진짜 타이핑으로 넣는다.** 세 번 클릭해 기존 값을 잡고 친다.
넣은 뒤에는 **값이 아니라 결과를 확인한다.** 금액이 바뀌었는지, 버튼이 켜졌는지 본다.

**5. 내 탭이 활성 탭이 아니면 페이지가 죽은 척한다.**

`mcp__claude-in-chrome` 이 만드는 탭은 **배경 탭으로 생긴다.** `tabs_create_mcp` 도 `navigate` 도 탭을 앞으로 안 세운다.
사람이 다른 탭을 보고 있으면 내 탭은 계속 `hidden` 이다. 그 상태에서 이런 일이 난다.

- 애니메이션으로 열리는 서랍, 모달, 바텀시트가 **DOM 에는 생겼는데 닫힌 자리에 그대로 있다**(transform 이 안 풀린다)
- 화면 캡처가 `Script injection timed out` 으로 죽는다. `javascript_tool` 은 멀쩡해서 더 헷갈린다
- 타이핑과 클릭이 들어가도 **React 상태가 안 바뀐다.** `__reactProps` 의 value 가 옛날 값이라 다음 버튼이 계속 회색이다

**판정은 한 줄이다.** `javascript_tool` 로 `document.visibilityState` 를 찍는다.

`hidden` 이면 우회하지 말고 탭을 앞으로 세운다. 네이티브 setter, onChange 직접 호출, CSS 로 transform 풀기는
**전부 헛수고다.** 260820 에 셋 다 해봤고 셋 다 상태에 안 붙었다. 탭이 보이는 순간 밀린 렌더가 한꺼번에 풀린다.

**단, 버튼 하나 누르는 것은 배경 탭에서도 된다 (260830 실측).** 값을 넣는 것과 버튼을 누르는 것을 갈라야 한다.

| 무엇 | 창이 최소화됨 | 내 탭이 배경 탭(창은 떠 있음) |
| --- | --- | --- |
| 동영상 붙이기 | 안 된다 | 안 된다 |
| 칸에 값 넣기 (`computer` 타이핑) | 안 된다 | **된다.** 칸을 먼저 잡아야 한다 |
| `computer` 좌표 클릭 | 안 된다 | **된다. 단 스크롤을 한 번 굴린 뒤에** |
| `element.click()` | 된다 | 되기도 하고 안 되기도 한다 |

**어느 쪽이 먹는지 외우려 들지 마라. 둘 다 해보고 결과로 판정한다.** 260830 실측으로 정반대 사례가 둘 나왔다.

- n8n `Execute workflow`: 좌표 클릭 두 번 헛방, `.click()` 한 번에 들어감
- 인스타 수정창 `완료`: `.click()` 은 창이 그대로, 좌표 클릭으로 저장됨

**`ref` 클릭과 좌표 클릭도 요소마다 갈린다 (260903 실측).** 같은 배경 탭 안에서 갈렸다.

- 내가 심은 `position:fixed` 임시 링크: `getBoundingClientRect()` 에 `k` 를 곱한 좌표로 두 번 눌러도
  **클릭 카운터가 0** 이었다. `find` 가 준 `ref` 로 누르니 한 번에 들어갔다
- 인스타 캡션 칸(`contenteditable`): `ref` 클릭으로는 `document.activeElement` 가 `BODY` 에 머물렀다.
  화면 캡처에서 눈으로 잰 좌표로 누르니 포커스가 잡혔다

**누르고 나서 확인할 것을 미리 정해 두면 헤매지 않는다.** 칸이면 `document.activeElement`,
내가 심은 요소면 클릭 카운터, 버튼이면 결과(API, 탭 제목, 라벨)다. 화면 캡처로 좌표를 재는 게
계산으로 내는 것보다 확실할 때가 있으니 한쪽을 고집하지 마라.

**배경 탭에서 좌표 클릭이 안 들어가면 스크롤부터 굴린다.** 새 화면의 첫 클릭이 안 닿는 함정이
배경 탭에서도 그대로 걸린다. 스크롤 → 좌표 다시 재기 → 클릭 순서를 지키면 배경 탭에서도 다 눌린다.
260830 에 이걸로 파일 넘기기, 공유 창, 캡션 저장을 전부 배경 탭에서 끝냈다.

버튼을 DOM 으로 고를 때는 **뷰포트 안에 있는 것만 걸러라.** 같은 글자를 단 버튼이 화면 밖에도 있다.

### 입력이 통째로 안 닿을 때가 있다. 한 번의 실제 클릭으로 판정한다 (260904 실측)

배경 탭에서 클릭도 타이핑도 **하나도** 안 들어가는 상태가 있다. 크롬 창이 다른 창 뒤에 있을 때다.
`javascript_tool` 은 멀쩡히 돌고 `read_page` 도 되니까 페이지가 살아 있는 것처럼 보인다.
알프레드 급여표에서 이걸로 30분을 썼다. F2 가 안 열리고, `type` 한 숫자가 안 들어가고,
`.value` 를 넣고 Enter 를 눌러도 커밋이 안 됐다. **원인을 엉뚱한 데서 찾게 된다**
(React 제어 입력, 네이티브 setter, Handsontable 에디터 상태를 차례로 의심했는데 전부 아니었다).

**판정은 한 번의 실제 클릭이다.** 지금 선택된 것과 다른 요소를 `computer` 로 클릭하고
선택이 옮겨갔는지 본다. 안 옮겨가면 입력이 그 탭에 안 닿는 것이다.

```
computer left_click <다른 셀 좌표>  →  javascript_tool 로 선택 위치 확인
움직였다 = 입력이 닿는다. 그대로다 = 닿지 않는다
```

**JS 로 만든 이벤트가 이걸 가린다.** `dispatchEvent` 로 쏜 `mousedown` 은 시각적 선택
(`td.current` 같은 것)을 바꿔 놓아서 클릭이 먹은 것처럼 보인다. 그런데 앱의 내부 상태는 안 바뀐다.
**판정할 때는 JS 로 쏘지 말고 실제 클릭만 쓴다.**

닿지 않으면 우회로가 없다. 확장에는 탭을 앞으로 세우는 도구가 없고 PowerShell 로 창을 뺏으면
사람이 하던 일을 멈춘다. **사람에게 그 탭을 한 번 눌러 달라고 한다.** 누르면 바로 살아난다.
사람 손이 어차피 필요한 칸(주민등록번호 같은 것)이 있으면 그 부탁과 같이 묶어서 한 번만 부른다.

### `computer` 의 `zoom` 이 실패하면 그 탭 뷰포트가 굳는다 (260902 실측)

`zoom` 은 화면 크기 덮어쓰기를 걸고 잘라 찍은 뒤 되돌린다. 그런데 그 사이에
`CDP sendCommand "Page.captureScreenshot" timed out after 30000ms` 로 죽으면 **되돌리기가 안 돈다.**
덮어쓴 값이 그대로 남아 `window.innerWidth` 가 **잘라 보려던 조각 크기**로 고정된다.
2560 짜리 창이 213 이 되고, `outerWidth` 도 같이 거짓말을 한다.

**증상이 원인을 안 가리킨다.** 페이지는 멀쩡히 돌고 `javascript_tool` 도 다 되는데,
화면 캡처가 조각만 나오고 모달 요소의 `getBoundingClientRect()` 가 음수 좌표를 뱉는다.
그 상태에서 좌표 클릭은 통째로 막힌다. **판정은 `window.innerWidth` 한 줄이다.**

**되돌리는 길은 하나뿐이다. 탭을 닫고 새 탭을 연다.** 덮어쓰기는 탭 단위라 새 탭은 멀쩡하다.
아래 셋은 다 해봤고 **하나도 안 풀렸다.**

- `resize_window` — OS 창만 바뀌고 뷰포트는 그대로
- `list_connected_browsers` → `select_browser` 재접속 — 그대로
- `zoom` 을 다시 성공시키기 — 굳은 값을 원래 값으로 알고 거기로 되돌린다

**타이핑은 굳어도 멀쩡하다.** `computer` 타이핑은 포커스된 요소로 가지 좌표를 안 탄다.
그러니 급하면 타이핑까지는 그 탭에서 끝내고, 좌표가 필요한 단계만 새 탭으로 옮긴다.

**애초에 `zoom` 을 쓰지 마라.** 화면 일부를 크게 보고 싶으면 그냥 캡처를 찍고,
색이나 선택 상태처럼 눈으로 애매한 것은 `javascript_tool` 로 `getComputedStyle` 을 읽는 게 정확하다.

### 창을 앞으로 못 세울 때, 가림만 푼다 (260830 실측)

포커스를 뺏는 길은 대개 막혀 있다. `SetForegroundWindow` 는 다른 프로세스가 포그라운드면
**`True` 를 돌려주고도 안 올라온다.** 최소화 후 복원도 원래 최소화된 창에만 듣는다.
computer-use 로 브라우저를 띄우는 것도 읽기 등급이라 사용자가 거절할 수 있다.

**내가 연 창이라면 포커스를 안 건드리고 가림만 풀 수 있다.**
`SetWindowPos` 에 `HWND_TOPMOST` 와 `SWP_NOACTIVATE`(0x0010)를 준다.
사용자가 보던 창은 포커스를 그대로 쥐고, 내 창만 위로 올라온다. 그 순간 `visibilityState` 가
`visible` 이 되어 동영상까지 붙는다. **사람 창에는 쓰지 마라. 내가 연 팝업에만 쓰고 끝나면 닫는다.**

```js
[...document.querySelectorAll('button')]
  .filter(x => /버튼 글자/.test(x.innerText))
  .find(x => { const r = x.getBoundingClientRect(); return r.width > 0 && r.y > 0 && r.y < window.innerHeight; })
  .click();
```

**눌렸는지는 화면 말고 결과로 본다.** 탭 제목, 서버 기록, API 응답 같은 것이다.
같은 자리를 또 누르면 토글이 되돌아가니 확인 없이 반복하지 마라.

**탭을 앞으로 세우는 법.** 확장에는 탭 활성화 도구가 없다. 그리고 **PowerShell 로 창을 앞으로 끌어오지 마라.**
사람이 쓰고 있는 창을 뺏는다. 260820 에 그러다 사람이 하던 일을 멈췄다.
`SetForegroundWindow` 와 `SendKeys` 로 Ctrl+Tab 이나 탭 검색(Ctrl+Shift+A)을 돌리는 것도 같다.
게다가 **접힌 탭 그룹 안의 탭은 Ctrl+Tab 이 건너뛰어서** 그 길로는 닿지도 않는다.

**사람에게 한 줄로 부탁한다.** 찾기 쉽게 제목부터 바꿔 놓고 부른다.

```js
Object.defineProperty(document, 'title', {configurable: true, get: () => '★여기 눌러주세요★', set: () => {}});
document.getElementsByTagName('title')[0].textContent = '★여기 눌러주세요★';
```

### 팝업과 새 창은 안 잡힌다. 주소를 가로채서 내 탭에서 연다

**실측한 것.** 페이지가 `window.open` 으로 띄운 팝업도, `target="_blank"` 로 연 새 탭도
`tabs_context_mcp` 목록에 **안 나온다.** 그룹 밖에 생기기 때문이다. 화면에는 보이는데 만질 수가 없다.
헤매지 말고 아래대로 한다.

**1. 누르기 전에 가로채기를 심는다.**

```js
window.__opened = [];
const _open = window.open;
window.open = function(u, ...r){ if(u) window.__opened.push(String(u)); return _open.call(window, u, ...r); };
document.addEventListener('click', e => {
  const a = e.target.closest && e.target.closest('a[target="_blank"]');
  if (a && a.href) window.__opened.push(a.href);
}, true);
```

**2. 버튼을 누른다. 3. `window.__opened` 를 읽는다. 4. 그 주소를 내 탭에서 연다.**

```
navigate {tabId: <내 탭>, url: <가로챈 주소>}      기존 탭에서 이어서
tabs_create_mcp → navigate                          원래 탭을 남겨야 하면
```

이제 그 화면은 내 탭이라 `read_page`, `form_input`, 클릭이 다 된다.

**팝업이 아예 안 뜰 때도 있다.** 확장이 만든 클릭은 사용자 제스처로 안 쳐줘서 팝업 차단기에 막힌다.
위 가로채기는 차단돼도 주소를 남기니 그대로 쓰면 된다.

**같은 탭에서 열어버리는 방법**도 있다. 폼 입력만 하면 되는 팝업엔 이게 제일 간단하다.

```js
window.open = u => { if(u) location.href = u; return null };
document.querySelectorAll('a[target="_blank"]').forEach(a => a.removeAttribute('target'));
```

단 **OAuth 와 결제 인증창에는 쓰지 마라.** 그건 팝업이 부모 창에 결과를 돌려주는 구조라 흐름이 깨진다.
그런 창은 주소를 가로채 새 탭에서 열고, 끝나면 원래 탭으로 돌아간다.

### 내가 띄운 팝업이 구글 로그인을 거치면 그 팝업을 잃는다 (260903 실측)

같은 출처 팝업을 띄워 `__pop.document` 로 만지고 있었는데, 그 안에서 **유튜브 계정 전환**을 눌렀다.
팝업이 `accounts.google.com` 을 거쳐 유튜브로 돌아왔고, 그 뒤로 `__pop.location.href` 가
`SecurityError` 를 낸다. 같은 출처로 돌아와도 안 풀린다(COOP 로 브라우징 컨텍스트가 갈린다).

**되살리려 애쓰지 마라.** 확인할 것은 하나다. **그 작업이 세션 단위로 걸리는 것이었나.**
계정 전환, 로그인, 언어 설정처럼 프로필 전체에 걸리는 것은 **이미 반영돼 있다.**
팝업을 `close()` 로 닫고 확장 탭에서 같은 주소를 다시 열면 바뀐 상태로 이어 갈 수 있다.

**팝업 안에서 5초짜리 영상을 열어 뒀으면 그 사이 자동재생이 넘어간다.** 팝업을 못 만지는 동안
`pause()` 인터벌도 같이 죽는다. 돌아와서 주소부터 다시 확인한다.

**브라우저 밖 창은 여기서 못 만진다.** 윈도우 파일 선택창, 공동인증서 창, ActiveX 결제창이 그렇다.
그건 L4 로 가야 하는데 컴퓨터 제어는 브라우저가 읽기 등급이라 클릭이 막힌다. 이 경우만 사람을 부른다.

### 내 페이지로 File 을 넘길 때는 `rel="opener"`

로컬 서버를 띄워 `postMessage` 로 File 을 건네는 방법을 쓸 때다.
`window.open` 은 첫 번째만 되고 그 뒤로 팝업 차단에 걸리니 임시 `<a>` 를 만들어 진짜로 클릭하는데,
`target="_blank"` 만 주면 크롬이 **기본으로 `noopener`** 를 걸어 `window.opener` 가 `null` 이 된다.
보내는 쪽이 돌려보낼 길이 없어진다. `rel="opener"` 를 같이 준다.

## DM 함을 만졌을 때 되돌리기

읽기 전에 안 읽은 방을 적고, 다 읽으면 되돌린다. 규칙은 `AGENTS.md` 에 있고 여기는 손놀림이다.

**목록을 세는 법.** 인스타 DM 목록은 가상 스크롤이라 화면에 보이는 것만 DOM 에 있다.
아래로 내리면서 모은다. 표시가 안 잡히면 캡처해서 파란 점을 눈으로 센다.

**되돌리는 법.** 방 줄에 `right_click` 하면 메뉴가 뜬다. 거기서 "읽지 않음으로 표시" 를 누른다.
메뉴가 안 뜨면 방 줄 오른쪽 끝의 점 세 개 버튼을 눌러도 같은 메뉴가 나온다.
되돌린 뒤 목록을 다시 읽어 개수를 맞춰 본다.

## 구글 시트를 만질 때

**읽기는 화면을 훑지 마라. gviz 로 CSV 를 통째로 받는다.** 로그인된 크롬 탭에서 같은 출처로 fetch 하면 된다.
998행짜리 시트도 한 번에 오고, 눈으로 세는 것보다 정확하다.

```js
const u = `https://docs.google.com/spreadsheets/d/${ID}/gviz/tq?tqx=out:csv&headers=2&sheet=${encodeURIComponent(탭이름)}`;
const t = await (await fetch(u, {credentials:"include"})).text();
```

- `headers=` 는 **머리글이 몇 행인지** 알려주는 값이다. 제목 행이 따로 있으면 `headers=2` 로 줘야 첫 줄에 진짜 헤더가 나온다.
  `headers=0` 으로 두면 gviz 가 열마다 자료형을 정해 버려서, **숫자 열과 체크박스 열의 헤더 글자를 조용히 버린다.**
  팔로워나 금액 열의 헤더만 빈칸으로 나오면 이 문제다. 값은 멀쩡해서 더 헷갈린다.
- `export?format=csv` 는 쓰지 마라. 다른 호스트로 넘겨서 CORS 에 막힌다. gviz 는 같은 출처라 통한다.
- 탭 이름과 gid 를 모으려면 `.docs-sheet-tab` 을 하나씩 눌러 `location.hash` 를 읽는다.

**쓰기는 창이 보여야 한다.** 시트 편집기는 탭이 가려지면 입력을 흘린다. 화살표 키가 열 번 중 예닐곱 번만 먹고
나머지는 오류도 없이 사라진다. `repeat` 를 줘도 똑같다. 좌표를 의심하게 되는데 좌표 문제가 아니다.

- `document.visibilityState` 가 `hidden` 이면 그 상태다. 최소화가 아니라 **다른 창에 완전히 가려도** 그렇게 된다
- 키를 한 번 보내고 `#t-name-box` 값이 기대만큼 안 움직였으면 흘린 것이다
- 화면 캡처가 `Script injection timed out` 으로 죽는 것도 같은 원인이다

창을 앞으로 못 끌어내면 **대량 편집을 여기서 하지 마라.** 지우기와 붙여넣기가 반쯤 먹으면 기록이 깨진다.
그럴 땐 Codex 로 넘긴다. 넘길 때 넣을 수식과 검증할 숫자를 같이 적어 준다.

**범위 선택은 주소로 한다.** 이름 상자를 JS 로 `focus()` 하면 렌더러가 45초 타임아웃으로 얼어붙는 일이 있다(260819 실측).
대신 주소에 `?gid=<gid>&range=I3` 을 붙여 새로 열면 그 칸이 잡힌 채로 뜬다.
**이미 그 gid 에 떠 있는 탭에서는 안 먹는다.** 새로 이동해야 한다.

## 로그인 창을 만났을 때

> **회사 계정은 크롬 세 프로필에 전부 들어 있다 (260826).** 구글, 인스타 16개, 네이버, 카페24,
> 피그마, 쿠팡, 노션, 틱톡, 사람인, 카카오클라우드 등 50건 넘게 저장돼 있다.
> **그러니 로그인 창을 만나도 사람을 부를 일이 거의 없다.** 3번이 통한다.
> 안 통하면 그때 `node "<OPS>/scripts/login-preflight.mjs"` 로 지금 프로필에 뭐가 있는지 본다.

**사람을 부르기 전에 이 순서로 한다.** 대부분 1번이나 2번에서 끝난다.

1. `tabs_context_mcp` 로 이미 그 사이트 탭이 열려 있는지 본다. 세션이 살아 있으면 로그인이 안 뜬다
2. 화면에 **"구글로 로그인"** 이나 SSO 버튼이 있으면 그걸 누른다. 팝업이 뜨면
   위 "팝업과 새 창" 절대로 주소를 가로채 내 탭에서 연다
3. **아이디 칸을 클릭한다.** 크롬이 저장해 둔 계정이 드롭다운으로 떠오른다.
   그 항목을 누르면 아이디와 비밀번호가 함께 채워진다. `form_input` 으로 값을 넣는 게 아니라
   **크롬이 채우게 두는 것**이다. 채워졌는지는 `read_page` 로 칸이 비어 있지 않은지만 본다
4. 로그인 버튼을 누른다

**3번에서 드롭다운이 안 뜨면 이것부터 본다.** 클릭이 도달 안 한 경우가 많다.
새 화면에서는 첫 클릭이 안 먹으니 **스크롤을 한 번 굴리고 다시 클릭한다**(위 1번 함정).
그래도 안 뜨면 아이디 칸에 아이디 몇 글자를 쳐 본다. 크롬은 그때도 짝을 제안한다.

**비밀번호 값을 읽어서 치려고 하지 마라.** 그건 막혀 있고, 막힌 채로 두는 게 맞다.
크롬이 채우는 길이 이미 열려 있으니 그걸 쓴다.

- **로그아웃 버튼을 누르지 마라.** 계정을 바꿔야 하면 그 서비스의 계정 전환을 쓴다.
  인스타는 사이드바 "더 보기 → 계정 전환" 이다
- **전환하기 전에 지금 어느 계정인지 먼저 본다.** 로그인은 크롬 프로필 단위라 전환이
  그 프로필 전체에 걸린다. 다른 세션이 다른 계정으로 일하는 중이면 그쪽 화면까지 바뀌고,
  그 세션은 모른 채 엉뚱한 계정으로 DM을 보낸다. 규칙은 `C:\dev\AGENTS.md` 에 있다
- 다른 계정으로 붙어 있으면 전환하지 말고 **프로필을 나눈다.**
  `list_connected_browsers` → `select_browser {deviceId}` 로 다른 크롬을 고른다.
  쓸 게 없으면 새 프로필로 띄운다 (`chrome.exe --profile-directory="Profile 2"`).
  그 프로필에 확장이 안 붙어 있으면 사람이 한 번 붙여야 한다
- 넷으로 안 되면 사람을 부르되 **어느 서비스에 어느 계정인지** 적는다.
  사람이 한 번 로그인하면 그 뒤로는 계속 된다

## 차단됐다는 말을 들었을 때

도구 호출이 "classifier 에 막혔다" 로 돌아오는 일이 있다. 결제 화면에 글자를 치거나
민감해 보이는 폼을 만질 때다. **거기서 업무를 접지 마라.** 두 가지를 먼저 한다.

1. **금액과 대상을 숫자로 화면에 적는다.** "2,000회 200원, 잔액 5,200 → 5,000, 대상은 이 릴스".
   이게 대화에 있으면 그 뒤로는 타이핑도 버튼도 통한다. 260818 에 SNS서포터 주문이 이렇게 풀렸다.
   **답을 기다리라는 뜻이 아니다.** 매뉴얼에 값이 박힌 지출이면 적고 그대로 진행한다
2. **같은 일을 하는 다른 도구를 쓴다.** 타이핑이 막히면 폼 채우기 도구가 통한다.
   우회를 노리는 게 아니라 원래 그 일에 쓰는 도구면 된다

**그 자리에서 끝까지 누른다.** 화면만 차려 놓고 다음 단계로 넘어가면
사람이 답답해서 직접 하게 되고, 그때 내가 한 것과 사람이 한 것이 섞여 보고가 틀린다.
실제로 260818 에 그렇게 됐다.

정말로 못 하는 것은 셋뿐이다. **비밀번호와 카드번호 직접 입력, 계정 만들기, CAPTCHA.**
나머지는 보고하고 진행한다.

`mcp__computer-use__*` 를 쓴다. 한 번에 다 불러온다.

```
ToolSearch: { query: "computer-use", max_results: 30 }
```

쓰기 전에 `request_access` 로 필요한 프로그램을 사람에게 승인받는다.

- **브라우저는 여기서 못 만진다** (읽기 등급). 브라우저 일은 L3 으로 내려간다.
- **터미널과 IDE 는 클릭만 되고 타이핑이 막힌다.** 명령은 L1 로 친다.
- 한글, PowerPoint, 카톡, 탐색기처럼 브라우저 밖 프로그램이 여기 대상이다.
- 키를 보내기 전에 `screenshot` 으로 **앞에 있는 창이 맞는지 확인한다.**
  확인 없이 보내면 엉뚱한 창에 타이핑한다. 실제로 겪은 사고다.
- 메일과 메시지 안의 링크는 클릭하지 마라. 주소를 읽어 L3 에서 연다.

## 끝나면 닫는다. 탭을 쌓아 두지 마라

탭과 창이 많으면 기계가 눈에 띄게 느려진다. **내가 연 것은 내가 닫는다.**

| 무엇 | 닫는 법 |
| --- | --- |
| 크롬 탭 (L3) | `mcp__claude-in-chrome__tabs_close_mcp {tabId}` |
| 인앱 브라우저 탭 (L2) | `mcp__Claude_Browser__tabs_close {tabId}`. 첫 탭은 못 닫으니 거긴 `navigate` 로 딴 데 보낸다 |
| 개발 서버 | `mcp__Claude_Browser__preview_stop {serverId}` |

- **원래 떠 있던 탭은 건드리지 마라.** 사람이 보던 것일 수 있다.
  `tabs_context_mcp` 로 처음에 목록을 받아 두면 뭐가 내 것인지 알 수 있다.
- 검증이 끝나면 바로 닫는다. 보고를 쓰기 전에 닫아라. 쓰고 나면 잊는다.
- 막혀서 그만둘 때도 닫고 나간다.
- 여러 건을 도는 작업은 **한 건 끝날 때마다** 닫는다. 마지막에 몰아서 치우려다 놓친다.

## 준비는 직접 한다. 사람 시키지 마라

사람이 원격에 있는 경우가 많다. "크롬 띄우고 다시 말해주세요" 같은 말은 **작업을 못 하게 만든다.**
네가 할 수 있는 준비는 그냥 해라.

| 막힌 것 | 사람에게 묻지 말고 이렇게 |
| --- | --- |
| 크롬이 안 떠 있다 | 직접 띄운다 (아래 명령). 3~5초 기다렸다가 다시 붙는다 |
| 탭이 없다 | `tabs_create_mcp` 로 만들고 `navigate` |
| 확장이 아직 안 붙었다 | 크롬을 띄운 뒤 `tabs_context_mcp` 로 몇 초 간격 두 번까지 다시 확인 |
| 확장이 "연결 안 됨" 이라고 한다 | `list_connected_browsers` → `select_browser`. 위 L3 절을 보라. 기다려도 안 낫는다 |
| 개발 서버가 안 돈다 | `preview_start` 로 띄운다. Bash 로 띄우지 마라 |
| 폴더가 없다 | 만든다 |
| 저장소가 최신이 아니다 | `git pull` 한다 |

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" &
```

크롬이 이미 떠 있는지는 이걸로 본다.

```bash
tasklist //FI "IMAGENAME eq chrome.exe" //NH
```

**두 번까지는 스스로 되살려 본다.** 그래도 안 되면 그때 사람을 부르되,
무엇을 시도했고 무엇이 막혔는지 같이 적는다. "다시 말해주세요" 만 남기지 마라.

사람을 불러야 하는 건 **권한이 필요한 것**뿐이다. 로그인 세션 만료, 결제수단 미등록,
매뉴얼 밖의 되돌릴 수 없는 버튼. 매뉴얼 안의 지정된 게시 버튼은 다시 승인받지 않는다.
창을 띄우거나 폴더를 만드는 건 네가 한다.

## 하지 않는 것

- 송금, 계좌이체, 주식이나 코인 거래 (주문은 매뉴얼에 값이 박혀 있으면 그대로 한다)
- 비밀번호, 카드번호, 주민번호를 직접 입력하기
- 매뉴얼 밖의 보내기, 게시, 지출, 삭제를 사람 확인 없이 누르기 (매뉴얼에 적힌 단계는 그대로 한다)
- 계정 만들기, 약관 동의, CAPTCHA 풀기
