## 읽기는 CSV 로 통째로 받는다

**화면을 훑지 마라.** 로그인된 크롬 탭에서 같은 출처로 fetch 하면 998행짜리도 한 번에 온다.

```js
const u = `https://docs.google.com/spreadsheets/d/${ID}/gviz/tq?tqx=out:csv&headers=2&sheet=${encodeURIComponent(탭이름)}`;
const t = await (await fetch(u, {credentials:"include"})).text();
```

- `headers=` 는 **머리글이 몇 행인지**다. 제목 행이 따로 있으면 `headers=2` 로 준다.
  `headers=0` 으로 두면 gviz 가 열마다 자료형을 정해 버려서 **숫자 열과 체크박스 열의 헤더 글자를 조용히 버린다.**
  팔로워나 금액 열의 헤더만 빈칸으로 나오면 이 문제다. 값은 멀쩡해서 더 헷갈린다
- 브라우저 fetch 에서 `export?format=csv` 는 쓰지 마라. 다른 호스트로 넘겨서 CORS 에 막힌다
- 탭 이름과 gid 를 모으려면 `.docs-sheet-tab` 을 하나씩 눌러 `location.hash` 를 읽는다

### 링크 공유된 시트는 셸로 수식까지 읽는다

"링크 있는 누구나" 로 열린 시트는 로그인 없이 `curl` 로 받는다. 셸이라 CORS 도 없다(260914).

```bash
curl -sL -o sheet.xlsx "https://docs.google.com/spreadsheets/d/<ID>/export?format=xlsx"
curl -sL -o sheet.html "https://docs.google.com/spreadsheets/d/<ID>/htmlview"
grep -o '{name: "[^"]*"[^}]*gid: "[0-9]*"' sheet.html   # 탭 이름과 gid. 탭을 눌러 볼 필요가 없다
```

- **gviz 와 커넥터 본문 읽기는 화면 값만 준다.** 수식 칸과 손으로 친 칸이 똑같이 보인다.
  xlsx 를 openpyxl `load_workbook` 기본값으로 열면 수식이 `=` 로 시작하는 문자열로 나온다.
  드롭다운 범위(`data_validations`), 조건부 서식, 병합, 고정 행도 같이 읽힌다
- 판정법: 번호 열이 1, 2, 3 으로 보여도 xlsx 에서 한 칸만 숫자면 그 칸은 수식이 끊긴 것이다.
  260914 매장 체크리스트 원본은 A8 만 숫자 1 이고 A9 부터 `=IF($B9="","",ROW()-7)` 였다.
  사본을 비울 때 계정만 지우면 빈 표에 1 이 남는다
- 링크 공유가 안 된 시트는 `401` 과 로그인 안내 HTML(9KB 안팎)이 온다. 받은 파일을 `file` 로 보면
  `HTML document` 로 나온다. 그때는 커넥터로 읽는다

### gviz 가 401이면 인증 커넥터로 읽는다

공개 URL을 `curl`로 받았을 때 401이 나고, 브라우저의 읽기 전용 실행 환경에서 `fetch`를 쓸 수 없으면
Google Drive 커넥터의 `get_spreadsheet_range`를 쓴다. 실제 사용 범위를 지정하고
`value_render_option: "FORMATTED_VALUE"`로 읽은 뒤 표준 CSV 인용 규칙으로 직렬화한다.
작업 전·후 덤프는 같은 방법과 같은 범위를 써야 한다. 줄 끝 차이는 제거한 뒤 내용이 같은지 비교한다.

## claude 런너가 직접 써야 할 때 (사용자가 예외를 줄 때만)

260922 에 사용자가 "codex 가 못 도니 이번은 네가 해라" 고 해서 L3 으로 직접 썼다. 이 순서면 된다.

**확장 탭은 늘 배경이라 시트가 키 입력을 버린다.** `document.visibilityState` 가 `hidden` 이면
셀에 글자가 한 자도 안 들어간다. 이름 상자 같은 진짜 `input` 에는 들어가니 "키가 안 간다" 로 오진하기 쉽다.
판정은 그 입력칸에 한 글자 넣어 보는 것이다.

**뚫는 법은 화면 값을 덮어쓰는 것이다.** 탭을 앞으로 못 세우니 문서가 스스로를 보이는 것으로 알게 만든다.

```js
Object.defineProperty(document,'hidden',{get:()=>false,configurable:true});
Object.defineProperty(document,'visibilityState',{get:()=>'visible',configurable:true});
document.dispatchEvent(new Event('visibilitychange'));
```

그다음 **좌표 클릭으로 셀을 한 번 누르면** 그때부터 타이핑과 Enter 가 그대로 먹는다.
팝업 창을 열어 보는 길(`window.open`)은 **팝업이 확장 탭 그룹 밖이라 키를 못 보낸다.** 시간 쓰지 마라.

- **좌표는 CSS 픽셀이 아니다.** 스크린샷이 알려 주는 좌표계(예: 1568x545)와 `window.innerWidth`(예: 2560)의
  비율로 환산한다. 이걸 빼먹으면 화면 밖을 누르고 "클릭이 안 먹는다" 로 잘못 읽는다
- 세로로 이어진 칸은 **값 하나 치고 Enter** 를 반복한다. 탭 문자로 한 번에 넣지 마라
- 칸을 고를 때는 이름 상자를 **좌표로 눌러** 주소를 치고 Enter 한다. JS `focus()` 는 렌더러를 45초 얼릴 수 있다
- 주소에 `&range=H4` 를 붙여 다시 여는 길은 쓰지 마라. 되읽기가 끝나면 화면 값 덮어쓰기가 풀리고,
  저장 중이면 "사이트에서 나가시겠습니까" 로 막힌다
- **긴 글의 한 조각만 고칠 때는 F2 로 편집에 들어가 화살표로 옮겨 지우고 친다.** 한국어 문장을 통째로 다시 치면
  깨질 자리가 는다. `2026.09.18` 의 `18` 만 바꿀 때는 F2, Left 4번, Backspace 2번, `22` 였다
- **수식 칸 출력은 `&` 와 `=` 때문에 통째로 막힌다.** 읽을 때 `.split('&').join('〈AMP〉')` 처럼 바꿔 꺼낸다
- **확인은 `export?format=csv` 로 한다.** `gviz/tq` 는 캐시가 오래 남아 방금 쓴 값이 안 보인다.
  이걸 모르면 잘 들어간 값을 "안 들어갔다" 로 판정하고 두 번 쓴다

## 지표 시트에 이력 메모를 남기지 않는다

260922 사용자 지시다. "전에 얼마였음", "언제 확인함" 같은 셀 메모를 새로 달지 말고, 붙어 있던 것도 지운다.
고객사와 협업사가 보는 표에는 **지금 값만** 있어야 한다.

- 지우는 길은 범위를 잡고 **수정 → 삭제 → 참고** 다. "참고" 가 메모를 뜻한다(오역)
- 오른쪽 클릭 차림표는 메모가 있는 칸을 눌러도 `메모 삽입` 만 내놓아서 못 지운다. 시간 쓰지 마라
- 확인은 `export?format=xlsx` 를 받아 `xl/comments1.xml` 의 `<comment>` 개수를 센다
- **확인 날짜와 기준 설명도 안 남긴다.** 제목 띠의 `| 2026.09.22 확인` 같은 꼬리와 표 아래 `지표 기준` 블록이 여기 해당한다.
  콘텐츠 `업로드일` 열은 우리가 잰 날이 아니라 올라간 날이라 그대로 둔다
- **버전 기록은 못 지운다.** 옛 값이 보이면 곤란한 자리면 값만 복사한 새 시트로 옮기고 링크를 간다

## 쓰기 안전 게이트

Google Sheets API 쓰기는 다음 순서를 지킨다. 빠른 작업도 생략하지 않는다.

1. 2행 헤더와 계정 열을 읽는다.
2. 작업 직전 `headers=2` CSV를 로컬에 저장한다.
3. 계정 키·헤더 이름·허용 열·보호 열로 쓰기 계획을 만든다. 고정 행 번호와 열 번호는 계획에 넣지 않는다.
4. 쓰기 직전에 계정으로 현재 행을 다시 찾고 대상 행 전체를 읽는다.
5. 서로 떨어진 셀은 별도 요청으로 쓴다. 한 요청은 의도한 연속 구간 하나만 바꾼다.
6. 요청마다 대상과 좌우 인접 셀을 다시 읽는다.
7. 작업 직후 같은 범위의 CSV를 저장하고 계정·헤더 기준으로 대조한다.

`updateCells`의 `rows[].values`에서 `{}`는 “건너뛰기”가 아니다. `fields:"userEnteredValue"`와 함께
쓰면 중간 셀 값을 지운다. 떨어진 두 셀 사이를 `{}`로 채운 넓은 요청은 금지한다.

기존 값 삭제와 행 삭제는 일반 쓰기보다 엄격하게 처리한다.

- 기존 값을 비우려면 계정·열·사유를 사전 승인 목록에 적는다.
- 행을 지우려면 사용자 승인, 정규화 계정, 현재 행 해시, 삭제 사유를 기록한다.
- 삭제 직전 행을 다시 읽고 내림차순으로 삭제한다.
- 동시 변경이 감지되면 정렬·삭제·자동 복원을 하지 않는다.

운영 시트는 일일 읽기 전용 전체 CSV 백업과 매 작업 직전·직후 CSV를 함께 둔다. Drive 사본이나 이름
있는 버전이 한도에 막혀도 로컬 백업은 생략하지 않는다. 자동 버전 기록은 보조 복구 수단이다.

정확한 수식과 사용자가 적은 표본 기대값이 충돌하면 표본을 맞추려고 수식을 바꾸지 않는다. 정확한
수식을 적용하고 계산 과정과 충돌을 보고한다.

## 알려진 함정

- **창이 가려지면 입력을 흘린다.** 최소화가 아니라 다른 창에 완전히 가려도 그렇다.
  화살표 키가 열 번 중 예닐곱 번만 먹고 나머지는 오류도 없이 사라진다.
  `document.visibilityState` 가 `hidden` 이면 그 상태다
- **이름 상자를 JS 로 `focus()` 하면 렌더러가 45초 얼어붙는 일이 있다** (260819 실측).
  범위 선택은 주소로 한다. `?gid=<gid>&range=I3` 을 붙여 새로 연다.
  **이미 그 gid 에 떠 있는 탭에서는 안 먹는다.** 새로 이동해야 한다
- 열을 넣거나 뺐으면 **돌고 있는 다른 세션이 있는지 확인하고 사람에게 알린다.** 그쪽 열 매핑이 깨진다
- 현재 버전 이름 저장 버튼이 시간 초과를 내도 대화상자가 남아 있을 수 있다. 화면 구조를 다시 읽고
  이름이 입력된 상태면 저장 버튼만 한 번 다시 누른다. 마지막 확인은 버전 기록 화면의 이름 입력란으로 한다
- **예상 마지막 행까지만 읽으면 삭제 실패와 꼬리 데이터를 놓친다.** 삭제 뒤 1,316행을 기대한다고
  1,318행까지만 검사하면 1,319행 아래에 남은 값은 보이지 않는다. 메타데이터의
  `gridProperties.rowCount`까지 계정 키 열을 읽어 실제 마지막 데이터 행·행 수·정규화 중복을 계산한다.
  예상 마지막 행 아래에 값이 있으면 완료로 판정하지 않는다.
- **배열 수식은 표본값이 보여도 전체 열이 깨질 수 있다.** 수식 변경 직후 앵커 셀을 셀 메타데이터로
  다시 읽어 `effectiveValue.errorValue`를 확인한다. `#REF!`이면 메시지가 지목한 방해 셀과 행을
  먼저 읽는다. 그다음 데이터가 있는 마지막 행까지 수식 오류와, 키·입력값이 있는데 산출값이 빈 행을
  전수 검사한다. 표본 계정 몇 개만 맞는 것은 완료 근거가 아니다.
- **작업 사본만 맞고 원본이 다를 수 있다.** 원본 반영 뒤 작업 사본과 원본의 실제 행 수,
  마지막 계정, 정규화 중복 수, 수식 오류 수를 따로 읽어 비교한다. 배치 성공 응답만 믿지 않는다.
- **수식 정렬키 입력과 정렬을 같은 batch 요청에 넣으면 성공 응답만 오고 정렬이 안 될 수 있다.**
  수식 재계산 전의 예전 값을 정렬키로 쓰기 때문이다. 정렬키를 숫자 상수로 쓰거나, 수식 값을 다시
  읽은 뒤 정렬을 별도 요청으로 실행한다.
- **열을 삭제한 뒤 옛 열 번호로 계속 쓰면 옆 열을 고친다.** 구조 변경 직후 2행 헤더를 다시 읽고
  이후 모든 범위를 새 매핑으로 만든다.
- **필터 보기는 일반 표와 독립된 정렬 조건을 가질 수 있다.** 화면과 API 정렬 결과가 다르면 먼저
  전체 행 순위의 역전 수를 계산하고, 역전이 0이면 필터 보기의 sort spec을 확인한다.
- **merged 제목 행 때문에 gviz의 헤더 행 모양이 실행마다 달라질 수 있다.** `headers=2`를 쓰고,
  전후 비교는 줄 번호가 아니라 계정 키와 헤더 이름으로 맞춘다.
- **운영 원장은 수정 후 다시 정렬한다.** 다만 사용자가 현재 작업에서 `행 순서를 바꾸지 마라`,
  `수식만 고쳐라`라고 명시했거나 동시 변경이 감지되면 정렬하지 않는다. 정렬했다면 전체 행 역전
  0건을 확인한다.
- **메모가 있다고 진행 단계가 높아지는 것은 아니다.** 협상 메모에는 `DM불가`, 방문 계획 없음,
  언어권·콘텐츠·캠페인 부적합 같은 운영 피드백도 들어간다. 진행 단계는 DM·응답·합의 단가·확정·
  방문 일정과 후속 체크박스로 계산하고, 진행 불가 피드백은 같은 상태의 뒤로 보낸다.
- **사람이 직접 선별한 외부 목록은 명시된 동률 기준으로 쓴다.** 목록 계정을 정규화 계정으로
  대조하고, `발견 방식` 같은 출처 열에 사람이 읽을 수 있는 표기를 남긴 뒤 같은 상태와 실제 진행 단계에서
  먼저 둔다. 외부 목록의 존재만으로 상태나 체크박스를 바꾸지 않는다.
- **진행 불가 피드백은 상태로 분류한다.** 연락 통로나 방문 시점이 없어 나중에 다시 볼 후보는 `보류`,
  콘텐츠·언어권·캠페인 적합도가 낮아 내부에서 제외한 후보는 `반려`, 상대가 명시적으로 거절한 후보는
  `거절`로 구분한다.
