# 문서 만들기

- **무엇에 쓰나**: PDF, PPT, 워드, 엑셀, 한글 파일을 읽고 만든다
- **제어층**: L1 (스킬과 라이브러리로 직접 만든다). 한글만 L4
- **못 하는 것**: 한글(HWP) 파일을 코드로 편집하는 것

---

## 무엇으로 만드나

| 만들 것 | 어떻게 |
| --- | --- |
| 제안서, 발표자료, 덱 | **피그마로 만든다.** `피그마.md` 를 보라. PPT 로 만들지 마라 |
| PPT 파일이 꼭 필요할 때 | `pptx` 스킬 (python-pptx). 만든 뒤 PDF 로 변환해 **눈으로 검증** |
| 워드 문서 | `docx` 스킬 |
| 엑셀 | `xlsx` 스킬 |
| PDF 읽기, 합치기, 쪼개기 | `pdf` 스킬 |
| 한글(HWP) | 아래 |

**제출용 자료의 기본은 피그마다.** PPT 는 서식이 요구될 때만 쓴다.

## PDF 읽기

`Read` 도구에 `pages` 를 주면 페이지를 이미지로 본다. 표와 도식이 있는 자료는 이게 정확하다.

```
Read { file_path: "...pdf", pages: "1-8" }
```

한 번에 20쪽까지다. 10쪽 넘는 PDF 는 `pages` 가 필수다.

## HTML 로 만들어 PDF 로 뽑기

간단한 자료는 HTML 을 짜서 헤드리스 크롬으로 뽑는 게 제일 빠르다.

```bash
"/c/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu \
  --no-pdf-header-footer --virtual-time-budget=15000 \
  --print-to-pdf="out.pdf" "file:///.../out.html"
```

`@page { size: 1280px 720px; margin: 0 }` 를 주면 16:9 슬라이드가 된다.
웹폰트를 쓰면 `--virtual-time-budget` 을 넉넉히 줘야 글꼴이 붙는다.

**다 뽑고 나서 반드시 PDF 를 이미지로 열어 눈으로 본다.** 글자가 상자 밖으로 나가거나
아래 요소와 겹치는 건 코드로 안 잡힌다.

## 한글(HWP)

**코드로 편집하지 못한다.** 내용을 읽어야 하면 `olefile` 로 BinData 를 꺼내 볼 수 있고,
서식을 채워야 하면 L4 로 한글 프로그램을 직접 만진다.

COM 자동화로 변환할 때 **타이핑 포커스를 뺏는다.** 사람이 다른 일을 하고 있으면 글자가 엉뚱한 데 들어간다.
별도 데스크톱에서 돌리면 안 뺏는다.

## 한글이 깨질 때

- **PowerShell 로 소스 파일을 고쳐 쓰지 마라.** CP949 왕복으로 한글이 `??` 로 깨진다.
  치환이 필요하면 node 나 python 스크립트로 한다
- Windows `curl` 에 한글을 인자로 넘기면 CP949 로 깨진다. UTF-8 파일로 저장해 `--data-binary @file` 로 넘긴다
- 파일을 새로 쓸 때는 `Write` 도구를 쓴다. 셸 히어독보다 안전하다

## 글 쓰는 규칙

산출물 문체는 회사 규칙을 따른다. 세 가지만 기억하면 대부분 걸러진다.

- **가운뎃점과 줄표를 쓰지 않는다.** 쉼표나 괄호로 바꾼다
- **제목은 명사구.** 주장하는 문장으로 제목을 달지 않는다
- **본문에 회색 작은 글씨를 깔지 않는다.** 안 보인다고 지적받는다

만들고 나서 `·` 와 `—` 를 전수 검사하는 습관을 들여라. 한 번에 걸린다.
