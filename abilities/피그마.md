# 피그마

- **무엇에 쓰나**: 제안서, 발표자료, 소개서, IR 덱을 만든다. 있는 덱을 고친다
- **제어층**: L1 (Figma MCP 가 플러그인 API 로 직접 그린다. 브라우저 클릭 아님)
- **못 하는 것**: 파일 이름은 만들 때만 정할 수 있다. 나중에 못 바꾼다

---

## 순서

**맨손으로 새로 그리지 마라.** 회사에는 이미 완성된 덱이 여러 벌 있고,
새 자료는 그중 하나의 디자인 체계를 그대로 떠서 쓴다. 그게 제일 빠르고 결과도 제일 좋다.

1. **어느 덱을 본뜰지 정한다** (아래 표)
2. **그 파일에서 토큰을 실측한다.** 기억으로 색과 크기를 지어내지 마라
3. **새 파일을 만든다**
4. **슬라이드를 한두 장씩 짓고 매번 눈으로 본다**
5. **PDF 로 뽑는다**

## 본뜰 덱

| 쓸 자리 | 파일 | 결 |
| --- | --- | --- |
| 회사 소개, IR, 투자자와 대기업에 내는 것 | `35J7WaToONP9rKSXyzOe1p` (IR 덱) | 파란 그라데이션, 흰 카드, 강조 #1e62a8 |
| 서비스 제안서, 협업 제안, 소개서 | `YFZ8PcMMTuYSUJkjC21fn4` (병의원 마케팅) | 따뜻한 베이지 #f5f1ea, 다크 필 #2b2723, 강조 레드 #c0392b |

둘 다 1920x1080 이고 폰트는 Pretendard 다. 영문 라벨만 Inter 를 쓴다.
**한글에 Inter 를 넣으면 글자가 사라진다.** 섞지 마라.

## 토큰 뜨는 법

`use_figma` 로 읽기 스크립트를 돌려 실제 값을 받아온다. 대표 슬라이드 두세 장이면 충분하다.

```js
// 프레임 목록
const fr = figma.currentPage.children.filter(n => n.type === 'FRAME');
fr.sort((a,b) => (a.y-b.y) || (a.x-b.x));
return fr.map(f => ({ id:f.id, name:f.name, w:Math.round(f.width), h:Math.round(f.height) }));
```

그다음 한 프레임의 자식을 좌표, 색, 폰트, 크기, 자간, 행간까지 통째로 덤프해서 그대로 베낀다.
프레임 자체의 `fills` 도 같이 뜬다. 배경 그라데이션이 거기 있다.

## 만들고 그리기

**스킬 두 개가 필수다. 안 부르면 조용히 깨진다.**

- `create_new_file` 을 부르기 전에 **`figma-create-new-file` 스킬**
- `use_figma` 를 부르기 전에 **`figma-use` 스킬**

새 파일은 `whoami` 로 planKey 를 받아서 만든다. **이름은 이때만 정할 수 있다.**

슬라이드는 프레임을 격자로 깐다. 가로 2120 간격, 세로 1380 간격이면 겹치지 않는다.
한 번에 한두 장씩 짓고 `await frame.screenshot({scale:0.5})` 로 **매번 눈으로 확인한다.**
열 장을 한 번에 짓고 나중에 보면 다 뜯어고치게 된다.

## 그림 자료

**픽토그램은 직접 그리지 마라.** 손으로 그린 티가 나서 오히려 반감을 산다.
Lucide 아이콘을 받아 색만 바꿔 올린다.

```bash
curl -sL -o factory.svg "https://unpkg.com/lucide-static@latest/icons/factory.svg"
# currentColor 를 실제 색으로 바꾸고 width/height 를 키운다
```

`upload_assets` 로 올리면 **편집 가능한 벡터**로 들어온다. 올릴 때 파일 이름이 레이어 이름이 되니
`icon-factory.svg` 처럼 이름을 붙여 올리면 나중에 찾기 쉽다.
슬라이드에 넣을 때는 원본을 `clone()` 해서 쓰고, 원본은 캔버스 밖(x = -900 쯤)에 세워둔다.

사진은 무료 라이선스에서 받는다. 표지와 클로징에만 쓰고 본문은 도식으로 채우는 게 낫다.
스톡 사진을 장마다 깔면 오히려 싸 보인다.

## 도식

화살표는 **글자 `→` 를 띄워놓지 말고 진짜 벡터로 그린다.** 선 하나와 삼각형 하나면 된다.
좌표는 절대값으로 계산해 놓고, 경로 데이터는 bbox 기준으로 옮긴 뒤 노드 x, y 를 bbox 원점에 둔다.
그래야 어긋나지 않는다.

## PDF 로 뽑기

Figma MCP 에는 PDF 내보내기가 없다. 프레임을 하나씩 받아서 묶는다.

```
get_screenshot {fileKey, nodeId, maxDimension: 1920}   # 프레임마다 한 번
```

돌아온 URL 을 curl 로 받고 PIL 로 묶는다.

```bash
python -c "
from PIL import Image; import glob
fs=sorted(glob.glob('s*.png')); ims=[Image.open(f).convert('RGB') for f in fs]
ims[0].save('deck.pdf', save_all=True, append_images=ims[1:], resolution=150.0)"
```

프레임 이름을 `01-표지` 처럼 번호로 시작하게 지어두면 정렬이 그대로 순서가 된다.

## 글 쓰는 규칙

산출물 문체는 회사 규칙을 그대로 따른다. 특히 이 셋을 어기면 다시 만들게 된다.

- **제목은 명사구.** "첫 콘텐츠를 올립니다" 가 아니라 "첫 콘텐츠 업로드까지"
- **가운뎃점과 줄표를 쓰지 않는다.** 쉼표나 괄호로 바꾼다. 만들고 나서 한 번 전수 검사해라
- **회색 작은 글씨 금지.** 본문은 17px 이상, 충분히 진한 색으로

## 알려진 함정

- 파일 이름은 `create_new_file` 때만 정해진다. 플러그인 API 로 못 바꾼다. 바꾸려면 사람이 UI 에서 한다
- `layoutSizing` 은 부모가 오토레이아웃일 때만 `HUG` 와 `FILL` 이 먹는다. `appendChild` 부터 하고 설정한다
- 색은 0에서 1 범위다. 255 로 넣으면 튕긴다
- 텍스트를 만지기 전에 **그 노드가 쓰는 폰트를 먼저 로드**한다. 안 하면 "unloaded font" 로 죽는다
- 어떤 파일은 본문에 특수 제어문자가 섞여 `get_metadata` 가 아예 안 된다. 그럴 땐 `use_figma` 읽기 스크립트로 구조를 본다
