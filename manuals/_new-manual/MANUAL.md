# 처음 하는 업무를 매뉴얼로 남기기

- **부르는 말**: 매뉴얼 없는 일, 처음 하는 업무, 이거 매뉴얼로 만들어줘
- **런너**: claude
- **제어층**: 그 업무가 쓰는 층을 그대로 따른다
- **한 번에 걸리는 시간**: 그 업무 시간 + 15분

---

## 무엇을 만드는 업무인가

매뉴얼이 없는 업무를 **기록 모드로** 한 번 해내고, 그 기록을 `manuals/<새 id>/MANUAL.md` 로 남긴다.
다음부터는 사람이 한 문장만 말하면 그 매뉴얼로 돈다.

## 절차

1. **먼저 확인한다 — L1**
   ```bash
   node "<OPS>/ops.mjs" manuals "사람이 말한 업무"
   ```
   비슷한 게 나오면 새로 만들지 말고 그걸 **고친다.** 매뉴얼이 둘로 갈라지는 게 제일 나쁘다.

2. **기록 파일을 연다 — L1**
   `<OPS>/work/<taskId>/기록.md` 를 만들고, 진행하면서 **그때그때** 적는다.
   끝나고 몰아서 쓰면 함정을 다 까먹는다. 적을 것:
   - 무슨 명령을 쳤나 (그대로 복사)
   - 어떤 화면에서 무엇을 눌렀나 (요소 이름으로. 좌표 말고)
   - 어디서 막혔고 어떻게 뚫었나
   - 사람에게 물어본 것과 그 답

3. **업무를 실제로 해낸다**
   되돌리기 어려운 단계에서는 멈추고 묻는다. 처음 하는 업무라 더 그렇다.

4. **매뉴얼로 승격한다 — L1**
   ```bash
   cp -r "<OPS>/manuals/_template" "<OPS>/manuals/<새-id>"
   ```
   `<새-id>` 는 영문 소문자와 하이픈으로. 기록.md 를 보고 템플릿 칸을 채운다.

   채울 때 지키는 것:
   - **도구 이름을 쓰지 마라.** "claude-in-chrome 으로" 가 아니라 "L3 으로".
   - **절대경로를 박지 마라.** `<OPS>` `<DEV>` 로 쓴다. 다른 컴에서도 돌아야 한다.
   - 막혔다가 뚫은 건 전부 "알려진 함정" 에 옮긴다. 이게 제일 값어치 있다.
   - 기계로 검사할 수 있는 완료 조건이 있으면 `checks.mjs` 를 같이 만든다.

5. **한 번 검증한다**
   ```bash
   node "<OPS>/ops.mjs" manuals <새-id>
   ```
   목록에 제대로 뜨는지 본다. 제목·부르는 말·런너·제어층이 안 나오면 머리말 형식이 틀린 것이다.

## 완료 검사

- [ ] (기계) `manuals/<새-id>/MANUAL.md` 가 있고 `manuals` 목록에 머리말 네 줄이 다 뜬다
- [ ] (사람) 매뉴얼만 읽고 이 업무를 처음부터 할 수 있는가. 빠진 준비물이 없는가
- [ ] (사람) 도구 이름과 절대경로가 안 들어갔는가

## 알려진 함정

- 끝나고 기억으로 쓰면 **막혔던 지점이 통째로 빠진다.** 그게 다음 세션이 또 막히는 지점이다.
  진행하면서 적어라.
- 잘 된 경로만 적으면 매뉴얼이 반쪽이다. **안 되는 길도 적어야** 다음 세션이 거기 안 빠진다.
  "일괄 수정은 별도 창이라 안 된다 → 개별 수정으로 돌아간다" 같은 문장이 핵심이다.
- 업무를 처음 하면서 매뉴얼까지 완벽하게 만들려 하지 마라. 초안이면 된다.
  두 번째 실행에서 틀린 데를 고치는 게 훨씬 빠르다.
