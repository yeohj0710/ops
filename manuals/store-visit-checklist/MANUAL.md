# 매장별 인플루언서 방문 체크리스트 추가

- **부르는 말**: 체크리스트 시트 하나 더 만들어줘, 매장 체크리스트 추가해줘, 방문 체크리스트 만들어줘, 명동점처럼 시트 만들어줘, 약국 체크리스트 시트 추가, 인플루언서 체크리스트 새로 만들어줘
- **미리 허가**: 드라이브 [운영] 인플루언서 시딩 폴더에 새 구글 시트 사본 만들기, 그 사본의 제목 칸과 입력 칸 쓰기
- **런너**: codex
- **제어층**: L1 (드라이브 커넥터로 원본 찾기와 복사, 셸로 원본 수식 읽기, 시트 API 로 사본 쓰기와 검증)
- **한 번에 걸리는 시간**: 10분

---

## 무엇을 만드는 업무인가

인플루언서가 방문 촬영하는 매장마다 방문 체크리스트 구글 시트를 하나씩 둔다. 인스타 계정, 이름, 방문 일시,
리쥬닉 키트 수령 여부를 적는 표다.
끝나면 `내 드라이브/[운영] 인플루언서 시딩/` 에 `<매장 이름> 인플루언서 체크리스트` 가 생겨 있다.
제목 칸은 새 매장 이름이고 입력 칸은 비어 있다. 서식, 드롭다운, 수식은 본뜬 매장 시트와 같다.

260914 기준 매장 시트는 넷이다. OWM 성수점, OWM 신사점, 퓨어약국 명동점, 퓨어약국 성수점.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차, 후속 작업, 완료 검사를 한 번에 실행한다.
중간 산출물만 남기고 멈추거나 게시, 전송, 주문 버튼을 사람에게 넘기지 않는다. 매뉴얼에
명시된 외부 행동은 호출에 포함된 승인으로 본다. 매뉴얼 밖의 대상, 비밀번호와 CAPTCHA,
매뉴얼 밖 결제, 되살릴 수 없는 삭제만 사람에게 묻는다.

## 준비물

- 새 매장 이름. 사람이 말한 이름을 파일 이름과 제목 칸에 그대로 쓴다 (예: 퓨어약국 성수점)
- 본뜰 매장 시트. "○○점처럼" 이라고 했으면 그 시트, 말이 없으면 가장 최근에 만든 매장 시트
- 드라이브 커넥터(원본 찾기, 복사, 권한 읽기)와 시트 API 쓰기

## 절차

1. **루트 가드 기준을 뜬다 (L1)**
   ```bash
   node "<OPS>/scripts/drive-root-guard.mjs" snapshot --out "<OPS>/work/<taskId>/drive-root-before.json"
   ```

2. **원본 파일 ID 와 폴더 ID 를 찾는다 (L1)**
   `.gsheet` 바로가기는 셸로 안 읽힌다. 드라이브 커넥터 검색에
   `title contains '인플루언서 체크리스트' and mimeType = 'application/vnd.google-apps.spreadsheet'` 를 걸면
   매장 시트마다 `id` 와 `parentId` 가 나온다.
   새 매장 이름으로 된 파일이 이미 있으면 새로 만들지 않고 그 파일 상태를 보고한다.

3. **원본 구조를 읽는다 (L1)**
   원본이 링크 공유돼 있으면 셸로 받는다. 방법은 `abilities/구글시트.md` 의 "링크 공유된 시트는 셸로 수식까지 읽는다".
   xlsx 에서 칸마다 수식인지 값인지, 드롭다운 범위, 조건부 서식, 병합, 고정 행을 적고, htmlview 에서 탭 이름과 gid 를 뽑는다.
   260914 퓨어약국 명동점 원본의 모양은 이랬다. **외워 쓰지 말고 매번 다시 읽는다.**
   - 탭 `기프트 체크리스트` 와 `설정`
   - A1:F1 병합 제목 `<매장 이름> 인플루언서 방문 체크리스트`, A2:F2 병합 안내문
   - 4~5행 집계, A5 는 `=COUNTA($B$8:$B$67)&" 명"`
   - 7행 헤더 `No. / 인스타 계정 / 이름 / 방문 일시 / 리쥬닉 키트 수령 여부 / 비고`
   - 입력 칸 8~67행. No. 열은 `=IF($B9="","",ROW()-7)` 꼴 수식, E8:E67 에 O,X 드롭다운과 조건부 서식 2개
   - 1~7행 고정, 69~70행 TIP 두 줄

4. **사본을 만든다 (L1)**
   드라이브 커넥터 복사에 제목 `<매장 이름> 인플루언서 체크리스트` 와 `parentId`(원본 폴더 ID)를 준다.
   이게 보이면 성공: 응답의 `parentId` 가 원본 폴더 ID 와 같고, 사본 본문을 읽으면 원본과 같다.

5. **사본의 제목을 바꾸고 입력 칸을 비운다 (L1, 시트 API)**
   `abilities/구글시트.md` 의 쓰기 안전 게이트를 따르고, 요청 세 개를 따로 보낸다.
   1) 제목 칸 값만 새 매장 이름으로 바꾼다. 병합과 서식은 둔다
   2) 입력 칸(인스타 계정부터 비고까지, 8~67행)의 값만 지운다. 지우기 전에 읽어서 원본 매장 인플루언서 말고
      다른 값이 없는지 본다. 서식, 드롭다운, 조건부 서식은 남긴다
   3) No. 열 8~67행에서 수식이 아닌 칸을 옆 행과 같은 꼴 수식으로 채운다

   **claude 런너는 이 단계를 브라우저로 하지 않는다.** 1~4단계까지 하고, 사본 URL, 탭 이름, gid, 지금 모양,
   바꿀 칸, 확인할 것, 하지 말 것을 넣은 붙여넣을 프롬프트를 사람에게 준다.
   프롬프트 첫 줄은 "헤더 행(A열이 No. 인 행)을 먼저 읽어서 열 위치를 확인하고 시작하라" 다.

6. **공유 설정을 맞출지 사람에게 묻는다**
   복사는 공유 설정을 안 가져온다. 드라이브 커넥터로 원본 권한을 읽어서, 원본이 링크 있는 누구나 편집이면
   사본도 같게 열지 묻는다. 답을 받기 전에 열지 않는다.

7. **루트 가드를 검사한다 (L1)**
   ```bash
   node "<OPS>/scripts/drive-root-guard.mjs" check --before "<OPS>/work/<taskId>/drive-root-before.json"
   ```
   `새 클라우드 문서가 루트에 남지 않았다` 가 나오면 통과다.

## 산출물

- `내 드라이브/[운영] 인플루언서 시딩/<매장 이름> 인플루언서 체크리스트` (구글 시트)
- `<OPS>/work/<taskId>/` 에 루트 가드 기준 파일, 작업 폴더에 원본 xlsx

## 완료 검사

- [ ] (기계) 사본의 `parentId` 가 `[운영] 인플루언서 시딩` 폴더다
- [ ] (기계) 제목 칸이 새 매장 이름이고 A5 집계가 `0 명` 이다
- [ ] (기계) 입력 칸 8~67행이 화면 값 기준으로 전부 비어 있다
- [ ] (기계) No. 열 8~67행이 전부 `=IF($Bn="","",ROW()-7)` 꼴 수식이다 (n 은 그 행 번호)
- [ ] (기계) 헤더, TIP, 드롭다운, 조건부 서식, 설정 탭이 원본과 같다
- [ ] (기계) 원본 매장 시트는 그대로다
- [ ] (기계) 루트 가드 통과
- [ ] (사람) 사본 공유 설정을 원본처럼 열지 정했다

## 알려진 함정

- 입력 칸만 비웠는데 빈 표 No. 칸에 `1` 이 남는다 → 원본 A8 만 숫자 1 이 박혀 있고 A9 부터 수식이다
  (260914 퓨어약국 명동점). 값으로 읽으면 1, 2, 3, 4 로 똑같이 보인다 → 3단계에서 xlsx 로 수식 칸을 확인하고
  5단계 3) 에서 채운다
- 매장 쪽에서 링크로 시트를 못 연다 → 복사는 공유 설정을 안 가져온다 → 6단계에서 사람에게 묻고 연다
- `cat` 으로 `.gsheet` 를 읽으려다 `Invalid request code` 가 난다 → 드라이브 바로가기라 셸로 안 읽힌다
  → 2단계처럼 커넥터 검색으로 ID 를 얻는다
- 사본을 셸로 받으려다 `401` 과 HTML 이 온다 → 사본은 아직 링크 공유가 안 된 상태다 → 원본을 읽거나 커넥터로 읽는다
- 집계 B5, D5(완료, 일부 수령) 수식이 xlsx 에서 `#REF!` 로 나온다. 260914 퓨어약국 명동점 원본이 원래 그렇다
  → 이 업무에서는 원본 그대로 두고 고치지 않는다. 고칠지는 사람이 정한다

## 사람에게 물어야 하는 지점

- 사본을 링크 있는 누구나 편집으로 열지 (6단계)
- 새 매장 이름으로 된 파일이 이미 있을 때
- 입력 칸에 원본 매장 인플루언서 말고 다른 값이 있을 때
