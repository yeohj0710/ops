# 인스타 카드뉴스 만들기

- **부르는 말**: 카드뉴스 만들어줘, 캐러셀 만들어줘, 카드뉴스 뽑아줘, 카드뉴스 생성, 캐러셀 하나 만들어줘
- **미리 허가**: 없음. 피그마 파일과 PNG, 캡션 파일만 만든다. 인스타 게시는 사람이 따로 시킨다
- **런너**: claude
- **제어층**: L1 (피그마 MCP 로 그린다), L3 (레퍼런스 캡처, 이미지 생성)
- **한 번에 걸리는 시간**: 한 벌에 40~60분. 이미지 생성이 들어가면 더

---

## 무엇을 만드는 업무인가

담당 약사 계정에 올릴 인스타 캐러셀 한 벌을 만든다. 끝나면 이 세 가지가 있어야 한다.

- 피그마 파일에 카드 4~6장 (1080x1350)
- `<드라이브>/여형준님/29 카드뉴스/etc/<YYMMDDhhmm 제목>/` 에 PNG
- 같은 폴더에 `캡션.html`

**한 벌 = 레퍼런스 디자인 하나 + 내용 하나.**
같은 내용을 여러 디자인으로 뽑거나, 같은 디자인에 여러 내용을 얹지 않는다. 1대1이다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차와 완료 검사를 한 번에 실행한다.
중간 산출물만 남기고 멈추지 않는다. 대상 계정과 소재만 확인하면 나머지는 끝까지 간다.

## 절차

### 1. 대상 계정을 확인하고 그 계정을 본다 (L3)

인스타에서 최근 게시물을 훑어 결과 지금 뭘 하고 있는지 본다.
DOM 에서 긁으면 눈으로 세는 것보다 빠르다.

```js
// 인스타 탭에서
const r = await fetch(`/api/v1/feed/user/${userId}/?count=33`, {headers:{'x-ig-app-id':'936619743392459'}});
```

`userId` 는 프로필 HTML 의 `"profile_id":"(\d+)"` 로 뽑는다.
`web_profile_info` 는 비즈니스 계정에서 400 이 뜨니 이 길로 간다.

### 2. 레퍼런스 디자인을 하나 고른다 (L1)

**맨손으로 디자인하지 마라.** 판 목록은 `<DEV>/cardnews-refs/designs.md` 에 있다.

```bash
cat C:/dev/cardnews-refs/designs.md
```

지금 여덟 판이다. 정보 밀도판, 노트판, 표판, 매거진판, 실사판, 인물 누끼판, 자막판,
제품 실사 오픈판. **기본은 정보 밀도판이다.** 사진이 필요 없고 저장을 제일 많이 받는다.
260827 에 여덟 판을 한 벌씩 다 지어 뒀으니 새로 지을 때 그 파일을 열어 보고 시작한다.

실측 원본 이미지는 두 곳에 있다.

- `<DEV>/cardnews-refs/shots/<계정>/<코드>/`
- `<드라이브>/여형준님/29 카드뉴스/etc/2608270900 공동구매 캐러셀 레퍼런스/` (82장)

**사진이 필요한 판도 사진이 없다고 건너뛰지 않는다.** 실사판, 인물 누끼판, 자막판,
제품 실사 오픈판은 원래 그 약사 본인 촬영분이나 제품 실물이 필요한 판이다.
그 자리에 **생성 사진을 넣어 판을 완성해 두고**, 나중에 진짜 사진이 오면 한 장만 갈아 끼운다.
어느 자리가 교체 자리인지는 카드 밖 레퍼런스판에 적는다.

**사람 얼굴은 생성하지 않는다.** 약사 계정에 가짜 사람이 올라가면 안 된다.
인물 누끼판은 인물 자리를 대형 제품 누끼로 대신 채운다.
공구 알림 포맷(실사판, 제품 실사 오픈판)은 행사 문구를 빼고 정보형으로 돌려 쓴다.

### 2-0. 커버만 보고 만들지 마라

**캐러셀 안쪽 장까지 받아서 본다.** 커버만 보면 판을 절반만 안 것이다.
260827 에 커버만 보고 지었다가 "레퍼런스랑 너무 다르다" 로 반려됐다.
안쪽 장이 그 판에서 **정보를 어떻게 넣는지**를 알려 준다.

```js
const cm = it.carousel_media;               // media/{id}/info/ 응답
const url = (cm[i].image_versions2?.candidates||[]).sort((a,b)=>b.width-a.width)[0]?.url;
```

받고 나서 이 넷을 적는다.

- **글꼴의 결**: 둥근가 각진가, 손글씨인가 고딕인가
- **글자 판의 폭**: 글자 폭에 딱 맞는가, 화면 폭을 다 쓰는가
- **판의 색**: 어두운 판에 흰 글자인가, 밝은 판에 검정 글자인가
- **제목의 자리**: 위인가 아래인가

### 2-0-1. 글꼴을 먼저 맞춘다

**Pretendard 로만 지으면 어떤 판을 흉내 내도 같은 얼굴이 나온다.** 판마다 글꼴이 다르다.

| 결 | 글꼴 | 어디에 |
| --- | --- | --- |
| 둥글고 친근한 손글씨풍 | `Jua` (Regular 하나뿐) | 제품 실사 오픈판 제목과 라벨 |
| 노트 손글씨 | `Gaegu` (Bold/Regular/Light) | 노트판 |
| 펜으로 쓴 메모 | `Nanum Pen` (Regular) | 인물 누끼판 마무리 줄 |
| 굵고 각진 자막 | `Pretendard Black` + 검정 테두리 | 자막판, 인물 누끼판 제목 |
| 본문과 표 | `Pretendard` | 전부 |

`Black Han Sans`, `Do Hyeon`, `BM HANNA_TTF`, `Gothic A1`, `Noto Sans KR` 도 있다.
`figma.listAvailableFontsAsync()` 로 확인하고 쓴다.

### 2-1. 왜 정보 밀도판이 기본인가

**후킹 문구를 지어내는 것보다 정보를 꽉 채우는 게 세다.**
인스타에서 잘 도는 약사 카드뉴스는 표가 화면을 꽉 채우고, 한 셀에 두세 줄이 들어가 있다.
사람들이 "이건 저장해야겠다" 로 반응한다. 약들약 영양제 섭취법이 하트 1,345,
바른약 영양제 총정리표가 하트 5,531 이다. 같은 계정 공구 게시물의 열 배가 넘는다.

캡션도 저장을 부르는 말로 끝낸다. "저장해두시고 필요할 때 꺼내 보세요".

**행 수는 6~8이 상한이다.** 13행짜리를 만들면 글자가 너무 작아진다.
내용이 넘치면 장을 나눈다. 한 장에 밀어 넣지 마라.

### 4. 근거 페이지를 이미지로 뽑는다 (L1)

만든 카드 **옆에** 원본 책 페이지를 붙여 둔다. 어디서 온 내용인지 바로 보인다.

**카드 안에는 출처와 레퍼런스를 적지 마라.** 올라가는 건 카드 이미지뿐이고,
거기 "참고 건강상담 Checker 236쪽" 같은 줄이 박혀 있으면 읽는 사람에게 군더더기다.
출처, 레퍼런스 링크, 판 이름은 전부 **피그마 캔버스의 카드 밖 패널**에 둔다.
캡션에 한 줄 넣는 것은 괜찮다.

pix = doc.load_page(PDF쪽 - 1).get_pixmap(matrix=fitz.Matrix(2, 2))

### 5. 뼈대를 글로 적는다 (L1)

카드 장수와 각 장에 무엇을 둘지 먼저 글로 적는다. 바로 그리지 마라.

- **정보형은 6장을 넘기지 않는다.** 나눔과 이벤트는 3장이 상한
- 한 장에 한 가지만 말한다
- 20장짜리는 아무도 끝까지 안 넘긴다

### 5-1. 글자 크기가 제일 자주 틀린다

**1080x1350 은 폰에서 가로 400px 남짓으로 줄어든다. 캔버스에서 읽히는 크기가 폰에서는 안 읽힌다.**
아래가 최소선이다. 이보다 작게 쓰지 마라.

| 자리 | 최소 | 권장 |
| --- | --- | --- |
| 큰 제목 | 84 | 88~104 |
| 1장 제목 | 92 | 96~106 |
| 표 헤더 | 32 | 34~36 |
| 표 첫 열 (항목 이름) | 36 | 38~42 |
| 표 본문 셀 | 32 | 34~36 |
| 본문 문장 | 34 | 40~42 |
| 부연, 캡션 | 28 | 31~34 |
| 계정 핸들 | 26 | 28~42 |

**글자를 키우려면 행을 줄여야 한다. 행 4개가 기본이고 6개가 상한이다.**
내용이 넘치면 장을 나눈다. 한 장에 밀어 넣으면 폰에서 글자가 뭉개진다.

만들고 나서 `get_screenshot` 에 `maxDimension: 430` 을 줘서 **폰 크기로 한 번 본다.**
거기서 안 읽히면 실제로도 안 읽힌다.

### 5-2. 본문에는 반드시 키워드 강조를 넣는다

문장이나 셀에 글이 있으면 **핵심 어절을 색과 굵기로 뺀다.** 통짜 회색 글은 아무도 안 읽는다.

```js
function hi(t, words, color, style='Black'){
  words.forEach(w=>{ let i=t.characters.indexOf(w);
    while(i!==-1){
      t.setRangeFills(i, i+w.length, [{type:'SOLID', color}]);
      t.setRangeFontName(i, i+w.length, {family:'Pretendard', style});
      i = t.characters.indexOf(w, i+w.length);
    }});
}
```

- 표 본문은 성분명과 약 이름을 빨강(`#C0392B`), 증상을 파랑(`#1F5FA8`)
- 어두운 판에서는 주황(`#F0AC63`) 이나 흰색
- **한 셀에 한두 어절만.** 다 칠하면 아무 데도 안 보인다
- `setRangeFontName` 전에 그 스타일을 `loadFontAsync` 로 올려둬야 한다

### 6. 말투를 지킨다

**여기가 제일 자주 틀린다.**

- **제목은 복합명사만 나열한다.** 문장형과 관형절은 그대로 AI 티가 난다
  - `약은 잘 챙겨 먹는데 왜 계속 피곤할까요` → `약물 유발 영양소 고갈`
  - `빠지는 이유 3가지` → `고갈 경로 3가지`
  - `그래서 챙길 5가지` → `보충 우선순위 5`
  - 커버도 예외가 아니다
- **본문은 `~해요` 체로 쓴다.** `~합니다` 는 딱딱해서 카드뉴스에 안 맞는다
  - `흡수되지 않습니다` → `흡수되지 않아요`
  - `식후에 복용하세요` → `꼭 식후에 드세요`
  - 표 안의 명사구는 그대로 둔다
- 줄표(—)와 가운뎃점(·)은 쓰지 않는다. 쉼표나 줄바꿈으로 바꾼다

### 6-1. 첫 장부터 정보를 보여준다

**제목만 있는 표지는 기본이 아니다.** 1장부터 표나 목록을 보여주는 게 낫다.
정보가 꽉 차 있으면 그것 자체가 후킹이다.

표지를 따로 두는 것은 **그 제목이 진짜로 내용을 궁금하게 만들 때만**이다.
매거진판처럼 판 자체가 표지를 요구하는 경우도 예외다.

### 7. 이미지가 필요하면 생성한다 (L3)

크롬에 로그인된 ChatGPT 로 뽑는다. 사람 유료 계정이라 따로 돈이 안 나간다.
`chatgpt.com` 새 탭에서 **새 채팅**을 누른다. 쓰던 대화에 이어 쓰면 그 대화가 오염된다.

프롬프트에 반드시 넣을 것.

- **각각 개별 이미지로 몇 장** 이라고 못 박는다. 안 그러면 콜라주 한 장으로 준다
- 세로 4:5 비율
- 글자, 숫자, 라벨, 브랜드 로고, 워터마크 절대 금지
- 물방울과 기포 금지
- 실사 사진 느낌. 광택 3D 렌더링이나 클립아트 말고

조명은 이렇게 적는다. **사용자가 말하는 "예쁜 조명"은 전등이 아니라 사진의 조명 연출과 색보정이다.**

> 창을 통과한 부드러운 자연광, 길게 드리운 그림자, 은은한 역광, 따뜻한 금빛 색보정, 빛망울

프롬프트 입력은 `computer` 의 `type` 도, `execCommand('insertText')` 도 쓰지 않는다.
`type` 은 긴 한국어에서 **공백이 전부 사라지고**, `insertText` 는 글자는 들어가는데
리액트가 빈 칸으로 알고 있어서 **전송 버튼이 안 켜진다.**
붙여넣기 이벤트로 넣어야 프로즈미러와 리액트 상태가 같이 갱신된다.

```js
const pm = document.querySelector('#prompt-textarea');
pm.focus();
document.execCommand('selectAll'); document.execCommand('delete');
const dt = new DataTransfer(); dt.setData('text/plain', "프롬프트 전문");
pm.dispatchEvent(new ClipboardEvent('paste', {clipboardData: dt, bubbles: true, cancelable: true}));
```

넣고 나서 `computer` 의 `key: Return` 으로 보낸다. 스크립트로 버튼을 찾아 누르지 않는다.

**전송이 안 된 것처럼 보여도 실제로는 갔을 때가 많다.** 탭을 닫기 전에 왼쪽 대화 목록을 본다.
260827 에 이미 보낸 걸 모르고 탭을 닫아 같은 요청을 세 번 돌렸다.
확실하게 보내려면 `Return` 말고 **전송 버튼 좌표를 재서 클릭한다.**

```js
const btn=[...document.querySelectorAll('button')].find(b=>/보내|Send/.test(b.getAttribute('aria-label')||''));
const r=btn.getBoundingClientRect(), sc=1568/innerWidth;
// {x:(r.x+r.width/2)*sc, y:(r.y+r.height/2)*sc} 를 computer 의 left_click 에 넣는다
```

**한 메시지에 한 장씩 시킨다.** 네 장을 한 번에 달라고 하면 오류로 끝난다.

**탭이 얼면 되살리려 하지 말고 닫고 새로 연다.** 이미지를 서너 장 뽑고 나면
`Runtime.evaluate` 가 45초 타임아웃으로 죽는다. 대화는 서버에 남으니 새 탭에서 이어가면 된다.
한 대화에 이미지를 세 장까지만 뽑고 새 채팅으로 넘어가는 편이 빠르다.

받는 것은 `fetch` 로 바로 blob 을 받아 떨구는 게 캔버스보다 확실하다.

```js
const r = await fetch(im.src); const b = await r.blob();
const a = document.createElement('a'); a.href = URL.createObjectURL(b); a.download = 'shot.png';
document.body.appendChild(a); a.click(); a.remove();
```

받는 것은 페이지 안에서 캔버스에 그려 다운로드 폴더로 떨군다.

```js
const im = new Image(); im.crossOrigin = 'anonymous';
await new Promise((ok,no)=>{im.onload=ok; im.onerror=no; im.src=URL});
const c = document.createElement('canvas'); c.width=im.naturalWidth; c.height=im.naturalHeight;
c.getContext('2d').drawImage(im,0,0);
const b = await new Promise(r=>c.toBlob(r,'image/png'));
const a = document.createElement('a'); a.href=URL.createObjectURL(b); a.download='shot.png';
document.body.appendChild(a); a.click(); a.remove();
```

### 8. 피그마에서 짓는다 (L1)

`figma-create-new-file` 스킬 → `create_new_file` → `figma-use` 스킬 → `use_figma` 순서다.
**스킬을 안 부르면 조용히 깨진다.**

**호출 수가 비용이지 요소 수는 아니다.** 한 파일에 카드가 스무 장 있어도 느려지지 않는다.
비싼 건 `use_figma` 왕복과 `get_screenshot` 이다. 그래서 이렇게 한다.

- **한 줄(카드 5장)을 스크립트 하나로 짓는다.** 한 장씩 짓지 마라
- 헬퍼(`card`, `T`, `hi`, `table`)를 스크립트 맨 위에 두고 돌려 쓴다
- 확인은 그 줄에서 **한두 장만** `frame.screenshot({scale:0.32})` 로 본다
- 최종 PNG 뽑기만 카드마다 `get_screenshot` 을 부른다
- 스크립트 한 개 상한은 5만 자다. 넘으면 줄을 쪼갠다

- 프레임 1080x1350, 가로 1220 간격으로 깐다
- 한 벌이 한 줄이다. 세트가 여럿이면 세로 1900 간격으로 줄을 늘린다
- **페이지를 나누지 마라.** 한 페이지에 다 놓아야 한눈에 비교한다
- **각 줄 왼쪽에 레퍼런스 원본 이미지와 링크, 책 원본 페이지를 붙인다**
- 한두 장 짓고 `await frame.screenshot({scale:0.5})` 로 **매번 눈으로 본다**

이미지는 `upload_assets` 로 주소를 받아 `curl` 로 올리고 해시를 `fills` 에 꽂는다.

```bash
curl -s -X POST "<submitUrl>" -F "file=@shot.png;type=image/png"
```

### 9. PNG 로 뽑아 드라이브에 둔다 (L1)

`get_screenshot` 에 `maxDimension: 1350` 을 주면 1080x1350 원본 크기로 나온다.
반환된 주소를 `curl` 로 받아 드라이브 폴더에 넣는다.

### 10. 캡션을 쓴다 (L1)

같은 폴더에 `캡션.html` 로 둔다. 복사 버튼이 있는 한 장짜리 페이지다.
본문, 해시태그, 슬라이드 차례, 만든 곳을 나눠 담는다. 기존 파일을 본떠 쓴다.

- [ ] (사람) **1장 제목이 한눈에 들어오는가.** 92 밑이면 다시 키운다
- [ ] (사람) **본문마다 키워드 강조가 들어갔는가.** 통짜 회색 글이 있으면 다시

## 알려진 함정

- **대상 계정을 지어내지 마라.** 260827 에 지정 없이 `kimjejo_pharma` 로 만들었다가 반려됐다
- **레퍼런스는 참고가 아니라 따라 그릴 원본이다.** 260827 에 판 문법을 바꿔 지었다가 반려됐다.
  약사임당 판은 원본에 검정 반투명 풀폭 박스가 없는데 깔았고,
  유진약사 판은 제목이 아래에 있는데 위로 올렸다. **원본 배치를 재서 옮긴다**
- **레퍼런스를 봤으면 그대로 따라라.** 어도비 판은 제목이 아래쪽 52~79% 자리인데
  위로 올려서 만들었다가 반려됐다. 원본 좌표를 재서 옮긴다
- **같은 내용을 여러 판으로 뽑지 마라.** 판 하나에 내용 하나다
- **`figma.createAutoLayout()` 은 흰 fill 이 기본이다.** `fills=[]` 를 안 하면 글자 줄마다 흰 띠가 깔린다
- **피그마 `query()` 셀렉터에 한글을 넣으면 파서가 죽는다.**
  `findOne(n => n.type==='TEXT' && n.characters.indexOf('완판')!==-1)` 로 잡는다
- **`use_figma` 는 한 번에 `setCurrentPageAsync` 를 한 번만 부를 수 있다.**
  현재 페이지는 지울 수 없으니, 다른 페이지로 옮긴 뒤에 지운다
- **인스타 `web_profile_info` 는 비즈니스 계정에서 400 이 뜬다.** 프로필 HTML 에서 id 를 뽑는다
- **인스타 태그와 ChatGPT 이미지는 배경 탭에서 안 그려진다.** `naturalWidth` 가 0 이면
  `new Image()` 로 따로 불러온다. DOM 렌더링과 무관하게 로드된다
- **이미지 생성은 한 번에 안 된다.** 260827 에 세 번 돌렸다
  1. 조용한 정물 → 정확한데 스크롤을 못 멈춘다
  2. 알약 폭포와 손바닥 산더미 → 약 오남용 스톡사진처럼 보인다. 사람 손도 반려됐다
  3. 약통 하나 + 채워야 할 영양소 식재료 + 자연광 → 통과
  **주제가 흐려지면 실패다.** 예쁘게 하려고 풍경만 넣으면 약 얘기인 줄 모른다
- **네이버 블로그는 브라우저 도구로 못 연다.** `curl` 로 `PostView.naver?blogId=..&logNo=..` 를 받는다
- **인앱 브라우저 패널은 이 기계에서 앱을 죽인다.** 크롬 익스텐션이나 `curl` 로 간다
- **구글 드라이브(G:) 위에서 `mv` 로 한글 파일명을 바꾸지 마라.** 새 이름으로 `cp` 하고 확인한 뒤 지운다
- **`upload_assets` 로 올린 그림은 캔버스에 빈 프레임으로 남는다.** 해시만 쓰고 프레임은 지운다.
  다 짓고 나서 카드(1080x1350)와 레퍼런스판(1560x1350)이 아닌 것을 전부 지우면 깔끔하다
- **`curl -F "file=@/c/..."` 는 깃배시에서 파일을 못 연다.** 그 폴더로 `cd` 해서 파일명만 쓴다.
  실패해도 출력이 안 나올 때가 있으니 `-sS -w "HTTP=%{http_code}"` 를 붙인다
- **키워드 강조 배열에 그 노드에 없는 말을 넣으면 조용히 아무 일도 안 일어난다.**
  제목에 없는 말을 제목 배열에 넣어 놓고 강조가 됐다고 착각하기 쉽다. 뽑아서 눈으로 본다
- **마지막 행이 하단 핸들 배지를 덮는다.** 행 시작 y + 행간 x (행 수 - 1) + 소제목 두 줄까지
  더해서 1230 을 넘는지 계산하고 짓는다. 넘으면 행간을 줄이거나 문장을 한 줄로 줄인다
- **정보 판을 화면 폭으로 깔지 마라.** 레퍼런스의 판은 **글자 폭에 딱 맞는다.**
  텍스트를 먼저 만들어 폭을 재고, 그 폭 + 좌우 여백으로 사각형을 만들어 뒤에 넣는다.
  풀폭 검정 박스를 깔면 사진이 죽고 판이 달라 보인다
- **배지와 라벨의 위아래 여백을 손으로 계산하지 마라.** 줄 높이 때문에 반드시 어긋난다.
  사각형을 만든 뒤 텍스트를 `textAutoResize='NONE'` 으로 같은 크기로 늘리고
  `textAlignVertical='CENTER'` 로 맞춘다. 그래야 위 여백과 아래 여백이 같아진다
- **한 사진으로 다섯 장을 다르게 보이게 하려면 `scaleMode:'CROP'` 에 `imageTransform` 을 준다.**
  `[[sx,0,tx],[0,sy,ty]]` 가 보여줄 사각형이다. 레퍼런스도 한 번 촬영한 장소를 아홉 장에 나눠 쓴다
- **자막체(흰 글자 검정 두꺼운 테두리)는 텍스트 노드의 `strokes` 로 만든다.**
  `strokeWeight` 14~20, `strokeAlign='OUTSIDE'`. 그림자를 하나 더 얹으면 사진 위에서도 뜬다
