# 인스타 카드뉴스 만들고 올리기

- **부르는 말**: 카드뉴스 올려줘, 캐러셀 올려줘, 카드뉴스 업로드, 카드뉴스 만들어줘, 캐러셀 만들어줘, 카드뉴스 뽑아줘, 카드뉴스 생성, 캐러셀 하나 만들어줘, 카드뉴스 만들어서 올려줘
- **미리 허가**: 지정 계정에 인스타 캐러셀 공개 게시. 그 밖에는 피그마 파일과 PNG, 캡션 파일만 만든다
- **런너**: claude
- **제어층**: L1 (피그마 MCP 로 그린다, 파일 서버, 게시 판정), L3 (레퍼런스 캡처, 이미지 생성, 인스타 게시)
- **한 번에 걸리는 시간**: 만들기 한 벌에 40~60분. **올리기만 하면 한 벌에 10~15분**
  (게시 5분, 캡션을 수정 화면에서 다시 넣는 데 5분)

---

## 무엇을 만드는 업무인가

담당 약사 계정에 올릴 인스타 캐러셀 한 벌을 **만들고 그 계정에 올린다.**
끝나면 이 넷이 있어야 한다.

- 피그마 파일에 카드 4~6장 (1080x1350)
- `<드라이브>/영상 편집/AI 크리에이터/카드뉴스/<YYMMDDhhmm 제목 (판이름) (계정)>/` 에 PNG (4x, 4320x5400). 어라운드팜, 미미팜은 9절의 게시 폴더에 둔다
- 같은 폴더에 `캡션.txt` 와 `캡션.html`
- **인스타에 올라간 캐러셀 하나.** 올린 폴더는 `업로드 완료/` 로 옮겨져 있다

**한 벌 = 레퍼런스 디자인 하나 + 내용 하나.**
같은 내용을 여러 디자인으로 뽑거나, 같은 디자인에 여러 내용을 얹지 않는다. 1대1이다.

### 만들기와 올리기는 따로 시킬 수 있다

| 시킨 말 | 하는 것 |
| --- | --- |
| 카드뉴스 만들어줘 | 절차 1~10. 폴더에 PNG 와 캡션까지. **올리지 않는다** |
| 카드뉴스 올려줘 | 절차 U1~U5. 만들어 둔 것 중 한 벌을 골라 올린다 |
| (둘 다) 카드뉴스 만들어서 올려줘 | 1~10 뒤에 바로 U1~U5 |

**만들기를 시켰는데 밀린 게 쌓여 있으면 한 줄로 알린다.** 대기 벌 수는 `cardnews-next.mjs` 가 찍어 준다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차와 완료 검사를 한 번에 실행한다.
중간 산출물만 남기고 멈추지 않는다. 대상 계정과 소재만 확인하면 나머지는 끝까지 간다.
**올리기를 시켰으면 게시 버튼 직전에 다시 승인받지 않는다.** 계정, 장수, 비율, 캡션만 확인하고 올린다.

**한 호출에 한 벌만 올린다.** 대기 폴더에 여덟 벌이 있어도 한 번에 다 올리지 않는다.
같은 계정 피드에 캐러셀을 연달아 쏟으면 서로 도달을 갉아먹는다.

## 표기 규칙 (어라운드팜, 미미팜. 벌을 만질 때마다 지킨다)

사용자가 여러 번 짚었다. 260915 "미미팜은 MIMIPharm으로 표기 통일해. 다른 언어권도 모두. 이거는 워크플로우에 딱박아놓고 너도 지켜."
260916 R3 에 `미미팜` 이 남아 있자 "MIMIPharm으로 표기형식 통일하랬는데 왜 안함. 이거 에이전트폴더에 규칙세팅해놓고 반드시 지키셈."
같은 날 "약사라고 하지 말고 약사님이라고 적으삼. 약사님들과 밀접한 채널이라."

| 규칙 | 쓰는 것 | 쓰지 않는 것 |
| --- | --- | --- |
| 약국 이름 (미미팜 계정, 네 언어) | `MIMIPharm` 하나. 한국어 문장 안에서도 `4층 MIMIPharm에서`, `MIMIPharm 약사님이`, 해시태그 `#MIMIPharm` | `미미팜`, `미미 약국`, `미미약국`, `MIMI Pharm`, `MIMI K-BEAUTY CARE PHARMACY`, `ミミファム`, `ミミファーム`, `米米药房`, `MIMI药房`, `MIMI薬局`, `#mimipharm`, `#미미팜` |
| 약사 호칭 (어라운드팜, 미미팜 한국어 카드와 캡션) | `약사님`. `약사님이 골라 드려요`, `약사님과 상담`, `약사님 추천`, 제목도 `약사님이 고른` | 사람을 가리키는 `약사`. `약사가`, `약사와`, `약사 추천`, `약사가 고른` |

- **"내보낼 때 고친다" 로 미루지 않는다.** 벌을 새로 짓든, 한 장만 고치든, 캡션만 옮기든, 그 벌을 여는 순간 카드 글과 캡션 칸 전부를 아래 검사로 훑고 걸린 곳을 그 자리에서 고친다. 260915 에 "벌마다 내보낼 때 고친다" 로 미뤘다가 R3~R8, S4~S12 에 `미미팜` 이 남아 다시 지적받았다.
- 건물 이름 `미미라인`, `MIMILINE`, `Mimiline`, `ミミライン` 과 계정 핸들 `@mimipharm_official` 류는 약국 이름이 아니라서 그대로 둔다. `약사법`, `약사회`, `약사공론` 같은 고유명사와 `#약사추천` 같은 검색용 해시태그도 그대로 둔다(해시태그 `#미미팜` 은 바꾼다).
- 글자를 바꿀 때는 `insertCharacters` 다음 `deleteCharacters` 로 그 구간만 간다(강조와 이모지 글꼴이 안 풀린다). 사용자가 고치는 중일 수 있으니 프레임을 다시 그리지 않는다.
- `MIMIPharm` 은 `미미팜` 보다 넓다. 바꾼 글상자는 다음 호출에서 높이와 오른끝을 다시 읽어 줄 수가 늘었거나 옆 요소에 닿았는지 본다.
- 이미 올라간 게시물(`게시 목록.json` status `게시`)은 인스타 글을 몰래 고치지 않는다. 피그마 원본은 고쳐도 된다.

피그마 검사(최종 페이지에서 벌 이름으로 시작하는 프레임을 다 본다. 결과가 빈 배열이어야 한다):

```js
const page = await figma.getNodeByIdAsync('66:2');           // 미미팜 최종. 어라운드팜은 그 파일의 최종 페이지
await figma.setCurrentPageAsync(page);
const SET = 'R3';                                            // 검사할 벌
const bad = [/미미팜/, /미미 ?약국/, /MIMI Pharm/i, /MIMI K-?BEAUTY CARE PHARMACY/i, /ミミファ/, /米米/, /MIMI(药房|薬局)/];
const hits = [];
for (const f of page.children.filter(n => n.name.startsWith(SET + '-'))) {
  for (const t of f.findAll(n => n.type === 'TEXT')) {
    const s = t.characters;
    for (const re of bad) { const m = s.match(re); if (m) hits.push({frame: f.name, id: t.id, word: m[0]}); }
    const h = s.match(/#mimipharm/i); if (h && h[0] !== '#MIMIPharm') hits.push({frame: f.name, id: t.id, word: h[0]});
    const p = s.replace(/#\S+/g, '').match(/약사(?!님|법|회|공론)/); if (p) hits.push({frame: f.name, id: t.id, word: p[0]});
  }
}
return hits;
```

드라이브 캡션 검사는 `cardnews_folders.py check <브랜드>` 에 들어 있다(올리지 않은 벌의 `캡션.txt` 에서 같은 말을 찾아 문제로 센다).

## 절차

### 1. 대상 계정을 확인하고 그 계정을 본다 (L3)

인스타에서 최근 게시물을 훑어 결과 지금 뭘 하고 있는지 본다.
DOM 에서 긁으면 눈으로 세는 것보다 빠르다.

```js
// 인스타 탭에서
const r = await fetch(`/api/v1/feed/user/${userId}/?count=33`, {headers:{'x-ig-app-id':'936619743392459'}});
```

`userId` 는 프로필 HTML 의 `"profile_id":"(\d+)"` 로 뽑는다.
`web_profile_info` 는 비즈니스 계정에서 400 이 뜨니 이 길로 간다.

### 2. 레퍼런스 디자인을 하나 고른다 (L1)

**맨손으로 디자인하지 마라.** 판 목록은 `<DEV>/cardnews-refs/designs.md` 에 있다.

```bash
cat C:/dev/cardnews-refs/designs.md
```

지금 열한 판이다. 정보 밀도판, 노트판, 표판, 매거진판, 실사판, 인물 누끼판, 자막판,
제품 실사 오픈판, 노트 카드판, 손그림 표판, 파스텔 배경판.

**공구 알림과 릴스 캡처를 카드뉴스로 착각하지 마라.** 260827 에 그걸 레퍼런스로 잡았다가 반려됐다.
카드뉴스는 **그래픽으로 짠 정보 카드**다. 사진 위에 자막만 얹은 것, 제품을 들고 찍은 홍보 게시물은 아니다.
고를 때 이 셋을 본다. 배경이 그래픽인가, 한 장에 정보가 여러 줄 들어가는가, 마지막에 저장을 부르는가. **기본은 정보 밀도판이다.** 사진이 필요 없고 저장을 제일 많이 받는다.
260827 에 여덟 판을 한 벌씩 다 지어 뒀으니 새로 지을 때 그 파일을 열어 보고 시작한다.

실측 원본 이미지는 두 곳에 있다.

- `<DEV>/cardnews-refs/shots/<계정>/<코드>/`
- `<드라이브>/여형준님/29 카드뉴스/etc/2608270900 공동구매 캐러셀 레퍼런스/` (82장)

**사진이 필요한 판도 사진이 없다고 건너뛰지 않는다.** 실사판, 인물 누끼판, 자막판,
제품 실사 오픈판은 원래 그 약사 본인 촬영분이나 제품 실물이 필요한 판이다.
그 자리에 **생성 사진을 넣어 판을 완성해 두고**, 나중에 진짜 사진이 오면 한 장만 갈아 끼운다.
어느 자리가 교체 자리인지는 카드 밖 레퍼런스판에 적는다.

**사람 얼굴은 생성하지 않는다.** 약사 계정에 가짜 사람이 올라가면 안 된다.
인물 누끼판은 인물 자리를 대형 제품 누끼로 대신 채운다.
공구 알림 포맷(실사판, 제품 실사 오픈판)은 행사 문구를 빼고 정보형으로 돌려 쓴다.

### 2-0. 커버만 보고 만들지 마라

**캐러셀 안쪽 장까지 받아서 본다.** 커버만 보면 판을 절반만 안 것이다.
260827 에 커버만 보고 지었다가 "레퍼런스랑 너무 다르다" 로 반려됐다.
안쪽 장이 그 판에서 **정보를 어떻게 넣는지**를 알려 준다.

```js
const cm = it.carousel_media;               // media/{id}/info/ 응답
const url = (cm[i].image_versions2?.candidates||[]).sort((a,b)=>b.width-a.width)[0]?.url;
```

받고 나서 이 넷을 적는다.

- **글꼴의 결**: 둥근가 각진가, 손글씨인가 고딕인가
- **글자 판의 폭**: 글자 폭에 딱 맞는가, 화면 폭을 다 쓰는가
- **판의 색**: 어두운 판에 흰 글자인가, 밝은 판에 검정 글자인가
- **제목의 자리**: 위인가 아래인가

### 2-0-1. 글꼴을 먼저 맞춘다

**Pretendard 로만 지으면 어떤 판을 흉내 내도 같은 얼굴이 나온다.** 판마다 글꼴이 다르다.

### 5-2. 본문에는 반드시 키워드 강조를 넣는다

문장이나 셀에 글이 있으면 **핵심 어절을 색과 굵기로 뺀다.** 통짜 회색 글은 아무도 안 읽는다.

```js
function hi(t, words, color, style='Black'){
  words.forEach(w=>{ let i=t.characters.indexOf(w);
    while(i!==-1){
      t.setRangeFills(i, i+w.length, [{type:'SOLID', color}]);
      t.setRangeFontName(i, i+w.length, {family:'Pretendard', style});
      i = t.characters.indexOf(w, i+w.length);
    }});
}
```

- 표 본문은 성분명과 약 이름을 빨강(`#C0392B`), 증상을 파랑(`#1F5FA8`)
- 어두운 판에서는 주황(`#F0AC63`) 이나 흰색
- **한 셀에 한두 어절만.** 다 칠하면 아무 데도 안 보인다
- `setRangeFontName` 전에 그 스타일을 `loadFontAsync` 로 올려둬야 한다
- **계정별 색(260915).** 미미팜 밝은 판 Pretendard Bold `#C8412B`, 어두운 사진 판 Bold 민트 `#BFE3DA`, 경고 말(따가움, 붉은기) 복숭아 `#F2A47E`, 사진 위 흰 부제는 흰 Bold.
  어라운드팜 제품 카드는 Noto Sans KR Bold `#0E7490`, 표지와 요약 카드 부제는 Bold `#1B1917`. 밑줄은 두 계정 모두 안 쓴다
- 이런 분께, 바르는 법, 주의 같은 목록 줄도 줄마다 한 어절씩 뺀다. 어라운드팜 기준 카드(최종 페이지 386:4)가 그렇다
- 이미 색이 든 라벨(`Pharmacist's Tip:`) 바로 뒤 말은 칠하지 않는다. 라벨과 붙어 한 덩어리로 읽힌다
- `U+2028` 로 끊은 글은 `characters` 에서 `U+2028` 을 빈칸으로 바꾼 사본에서 찾는다. 길이가 같아 위치가 안 밀린다
- 굵게 바꾸면 줄이 길어진다. 폭 고정 글상자는 칠한 뒤 줄 수(높이 ÷ 행간)가 그대로인지 본다. 가운데 정렬 자동 폭 글상자는 피그마가 가운데를 지킨다
- 빠진 벌 찾기: 벌마다 15자 이상, 40px 이하 글상자를 세고 `getStyledTextSegments(['fontName','fills'])` 스타일이 둘 이상인 글상자 수를 센다. 0 이면 통짜 본문이다

### 6. 말투를 지킨다

**여기가 제일 자주 틀린다.**

- **제목은 복합명사만 나열한다.** 문장형과 관형절은 그대로 AI 티가 난다
  - `약은 잘 챙겨 먹는데 왜 계속 피곤할까요` → `약물 유발 영양소 고갈`
  - `빠지는 이유 3가지` → `고갈 경로 3가지`
  - `그래서 챙길 5가지` → `보충 우선순위 5`
  - 커버도 예외가 아니다
- **본문은 `~해요` 체로 쓴다.** `~합니다` 는 딱딱해서 카드뉴스에 안 맞는다
  - `흡수되지 않습니다` → `흡수되지 않아요`
  - `식후에 복용하세요` → `꼭 식후에 드세요`
  - 표 안의 명사구는 그대로 둔다
- 줄표(—)와 가운뎃점(·)은 쓰지 않는다. 쉼표나 줄바꿈으로 바꾼다

표지를 따로 두는 것은 **그 제목이 진짜로 내용을 궁금하게 만들 때만**이다.
매거진판처럼 판 자체가 표지를 요구하는 경우도 예외다.

### 10-3. 한국어 줄바꿈은 단어 단위로 끊는다 (L1)

사용자(260914): "미미팜 어라운드팜 둘다 카드뉴스 전체에 대해서, 줄 끊기를 단어 단위로 끊어야 하는데 왜 글자단위로 끊음?"
피그마는 한글 음절 사이 어디서나 줄을 바꾼다(CSS `word-break: keep-all` 같은 설정이 플러그인 API 에도 없다).
폭이 정해진 글상자에 긴 문장을 넣으면 "식혀/요", "주/2~3회" 처럼 단어 가운데서 끊긴다.

- 대상은 카드 안 `textAutoResize` 가 `HEIGHT` 나 `NONE` 인 한국어 글상자다. `WIDTH_AND_HEIGHT` 는 줄바꿈이 없어 뺀다.
- 문단마다 한 줄 폭을 재서 넘치면 단어를 앞에서부터 쌓고, 넘치기 직전 단어 앞 빈칸을 `U+2028`(Shift+Enter)로 바꾼다.
  `\n` 은 새 문단이라 문단 간격과 목록 기호가 붙는다.
- 폭은 같은 글꼴, 크기, 자간, textCase 로 만든 `WIDTH_AND_HEIGHT` 측정 글상자에 글을 넣고 바로 `width` 를 읽는다.
  스타일이 섞인 글은 `getStyledTextSegments` 구간마다 재서 더한다. 측정 글상자는 끝나면 지운다.
- 바꾸기는 `insertCharacters(i, U+2028, 'BEFORE')` 다음 `deleteCharacters(i+1, i+2)`. 굵기와 색이 안 풀린다.
- **바꾼 뒤 다음 호출에서 높이를 다시 읽는다.** 원래 한 줄이던 글이 두 줄이 됐으면 되돌린다(여유 3px 안쪽 오차).
  두 줄이 세 줄이 되어 아래를 밀면 글상자 폭을 늘리거나 뒤 상자를 키운다.
- **캡션 칸은 건드리지 않는다.** 캡션 글은 인스타에 그대로 붙여 넣는 원문이라 줄바꿈을 넣으면 게시글이 바뀐다.
- 함정: `hasMissingFont` 를 글꼴 불러오기 전에 읽으면 참이라 전부 건너뛴다. 구간 객체에 속성을 붙이면
  `object is not extensible`. 정규식 리터럴 안에 `U+2028` 을 쓰면 문법 오류라 `String.fromCharCode(0x2028)` 로 만든다.

### 12. 제품 상세페이지를 긁는 법

카카오 스토어(`store.kakao.com/<핸들>`)는 SPA다. curl 로는 껍데기만 온다.

- **상품 목록**: 브라우저로 `/category` 를 열고 `a[href*="/products/"]` 를 긁는다
- **대표 이미지**: 상품 페이지 HTML 을 같은 출처에서 `fetch` 하면 `og:image` 가 서버 응답에 있다.
  `thumb/C375x375.fjpg/?fname=` 를 벗기면 원본 URL 이 나온다
- **상세 이미지**: 이건 서버 HTML 에 없다. **상품 페이지를 실제로 열어야** `img[src*=editor]` 가 붙는다.
  `browser_batch` 로 navigate 와 추출을 묶어서 돈다. 한 건이 비면 `wait 3` 을 끼우고 다시 본다
- 내려받을 때 `-e "https://store.kakao.com/"` 를 붙인다. 리퍼러 없으면 막힌다

### 13. 누끼와 배경 합성으로 실사를 대신한다

약사가 제품을 들고 찍은 사진이 없을 때 쓴다. **얼굴은 생성하지 않는다.**

```python
from rembg import remove          # 첫 실행 때 모델 1GB 를 받는다
o = remove(Image.open(src).convert('RGB').crop((0,0,W,int(H*0.74))))   # 반사 잘라내고
o = o.crop(o.getbbox()); o.save('cut.png')
```

- 상품 이미지 아래쪽 **반사(거울상)를 먼저 잘라야** 누끼가 깨끗하다. 세로 74% 선이 대체로 맞는다
- 배경은 ChatGPT 로 **사람과 글자 없이** 뽑는다. "앞쪽에는 아무것도 없는 카운터" 를 넣으면 제품 놓을 자리가 생긴다
- 합성할 때 알파를 6% 높이로 눌러 blur 18 을 먹이면 바닥 그림자가 된다. 이게 없으면 떠 보인다
- **인물과 제품은 위 65% 안에 둔다.** 아래 3분의 1은 흰 띠 자리다

### 14. 브랜드 이름만 있고 계정이 없을 때 (레퍼런스 추적)

사람이 자료에 브랜드 이름만 적어 줬을 때 계정을 찾아 캐러셀을 통째로 내려받는 길이다.
260828 김제조 건에서 브랜드 아홉 곳을 이 순서로 다 찾았다.

**1) 핸들 찾기.** 크롬(L3)에서 인스타에 로그인된 상태로 검색 API 를 부른다. 익명으로는 401 이다.

```js
await fetch(`/api/v1/web/search/topsearch/?context=blended&query=${encodeURIComponent('담백하루')}&count=10`,
  {headers:{'x-ig-app-id':'936619743392459'}})
// users[].user 에 username, full_name, pk(숫자 id) 가 다 들어 있다
```

**2) 프로필 확인.** `web_profile_info` 는 연속 호출하면 금방 막힌다. 막히면 **프로필 페이지로 그냥 이동해서**
`get_page_text` 로 읽는다. 팔로워, 게시물 수, bio, 외부 링크가 다 나온다. 이게 제일 안 막힌다.

**3) 게시물 한 번에 긁기.** 숫자 id 를 알면 피드 엔드포인트가 **캐러셀 자식 이미지까지 한 번에** 준다.
스크롤해서 `a[href*="/p/"]` 를 모으는 방식은 가상 스크롤 때문에 대여섯 개밖에 안 잡힌다. 쓰지 마라.

```js
const r = await fetch(`/api/v1/feed/user/${pk}/?count=24`, {headers:{'x-ig-app-id':'936619743392459'}});
const d = await r.json();          // d.items[].carousel_media[].image_versions2.candidates[0].url
                                   // d.next_max_id 로 다음 장
// media_type 8 이 캐러셀, 2 가 릴스, 1 이 단일 사진
```

**4) URL 목록 꺼내기.** 이미지 URL 하나가 400자라 60장이면 24KB 다. 화면에 찍지 말고
페이지에서 blob 로 만들어 내려받은 뒤 셸에서 curl 로 받는다. **인앱 브라우저는 blob 다운로드를 삼킨다. 크롬 익스텐션으로 한다.**

```js
const b=new Blob([lines.join('
')],{type:'text/plain'}); const u=URL.createObjectURL(b);
const a=document.createElement('a'); a.href=u; a.download='refurls.txt'; document.body.appendChild(a); a.click();
```

받을 때 헤더에 `Referer: https://www.instagram.com/` 를 넣는다.

**5) 무엇을 고를 것인가.** 계정마다 캐러셀을 다 뜯을 필요가 없다.
**같은 계정 안에서 댓글 수가 튀는 게시물**을 고른다. 거기에 그 계정의 무기가 들어 있다.
닥터체크는 일반 글 댓글 0인데 찜 이벤트만 218, 더리틀스는 제품 글 댓글 2인데 시즌 이벤트만 127이었다.

**6) 알아둘 것.** 브랜드 공식 계정은 대체로 죽어 있다. 더좋은은 612건 전부 하트 3, 담백하루는 게시물이 0이다.
**소재는 브랜드가 만들고 파는 일은 약사가 한다.** 그러니 브랜드 계정만 보고 "레퍼런스가 없다" 고 하지 말고
그 브랜드를 실제로 파는 약사 계정으로 넘어가서 본다. 제품 이름을 검색어로 넣으면 나온다.

## U3. 파일을 인스타 탭으로 넘긴다 (L3)

인스타 탭에 리스너를 심고, `rel="opener"` 를 준 임시 링크를 만들어 **좌표로 진짜 클릭**한다.
`.click()` 은 팝업 차단에 걸린다. **누르기 전에 스크롤을 한 번 굴린다.**

```js
window.__got = null;
addEventListener('message', e => { if (e.data && e.data.__reel) window.__got = e.data.files; });
const a = document.createElement('a');
a.href = 'http://127.0.0.1:8791/sender.html'; a.target = '_blank'; a.rel = 'opener';
```

좌표는 `k = 1568 / window.innerWidth` 를 곱해서 낸다. **누를 때마다 다시 잰다.**
파일이 오면 `window.__got` 이 File 배열이다. 이름과 개수를 확인하고 **sender 탭을 닫는다.**

## U4-1. 캡션은 게시 뒤 수정 화면에서 넣는다 (L3)

**게시 화면에서 넣으면 빈 채로 나간다(260902 실측).** 진짜 타이핑으로 넣어서

2. 캡션 칸을 **스크롤 한 번 굴리고 좌표로 클릭**한다. `document.activeElement` 로 잡혔는지 본다

   `팔로우 👉 @haruyaksa` 까지 치고 **띄어쓰기 한 칸을 먼저 쳐서** 멘션 자동완성을 닫은 다음

4. `innerText` 를 `캡션.txt` 와 글자 단위로 대조한다. 빈 줄까지 그대로 들어간다
5. `완료` 를 **좌표로 클릭**한다. `.click()` 은 안 먹는다
6. `/api/v1/media/<pk>/info/` 로 `caption.text` 길이를 확인한다. 이게 유일한 증거다

```js
const j = await fetch("/api/v1/media/<pk>/info/", {headers:{"x-ig-app-id":"936619743392459"}}).then(r=>r.json());
(j.items[0].caption?.text || "").length   // 0 이면 아직 안 들어간 것이다

```
<드라이브>/영상 편집/AI 크리에이터/카드뉴스/
├─ <YYMMDDhhmm 제목 (판이름) (계정)>/     올릴 차례를 기다리는 벌

## 알려진 함정

### 올리기 (260902 실측)

- **게시 화면 캡션 칸은 카드뉴스도 빈 채로 나간다.** 260831 에 "한 번에 들어간다" 고 적었는데
  260902 에 정반대였다. 진짜 타이핑으로 699자를 넣어 카운터가 `699/2200` 이 됐고 화면에도
  전부 보였는데, 공유 뒤 `caption.text` 가 `0` 이었다. 여섯 번을 5초 간격으로 다시 불러도 `0` 이다.
  **캡션은 U4-1 대로 게시 뒤 수정 화면에서 넣는다.** 게시 화면에서 넣으려는 시도 자체를 하지 마라
- **`zoom` 을 인스타 업로드 중에 쓰지 마라. 실패하면 뷰포트가 굳는다.**
  `zoom` 이 `Page.captureScreenshot` 타임아웃으로 죽으면 CDP 화면 크기 덮어쓰기가 그대로 남아
  `window.innerWidth` 가 **잘라 보려던 조각 크기**(213x228 같은 값)로 고정된다.
  화면 캡처도 그 크기로 나오고, 다이얼로그 요소가 뷰포트 밖(x 가 음수, y 가 음수)으로 밀려
  좌표 클릭이 통째로 막힌다. `resize_window` 도, `select_browser` 재접속도, `zoom` 다시 부르기도
  **하나도 안 풀린다**(셋 다 해봤다). 덮어쓰기는 탭 단위라 **탭을 닫고 새 탭을 열어야 풀린다.**
  판정은 `window.innerWidth` 한 줄이다. 확인은 `zoom` 말고 화면 캡처를 그냥 찍어서 한다
- **뷰포트가 굳어도 `computer` 타이핑은 멀쩡하다.** 타이핑은 포커스된 요소로 가지 화면을 안 탄다.
  그러니 뷰포트가 굳었으면 좌표가 필요한 단계만 새 탭으로 옮겨서 하면 된다

### 올리기 (260831 실측)

- **구글 드라이브(G:)에서 `fs.cpSync` 와 `fs.rmSync({recursive:true})` 는 프로세스를 죽인다.**
  예외도 stderr 도 없이 **종료 코드 127** 만 남는다. 앞줄 `console.log` 까지만 찍혀서 어디서 죽었는지도 안 보인다.
  한 파일씩 `readFileSync`/`writeFileSync`, `unlinkSync` 후 `rmdirSync` 로 하면 멀쩡하다.
  `cardnews-done.mjs` 가 그렇게 돼 있다. **G: 위에서 재귀 fs 호출을 새로 쓰지 마라**
- **카드뉴스는 팝업이 필요 없다.** 이미지는 배경 탭에서도 13ms 만에 붙는다.
  릴스에서 쓰던 팝업 + `SetWindowPos` TOPMOST 절차를 여기 들고 오면 시간만 버린다
- **자르기 옵션이 영상과 다르다.** 이미지는 `원본 / 1:1 / 4:5 / 16:9` 다. `9:16` 은 없다.

- **파일 input 은 `multiple` 이다.** 5장을 한 `DataTransfer` 에 담아 한 번에 넣으면 캐러셀이 된다.
  한 장씩 다섯 번 넣는 길을 찾지 마라
- **sender 링크는 `.click()` 이 팝업 차단에 걸린다.** 좌표로 진짜 클릭한다. 스크롤을 한 번 굴리고 누른다
- **폴더 이름의 괄호 두 개가 규격이다.** `(판이름) (계정)` 이 없으면 `--account` 한정이 안 먹어

- **한 번에 여러 벌 지으면 폴더 시각이 다 같다.** 그때는 폴더 이름 가나다순으로 순서가 정해진다.

  사각형을 만든 뒤 텍스트를 `textAutoResize='NONE'` 으로 같은 크기로 늘리고
  `textAlignVertical='CENTER'` 로 맞춘다. 그래야 위 여백과 아래 여백이 같아진다
- **한 사진으로 다섯 장을 다르게 보이게 하려면 `scaleMode:'CROP'` 에 `imageTransform` 을 준다.**
  `[[sx,0,tx],[0,sy,ty]]` 가 보여줄 사각형이다. 레퍼런스도 한 번 촬영한 장소를 아홉 장에 나눠 쓴다
- **자막체(흰 글자 검정 두꺼운 테두리)는 텍스트 노드의 `strokes` 로 만든다.**
  `strokeWeight` 14~20, `strokeAlign='OUTSIDE'`. 그림자를 하나 더 얹으면 사진 위에서도 뜬다


- **ChatGPT 가 "문제가 발생했습니다" 를 띄워도 이미지는 나온다.** 그 문구는 텍스트 응답에 붙는 것이고
  아래에 이미지 자리가 따로 생긴다. 30~60초 뒤에 `img[naturalWidth>600]` 을 다시 본다.
  같은 이미지가 여러 img 태그로 잡히니 `src` 로 유일화해서 세어야 몇 장인지 안다
- **`__send()` 가 SENT 를 돌려줘도 안 갔을 수 있다.** 실패하면 본문이 입력창으로 되돌아온다.
  화면을 찍어 입력창이 비었는지 보고, 남아 있으면 전송 버튼 좌표를 직접 클릭한다
- **33장을 33번 호출로 뽑지 마라.** 카드를 복제해 가로로 이어 붙인 `STRIP` 프레임 하나를 만들고
  `maxDimension` 을 전체 폭(예: 7560)으로 줘서 한 번에 받은 뒤 로컬에서 1080 단위로 자른다. 6번이면 끝난다
- **`setRangeFills(i, i+n)` 의 n 은 글자 수다.** `'39,000원'` 은 7자다. 눈으로 센 8 을 넣으면
  문자열 끝에서 범위 초과로 죽고, 중간이면 조용히 옆 글자까지 물든다. 반드시 `word.length` 를 쓴다
- **`indexOf` 가 -1 이면 `setRangeFills(-1, ...)` 로 죽는다.** 못 찾으면 그냥 넘어가는 helper 를 쓴다
- **가운뎃점(·)을 산출물에 넣지 마라.** 쉼표나 두 칸 띄우기로 바꾼다. 카드 안 글자도 마찬가지다

- **인스타 검색과 프로필 API 는 로그인해야 200 이다.** 익명 호출은 401. 그리고 `web_profile_info` 를
  연속으로 부르면 열 번쯤에서 빈 응답이 온다. 프로필 페이지를 열어 `get_page_text` 로 읽는 게 더 안 막힌다
- **프로필 그리드를 스크롤해서 게시물을 모으지 마라.** 인스타는 화면 밖 카드를 DOM 에서 지운다.
  스물네 번 스크롤해도 다섯 개밖에 안 남는다. `feed/user/<숫자 id>` 엔드포인트를 쓴다
- **`setRangeTextDecoration(0, 8, ...)` 도 같은 함정이다.** `'60,000원'` 은 7자다.
  숫자를 손으로 세지 말고 `t.characters.length` 를 넣는다. 스크립트는 원자적이라 여기서 죽으면 앞의 40장도 안 만들어진다
- **카드 안에 제품 누끼를 놓을 때 `scaleMode` 는 `FIT` 이고 사각형 비율을 이미지 비율에 맞춰야 한다.**
  `FILL` 로 두면 제품이 잘린다. 누끼마다 가로세로 비를 미리 재서 표로 들고 있는다
- **누끼와 텍스트 블록이 겹치는지 좌표로 검산한다.** 눈으로는 화면을 줄여 보느라 못 본다.
  `제품 y범위 = cy±(w/ar)/2` 를 다음 블록의 y 와 비교한다. 40장이면 반드시 두세 장이 겹친다

- **계정을 바꾸는 일에 판을 새로 짓지 마라.** 260828 에 하루건강약사 릴스 표지를 뜯어 45장을
  다시 그리려다 반려됐다. 시킨 일은 핸들 교체와 캡션이었다. **무엇을 바꾸는 일인지 한 줄로 확인하고 시작한다**
- **`t.x - card.x` 로 카드 안 좌표를 재지 마라.** 중첩 노드의 `x` 는 부모 기준이라 음수가 나온다.
  `absoluteBoundingBox` 끼리 빼야 카드 안 위치가 나온다
- **인스타 계정을 볼 때 캐러셀이 없을 수도 있다.** 하루건강약사는 릴스 전용이라 캐러셀 레퍼런스가 없다.
  그럴 때 판은 **릴스 표지**에서 뜬다. 표지가 곧 인포그래픽이다
- **45장을 스트립 9개로 뽑으면 `get_screenshot` 이 9번이면 끝난다.** 벌마다 카드 5장을 복제해
  5400x1350 프레임에 이어 붙이고 `maxDimension: 5400` 으로 받은 뒤 로컬에서 1080 단위로 자른다.
  다 뽑고 스트립 프레임은 지운다
- **확정 카드의 배치 숫자를 재서 옮긴다(260915 미미팜 R1 기준).** 대표 카드(02) 제품은 가운데, y 740, 높이 670 이고
  튜브는 아래 60 이 잘려도 된다. 병과 상자는 통째로 보이게 올려 바닥을 1335 에 둔다. 루틴 카드(03~05) 제품은
  폭 232~304, 높이 760, 회전 -6 이고 오른쪽 끝이 460 을 넘으면 패널 글자에 닿는다. 표지(01) 제품은 높이 460~516,
  바닥 926 이고 번호 표시를 제품 가운데 아래로 같이 옮긴다
- **`FILL` 이미지는 상자 비율과 원본 비율이 다르면 제품이 잘린다.** 비율 차가 4% 넘는 노드를
  `figma.getImageByHash(hash).getSizeAsync()` 로 전수 검사한다. `CROP` 은 `imageTransform` 의 가로 배율과 세로 배율이
  다르면 사진이 늘어난다(A12-01 배경이 세로 11% 늘어나 있었다). 위를 잘라야 하면 두 배율을 같게 주고 좌우를 같이 줄인다
- **회전한 노드는 `absoluteBoundingBox` 가 실제 제품보다 크다.** 경계 박스로 모서리 잘림을 세면 거짓 경보가 섞이니
  뽑아서 눈으로 본다. 진짜 잘림(A14-05 크림 통 위쪽, A16-02 오른쪽 바이알)은 12~15% 줄이고 카드 안으로 당긴다
- **`upload_assets` 의 `scaleMode` 는 한 번 부를 때 전체에 걸린다.** FIT 노드와 FILL 노드를 같은 호출에 넣으면
  한쪽이 잘리거나 작아진다. 따로 부른다. FILL 노드는 새 누끼 비율로 먼저 `resize` 한다
- **글자 단위로 끊긴 줄이 있는지 뽑아서 본다.** A9-03 에 "1,000mg까 / 지" 가 있었다. 고칠 때는 글상자를 `clone` 해
  `WIDTH_AND_HEIGHT` 로 줄 폭을 재고, 빈칸과 U+2028 을 한 글자씩 맞바꿔 강조 범위가 안 밀리게 한다
- **글이 가리키는 제품과 사진이 같은지 본다.** A11-05 는 글이 "닥터멜락신 칼슘 본딩 크림에 나이아신아마이드 2%" 인데
  사진은 제나벨 멜라케어였다. 성분은 공식몰 전성분으로 확인하고 사진을 글에 맞췄다
- **다른 카드의 글 스타일을 복사할 때 바탕색을 본다.** S1-02 푸터(흰 글자, 어두운 매장 사진)를 밝은 S8 카드에 그대로
  옮기자 글자가 안 보였다. 글 내용만 맞추고 색은 그 카드의 회색(#9A9A9A)으로 둔다
- **`download_assets` 주소를 파이썬 `urllib` 로 받지 마라(260915 R2).** 14장 중 13장이 오류 없이 1MiB 단위에서 끝이 잘려 왔다
  (9437184, 2097152 바이트). `curl -sS -L --fail -o` 로 받으면 응답의 `sizeBytes` 와 같다. 주소는 15분 넘게 지나도 받혔다
- **주소 목록을 파이썬 `print` 로 써서 `xargs` 에 넘기지 마라.** 윈도우 줄끝의 `\r` 이 파일 이름 끝에 붙어 `KR_01.png_` 처럼 저장되고
  확인 스크립트는 파일이 없다고 본다. 파이썬 안에서 `subprocess` 로 curl 을 부른다
- **`post_copy.py` 는 KR 폴더만 덮는다.** 네 언어를 다시 뽑았으면 `<언어>\NN.png` 에 직접 덮고 md5 를 대조한 뒤 `check`, `index` 를 돌린다
- **내보낸 PNG 를 게시 폴더에 넣을 때는 드라이브 `카드뉴스\도구\post_copy.py <계정> <벌> <내보낸 폴더>` 를 쓴다.**
  `cardnews_folders.py folder` 로 경로를 받아 KR 의 같은 번호 파일에 덮고, md5 를 대조하고, `check` 가 0건인지까지
  한 번에 본다. 장 수가 다르면 경고한다

## 사람에게 물어야 하는 지점

- **대상 계정을 안 정해줬을 때.** 이것만은 반드시 묻는다
- 소재를 지정하지 않았고 후보가 여럿일 때는 한 줄로 알리고 하나 골라 진행한다
- 게시할 벌이 **지정 계정 폴더가 아닐 때.** 그때만 멈춘다. 그 밖에 게시 버튼은 다시 묻지 않는다
