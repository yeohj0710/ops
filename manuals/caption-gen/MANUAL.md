# 편집 끝난 영상에 인스타 캡션 달기

- **부르는 말**: 캡션 생성해줘, 캡션 뽑아줘, 캡션 써줘, 오약 캡션, 제선영 캡션, 오늘 작업된 영상 캡션
- **런너**: claude
- **제어층**: L1 (영상 찾기·분석) · L3 (인스타 레퍼런스 볼 때만)
- **한 번에 걸리는 시간**: 영상 하나에 10~15분

---

## 무엇을 만드는 업무인가

편집자가 편집을 끝내면 영상이 `<드라이브>/영상 편집/` 안쪽에 올라온다.
그 영상을 찾아 내용을 보고, 그 사람 톤에 맞는 인스타 캡션을 만들어 **영상 옆에 `캡션.html`** 로 둔다.

**캡션 전문을 채팅에 코드블록으로도 찍는다.** 사람이 폰으로 시키는 경우가 많아 파일만 만들면 볼 수가 없다.

탐색기에서도 숨김 파일 보기를 켜야 나온다.

## 절차

1. **대상 영상을 찾는다 — L1**
   ```bash
   node "<OPS>/manuals/caption-gen/scripts/find-latest.mjs"            # 최근 2일, 네 사람
   node "<OPS>/manuals/caption-gen/scripts/find-latest.mjs" 오약        # 그 사람만
   node "<OPS>/manuals/caption-gen/scripts/find-latest.mjs" 제선영 --days 7
   ```
   `오약`·`제약`·`김제조` 같은 줄임말도 알아듣는다. 0.1초면 끝난다.

   **여러 개가 나오면 사람에게 무엇을 할지 묻지 말고, 캡션이 없는 것부터 순서대로 한다.**
   사람이 특정인을 지목했으면 그 사람 것만 한다.

2. **영상을 본다 — L1**
   ```bash
   ffprobe -v error -show_entries format=duration -of csv=p=0 "<영상>"
   ffmpeg -i "<영상>" -vf fps=1 -q:v 3 "<임시폴더>/%03d.jpg"    # 1초마다 한 장
   ```
   뽑은 장면을 **직접 읽는다.** 화면에 적힌 문구·제품명·성분명·순서가 캡션의 재료다.
   소리가 있으면 말도 확인한다. 파일명과 폴더명(주제)도 단서다.

3. **그 사람 톤을 확인한다 — L1**
   `<드라이브>/영상 편집/[공통] 유용한 소스/캡션 자동 생성/학습용 데이터/<사람> (@핸들)/`
   - `프로필.html` — 표시 이름·핸들·정체성·톤. **여기 없는 경력이나 전문성을 지어내지 마라**
   - 하위 예시들의 `캡션.html` — 실제로 쓰는 문장 형태

   같은 사람 예시를 우선하되, 지금 영상 주제와 가까운 예시를 더 강하게 따른다.
   예시가 부족하면 아래 "레퍼런스 늘리기" 를 먼저 한다.

4. **캡션을 쓴다.** 사람마다 형식이 다르다. 섞지 마라.

   | 사람 | 특징 |
   | --- | --- |
   | 제선영 | 이모지 많음, 구어체 반말체 설명, `━━━` 구분선, `1️⃣2️⃣3️⃣` 항목, 훅이 강함 |
   | 하루건강약사 | 존댓말, 50대 이후 대상, `1️⃣ 1위 …` 랭킹, 끝에 `팔로우 👉 @haruyaksa` |
   | 오주헌·김주성 | 예시가 적다. `프로필.html` 과 실제 계정을 보고 맞춘다 |

5. **`캡션.html` 을 영상과 같은 폴더에 만든다 — L1**
   기존 파일 형식을 그대로 본뜬다. 본문은 `<textarea id="caption">` 안에 넣는다.
   `find-latest.mjs` 가 알려준 `folder` 에 둔다. 다른 데 만들지 마라.

6. **채팅에 코드블록으로 찍는다.** 이걸 빼먹지 마라 — 폰에서 시킨 사람은 파일을 못 연다.

## 레퍼런스 늘리기 (정확도가 여기서 갈린다)

예시가 적으면 캡션이 그 사람 말투를 못 따라간다. 지금 상태는 이렇다.

| 사람 | 캡션 예시 | 상태 |
| --- | --- | --- |
| 제선영 | 8개 | 쓸 만하다 |
| 오주헌 | 4개 | 얇다 |
| 김주성 | **1개** | 거의 없다 |
| 전종열 | **폴더 없음** | 만들어야 한다 |

늘리는 법 — **인스타 실제 게시물에서 가져온다.**

1. `yt-dlp` 로는 인스타 프로필을 못 읽는다(지원이 끊겼다). **크롬 확장(L3)으로 한다**
2. 그 사람 인스타 계정에 들어가 최근 릴스를 연다
3. 캡션 원문과 화면을 가져와 학습용 데이터에 넣는다
   ```
   학습용 데이터/<사람> (@핸들)/<주제>/
     캡션.html          ← 원문 그대로. 요약하거나 다듬지 마라
     <영상>.mp4         ← 있으면 좋다
   ```
4. **원문을 그대로 넣는다.** 손보면 톤 학습이 망가진다

`프로필.html` 이 없으면 계정 소개글을 보고 만든다.

- [ ] (사람) 영상에 나온 내용인가. 화면에 없는 제품·성분을 지어내지 않았는가
- [ ] (사람) 채팅에 캡션 전문을 코드블록으로 찍었는가

## 알려진 함정

- **약사님 폴더는 점으로 시작한다** (`.오주헌 약사님`). `ls`·glob 으로 안 보인다
- **드라이브 전체를 `find` 하면 2분을 넘겨 죽는다.** 주제 폴더 mtime 으로 좁힌 뒤 그 안만 뒤진다.
  `find-latest.mjs` 가 그렇게 한다
- **원본 촬영분과 편집 완성본을 헷갈리지 마라.** 주제 폴더 바로 아래의 수백 MB `.mov` 는 카메라 원본이다.
  캡션 대상은 편집자 폴더 안의 것이거나 작은 `.mp4` 다. 스크립트가 걸러 주지만 눈으로도 확인한다
- **차수가 최종본이다.** `_수정1` `_수정2` 가 있으면 **가장 높은 숫자**를 쓴다
- 프리미어 자동저장 폴더(`Adobe Premiere Pro Auto-Save`)에는 영상이 없다. 들어가지 마라
- **사람마다 캡션 형식이 다르다.** 제선영 형식을 오주헌에게 쓰면 어색하다
- `프로필.html` 에 없는 경력·전문성·수상을 지어내지 마라

## 사람에게 물어야 하는 지점

- 전종열 약사님 인스타 핸들 — 계정 정보에 없다
- 한 폴더에 완성본이 여러 개인데 어느 것이 최종인지 애매할 때
- 영상 내용이 의학적 판단을 요구해 캡션이 위험해질 수 있을 때
