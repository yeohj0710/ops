# 인스타 팔로워 나눠서 반복 주문하기

- **부르는 말**: 팔로워 주문해줘, 팔로워 분할 주문, 팔로워 나눠서 넣어줘, 팔로워 나눠 넣어줘, 팔로워 반복 주문, 팔로워 천천히 올려줘, 팔로워 올려줘, 팔로워 늘려줘, 팔로워 넣어줘, 한국인 팔로워 주문, 외국인 팔로워 주문, 해외 팔로워 주문, 이 계정에 팔로워, 10명씩 10번, 30분마다 팔로워, 팔로워 드립, 팔로워 묶음, 팔로워 묶음 상태 봐줘, 팔로워 주문 멈춰줘, snsfollow-drip
- **미리 허가**: snssupporter.com 에 사용자가 적어 준 인스타 아이디로 팔로워 주문 (미리 충전한 잔액에서 차감, 카드 입력 없음). 한국은 상품 1279 한 명 ₩110, 해외는 354 한 명 ₩9. 사용자가 적은 인원, 횟수, 간격 그대로 넣는다. 숫자를 안 줬으면 한국 10명 × 10번 × 30분(₩11,000), 해외 100명 × 10번 × 30분(₩9,000)
- **런너**: either
- **제어층**: L1 로 전부 한다 (API 주문, 로그인 없는 헤드리스 크롬으로 프로필 읽기)
- **한 번에 걸리는 시간**: 시작까지 1분. 그 뒤 주문은 배경 프로세스가 (횟수 - 1) × 간격 동안 혼자 돈다. 앞 주문이 서버에서 안 끝나면 그만큼 밀린다

---

## 무엇을 만드는 업무인가

사람이 준 인스타 아이디에 팔로워를 한꺼번에 넣지 않고, 정한 인원으로 잘게 나눠 일정 간격으로 반복 주문한다.
100명을 10명씩 10번, 30분마다 넣는 식이다. 끝나면 `<OPS>/work/snsview-drip/<묶음id>/` 에 주문번호와
주문 직전 팔로워 수(`profile-before.json`), 프로필 머리 화면 캡처(`profile-before.png`)가 남고,
SNS서포터 주문내역에도 같은 아이디로 횟수만큼 찍혀 있다.

주문 루프는 조회수 업무(`snsview-drip`)의 `snsview-drip.mjs` 를 그대로 쓴다. 이 업무의 `snsfollow-drip.mjs` 는
지역을 상품 번호로 바꾸고, 계정이 있는지와 공개인지 보고, 주문 직전 팔로워 수를 남긴 뒤 그 루프에 넘긴다.
묶음이 조회수 묶음과 같은 폴더에 쌓이므로 되살리기 예약 하나(`ops-snsview-drip-watch`)가 둘 다 살린다.

**조회수 업무와 헷갈리지 마라.** 게시물 링크에 넣는 것은 조회수(`snsview-drip`), 계정 아이디에 넣는 것은 이 업무다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차와 완료 검사를 한 번에 실행한다. 사용자가 아이디와 지역, 인원,
횟수, 간격을 적어 시킨 것이 곧 그 금액에 대한 승인이다. `plan` 결과를 적고 그대로 `start` 한다.
주문 버튼을 사람에게 넘기지 않는다. 멈추는 것은 아래 "사람에게 물어야 하는 지점" 뿐이다.

## 쉬운 설명

### 쓰는 상황

인스타 계정의 팔로워를 자연스럽게 늘리고 싶을 때 씁니다. 한 번에 100명이 붙으면 티가 나니까
10명씩 10번, 30분마다 나눠 넣습니다. 한국인으로 넣을지 외국인으로 넣을지, 몇 명씩, 몇 번,
몇 분 간격인지는 시킬 때 정합니다.

### 시키는 말

Claude 나 Codex 새 세션에 이렇게 말하면 됩니다.

> G드라이브 에이전트 폴더 참고해서 인스타 팔로워 나눠서 반복 주문하기 업무 해줘.
> 한국, 아이디 kimjejo_pharma 에 10명씩 10번, 30분 간격.

외국인으로 넣으려면 "해외" 라고 쓰면 됩니다. 해외 상품은 한 번에 최소 100명입니다.
진행이 궁금하면 "팔로워 묶음 상태 봐줘" 라고 하면 됩니다.

### 진행 순서

1. 잔액과 상품 가격을 봅니다.
2. 계정을 로그인 없이 열어서 있는 계정인지, 공개 계정인지, 지금 팔로워가 몇 명인지 봅니다. 비공개 계정에는 작업이 안 들어가서 주문하지 않습니다.
3. 총액을 계산합니다. 한국 10명씩 10번이면 11,000원입니다. 지금 돌고 있는 조회수 주문이 앞으로 쓸 돈까지 빼고 잔액이 되는지 봅니다.
4. 첫 주문 직전에 팔로워 수와 프로필 화면을 캡처해 둡니다. 판매자에게 A/S 를 요청할 때 필요합니다.
5. 첫 주문을 넣고, 나머지는 배경에서 간격마다 하나씩 넣습니다. 세션을 닫아도, 컴퓨터를 다시 켜도 이어서 돕니다.
6. 나중에 "상태 봐줘" 라고 하면 몇 번째까지 들어갔는지, 아직 안 들어온 인원이 몇 명인지, 팔로워가 시작 전보다 얼마나 늘었는지 보여줍니다.

### 결과물

SNS서포터 주문내역에 같은 아이디로 횟수만큼 주문이 찍혀 있고, 팔로워는 주문마다 조금씩 늘어납니다.
컴퓨터에는 묶음 폴더에 주문번호, 시작 전 팔로워 수, 프로필 캡처가 남습니다.

### 사람이 직접 눌러야 하는 것

해외로 넣을 때 한 가지입니다. 대상 계정에서 설정 및 활동 → 친구 팔로우 및 초대 → "검토를 위해 플래그 지정" 을
꺼 둡니다. 켜져 있으면 외국인 팔로워가 안 들어오고 환불도 안 됩니다. 잔액이 모자라면 충전만 사람이 합니다.

## 상품

인스타 팔로워 상품은 SNS서포터 카테고리 `팔로워` 에 17개가 있다. 260917 에 API 단가와 사이트 주문 화면 설명을 읽고 정리했다.
**"한국" 과 "해외" 만 말했으면 기본 상품을 쓴다.** 지금 값은 `products` 명령이 API 에서 그때그때 읽어 찍는다.

| 지역 | 상품 | 1명 | 최소 | 설명에 적힌 것 |
| --- | --- | --- | --- | --- |
| 한국 기본 | `1279` [혼합] 한국인 팔로워 | ₩110 | 5명 | 90일 A/S. 평균 1시간 안에 시작. 비공개 계정은 작업 안 됨. 주문 전 팔로워 수 캡처를 요구함 |
| 한국 | `1230` [리워드] 한국인 팔로워 | ₩80 | 10명 | A/S 없음. "매우 느리게 진행". 비공개 계정은 작업 안 됨 |
| 한국 | `1280`~`1287` 성별, 나이대 한국인 | ₩165~220 | 10명 | 사람이 성별이나 나이대를 말했을 때만 |
| 해외 기본 | `354` [A/S자동] 실제 외국인 팔로워 | ₩9 | 100명 | 90일 A/S(첫 구매 24시간 뒤부터). 이탈 10~20%. '검토를 위해 플래그 지정'이 켜져 있으면 작업도 환불도 없음 |
| 해외 | `342` [A/S자동] 유령 외국인 팔로워 | ₩8 | 100명 | 활동 없는 가계정. 90일 A/S. 이탈 10~20% |
| 해외 | `1246` [일반] 실제 일본인 팔로워 | ₩200 | 10명 | 30일 A/S. 평균 1시간 안에 시작 |
| 해외 | `1250`~`1253` 성별, 나이대 일본인 | ₩300 | 10명 | 사람이 성별이나 나이대를 말했을 때만 |

**한국 기본을 싼 1230 이 아니라 1279 로 둔 이유.** 1230 은 1명에 ₩30 싸지만 A/S 가 없고 아주 느리게 들어온다.
같은 아이디의 앞 주문이 안 끝나면 다음 회차가 못 들어가서, 분 단위로 나눠 넣는 이 업무와 안 맞는다.

## 준비물

- `SNSSUPPORTER_API_KEY`. 조회수 업무와 같은 키다. 없으면 `snsview-drip` 매뉴얼 절차 1 로 넣는다
- 인스타 아이디. @ 나 프로필 주소로 줘도 스크립트가 아이디만 남긴다. 게시물 링크를 주면 거절한다
- 지역, 1회 인원, 총 횟수, 간격. 안 준 것은 기본값을 쓴다
- playwright. 프로필을 읽는 데 쓴다. `check` 가 있는지 찍는다. 없으면 `--skip-profile` 로 넣고 보고에 적는다

## 절차

1. **키와 잔액을 본다 (L1)**
   ```bash
   node "<OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs" check
   ```
   키, 잔액(돌고 있는 묶음 몫을 뺀 실제 여유), 한국과 해외 기본 상품의 1명 값과 최소 수량, playwright 가 나오면 다음으로 간다.
   키가 없으면 `snsview-drip` 매뉴얼 절차 1 을 그대로 한다.

2. **입력값을 정리한다 (L1)**
   사용자 말에서 다섯을 꺼낸다. 지역(`--region`), 아이디(`--handle`), 1회 인원(`--qty`), 총 횟수(`--runs`), 간격(`--every`).
   - "한국", "국내", "한국인" 은 `kr`, "해외", "외국", "외국인", "글로벌" 은 `global` 이다. 한국어 그대로 줘도 받는다
   - "총 100명을 10번" 처럼 총량으로 말하면 1회 인원 = 총량 ÷ 횟수 로 바꾼다
   - 간격은 `30m`, `1h`, 숫자만 쓰면 분이다
   - 성별, 나이대, 일본인을 말했으면 `products` 로 상품 번호를 골라 `--service` 로 준다. `--region` 보다 앞선다
   - 안 준 것은 기본값(한국 10명, 해외 100명, 10번, 30분)이다. 스크립트가 `기본값` 줄을 찍으니 보고에 옮긴다
   - 우리 계정 아이디를 짐작해서 넣지 않는다. 사람이 준 아이디를 쓰고, 계정 이름만 들었으면 드라이브 `에이전트/기억/SNS 계정 운영/` 에서 아이디를 찾는다

3. **계획을 적는다 (L1)**
   ```bash
   node "<OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs" plan --region kr --handle <아이디> --qty 10 --runs 10 --every 30m
   ```
   계정 한 줄(공개 여부, 지금 팔로워 수)과 대상, 상품, 주문 구성, 비용과 잔액, 끝나는 시각이 나온다. **그대로 보고에 옮긴다.**
   답을 기다리지 않는다. 사용자가 숫자를 적어 시킨 것이 승인이다.
   `부족` 줄이 나오면 얼마 모자란지 적어 알리고 멈춘다. `막힘` 줄(없는 계정, 비공개)이 나와도 멈추고 알린다.
   `상품` 줄의 1명 값이 위 상품 표보다 비싸졌으면 멈추고 알린다. 싸졌거나 같으면 그대로 가고 표를 고친다.

4. **시작한다 (L1)**
   ```bash
   node "<OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs" start --region kr --handle <아이디> --qty 10 --runs 10 --every 30m
   ```
   프로필을 한 번 더 읽어 주문 직전 팔로워 수와 머리 화면 캡처를 남기고, 조회수 업무의 루프로 묶음을 만든다.
   `첫 주문 들어감: 주문번호 ...` 가 찍히면 성공이다. 안 찍히면 묶음 폴더의 `log.txt` 와 `run.err.txt` 를 본다.
   `첫 주문은 같은 대상의 앞 주문이 서버에서 끝나길 기다린다` 도 정상이다. 같은 아이디의 앞 주문이 서버에서 도는 중이면 나온다.

   스크립트가 주문하지 않고 거절하는 것은 다섯이다. 없는 계정, 비공개 계정, 잔액 부족(돌고 있는 묶음 몫까지 뺀다),
   인스타 팔로워가 아닌 상품 번호, 상품 최소 수량보다 적은 인원.
   같은 아이디로 도는 묶음이 있어도 시작을 거부한다. **사용자가 새로 시킨 주문이면 그게 겹쳐 넣을 이유다.**
   도는 묶음은 멈추지도 바꾸지도 않고 그대로 두고, 새 묶음은 `--force` 로 따로 건다 (조회수 업무 260917 규칙과 같다).

5. **보고한다 (L1)**
   묶음 id, 첫 주문번호, 주문 직전 팔로워 수, 총액과 잔액, 끝나는 시각을 적는다. 해외면 플래그 설정 한 줄을 같이 적는다.
   `start` 가 드라이브 `<DRIVE>/에이전트/보고/<날짜>-팔로워분할.md` 에 계획과 첫 주문번호를 이어 붙인다.
   배경 프로세스가 도는 동안 세션을 붙들고 있지 않는다. 끝날 때까지 기다리지 마라.

6. **"상태 봐줘" 라고 하면 (L1)**
   ```bash
   node "<OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs" status [묶음id] --api             # 서버 상태, 아직 안 들어온 인원, 서버가 적은 시작 팔로워 수
   node "<OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs" status [묶음id] --api --profile   # 지금 팔로워 수를 시작 전과 비교
   node "<OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs" list
   ```
   묶음 id 를 빼면 가장 최근 팔로워 묶음을 본다. `주의 3시간 넘게 한 명도 안 들어온 주문` 이 나오면
   해외는 플래그 설정을, 한국은 계정이 비공개로 바뀌었는지를 먼저 본다.
   멈추라고 하면 `stop <묶음id> --reason "<왜>"`, 이어 가라고 하면 `resume <묶음id>`. 둘 다 15초 안에 먹는다.
   끊긴 묶음 되살리기, `guard`, `watch` 는 조회수 업무 절차 6, 7 과 같다. 이 스크립트로 쳐도 그쪽으로 넘어간다.

## 산출물

- `<DRIVE>/에이전트/보고/<날짜>-팔로워분할.md`: 사람이 보는 보고

- [ ] (기계) `status --profile` 에서 팔로워가 시작 전보다 늘었다. 이탈이 있어서 넣은 인원과 딱 맞지는 않는다
- [ ] (사람) https://snssupporter.com/orders 에 같은 아이디로 횟수만큼 찍혀 있다

## 알려진 함정

- **팔로워 상품은 주문 대상에 주소가 아니라 인스타 아이디를 받는다 (260917 상품 설명).** 인스타 팔로워 상품 설명의 "주문링크 기입방법" 이 전부 "인스타그램 아이디를 입력해주세요" 이고 예시도 `snssupporter_official` 같은 아이디다. 조회수처럼 주소를 넣지 않는다 → 스크립트가 @, 프로필 주소, 대문자를 아이디로 맞춘다. 루프도 팔로워 상품에 주소가 오거나 조회수 상품에 아이디가 오면 주문 전에 거절한다
- **`snsview-drip.mjs` 에 `--handle` 을 주고 `--service` 를 빼면 조회수 상품 813 이 아이디로 나간다.** 그래서 루프가 `--service` 없는 `--handle` 을 거절한다. 팔로워는 늘 이 업무 스크립트로 넣는다. 그래야 시작 전 기록도 남는다
- **해외 기본 상품(354, 342)은 한 번에 최소 100명이다.** "해외 10명씩" 은 354 로 못 넣는다. 1279 는 5명, 1230 과 일본인은 10명부터다. 최소 수량은 판매자가 바꾼다(조회수 813 은 260904 에 50, 260909 에 100). `products` 가 찍는 값을 믿는다
- **354 는 대상 계정의 '검토를 위해 플래그 지정'이 켜져 있으면 작업도 환불도 리필도 없다 (상품 설명 점검기록).** 이 설정은 밖에서 읽을 수 없다. 그래서 해외로 넣을 때마다 `plan` 과 `start` 가 주의 줄을 찍고, 보고에도 한 줄 적는다. 설정을 바꾸는 것은 계정 주인의 일이라 사람에게 확인받는다
- **비공개 계정에는 작업이 안 들어간다 (1279, 1230 설명).** 354 는 비공개면 A/S 가 안 된다 → `start` 가 비공개로 읽히면 주문하지 않는다. 사람이 공개로 바꾸면 그때 다시 넣는다. `--allow-private` 는 읽기가 틀렸다고 확신할 때만 쓴다
- **로그인 없이 읽은 메타 설명의 팔로워 수는 낡은 값이다 (260917 실측).** 같은 순간 `og:description` 은 2,626명, 머리 화면과 페이지 안 JSON 은 2,650명이었다 → 스크립트는 `script[type="application/json"]` 안에서 `username` 이 같은 객체의 `follower_count`, `is_private` 를 읽고, 못 찾으면 머리 화면 숫자(`header [title]`)를 읽는다. 메타는 안 쓴다
- **로그인 없이 프로필을 열면 1~2초 뒤 로그인 권유 창이 머리 화면을 가린다.** 화면 전체를 찍으면 팔로워 수가 창 뒤에 깔린다 → Esc 로 닫고 `header` 요소만 찍는다
- **없는 계정도 HTTP 200 이다.** 제목이 "Profile을(를) 이용할 수 없습니다" 로 온다 → 상태 코드가 아니라 제목과 본문 글자로 가른다
- **브랜드 이름으로 아이디를 짐작하면 남의 계정에 들어간다 (260917 실측).** `mimipharm` 을 열어 보니 우리 미미팜과 상관없는 외국 개인 계정이었다 → 사람이 준 아이디만 쓰고, 이름만 들었으면 드라이브 기억 폴더에서 아이디를 찾는다. 찾아도 `plan` 의 계정 줄에서 팔로워 수가 우리가 아는 규모와 맞는지 본다
- **같은 아이디의 앞 주문이 서버에서 안 끝나면 새 주문은 `link_duplicate` 로 거절된다.** 조회수와 같은 규칙이다. 팔로워는 한 건이 몇 시간 걸릴 수 있어서, 간격을 30분으로 줘도 앞 주문이 끝나야 다음이 들어간다 → 이 업무는 앞 주문 상태를 1분마다 보고, 끝나면 바로 넣고, 5분마다 다시 넣어 보고, 6시간 넘게 안 끝나면 멈춘다(`--dup-poll 1m --dup-retry 5m --dup-max 6h`). 멈춘 묶음은 되살리기 예약이 5분 안에 다시 세운다. **실제 주문에서 한 건이 몇 분 걸리는지는 아직 모른다. 처음 돌린 세션이 `log.txt` 의 주문 간격을 보고 여기에 적는다**
- **stop 이 1분 넘게 안 먹을 뻔했다 (260917 시험).** 거절 뒤 앞 주문을 기다리는 동안 상태 조회 간격(1분)만큼 잠들어서 멈춤 표식을 늦게 봤다 → 루프가 조회 간격과 상관없이 15초마다 표식을 보게 고쳤다. 시험에서 stop 뒤 14초에 멈췄다
- **stop 직후 곧바로 resume 하면 묶음이 멈춘 채 남았다 (260917 시험).** 루프가 아직 표식을 못 본 사이 resume 이 "이미 돌고 있다" 로 돌아서고, 루프는 조금 뒤 표식을 보고 멈췄다 → resume 이 표식부터 지우게 고쳤다. 루프가 살아 있으면 그대로 이어 간다
- **1279 설명이 "주문전 수량을 반드시 캡쳐" 하라고 한다.** A/S 를 물을 때 기준이다 → `start` 가 첫 주문 직전에 `profile-before.png` 와 `profile-before.json` 을 남긴다. 서버도 첫 주문 때 팔로워 수를 `start_count` 로 적는다(`status --api` 의 `시작수` 줄). 둘이 다르면 서버 쪽이 A/S 기준이다
- **조회수 묶음과 잔액을 같이 쓴다.** 조회수 루프의 `start` 는 잔액만 보고 돌고 있는 묶음이 앞으로 쓸 돈은 안 뺀다. 팔로워 묶음은 한 번에 큰돈을 써서, 그대로 두면 김제조 자동 주문 같은 조회수 묶음이 중간에 잔액 부족으로 멈춘다 → 이 업무의 `start` 는 돌고 있는 묶음 몫을 빼고 모자라면 거절한다. `plan` 의 비용 줄에도 그 몫이 찍힌다
- **사이트 예약주문(드립피드)은 인스타 팔로워 중 1279 에만 켜져 있다 (260917 API `dripfeed`).** 354 에는 없다 → 두 지역을 같은 방식으로 돌리고 중간에 멈출 수 있게 우리 루프로 나눠 넣는다
- **스크립트를 고치면 가짜 API 로 먼저 돌려 본다.** 조회수 매뉴얼의 같은 이름 함정과 같은 방법이고 셋을 더 준다. `SNSFOLLOW_PROFILE_FILE` 에 `{"exists":true,"isPrivate":false,"followers":1234}` 같은 JSON 파일을 주면 크롬을 안 띄운다. `SNSVIEW_DRIP_NO_GUARD=1` 이면 시험 폴더용 되살리기 예약이 작업 스케줄러에 안 걸린다. `SNSVIEW_DRIP_MIN_EVERY=1` 이면 초 단위 간격을 받는다. 260917 에 가짜 API 로 성공, 비공개 거절, 없는 계정 거절, 잔액 부족 거절, 앞 주문 대기, 같은 아이디 겹쳐 걸기, stop, 곧바로 resume 을 돌렸다

## 사람에게 물어야 하는 지점

- API 키가 없을 때. 발급은 사람이 한 번 누른다 (조회수 업무 절차 1)
- 잔액이 모자랄 때. 충전은 사람이 한다
- 아이디를 안 줬을 때. 짐작해서 넣지 않는다
- 없는 계정이거나 비공개 계정일 때
- 해외를 100명 밑으로 쪼개라고 했을 때. 100명씩으로 올리면 총량과 총액이 바뀌고, 일본인 상품(1명 ₩200)으로 바꾸면 1명 값이 22배다. 둘 다 금액을 적어 사람이 고르게 한다
- 1명 값이 위 상품 표보다 비싸졌을 때
- 대상 계정의 설정(플래그 지정, 공개 전환)을 바꿔야 할 때
- 매뉴얼 밖의 결제, 삭제

## 묻지 말고 이렇게 한다

- 사용자가 아이디와 숫자를 적어 시켰으면 그 숫자가 승인이다. `plan` 결과를 적고 `start` 까지 간다
- 같은 아이디에 도는 묶음이 있어도 새 지시는 추가다. 기존 묶음은 그대로 두고 `start --force` 로 하나 더 건다
- 지역을 안 줬으면 한국, 숫자를 안 줬으면 기본값으로 넣고 보고에 기본값이라고 적는다
- 사람이 준 아이디가 인플루언서나 고객사 계정이어도 묻지 않고 넣는다
- 세션을 붙들고 끝까지 기다리지 않는다. 첫 주문번호를 확인하면 보고하고 끝낸다
