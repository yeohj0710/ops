# 어라운드팜·미미팜 릴스 4개 언어 게시

- **부르는 말**: 릴스 업로드 진행해줘, 릴스 업로드하고 주문까지, 릴스 올리고 조회수 주문, 어라운드팜 릴스 업로드, 미미팜 릴스 업로드, 릴스 올려줘, 언어판 릴스 게시, 릴스 4개 언어 올려줘
- **미리 허가**: 선택한 브랜드의 릴스 폴더에 준비된 영상 4벌을 4개 언어 계정에 릴스로 게시하고(캡션, 커버 포함), 게시 뒤 카드뉴스와 같은 반응(브랜드 계정끼리 좋아요, kmin.kyeong·yakdae.saram·lovellliiil 의 좋아요·저장·DM 공유, 게시물마다 한 곳 댓글, yakdae.saram 리포스트)까지 한다. 그리고 게시한 릴스 4개에 계정 등급표대로 인스타 조회수를 나눠 주문한다(snssupporter 잔액 차감, 브랜드 하나 ₩590, 두 브랜드 ₩1,180. 아래 "조회수 주문 등급표"). 틱톡, 유튜브에는 주문하지 않는다. 그 주(월~일)의 첫 릴스 업로드 때는 두 KR 공식 계정에 팔로워를 20명씩 나눠 넣는다(계정당 약 ₩2,200, 두 계정 ₩4,400. 아래 "주간 팔로워 주문")
- **런너**: either
- **제어층**: L1 파일 점검과 기록 → L3 로그인된 Chrome(프로필 **어라운드팜 & 미미팜**). 동영상이 안 붙으면 L1 로 창을 세우거나 팝업을 띄운다
- **한 번에 걸리는 시간**: 브랜드 하나 40~80분. 업로드 처리와 플랫폼 제한에 따라 달라진다

## 무엇을 만드는 업무인가

릴스 폴더 한 편(언어 4벌)이 그 브랜드의 4개 언어 계정에 릴스로 올라가 있고, 게시 URL 4개가 `릴스 목록.md` 표와 게시 기록 `state.json` 에 적혀 있고, 카드뉴스와 같은 반응이 끝나 있어야 한다. 카드뉴스 게시 업무(`<OPS>/manuals/pharmacy-sns-publish/MANUAL.md`)와 계정, 반응, 기록 방식이 같고 **올리는 물건이 이미지 여러 장이 아니라 mp4 한 개**라는 점만 다르다. 이 매뉴얼은 그 차이만 적고, 나머지는 카드뉴스 매뉴얼을 그대로 따른다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차·후속 작업·완료 검사를 한 번에 실행한다. 중간 산출물만 남기고 멈추거나 게시·전송 버튼을 사람에게 넘기지 않는다. 매뉴얼에 명시된 외부 행동은 호출에 포함된 승인으로 본다. 매뉴얼 밖의 대상, 비밀번호·CAPTCHA, 매뉴얼 밖 결제, 되살릴 수 없는 삭제만 사람에게 묻는다. 한 번 호출에 브랜드 하나(4개 언어) 또는 두 브랜드를 처리한다. 두 브랜드면 절차 아래 "두 브랜드를 같이 시키면" 순서를 따른다. **게시와 조회수 주문은 한 번에 이어서 한다.** 게시만 하고 주문을 다음으로 미루지 않는다. 콘텐츠 제작과 언어판 만들기는 포함하지 않는다(그건 편집 쪽 일이고, 결과가 릴스 폴더에 들어와야 이 업무가 시작된다).

## 입력과 계정

사용자는 "어라운드팜 릴스 업로드 진행해줘" 다음 줄에 게시 폴더 절대 경로만 준다. 게시 폴더는 `<계정 폴더>\릴스\<번호 날짜 제목>\` 이고 안에 언어 폴더 `KR` `EN` `CN` `JP` 가 있다. 언어 폴더마다 이렇게 들어 있다.

- `<번호 날짜 제목>_<언어>.mp4` 올릴 영상 한 개. 파일 이름 끝에 언어가 붙어 있어 폰으로 받아도 안 섞인다
- `캡션.txt` 그 언어 계정에 올릴 캡션. 그대로 쓰고 고치지 않는다
- `커버.png` 인스타 커버(썸네일)로 쓸 1080x1920 그림. **첫 프레임이 아니다.** 제품과 제품명 자막이 다 나오는 프레임으로 뽑는다(260922 사용자 지시). 그리드에서 무엇을 파는 영상인지 바로 보여야 한다. 인스타 기본값은 첫 프레임이라 커버 편집에서 `커버.png` 를 반드시 올린다

언어와 계정 짝은 카드뉴스와 같다. **EN 폴더 영상은 global 계정에, CN 은 cn 에, JP 는 jp 에.** 파일 이름 끝 언어와 Create 화면의 계정명을 게시 직전에 한 번 더 맞춘다.

| 언어 | 어라운드팜 | 미미팜 |
| --- | --- | --- |
| KR | aroundpharm_official | mimipharm_official |
| JP | aroundpharm_jp | mimipharm_jp |
| CN | aroundpharm_cn | mimipharm_cn |
| EN | aroundpharm_global | mimipharm_global |

Chrome 프로필은 **어라운드팜 & 미미팜** 이다. 미미팜 4개 계정이 전환 목록에 안 보이면 `mimipharm01` 로 먼저 전환하고 메뉴를 다시 연다. 반응 계정 3곳, 계정 판정법, 세션 재개 규칙은 카드뉴스 매뉴얼의 "입력과 계정", "새 세션 시작과 재개" 를 그대로 따른다.

## 절차

1. **원본 점검 (L1)**: 언어 폴더 4개에 mp4 한 개, `캡션.txt`, `커버.png` 가 다 있는지 본다. `ffprobe` 로 네 벌의 길이, 해상도(1080x1920 또는 2160x3840), 오디오 트랙 유무를 찍어 네 벌이 같은지 확인한다. 길이가 다르거나 오디오가 없는 벌이 있으면 올리지 않고 사용자에게 알린다. 캡션은 카드뉴스와 같은 표기 규칙 검사를 한다(미미팜은 `MIMIPharm`, 한국어 캡션의 사람은 `약사님`). 4K(2160x3840) 원본은 그대로 올린다. 인스타가 알아서 줄인다. 미리 1080p 로 줄이지 않는다.
2. **계획과 중복 확인 (L1/L3)**: 카드뉴스와 같이 `<OPS>/manuals/pharmacy-sns-publish/plan.mjs` 로 `<계정 폴더>\etc\게시 기록\<게시 폴더 이름>\logs\state.json` 을 만든다(어라운드팜 84건, 미미팜은 게시자 댓글 4건을 더해 88건. kmin.kyeong 리포스트는 skipped). 게시 폴더 안에는 아무것도 만들지 않는다. 같은 제목의 릴스가 그 계정에 이미 있으면 다시 올리지 않고 URL 을 재사용한다.
3. **게시 4건 (L3)**: 언어마다 계정 전환 → Create/Reels 화면의 **실제 사용자명** 확인 → 만들기 → 게시물 → `컴퓨터에서 선택` 에 `setFiles` 로 mp4 절대 경로를 넘긴다 → **동영상이 붙었는지 먼저 판정한다**(아래 함정 첫 줄) → 자르기에서 원본 비율(9:16) 선택 → 커버 편집에서 `커버.png` 를 커버 이미지로 올린다(기본값 첫 프레임은 쓰지 않는다) → Facebook 등 동시 게시는 끈다 → **게시 화면 캡션 칸에 `캡션.txt` 를 그대로 넣는다** → 공유. 게시 처리 중이면 릴스 URL 이 나올 때까지 기다린다(4K 는 몇 분 걸린다). 릴스 URL, 캡션, 그리드 커버, 소리가 나오는지까지 확인하고 `state.json` 에 적는다. 캡션이 비어 나갔으면 그때만 릴스 페이지 `...` → 수정에서 다시 넣는다.
   - **미미팜이면 게시 직후 같은 계정으로 게시자 댓글을 달고 고정한다.** 계정을 바꾸기 전에 한다. 원문과 규칙은 카드뉴스 매뉴얼 "게시자 댓글" 절(`<드라이브>\[운영] 미미팜 인스타그램\계정 세팅\게시자 댓글\<언어>.txt`).
   - **첫 편을 올린 뒤 음원 상태를 본다.** 상업 음원(예: The Girl From Ipanema, Stan Getz)이 깔린 영상은 인스타가 저작권으로 오디오를 막거나 음소거할 수 있다. 첫 편의 릴스 페이지에서 "오디오 사용 불가", 음소거 표시, 저작권 안내가 뜨면 **나머지 세 편을 올리지 말고** 멈춰서 사용자에게 알린다. 인터뷰 말소리까지 같이 사라지는 일이라 그대로 밀면 안 된다.
4. **조회수 주문 4건 (L1), 게시 4건이 끝나면 바로**: 반응보다 먼저 넣는다. 조회수는 몇 시간에 걸쳐 나눠 들어가서 일찍 걸수록 반응 작업과 겹쳐 돈다. 주문은 배경에서 혼자 돌고 1분이면 걸린다. 게시한 릴스 4개 각각에 아래 등급표대로 `<OPS>/manuals/snsview-drip/scripts/snsview-drip.mjs start` 를 건다. 숫자를 사용자에게 다시 묻지 않는다. 지출 직전에 `plan` 으로 한 줄 알리고 그대로 넣는다. 첫 주문번호와 묶음 이름을 `state.json` 의 게시 행 evidence 와 보고에 적는다. 잔액이 모자라면 그때만 멈추고 충전을 부탁한다.
   - **그 주 첫 릴스 업로드면 팔로워 주문도 여기서 건다.** 아래 "주간 팔로워 주문" 을 본다. 이미 이번 주에 걸었으면 건너뛰고 보고에 "이번 주 팔로워 주문은 <묶음 id> 로 이미 있음" 을 적는다.
5. **자기 스토리 4건**: PC 웹에는 기능이 없다(카드뉴스 매뉴얼 함정 260921). 폰 앱이 없으면 `blocked` 로 남기고 넘어간다.
6. **브랜드 계정 좋아요 16건, 반응 계정 반응, 댓글, 리포스트, DM 공유**: 카드뉴스 매뉴얼의 "반응 한 장 정리" 표와 절차 5~7을 그대로 한다. 릴스라고 다를 것이 없다. DM 공유 창이 굳으면 10분 쉬는 것도 같다.
7. **기록과 보고 (L1)**: `verify.mjs` 를 돌려 통과시키고, `<계정 폴더>\릴스\릴스 목록.md` 표의 그 줄에 상태 `게시`, 날짜(KR 실제 게시일), `KR 게시물` 칸에 KR 릴스 URL 을 넣고 비고에 언어판 URL 세 개를 적는다. 게시물 4개 링크와 항목별 건수, 남은 막힘을 보고한다. 자신이 연 탭만 닫고 시작 계정으로 복귀한다.

**두 브랜드를 같이 시키면 브랜드 단위로 끊는다.** 미미팜 4개 게시 → 미미팜 조회수 주문 4건 → 어라운드팜 4개 게시 → 어라운드팜 조회수 주문 4건 → 두 브랜드 반응 → 기록. 게시와 주문이 먼저 끝나야 조회수가 일찍 붙고, 반응은 계정 전환이 많아 한 번에 몰아 하는 편이 빠르다.

**미미팜 틱톡, 유튜브에도 올리면 게시자 댓글을 단다.** 업로드 자체는 이 매뉴얼 밖(`pharmacist-youtube-tiktok-upload` 처럼 Codex 런너)이지만, 올린 직후 같은 계정으로 유튜브는 `KR.txt`, 틱톡은 `틱톡_KR.txt` 를 달고 고정한다. 틱톡, 유튜브에는 조회수 주문을 넣지 않는다.

## 산출물과 명령

원본은 `<OPS>/manuals/pharmacy-reels-publish/` 다. 계획과 검사는 카드뉴스 것을 그대로 빌려 쓴다.

```sh
node <OPS>/manuals/pharmacy-sns-publish/plan.mjs aroundpharm "<게시 기록 폴더>/logs/state.json"
node <OPS>/manuals/pharmacy-sns-publish/verify.mjs "<게시 기록 폴더>/logs/state.json"
```

## 조회수 주문 등급표 (260922 사용자 지시, 260924 루틴으로 고정)

**릴스에만 넣는다.** 카드뉴스(이미지 게시물)는 조회수가 안 보여서 주문하지 않는다. 반응(좋아요, 저장, 공유, 댓글, 리포스트)은 카드뉴스와 릴스 모두 한다.
**틱톡, 유튜브에는 주문하지 않는다(260924 사용자 지시).** 인스타 8개 계정 릴스만이다.

상품 813 `[동영상] 한국인 조회수` (100회 ₩10). 간격 흔들기는 주지 않는다.

| 계정 | 주문 | 합계 | 명령 |
| --- | --- | --- | --- |
| `*_official` (KR) | 100회 × 50번, 10분 간격 | 5,000회 ₩500 | `start --link <릴스 URL> --qty 100 --runs 50 --every 10m` |
| `*_global` (EN) | 100회 × 5번, 1시간 간격 | 500회 ₩50 | `start --link <릴스 URL> --qty 100 --runs 5 --every 1h` |
| `*_cn`, `*_jp` | 100회 × 2번, 10시간 간격 | 200회 ₩20 | `start --link <릴스 URL> --qty 100 --runs 2 --every 10h` |

브랜드 하나 4편에 ₩590, 두 브랜드 8편이면 **₩1,180** 이다. 첫 적용은 260923 00:08 미미라인 광고, 혹시 어떤 제품을 좋아하시나요 8건(묶음 `260923-0008-*`). 좋아요는 사지 않는다. 좋아요는 위 반응 계정이 누른다.

- 주문 한 건은 ₩500 을 넘기지 않는다(260924 사용자 규칙). 위 표는 전부 건당 ₩10 이다.
- 같은 릴스에 이미 돌고 있는 묶음이 있으면 `list` 로 보고 새로 걸지 않는다. 사용자가 더 넣으라고 하면 멈추지 말고 `--force` 로 하나 더 건다.
- 인플루언서가 올린 미미팜, 어라운드팜 홍보 릴스는 이 표가 아니다. 그 사람 최근 게시물 중앙값 기준으로 따로 시킨다.
- SNS서포터 주문은 넣고 나면 취소가 안 된다(`action=cancel` 이 `error.cancel_unavailable`, 260924 틱톡 조회수, 좋아요에서 실측). 링크와 계정을 넣기 전에 맞춘다.

## 주간 팔로워 주문 (260924 사용자 지시)

릴스는 화요일, 목요일에 올라간다. **한 주(월~일)에 한 번, 그 주 첫 릴스 업로드(화요일이든 목요일이든 먼저 올라가는 날)에** 두 KR 공식 계정에 팔로워를 넣는다. 사용자가 "일주일에 한 번 릴스 업로드될 때" 로 정했다. 글로벌, 중국, 일본 계정에는 넣지 않는다.

| 계정 | 주문 | 명령 |
| --- | --- | --- |
| `aroundpharm_official` | 5명 × 4번, 24시간 간격(20명, 약 ₩2,200) | `node <OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs start --region kr --handle aroundpharm_official --qty 5 --runs 4 --every 24h` |
| `mimipharm_official` | 5명 × 4번, 24시간 간격(20명, 약 ₩2,200) | `node <OPS>/manuals/snsfollow-drip/scripts/snsfollow-drip.mjs start --region kr --handle mimipharm_official --qty 5 --runs 4 --every 24h` |

- 상품은 `--region kr` 이 고르는 한국인 팔로워(1279, 1,000명 ₩110,000)다. 첫 적용은 260918 묶음 `260918-1240-follow-*`(같은 꼴, 두 계정 합계 ₩4,400).
- 걸기 전에 `snsfollow-drip.mjs list` 로 이번 주에 시작한 `follow-<아이디>` 묶음이 있는지 본다. 있으면 새로 걸지 않는다(한 주 한 번). 한 브랜드만 올리는 날이어도 두 계정 모두 이번 주 몫이 없으면 두 계정 다 건다.
- 지출 직전에 `plan` 결과를 한 줄로 알리고 그대로 `start` 한다. 숫자를 다시 묻지 않는다. 잔액이 모자라면 그때만 멈춘다(조회수 묶음 몫을 뺀 잔액 기준, snsfollow-drip 매뉴얼 함정).
- 묶음 id 를 게시 기록 `state.json` 의 보고와 최종 보고에 적는다.

## 알려진 함정

- **동영상은 숨은 탭에서 안 붙는다. 이미지와 다르다.** 파일을 넘긴 뒤 "사진과 동영상을 여기에 끌어다 놓으세요" 화면에 계속 서 있으면 창이 최소화됐거나 내 탭이 배경 탭인 것이다. 판정과 처방은 `<OPS>/manuals/shorts-pipeline/MANUAL.md` 의 P6 첫 두 절이 원본이다. 요약하면 `document.visibilityState` 와 `outerWidth` 를 읽고, 최소화면 `scripts/chrome-front.ps1`, 배경 탭이면 같은 출처 팝업(`window.open("https://www.instagram.com/", "igpop", "width=1280,height=1000,...")`, **`popup=yes` 금지**)을 띄우고 `scripts/window-topmost.ps1 -Match "Instagram"` 으로 가림만 푼다. 끝나면 `-Off` 로 핀을 풀고 `__pop.close()` 로 닫는다.
- **캡션은 게시 화면에서 바로 넣는다 (260922 사용자 지시).** 게시 뒤 수정으로 다시 넣는 절차는 없앴다. 예전에 빈 채로 나간 것은 **팝업 창에서 합성 이벤트로 밀어 넣었기 때문**이다. 탭을 활성으로 만들어 진짜 타이핑으로 넣으면 그대로 들어간다. 확장 탭이 배경이라 동영상이 안 붙으면 팝업 대신 **탭을 활성으로 만드는 쪽**을 먼저 시도한다(아래 함정 첫 줄). 그래도 팝업으로 갈 수밖에 없으면 캡션만 게시 뒤 수정에서 넣고 그 사실을 보고에 적는다.
- **캡션이 들어갔는지는 게시 뒤 API 로 확인한다.** 글자 수 표시는 증거가 아니다. `/api/v1/media/<pk>/info/` 의 `caption.text` 길이를 본다.
- **계정 전환을 좌표로 누르지 마라. 바로 아래가 로그아웃이다.** DOM 에서 `계정 전환` 글자를 찾아 `.click()` 한다. 계정 판정은 주소창이 아니라 Create 화면의 사용자명이다.
- **새 화면 첫 클릭은 씹힌다.** 스크롤 한 번 굴리고 좌표를 다시 잰다.
- **4K 파일은 업로드와 처리에 몇 분 걸린다.** 진행 표시가 멈춘 것처럼 보여도 다시 누르지 않는다. 같은 파일을 두 번 넣으면 릴스가 두 개 올라간다. 처리 중이면 릴스 URL 이 생길 때까지 기다린다.
- **상업 음원은 오디오가 막힐 수 있다.** 절차 3의 첫 편 확인을 건너뛰지 마라.
- 반응 쪽 함정(합성 클릭이 안 먹는 버튼, DM 공유 창 굳음, API 로 세는 법)은 카드뉴스 매뉴얼 "알려진 함정과 검증 범위" 가 원본이다. 여기 다시 적지 않는다.
- 릴스 폴더 꼴과 언어판 만드는 방법은 `<계정 폴더>\릴스\릴스 작업 안내.md` 에 있다. 게시 업무는 그 폴더를 읽기만 한다.

## 막힘 처리

자격증명·CAPTCHA, 로그인 화면, 접근 불가능한 앱이 필요하면 정확한 항목과 필요한 사용자 조치를 알린다. 나머지 독립 작업은 끝낸다. 하나라도 남으면 전체 완료로 보고하지 않는다. 음원 제한으로 멈춘 경우는 어느 편에서 무슨 표시가 떴는지 그대로 적는다.
