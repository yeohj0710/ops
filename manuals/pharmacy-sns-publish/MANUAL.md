### DM 공유 창 다루는 법 (260922 실측)

- **수신자는 검색으로 고른다.** 공유 창 기본 격자에는 최근에 주고받은 사람 20명쯤만 나온다. 그 밖의 계정은 `검색` 칸에 **아이디를 그대로 쳐서** 결과 줄을 눌러야 한다. 한 번 보내고 나면 다음부터는 격자에 올라온다.
- 검색 결과 줄은 `div[role="button"]` 이 아니라 그냥 `div` 다. 줄 안의 `img` 에서 부모를 타고 올라가 너비 300 이상, 높이 40~120 인 칸을 잡는다. 줄 글자는 "표시이름 + 아이디" 라서 **`textContent.endsWith(아이디)` 로 맞춰야** 엉뚱한 사람에게 안 간다. 검색은 팔로우 관계를 안 가리고 전 세계 계정을 다 보여 준다.
- 검색 칸은 React 라 `value` 를 네이티브 setter 로 넣고 `input` 이벤트를 쏜다. 한 명 고른 뒤에는 칸을 비우고 다음 아이디를 넣는다.
- **"따로 보내기" 버튼은 보통 합성 클릭을 안 받는데, 포인터 이벤트를 다 갖춰 주면 받는다.** `pointerover, pointerenter, pointermove, pointerdown` 을 `PointerEvent` 로, 이어서 `mousedown, pointerup, mouseup, click` 을 보낸다. `MouseEvent` 만으로 만든 `pointerdown` 은 안 먹는다. 이 방법은 탭이 숨어 있어도 된다.
- **보냈는지는 창이 닫히는 걸로 판단하지 마라.** 보내도 창이 그대로 있다. `/api/v1/direct_v2/threads/<id>/` 의 `original_media_igid` 로 확인한다.
- **`/api/v1/direct_v2/ranked_recipients/` 가 200 인데 본문이 비면 그 계정은 공유가 막힌 것이다.** 공유 창이 회전만 하고 안 그려지고, 계정 전환 창까지 안 열린다. 받은 목록은 멀쩡히 오니 로그인 문제로 오해하기 쉽다. 260922 에 lovellliiil 로 하루 100건 가까이 보내다 걸렸다. **여기서 더 누르지 말고 멈춘다.** 몇 시간 뒤에 다시 본다.
- 한 계정이 하루에 보내는 DM 은 100건 근처에서 막혔다. lovellliiil 은 바깥 10명 x 8 + 삼각형 2명 x 8 = 96건이라 하루치를 꽉 채운다. **한 번에 몰아치지 말고 게시물 사이에 시간을 두고, 삼각형 공유부터 끝낸 뒤 바깥 공유를 돌린다.** 막히면 몇 시간 뒤에 다시 본다.

**얼마나 됐는지는 화면 말고 API 로 센다.** shortcode 를 base64 알파벳 `A-Za-z0-9-_` 로 되돌려 pk 를 얻고 `/api/v1/media/<pk>/info/` 를 부르면 지금 로그인한 계정의 `has_liked`, `has_viewer_saved` 와 `like_count`, `comment_count` 가 한 번에 나온다. DM 공유는 `/api/v1/direct_v2/threads/<id>/` 의 `original_media_igid` 로 센다. 받은 목록(inbox)은 스레드마다 두 건까지만 보여 줘서 못 쓴다.

## 새 세션 시작과 재개 (2026-09-16 실측)

- 먼저 이 매뉴얼 전체와 대상 게시 기록의 `logs/state.json`, `source-manifest.json`을 읽는다. 기존 계획을 다시 만들거나 완료 항목을 덮어쓰지 않는다. 게시 URL이 있으면 실제 게시물을 확인하여 재사용한다.
- 시작 시 게시·스토리·자기 게시물 좋아요·상호 좋아요·지정 계정 좋아요·저장·댓글·리포스트의 완료/미완료 수를 구분한다. 게시 4건 또는 브랜드 좋아요만 끝났다고 전체 완료로 보고하지 않는다. 두 브랜드 요청이면 브랜드별 원장을 따로 유지한다.

- 로그인 여부는 한 번의 전환 실패나 일부만 보이는 전환 목록으로 판단하지 않는다. 사이드바 내 프로필로 현재 계정을 확인하고, **계정 전환** 메뉴의 전체 목록을 연다. 미미팜 4개 계정이 보이지 않으면 `mimipharm01`로 먼저 전환하고 메뉴를 다시 연 뒤 `mimipharm_official`, `mimipharm_jp`, `mimipharm_cn`, `mimipharm_global` 중 대상 계정을 고른다. 이 경로까지 실패하고 Instagram이 실제 로그인 화면이나 세션 만료 오류를 보여줄 때만 로그인 필요로 기록한다.

## 절차

1. **원본 점검 (L1)**: 게시 폴더는 `<계정 폴더>\카드뉴스\<번호 날짜 제목>\` 이고, 언어마다 `KR\` `EN\` `CN\` `JP\` 폴더에 `01.png` 부터 장 순서대로와 `캡션.txt` 가 있다(260915 정리). 먼저 `python "<드라이브>\에이전트\기억\SNS 계정 운영\카드뉴스\도구\cardnews_folders.py" check <aroundpharm|mimipharm>` 로 규격을 본다. 네 언어 폴더가 다 있지 않으면 게시하지 않고 사용자에게 알린다. 파일 이름 순서대로 슬라이드를 놓고 언어, 장수, 비율, 잘림을 확인한다. `캡션.txt` 를 그대로 쓰고 임의로 번역하거나 고치지 않는다. 누락 언어를 다른 언어로 대체하지 않는다. **단 표기 규칙은 예외다.** `check` 가 `표기 위반` 을 찍으면(미미팜 캡션의 `미미팜`, `#미미팜` 류, 두 계정 한국어 캡션의 사람을 가리키는 `약사`) 올리기 전에 피그마 캡션 칸과 `캡션.txt` 를 같이 `MIMIPharm`, `약사님` 으로 고치고 `check` 를 다시 돌린다. 카드 PNG 에 같은 말이 보이면 피그마에서 고치고 그 장을 다시 뽑는다. 규칙은 `<OPS>/manuals/card-news/MANUAL.md` 맨 위 "표기 규칙"(260915, 260916 사용자 지시).
2. **계획과 중복 확인 (L1/L3)**: plan.mjs로 `<계정 폴더>\etc\게시 기록\<게시 폴더 이름>\logs\state.json` 에 행동 68건을 기록하되 kmin.kyeong 리포스트 4건은 skipped(수행 제외)로 만든다. 경로는 `cardnews_folders.py records <브랜드> <벌>` 로 받는다. 원본 경로, 언어별 파일 목록과 해시, 캡션, 시작 계정을 같은 기록 폴더에 적는다. 게시 폴더 안에는 아무것도 만들지 않는다. 기존 게시 기록과 실제 게시물을 대조해 동일 콘텐츠는 URL을 재사용한다. 매 행동 전 실제 사용자명과 대상 URL을 확인한다. 같은 Chrome 프로필의 계정 전환은 다른 탭에도 영향을 주므로 병렬 조작하지 않는다.
3. **게시 4건 (L3)**: 계정 전환 → 사용자명 확인 → 만들기 → 게시물 → 언어별 파일 선택 → 원본에 맞는 비율 → 필터 없이 다음 → 캡션 입력 → 게시. Facebook 등 추가 플랫폼 동시 게시는 이번 게시물에서 끈다. 새 URL을 열어 모든 슬라이드와 캡션을 확인한다. 캡션이 비면 더 보기 → 수정에서 입력하고 새로고침한다. 릴스는 준비된 동영상과 캡션을 사용하고 shorts-pipeline의 업로드 절차를 참고한다.
4. **자기 스토리 4건 (L3 → L4)**: 게시물 공유 → 스토리에 추가로 해당 계정에 공유한다. 공개 스토리를 열어 계정과 게시물 연결을 확인한다. PC에 기능이 없으면 로그인된 Instagram 앱 또는 연결된 휴대폰을 쓴다. 없는 UI를 있다고 가정하지 않는다. 다운로드·초안·독립 이미지 업로드는 게시물 스토리 공유 완료가 아니다. 앱도 접근할 수 없으면 해당 항목을 막힘으로 남기고 다른 작업을 진행한다.
5. **브랜드 계정 좋아요 16건 (L3)**: 브랜드 계정 4개가 각자 자기 게시물 1건과 같은 브랜드의 다른 계정 게시물 3건에 모두 좋아요를 누른다. 자기 게시물 좋아요 4건과 상호 좋아요 12건이다. 이미 좋아요 상태면 누르지 않는다. 계정·URL·좋아요 상태를 확인한다.
   - 두 브랜드 8개 계정의 오늘 카드뉴스 반응을 함께 요청하면 어라운드팜 16건, 미미팜 16건을 각각 수행한다. 브랜드 사이 교차 좋아요는 하지 않는다.
6. **반응 계정 반응 (L3 → L4)**: 위 "반응 한 장 정리" 표대로 한다. 좋아요와 저장은 세 계정이 전부, DM 공유는 셋이 삼각형으로, 댓글은 게시물마다 한 계정만, 리포스트는 yakdae.saram 만, lovellliiil 은 바깥 계정 10명 남짓까지 더 보낸다. kmin.kyeong 리포스트 4건은 위 기능 예외로 제외한다. 이미 반응한 것은 해제하거나 중복하지 않는다. 공유 창 열기와 링크 복사는 리포스트 완료가 아니다. 실제 리포스트 상태를 확인한다. 기능이 없으면 해당 항목만 막힘으로 기록한다.
   - DM 공유는 브랜드 하나만 시켰어도 그 브랜드 4개에 대해 세 계정이 삼각형으로 주고받는다(3 x 4 x 2 = 24건). 두 브랜드면 48건이다.
   - **lovellliiil 은 바깥으로도 보낸다.** `<OPS>/manuals/pharmacy-sns-publish/share-pool.json` 의 후보 명단에서 **게시물마다 10명을 새로 무작위로 뽑는다(260922 사용자 지시).** 매번 같은 사람에게 보내지 않는다. 브랜드 8개 계정과 약대사람, 김민경은 명단에 없다. 그 둘은 삼각형 공유로 따로 받는다.
   - PC 공유 창은 게시물과 UI 상태에 따라 `공유하기` 또는 `게시물 공유`로 보일 수 있다. 검색창이 `검색`이면 한 명을 선택해 보내고 두 번째 계정에 다시 공유한다. 수신자 입력창이 `받는 사람:`이면 두 명을 함께 선택해 한 번에 보낼 수 있다. 어느 형태든 실제 `전송됨` 표시나 공유 창 닫힘을 확인한다.
7. **댓글**: **게시물마다 반응 계정 세 곳 중 한 곳만 단다(260921 사용자 지시).** 게시물 8개를 각각 따로 뽑으며, 세 계정이 다 달면 티가 난다. 길이는 한 단어에서 세 단어까지다(찜, noted, 记下了, メモ). 고르고 남은 두 계정의 댓글 행동은 `blocked` 로 남기고 사유에 누가 뽑혔는지 적는다. 뽑은 결과는 게시 기록 폴더의 `comments.json` 에 적어 둔다. 아래 문장들은 이 규칙보다 앞선 판이라 긴 댓글을 요청받았을 때만 쓴다. 게시물 내용과 언어에 맞춰 그때그때 짧게 쓴다. 완결된 문장이나 교정된 띄어쓰기를 강제하지 않는다. 짧은 감탄, 궁금한 점, 눈에 들어온 제품 등 반응 지점을 달리하고 길이·어미·문장부호도 자연스럽게 바꾼다. 이모지는 안 쓰는 댓글을 기본으로 가끔만 쓰며 같은 이모지와 문장 틀을 반복하지 않는다. 다양성을 만들려고 일부러 오타를 넣거나 모든 댓글을 반말·인터넷 말투로 통일하지 않는다. 고정 예문을 돌려 쓰지 않고 이번 작업에서 앞서 쓴 댓글과 비교해 반복을 피한다. 방문·구매·사용 경험이나 효능을 꾸며 쓰지 않는다. 같은 계정의 기존 댓글을 확인해 중복을 막고 실제 게시된 본문을 확인한다. (2026-09-15 사용자 요청)
8. **기록과 보고 (L1/L3)**: 매 행동 직후 status와 evidence를 기록하고 logs/known_items.txt에 행동 ID를 추가한다. evidence에는 실제 상태를 확인한 화면 경로·설명·댓글 본문·URL 등을 적는다. URL만으로 행동 성공을 추정하지 않는다. verify.mjs 통과 후 게시물 4개 링크와 항목별 건수, 남은 제한을 보고한다. 보고 전에 `게시 목록.json` 에서 그 벌의 status 를 `게시`, date 를 KR 실제 게시일로 바꾸고 links 네 개를 넣은 뒤 `cardnews_folders.py rename <브랜드>` 와 `index <브랜드>` 를 돌린다. 요청하지 않은 완료 DM은 보내지 않는다. 자신이 연 탭만 닫고 시작 계정으로 복귀한다.

## 산출물과 명령

원본은 <OPS>/manuals/pharmacy-sns-publish/, Drive 배포본은 <드라이브>/에이전트/매뉴얼/pharmacy-sns-publish/MANUAL.md다. 실행 기록과 업로드용 JPG 변환본은 `<계정 폴더>\etc\게시 기록\<게시 폴더 이름>\` 에 둔다. 게시 폴더(원본)에는 쓰지 않는다. 260915 전에 올린 네 벌(어라운드팜 A1, A2와 미미팜 S1, R1)의 기록도 그 자리로 옮겼다.

```sh
node <OPS>/manuals/pharmacy-sns-publish/plan.mjs mimipharm "<게시 기록 폴더>/logs/state.json"
node <OPS>/manuals/pharmacy-sns-publish/verify.mjs "<게시 기록 폴더>/logs/state.json"
```

어라운드팜은 첫 인자를 aroundpharm으로 바꾼다. 기존 계획 파일은 덮어쓰지 않는다. status는 pending/done/blocked/skipped다. skipped는 kmin.kyeong 리포스트에만 허용하며 사용자 확인 근거를 적는다. blocked 는 스토리와 안 뽑힌 댓글에만 종료 상태로 인정하고, 다른 행동의 blocked 는 검사가 실패로 본다. 막힘에는 실제 오류와 다음 조치를 남긴다. ops 태스크에는 snsState에 이 state.json의 절대 경로를 넣어야 done 검사가 실행된다.

## 알려진 함정과 검증 범위

- 4320×5400 PNG 중 약 16~19MB 파일에서 “게시물을 공유할 수 없습니다. 더 작은 파일을 선택한 후 다시 시도해보세요.” 오류가 났다. 원본 보존 후 같은 해상도의 고품질 JPG 변환본으로 성공했다. 변환본은 게시 기록 폴더에 둔다. 임의 축소부터 하지 않는다.
- 작성창에 캡션을 넣어도 실제 본문이 비는 사례가 있었다. 게시 후 수정과 새로고침으로 복구했다.
- 계정 전환 중 일시적으로 로그인 화면이 나왔다. 기존 로그인 계정으로 돌아가 다시 전환한 뒤 실제 로그인 필요 여부를 판단한다. 반복 실패는 무한 재시도하지 않는다.
- 미미팜 4개 언어 캐러셀과 캡션은 수행 경험이 있다. 스토리·상호 좋아요·지정 계정 반응 전체 경로는 등록 시점에 실기 검증하지 않았다. 첫 실행에서 실제 UI 성공 근거를 기록한다.
- 플랫폼 활동 제한은 실제 메시지와 재시도 가능 시점을 기록한다. 임의 제한 수치를 만들거나 계정 전환으로 제한을 우회하지 않는다.
- **PC 웹에는 게시물을 스토리에 올리는 기능이 없다(260921 실측).** 공유 시트와 `...` 메뉴를 둘 다 열어 확인했고 "스토리에 추가" 항목이 없다. 폰 앱이 없으면 스토리 4건만 사유와 함께 `blocked` 로 남기고 나머지를 끝낸다. verify.mjs 는 스토리의 blocked 를 종료 상태로 받는다.
- **좌표 클릭이 조용히 씹히면 `document.visibilityState` 부터 본다.** 익스텐션 탭이 `hidden` 이면 좌표 클릭이 줄만 서고 페이지에 안 닿는다. 스크린샷은 `Page.captureScreenshot` 30초 타임아웃으로 죽는데 `javascript_tool` 은 멀쩡해서 좌표를 계속 의심하게 된다. 260921 에는 탭 제목을 `WB-SHARE-TASK` 로 바꾼 뒤 MSAA(`AccessibleObjectFromWindow` + `accDoDefaultAction`)로 그 탭을 활성으로 만들어 풀었다. 절차는 `<OPS>/runners/claude.md` 와 기억 `chrome-hidden-tab-breaks-media-and-first-click` 에 있다.
- **숨은 동안 쌓인 좌표 클릭은 탭이 보이는 순간 한꺼번에 처리된다.** 260921 에 "따로 보내기" 를 여러 번 누른 탓에 같은 게시물이 한 사람에게 2~3번 갔다. 안 먹는다고 같은 자리를 반복해서 누르지 말고 먼저 탭을 보이게 만든다.
- **합성 클릭(dispatchEvent)이 먹는 곳과 안 먹는 곳이 갈린다(260921 실측).** 좋아요, 저장, 공유 대상 고르기, 계정 전환 목록은 합성 클릭으로 된다. 리포스트 버튼과 공유의 "따로 보내기" 버튼은 진짜 클릭만 받는다. 이 둘은 탭을 보이게 만든 뒤 좌표로 누른다.
- **계정 전환 목록의 줄은 `elementFromPoint` 로 안 잡힐 때가 있다.** 대화상자 껍데기가 위에 깔려서 좌표 클릭이 껍데기에 닿고 아무 일도 안 난다. 줄 요소를 찾아 합성 클릭을 보내면 바로 전환된다.
- **반응이 실제로 들어갔는지는 화면 말고 API 로 센다.** shortcode 를 base64 알파벳 `A-Za-z0-9-_` 로 되돌려 pk 를 얻고 `/api/v1/media/<pk>/info/` 를 부르면 그 계정의 `has_liked`, `has_viewer_saved` 와 `like_count`, `comment_count`, `carousel_media` 장수가 한 번에 나온다. `/likers/` 는 게시물 주인으로 불러도 빈 배열이라 못 쓴다. 260921 에 kmin.kyeong 의 미미팜 좋아요 3건이 댓글 하트로 새어 나간 것을 이 방법으로 찾아 다시 눌렀다.
- **DM 공유는 `/api/v1/direct_v2/threads/<id>/` 의 `original_media_igid` 로 확인한다.** 받은 목록(inbox)의 items 는 두 건까지만 미리 보여 주므로 세기에 못 쓴다.
- 오래된 기억의 개설 전 정보보다 위 확정 핸들이 우선이다. 브랜드명은 MIMIPharm, 지도 등록명은 케이뷰티케어약국, 영업 종료는 다음 날 03:00이다. 이 배경만으로 준비된 캡션을 몰래 바꾸지 않는다.

## 막힘 처리

자격증명·CAPTCHA나 접근 불가능한 앱이 필요하면 정확한 항목과 필요한 사용자 조치를 알린다. 나머지 독립 작업은 끝낸다. 하나라도 남으면 전체 완료로 보고하지 않는다. 임의 DM 수신자, 새 결제, 계정 보안 변경은 업무에 포함하지 않는다.
