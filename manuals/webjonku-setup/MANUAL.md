# 웹쫀쿠 세팅

- **부르는 말**: 웹쫀쿠세팅해줘, 새 PC 웹쫀쿠 설치, 웹쫀쿠 세팅
- **미리 허가**: 지정 PC의 설치·설정·검증과 비공개 패키지 안의 기존 키 재사용. 로그인·2단계 인증·새 연결의 권한 승인은 사용자가 한다. 사용량 리셋은 포함하지 않는다
- **런너**: codex
- **제어층**: L1 설치·검사 → 필요할 때 L2 또는 L3에서 연결 확인
- **한 번에 걸리는 시간**: 설치·검사 약 30~60분. 사용자 인증 대기 시간은 별도

## 무엇을 만드는 업무인가

이 매뉴얼은 비공개 설치 패키지를 찾는 공개 안내문이다. 전체 절차와 실행 명령의 원본은
에이전트 폴더 아래 `웹쫀쿠 세팅/시작.md`와 `웹쫀쿠 세팅/references/설치절차.md`다.
패키지의 `scripts/`, `references/`, `private/`를 공개 저장소나 사이트에 복사하지 않는다.

## 준비물

- Windows x64 PC, Codex와 사용할 ChatGPT 계정, 동기화가 끝난 비공개 패키지.
- Python 3.11 이상, Node.js 20 이상, Git, ripgrep. 기존 설치를 먼저 찾고 없는 것만 원본 절차대로 준비한다.
- 해당 PC에서 패키지와 로컬 설치 폴더를 읽고 쓸 권한. 필요한 서비스 로그인과 2단계 인증은 사용자가 직접 처리한다.

## 절차

1. **패키지 위치 확인 (L1).** 현재 PC의 동기화된 에이전트 폴더를 찾고 그 아래 상대경로
   `웹쫀쿠 세팅/`을 사용한다. 관제탑이 있으면 `<OPS>/machine.json`의 `drive_root`를
   기준으로 `에이전트/웹쫀쿠 세팅/`을 찾는다. 드라이브 문자와 사용자 홈을 고정하지 않는다.
   원본 문서가 없거나 동기화되지 않았으면 경로·동기화 문제를 보고하고 임의의 설치 절차를 만들지 않는다.
2. **원본 읽기 (L1).** 패키지의 `시작.md`, `references/설치절차.md`를 순서대로 끝까지 읽는다.
   이 공개 안내와 버전별 상세 명령이 다르면 패키지 원본을 확인한다. 키·계정 정보는 공개 안내에 옮기지 않는다.
3. **설치와 연결 (L1 → 필요할 때 L2/L3).** 원본의 사전 검사·설치·복원 순서를 따른다.
   사용자가 승인한 기존 키는 `private/`에서 원본 스크립트가 필요한 위치로 복원하게 한다.
   값을 화면·채팅·로그·공개 파일에 출력하지 않는다. 기기마다 별도 터널을 준비하며 다른 PC의
   연결 ID나 실행 중인 세션을 복제하지 않는다. 새 권한이 필요하면 범위를 설명하고 사용자 승인을 받는다.
4. **실제 검증 (L1 → 필요할 때 L2/L3).** 설치한 PC에서 로컬 회귀 테스트, 웹 모델의 실제 파일 작업과
   이미지 검사, 외부 MCP의 검색·읽기, 설치된 외부 플러그인의 읽기 전용 호출을 원본대로 실행한다.
   MCP는 모델이 외부 도구를 호출하는 연결 방식이다. 응답에 도구 이름이나 성공 문구가 있는 것만으로 통과시키지 않는다.
5. **결과 기록 (L1).** 원본이 지정한 비공개 결과 위치에 검사별 통과·실패·건너뜀과 근거를 남긴다.
   공개 보고에는 비밀값, 연결 ID, 기기별 절대경로, 계정 정보를 넣지 않는다.

## 완료 검사

- [ ] 패키지 원본이 지정한 설치·복원 단계가 끝났고 새 PC의 실행 파일과 연결을 확인했다.
- [ ] 실제 검사 결과와 실패·건너뜀 사유를 기록했다. 제작 PC의 결과를 새 PC의 증거로 재사용하지 않았다.
- [ ] 필수 검사가 모두 통과한 경우만 전체 완료로 보고했다. 외부 연결이 미통과면 기본 사용 가능 여부와 외부 연결 미완료를 나눠 보고했다.

## 알려진 함정

- 제작 시 웹 모델의 외부 MCP 검색 검사는 차단되어 미통과였다. 새 PC에서도 실제 호출로 다시 판정한다.
  자동 안전 검사 차단, 도구 미노출, 인증 실패를 구분하고 같은 차단을 우회하거나 반복하지 않는다.
- Windows 심볼릭 링크 권한 때문에 검사가 건너뛰어질 수 있다. 건너뜀을 통과로 세지 않는다.
- 키 재사용 승인은 로그인·2단계 인증·새 연결 권한 승인까지 대신할 수 있다는 뜻이 아니다.
- 사용량 리셋 크레딧은 사용하지 않는다. 별도의 새 사용자 지시가 그 시점의 단일 리셋을 명시한 경우에만 처리한다.
