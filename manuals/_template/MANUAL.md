- **미리 허가**: 이 업무가 밖으로 하는 행동을 사람 말로. 업로드, 게시, 시트 쓰기, 주문, 배포 같은 것.
  밖으로 나가는 게 없으면 `없음. 무엇만 만든다` 로 적는다. 사이트와 드라이브 표의 호출문이 이 줄을 쓴다
- **런너**: claude | codex | either
- **제어층**: L1 → L3 처럼 사다리로. 주로 쓰는 층
- **한 번에 걸리는 시간**: 대략 몇 분

## 무엇을 만드는 업무인가

한두 문장. 끝났을 때 **무엇이 어디에 생겨 있어야 하는지**를 먼저 적는다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차·후속 작업·완료 검사를 한 번에 실행한다.
중간 산출물만 남기고 멈추거나 게시·전송·주문 버튼을 사람에게 넘기지 않는다. 매뉴얼에
명시된 외부 행동은 호출에 포함된 승인으로 본다. 매뉴얼 밖의 대상, 비밀번호·CAPTCHA,
매뉴얼 밖 결제, 되살릴 수 없는 삭제만 사람에게 묻는다.

## 준비물

시작 전에 있어야 하는 것. 없으면 `block` 으로 적고 사람에게 물어야 하는 것.

- 로그인 상태가 필요한 계정
- 입력 파일이나 값
- 사람이 미리 정해줘야 하는 것 (금액, 날짜, 대상)

## 절차

1. **(무엇을) (L1)**
   실제로 칠 명령이나 열 파일. 성공했는지 확인하는 법을 같이 적는다.

2. **(무엇을) (L1 로 시도, 막히면 L3)**
   왜 막히는지 한 줄. 어떤 화면에서 무슨 요소를 찾는지.
   **좌표를 적지 마라.** "왼쪽 위 3번째 메뉴" 도 배율 바뀌면 틀린다.
   "상품관리 → 상품 목록 링크" 처럼 이름으로 적는다.

3. **(무엇을) (L3)**
   `이게 보이면 성공` 을 반드시 적는다. 안 적으면 실패를 성공으로 착각한다.

## 산출물

어디에 무엇이 남는지. 경로는 `<OPS>/work/<taskId>/` 나 프로젝트 폴더 기준 상대경로로.

## 완료 검사

사람이 눈으로 볼 것과 기계가 볼 것을 나눠 적는다.
기계 검사는 이 폴더의 `checks.mjs` 에 넣으면 `done` 이 자동으로 돌린다.

- [ ] (기계) 파일이 생겼는지, 개수가 맞는지, 빌드가 통과하는지
- [ ] (사람) 눈으로 봐야 아는 것. 글이 어색하지 않은지, 이미지가 잘리지 않았는지

## 알려진 함정

이 업무를 하다 실제로 깨진 것들. **매뉴얼 값어치의 절반이 여기서 나온다.**
한 줄씩, 겪은 그대로 적는다.

- (증상) → (원인) → (그래서 이렇게 한다)

## 사람에게 물어야 하는 지점

매뉴얼 밖의 되돌릴 수 없는 단계나, 매뉴얼에 없는 값을 새로 정해야 하는 단계만 적는다.
매뉴얼에 명시한 게시·전송·주문·저장은 다시 묻지 않는다.

- 매뉴얼 밖의 보내기 / 게시 / 결제 / 삭제
- 금액이나 날짜를 매뉴얼에 없는 값으로 정해야 할 때
