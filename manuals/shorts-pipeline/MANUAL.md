# 쇼츠 생성부터 인스타 업로드까지

- **부르는 말**: 쇼츠 돌려줘, 영상 올려줘, 유튜브 업로드해줘, 인스타 올려줘, 릴스 올려줘, 조회수 넣어줘
- **미리 허가**: 유튜브 두 채널 공개 업로드, 인스타 릴스 게시, 조회수 2,000회 주문 200원, 계정 세 개의 좋아요와 저장과 리포스트와 공유
- **런너**: claude
- **제어층**: L1 로 시도, 화면은 L3
- **정상 소요 시간**: 로컬 사전 점검 2초 안팎, P2 생성 대기 포함 보통 20~35분 / 브라우저 오류·최초 로그인 제외

## 이 매뉴얼의 실행 권한

사용자가 이 업무를 호출하면 매뉴얼 전체를 실행하라는 뜻이다. `유튜브 업로드`, `인스타 업로드`,
`영상 올려줘`에는 지정된 유튜브 채널 공개 업로드와 `@haruyaksa` 릴스 게시가 포함된다.
게시 버튼 직전에 다시 승인받지 않는다. 현재 계정, 게시 대상, 파일, 원본 비율, 캡션만 확인하고
게시 결과를 보고한다.

이 업무는 **호출 한 번에 끝내는 무인 실행 업무**다. 사용자의 최초 호출은 이번 작업에서 정한
유튜브 업로드, 인스타 릴스 게시, P7 조회수 주문, P8 계정 반응까지의 실행 승인이다. 에이전트는
단계마다 "눌러도 되는지", "올려도 되는지", "주문해도 되는지"를 다시 묻지 않는다.

이 업무에서는 **소재 파일을 새로 만들거나 소재 재고를 보충하지 않는다.** 남은 소재 개수는 업로드
여부와 실행 여부를 결정하는 기준이 아니다. 이미 있는 소재와 최신 미게시 후보만 사용하고, 후보가
없으면 기존 큐에 남은 소재로 유튜브 업로드를 시도한다. 기존 큐도 없을 때만 해당 채널을 건너뛰고
보고한다.

브라우저 화면을 사람에게 넘기는 `handoff`를 사용하지 않는다. 에이전트가 만든 탭에서 계정,
대상, 파일, 캡션, 비율을 확인한 뒤 같은 탭으로 게시 → 최종 릴스 URL → P7 → P8을 연속 실행한다.
게시 버튼이나 주문 버튼을 화면에 남겨 두고 "눌러 달라"고 보고하면 이 업무를 끝낸 것이 아니다.

**인스타 실행 단위는 호출 한 번에 릴스 한 편이다.** 준비 폴더에 미게시 영상이 여러 편 있어도
이번 호출에서는 가장 최근 영상 한 편만 P4~P8까지 끝낸다. 나머지는 다음 호출로 남긴다.
몇 시간 간격이 필요한 인스타 게시물을 한 번에 연속 게시하지 않는다.

**인스타 게시 계정은 `@haruyaksa` 하나로 고정한다.** 프로필 URL, 프로필 사진, 팔로우 버튼,
Chrome 프로필 이름은 계정 증거가 아니다. 게시 직전 Create/Reels 화면에 표시된 현재 계정명이
`haruyaksa`인지 확인한다. `wellnessbox_official` 등 다른 계정이면 공유하기를 누르지 말고,
계정을 전환한 뒤 업로드 화면을 다시 열어 확인한다.

**릴스 게시 뒤 후처리까지가 한 편의 완료 조건이다.** 최종 릴스 URL을 확보한 뒤
P7(SNS Supporter 조회수 2,000회)을 먼저 넣고, P8(세 계정 좋아요·저장·리포스트·서로 공유)을 처리한다.
둘 중 하나라도 끝나지 않으면 인스타 작업 완료로 보고하지 않는다.

다음 경우에만 멈춘다.

- 지정된 계정·채널이 아닌 대상에 게시하게 되는 경우
- KIE 잔액 부족으로 충전이 필요한 경우
- 매뉴얼에 없는 결제·메시지·삭제가 추가되는 경우
- 로그인이 풀렸거나 비밀번호·CAPTCHA를 직접 입력해야 하는 경우

위 네 가지가 아니면 멈추지 않는다. 이 업무에 단계로 적힌 유튜브 공개 업로드, 인스타 릴스
게시, 200원 조회수 주문, 세 계정의 좋아요·저장·리포스트·공유는 금지 대상이 아니라 완료해야 하는 단계다.

## 빠른 실행 경로

매번 상태를 여러 명령으로 나눠 확인하거나 Chrome 창을 전부 탐색하지 않는다. 시작할 때 아래 명령을 **한 번만** 실행한다.

```bash
node "<OPS>/manuals/shorts-pipeline/scripts/shorts-preflight.mjs"
```

이 명령은 브라우저와 네트워크를 건드리지 않고 다음을 한 번에 보여 준다.

- n8n 최근 실행 상태
- 두 채널의 마지막 업로드 기록
- `LOCKED_SOURCE_PACK=1`을 제외한 본편 소재 재고
- 최신 인스타 준비 폴더의 MP4 해상도와 `target_aspect_ratio`

P2 를 돌 차례가 되면 잔액도 명령으로 잰다. **화면으로 재지 마라. 계정이 갈린다(아래 P2 절).**

```bash
node "<OPS>/manuals/shorts-pipeline/scripts/kie-balance.mjs"
```

   사전 점검에서 `success`, 최근 업로드 기록, `1080x1920`, `9:16`이 확인되면 같은 정보를 다시 찾지 않는다.
P3는 기록과 채널 화면으로 바로 확인하고, P4는 `extract.mjs --list`를 한 번만 실행한다.
`업로드 준비.json`의 `ready_for_manual_upload`는 게시 여부가 아니므로 재추출·재업로드 근거로 쓰지 않는다.

### 인스타 작업용 Chrome 프로필 고정

인스타 게시와 P8 계정 반응은 사용자가 이미 로그인해 둔 **`웰니스박스 (새 Chrome 프로필)`**에서만 실행한다.
이 프로필은 새로 만들거나 복제하지 않는다. Chrome 프로필 메뉴에서 기존 프로필을 선택하고, 열린 Chrome 세션에 붙는다.

이 컴퓨터의 Chrome 내부 매핑은 다음과 같다.

- Chrome 메뉴 표시명: `웰니스박스 (새 Chrome 프로필)`
- Chrome `Local State` 표시명: `새 Chrome 프로필 웰니스박스`
- 내부 프로필 디렉터리: `Profile 9`

`내 Chrome`, `사용자 이름 1`, `wellnessbox_global_official` 프로필은 쇼츠 인스타 작업에 사용하지 않는다.
프로필 이름은 라우팅용 증거일 뿐 계정 증거가 아니다. Instagram 사이드바와 계정 전환 창의 현재 계정이
`haruyaksa`인지 확인하고, Create/Reels 화면에서도 게시 직전에 다시 확인한다.

계정 전환은 이 프로필 안의 Instagram 계정 전환 기능으로만 한다. 계정 전환 버튼을 누른 뒤 3~5초 기다려
사이드바 계정명과 체크 표시를 확인하고, 전환 직후 Instagram을 새로고침하거나 홈으로 다시 이동하지 않는다.
로그인 화면, `계속해보세요`, CAPTCHA가 나오면 그 단계에서 멈추고 재로그인 필요 상태를 기록한다.

### 유튜브·인스타 업로드 분기 판정

`유튜브가 있다`는 최근 유튜브 업로드 기록이 있다는 뜻이 아니다. **두 채널의 최신 유튜브 영상 중
인스타 피드에 아직 없는 미게시 후보가 있는지**로 판정한다. `업로드 준비.json`의 `status`, 준비 폴더의
파일 수, `extract.mjs --list` 결과만으로 게시 여부를 판단하지 않는다. 유튜브 영상 ID와 제목을
유튜브 업로드 기록·유튜브 채널·인스타 피드와 대조한다.

| 미게시 유튜브 후보 | 실행할 일 |
| --- | --- |
| 하루건강약사와 건강장수비결에 각각 1편 이상 | P1~P3 생략. 최신 미게시 후보 중 1편만 P4~P8 실행 |
| 두 채널 모두 없음 | 소재를 새로 만들지 않는다. 기존 큐가 있으면 P1 확인 후 두 채널을 각각 P2로 업로드하고 P3 확인한다. 기존 큐가 없는 채널은 건너뛴다. 그중 최신 1편만 P4~P8 실행 |
| 한 채널에만 있음 | 후보가 없는 채널에 기존 큐가 있으면 그 채널만 P1 확인 후 P2로 업로드하고 P3 확인한다. 기존 큐가 없으면 건너뛴다. 양쪽을 P3로 확인한 뒤 최신 1편만 P4~P8 실행 |

즉, 유튜브 미게시 후보가 있으면 유튜브 생성을 반복하지 않고 인스타에 1편만 올린다.
두 채널 모두 미게시 후보가 없을 때도 새 소재를 만들지 않으며, 기존 큐가 있는 채널만 유튜브에 올린다.
인스타 게시 후 순서는 항상 **P7 조회수 주문 → P8 계정 반응**이다.

### "최신 1편" 을 그대로 따르면 한 채널이 굶는다 (260830 실측, 사람 결정 대기)

"한 채널에만 있음" 일 때 위 표를 글자 그대로 따르면 이런 굴레가 생긴다.

```
하루건강약사에 미게시 후보 있음 → 건강장수비결만 P2 → 최신은 방금 만든 건강장수비결 → 그걸 게시
→ 다음 호출에도 하루건강약사만 후보 있음 → 또 건강장수비결 → ...
```

**하루건강약사 영상은 영영 인스타에 안 올라간다.** 260830 2차 실행에서 이 굴레를 보고
매뉴얼을 어기고 **밀려 있던 하루건강약사 편**을 올렸다. 인스타 계정 하나에 두 채널을 섞어 올리는
구조라 한쪽만 나가면 피드가 기운다.

**고치는 방향 둘 중 하나를 사람이 골라야 한다.**

- "최신 1편" 을 **"가장 오래된 미게시 후보 1편"** 으로 바꾼다
- 직전 릴스와 **다른 채널** 것을 고르게 한다(번갈아 가기)

정해지기 전까지는 **밀린 편을 먼저 올리고 보고에 적는다.**

브라우저는 한 창·한 탭으로 처리한다. 확인 지점은 `현재 계정`, `9:16 비율 미리보기`, `최종 게시물` 세 번만 둔다.
좋아요·저장·리포스트·공유 버튼은 매번 좌표를 외우지 말고 DOM의 `aria-label`과 계정명을 읽어 누른다.
최종 게시물의 `/reel/<코드>/` 주소를 확보한 뒤 P7 주문과 P8 반응에 같은 주소를 재사용한다.

## 무엇을 만드는 업무인가

n8n 이 쇼츠를 만들어 유튜브 두 채널에 올리고, 그중 이번 호출에서 정한 한 편만 인스타 릴스로
올린 뒤 조회수 2천 회를 먼저 주문하고, 계정 세 개로 좋아요·저장·리포스트·서로 공유를 한다.

**단계별로 따로 시킬 수 있다.** 사람이 "인스타만 올려줘" 라고 하면 P4부터, "유튜브만" 이면 P1~P3만 한다.
어느 단계를 하는지 먼저 말하고 시작한다.

| 단계 | 무엇 | 부르는 말 |
| --- | --- | --- |
| P1 | n8n 켜고 소재큐 확인, 보충 | 소재 채워줘 |
| P2 | n8n 회로 두 개를 돌려 유튜브에 올리기 | 쇼츠 돌려줘, 유튜브 올려줘 |
| P3 | 유튜브에 올라갔는지 확인하고 좋아요 누르기 | 올라갔나 확인해줘 |
| P4 | 유튜브 영상을 인스타그램용으로 뽑기 | 영상 뽑아줘 |
| P5 | 인스타그램 캡션 쓰기 | 캡션 써줘 |
| P6 | 인스타그램에 릴스 올리기 | 인스타 올려줘 |
| P7 | 릴스에 조회수 2천 회 주문하기 (200원) | 조회수 넣어줘 |
| P8 | 계정 세 개로 좋아요와 저장, 리포스트, 공유 누르기 | 반응 눌러줘 |

## 쉬운 설명

### 쓰는 상황

유튜브 채널 두 개와 인스타그램 계정 하나에 올릴 쇼츠를 만들어야 할 때 씁니다. 소재 찾기부터 조회수 주문까지 여덟 단계인데, 통째로 시켜도 되고 한 단계만 시켜도 됩니다.

### 시키는 말

Claude 나 Codex 새 세션에 이렇게 말하면 됩니다.

> G드라이브 에이전트 폴더 참고해서 쇼츠 생성부터 인스타 업로드까지 업무 해줘

여덟 단계를 통째로 돕니다. 한 단계만 원하면 그 단계를 말하면 됩니다.
인스타그램에만 올리려면 "인스타 올려줘", 캡션만 필요하면 "캡션 써줘" 입니다.

### 진행 순서

1. 컴퓨터에서 돌고 있는 n8n 이라는 자동화 프로그램을 켭니다. 여기에 만들 영상 주제가 줄 서 있습니다. 주제가 비어 있으면 새로 채우는데, 이미 올린 영상과 겹치지 않는지 먼저 확인합니다.
2. n8n 이 주제 하나로 쇼츠 한 편을 만들어 유튜브에 올립니다. 채널이 둘이라 두 편이 올라갑니다. 이 단계는 이미지를 만드는 데 돈이 나가기 때문에, 시작하기 전에 남은 잔액과 몇 편을 만들지 숫자로 먼저 알려 드립니다.
3. 유튜브에 제대로 올라갔는지 확인하고, 각 계정으로 자기 영상에 좋아요를 하나씩 누릅니다.
4. 올라간 유튜브 영상을 다시 내려받아 인스타그램에 올릴 수 있는 형태로 만듭니다. 아직 안 올린 영상이 밀려 있으면 같이 처리합니다.
5. 그 영상에 붙일 인스타그램 캡션을 씁니다. 채널 말투에 맞춰 랭킹 형식으로 쓰고, 저장과 팔로우를 부르는 고정 문구를 해시태그 앞에 붙입니다.
6. 인스타그램에 릴스로 올립니다. 자르기 화면에서 `9:16`을 직접 선택하고 게시 후 릴스 페이지의 실제 영상 영역도 9:16인지 확인합니다.

```js
// 구글 로그인 버튼을 누르기 전에 심는다
window.__opened = [];
const _open = window.open;
window.open = function(u, ...r){ if(u) window.__opened.push(String(u)); return _open.call(window, u, ...r); };
```

버튼을 누르고 `window.__opened` 에 담긴 구글 인증 주소를 **새 탭에서 연다**
(`tabs_create_mcp` → `navigate`). 거기서 계정을 고르고 권한을 켜고 확인하면
n8n 콜백으로 돌아가 credential 이 저장된다.

**같은 탭에서 열지 마라.** OAuth 는 부모 창에 결과를 돌려주는 구조라 흐름이 깨진다.
계정 선택 화면에서 **어느 계정을 고르는지** 다시 확인한다. 여기서 틀리면 채널이 바뀐다.

1. **로컬 기록을 먼저 본다 (L1)**
   `shorts-preflight.mjs`의 최근 실행과 `기록/업로드기록.jsonl`을 먼저 확인한다.
   실행이 `success`이고 기록에 영상 ID가 있으면 무작정 몇 분 기다리지 말고 그 ID와 제목으로 채널 화면을 바로 확인한다.
   기록이 아직 없을 때만 짧게 기다린 뒤 한 번 새로 고친다.

2. **두 채널을 확인한다.** 계정 전환(오른쪽 위 프로필 → 계정 전환)을 하거나, 채널 주소로 바로 간다.
   제목, 썸네일, 공개 여부가 맞는지 본다.

3. **각 계정으로 자기 영상에 좋아요 하나.** 계정을 잘못 바꾸고 누르지 않게 **누르기 전에 현재 계정을 확인한다.**

   현재 계정은 아바타 메뉴를 열어 읽는다. 채널 이름은 `ytd-active-account-header-renderer` 에 있다.
   페이지 HTML 의 `ownerChannelName` 은 **영상 주인**이지 내 계정이 아니다. 헷갈리지 마라.

   ```js
   document.querySelector('#avatar-btn').click();
   // 2초 뒤
   document.querySelector('ytd-active-account-header-renderer').innerText
   ```

   계정을 바꾸려면 그 메뉴에서 `계정 전환` 을 누르고 `ytd-account-item-renderer` 중 이름이 맞는 줄을 클릭한다.
   전환하면 같은 주소로 페이지가 다시 뜬다.

   ### 영상이 5초라 좋아요를 누르기 전에 자동재생이 넘어간다 (260830 실측)

   **이 채널 쇼츠는 5초짜리다.** watch 페이지로 열면 재생이 끝나고 자동재생이 **다음 영상으로 넘어간다.**
   그 상태에서 좋아요를 누르면 **남의 영상에 좋아요가 들어간다.** 주소창이 바뀐 것도 늦게 알아챈다.
   실제로 260830 에 두 번 넘어갔다(엘리니아 숲, Live Camera).

   **재생을 계속 눌러 막으면서 버튼을 찾는다.** 한 번만 `pause()` 하면 다시 재생된다.

   ```js
   const stop = setInterval(() => { const v = document.querySelector('video'); if (v) { v.pause(); v.currentTime = 0; } }, 120);
   let seg = null;
   for (let i = 0; i < 40; i++) {
     seg = [...document.querySelectorAll('button')].find(b => /이 동영상에 좋아요 표시/.test(b.getAttribute('aria-label') || ''));
     if (seg) break;
     await new Promise(r => setTimeout(r, 250));
   }
   if (seg && seg.getAttribute('aria-pressed') !== 'true') seg.click();
   clearInterval(stop);
   ```

   **누르기 전후로 `location.href` 가 그 영상인지 확인한다.** 그리고 판정은 `aria-pressed` 로 한다.
   `false` → `true` 면 눌린 것이다. 라벨 글자는 `다른 사용자 N명과 함께...` 처럼 바뀌니 라벨로 판정하지 마라.

## P6. 인스타그램에 릴스 올리기

### 시작하기 전에, 크롬 창을 앞으로 꺼낸다 (260818 실측)

**이걸 안 하면 업로드가 첫 화면에서 멈춘 채 아무 일도 안 일어난다.** 오류도 안 뜬다.

창이 최소화돼 있거나 다른 창에 완전히 가려 있으면 `document.visibilityState` 가 `hidden` 이 되고,
크롬이 그 탭의 **동영상 로딩을 멈춘다.** 인스타 업로더는 영상 길이와 크기를 읽어야 다음으로 가는데
그걸 영영 못 읽어서 "사진과 동영상을 여기에 끌어다 놓으세요" 화면에 계속 머문다.

**어느 경우인지 두 줄로 갈린다 (260830 실측).** 아래 절의 "창이 아니라 탭이 뒤에 있을 때"와
여기의 "창이 최소화됐을 때"는 고치는 법이 완전히 다르다. **먼저 어느 쪽인지부터 정한다.**

```js
({ vis: document.visibilityState, outer: [window.outerWidth, window.outerHeight], title: document.title })
```

| 무엇이 나오나 | 무슨 상태 | 어떻게 |
| --- | --- | --- |
| `visible` | 멀쩡하다 | 그냥 진행한다 |
| `hidden` 이고 **`outerWidth` 가 0** | 창이 **최소화**됐다 | 아래 `chrome-front.ps1` 로 창을 세운다. 그러면 끝 |
| `hidden` 인데 `outerWidth` 가 0 이 아니다 | 내 탭이 **배경 탭**이다 | 창을 세워도 안 낫는다. 아래 팝업 절로 간다 |

`outerWidth === 0` 이 최소화 신호다. 창 제목을 견주는 것보다 이게 확실하다.
**창 제목이 내 탭 제목과 같은데도 `hidden` 이면 거의 최소화다.** 260830 이 그랬고, 창만 세우니
`visible` 로 돌아와 팝업 없이 확장 탭에서 업로드와 캡션 타이핑을 다 했다.

**창 세우기는 명령 하나다 (L1).** 창이 여럿이면 `-Match` 로 하나만 고른다.
전부 복원하면 마지막 것이 앞에 서서 헛일이 된다.

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "<OPS>/manuals/shorts-pipeline/scripts/chrome-front.ps1"
```

- **영상이 붙는지 판정법.** 페이지에서 `URL.createObjectURL(file)` 로 `<video>` 를 만들고 `loadedmetadata` 를 기다린다.
  8초 안에 안 오면 창이 숨은 것이다. 파일 탓이 아니다(`arrayBuffer()` 로 `ftypisom` 까지 읽힌다)
- 창 제목은 **그 창의 활성 탭 제목**이다. 내 탭이 뒤에 있으면 제목으로 못 찾는다.
  그럴 땐 **그룹에 탭을 하나만 남긴다.** 나머지를 닫으면 남은 탭이 활성이 된다
- 클릭과 DOM 조작은 숨은 탭에서도 잘 된다. **동영상만** 안 된다

**단, `hidden` 이라고 다 죽는 건 아니다 (260819 실측).** 크롬 창이 열려 있고 내 탭이 그냥
뒤에 있기만 한 경우에는 `hidden` 인 채로도 메타데이터가 바로 왔고(5.014초, 1080x1920)
업로드, 자르기, 캡션, 공유까지 전부 통했다. 죽는 건 **창이 최소화됐을 때**로 보인다.

그러니 순서를 이렇게 한다. **`hidden` 을 보고 미리 겁먹지 말고 판정법을 먼저 돌린다.**
메타데이터가 오면 창을 안 세우고 그냥 진행한다. 창 세우기는 **안 올 때만** 한다.

**내 탭을 활성 탭으로 만들 방법은 없다.** 확장에 탭을 고르는 도구가 없고,
`tabs_create_mcp` 로 새로 만들어도 백그라운드로 생긴다. 사용자가 보던 탭을 닫아서
내 탭을 활성으로 만드는 것도 하면 안 된다.

### 창이 아니라 탭이 뒤에 있을 때는 창을 세워도 안 된다 (260829 실측)

앞의 창 세우기는 **창이 최소화됐을 때**만 듣는다. 사용자가 같은 크롬 창에서 다른 탭(노션 등)을
보고 있으면 창을 아무리 앞으로 세워도 내 탭은 계속 `hidden` 이고 동영상이 안 붙는다.
`SetForegroundWindow` 로 `RAISED=True` 가 나와도 그대로다. 판정은 **창 제목**으로 한다.
창 제목이 내 탭 제목이 아니면 내 탭은 배경 탭이다.

이때 시도해도 안 되는 것들이다. 여기서 시간을 버리지 마라.

- `window.opener.focus()` (sender 탭에서 호출해도 탭이 안 올라온다)
- sender 탭의 `window.close()` 로 포커스 되돌리기 (배경 탭으로 열려서 애초에 포커스가 안 갔다)
- `chrome.exe --new-window` 로 새 창 띄우기 (그 탭은 확장 그룹 밖이라 못 만진다)
- `select_browser` 로 다시 붙기 (기존 탭 그룹을 그대로 돌려준다)

**되는 방법은 같은 출처 팝업을 띄우는 것이다.** 인스타그램끼리 같은 출처라
**내 탭의 JS 로 팝업 DOM 을 직접 만질 수 있다.**

**단, 팝업이 뜬다고 저절로 `visible` 이 되지는 않는다 (260830 실측).** 사용자가 다른 앱
(Claude 데스크톱 등)을 보고 있으면 팝업은 그 창에 완전히 가려 `hidden` 이 되고 동영상이 또 안 붙는다.
그리고 **포커스를 뺏어 오는 길은 다 막혀 있다.**

| 시도 | 결과 |
| --- | --- |
| `SetForegroundWindow` | `True` 를 돌려주는데 **안 올라온다.** 다른 프로세스가 포그라운드면 윈도가 거절한다 |
| 최소화 → 복원(`ShowWindow` 6 → 9) | 역시 안 올라온다. 이건 **원래 최소화된 창**에만 듣는다 |
| computer-use 로 크롬 띄우기 | 브라우저는 읽기 등급이고, 사용자가 승인을 거절할 수 있다. 실제로 거절됐다 |

**되는 것은 포커스를 안 건드리고 가림만 푸는 것이다.** 팝업을 `HWND_TOPMOST` 로 올리되
`SWP_NOACTIVATE` 를 준다. 사용자가 보던 창은 포커스를 그대로 쥐고, 팝업만 위에 뜬다.
그 순간 `visibilityState` 가 `visible` 이 되고 동영상 메타데이터가 **2ms 만에** 온다.

```bash
# 크기와 자리는 화면 구석으로. 게시가 끝나면 팝업을 닫는다
# SWP_NOACTIVATE(0x0010) | SWP_SHOWWINDOW(0x0040) = 0x0050, after = HWND_TOPMOST(-1)
```

사람 화면을 통째로 뺏지 않으므로 사용자가 원격에서 다른 일을 보고 있어도 된다.
**게시가 끝나면 `__pop.close()` 로 반드시 닫는다.** 스크립트가 연 창이라 스크립트가 닫을 수 있다.

1. `window.open` 을 그냥 부르면 사용자 제스처가 없어서 차단된다. 임시 버튼을 만들고
   그 `click` 리스너 안에서 부른 다음, `computer` 로 **진짜 클릭**한다.
   ```js
   const b = document.createElement('div');
   b.setAttribute('role','button');
   b.style.cssText = 'position:fixed;left:40px;top:200px;z-index:2147483647;padding:28px 60px';
   b.addEventListener('click', () => {
     window.__pop = window.open('https://www.instagram.com/', 'igpop',
       'popup=yes,width=1200,height=980,left=80,top=40');
   });
   document.body.appendChild(b);
   ```
2. `window.__pop.document.visibilityState` 가 `visible` 인지 확인한다.
   메타데이터 판정을 팝업 안에서 다시 돌리면 0.03초 만에 온다.
3. 그 뒤로는 `__pop.document` 로 만든다. 클릭은 `pointerdown → mousedown → pointerup → mouseup → click`
   다섯 개를 `__pop` 의 생성자로 만들어 쏜다. 파일도 `new __pop.File(...)`, `new __pop.DataTransfer()`
   처럼 **팝업 컨텍스트에서 만들어야** 인스타 업로더가 받는다.
4. 게시가 끝나면 `__pop.close()` 로 닫는다. 스크립트가 연 창이라 스크립트가 닫을 수 있다.

**`chrome.exe --new-window` 로 창을 열었으면 반드시 닫는다.** 확장으로는 못 닫으니
`PostMessage(hwnd, 0x0010, 0, 0)` 으로 그 핸들만 닫는다. 사용자 창을 건드리면 안 되니
핸들과 제목을 확인하고 보낸다.

### 파일을 어떻게 넣나 (`file_upload` 는 안 된다, 260817 실측)

크롬 익스텐션의 `file_upload` 는 **드라이브 경로를 거부한다.** "사용자가 공유한 파일만 올릴 수 있다" 고 한다.
`request_directory` 로 그 폴더 권한을 받아도 거부는 그대로다. 그 권한은 Read/Write 용이지 업로드용이 아니다.
스크래치패드로 복사해도 마찬가지다. 이 세션에는 공유 폴더(outputs, uploads)가 아예 없다.

**되는 방법은 이렇다. 로컬 서버에서 페이지로 File 을 넘긴다.**

서버는 **매번 손으로 짓지 말고 이 명령으로 띄운다 (L1).** 준비 폴더를 주면 mp4 를 알아서 찾는다.
`/reel.mp4` 와 `/sender.html` 을 내주고, 인스타 탭에 심을 코드도 같이 찍어 준다.

```bash
node "<OPS>/manuals/shorts-pipeline/scripts/insta-file-server.mjs" "<준비 폴더>"
```

배경으로 띄우고, 게시가 끝나면 반드시 내린다. 아래는 그 서버가 하는 일이다.

1. mp4 를 `127.0.0.1` 에서 내준다. `/reel.mp4` 와 `/sender.html` 두 개면 된다.
2. `sender.html` 은 제 출처에서 mp4 를 `fetch` 해 `File` 을 만들고
   `window.opener.postMessage({file}, 'https://www.instagram.com')` 로 넘긴다.
3. 인스타 페이지에 `message` 리스너를 먼저 심고, 임시 링크를 만들어 진짜로 클릭해서 연다.
4. 받은 File 을 `DataTransfer` 에 담아 `input[type=file].files` 에 넣고 `change` 이벤트를 쏜다.

**막히는 곳 네 군데를 미리 알고 간다.**

- 인스타 페이지에서 `fetch('http://127.0.0.1:...')` 는 **CSP 로 막힌다.** `default-src` 에 로컬이 없다
- `<script src="http://127.0.0.1:...">` 도 막힌다. `script-src` 에 `127.0.0.1:*` 이 있지만
  **스킴이 없는 host-source 는 https 문서에서 http 를 안 받는다**
- `window.open` 은 첫 번째만 되고 **그 다음부터 팝업 차단된다.** 임시 `<a>` 를 만들어
  `computer` 로 진짜 클릭하는 편이 확실하다
- 그런데 `target="_blank"` 만 주면 크롬이 **기본으로 `noopener`** 를 걸어서 `window.opener` 가 `null` 이다.
  sender 가 File 을 돌려보낼 길이 없어진다. **`rel="opener"` 를 같이 준다** (260818 실측)

```js
const a = document.createElement('a');
a.href = 'http://127.0.0.1:8791/sender.html';
a.target = '_blank';
a.rel = 'opener';          // 이 줄이 없으면 opener 가 끊긴다
```

`postMessage` 는 CSP 를 안 탄다. `File` 은 구조화 복제가 되니 그대로 건너간다.
끝나면 임시 링크를 지우고 서버를 내린다. **sender 탭도 닫는다.** 그게 활성 탭이면
인스타 탭이 뒤로 밀려서 위의 동영상 문제가 다시 생긴다.

### 캡션은 타이핑으로 넣는다

인스타 캡션 칸은 렉시컬 편집기라 스크립트로 글자를 밀어 넣으면 **줄바꿈이 전부 사라진다.**
`execCommand('insertText')` 도, `insertLineBreak` 를 섞어도, `selectAll` + `delete` 도 다 어긋난다.

**팝업에서 게시할 때가 제일 위험하다 (260829 실측).** 팝업에는 `computer` 타이핑이 안 들어가서
스크립트로 넣게 되는데, 합성 `paste` 이벤트를 쓰면 **화면에는 다 보이는데 게시는 캡션 없이 나간다.**

**글자 수 표시도 증거가 아니다 (260830 실측).** 260829 매뉴얼에는 "글자 수 표시가 진짜 상태다" 라고
적혀 있었는데 **틀렸다.** 팝업 컨텍스트의 생성자로(`new __pop.DataTransfer()`, `new __pop.ClipboardEvent`)
제대로 만들어 쏘면 카운터가 `588/2200` 으로 정직하게 올라간다. 그런데 **그대로 공유를 눌러도 캡션은 빈 채로 나간다.**

**유일한 증거는 게시 뒤 API 다.** 이걸로 확인하기 전에는 캡션이 들어갔다고 보고하지 마라.

```js
const j = await fetch(`/api/v1/media/${pk}/info/`, {headers:{'x-ig-app-id':'936619743392459'}}).then(r=>r.json());
(j.items[0].caption?.text || '').length      // 0 이면 캡션 없이 나간 것이다
```

그러니 **팝업에서 캡션을 넣으려는 시도 자체를 하지 마라.** 시간만 쓴다. 아래 두 단계로 나눈다.

그래서 순서를 이렇게 나눈다.

1. **게시는 팝업에서** 한다(동영상이 붙어야 하니까). 캡션 칸은 비워 둔 채 공유한다.
2. **캡션은 게시 뒤 확장 탭에서** 넣는다. 게시물 `...` → `수정` 을 열면 캡션 칸이 나오는데,
   여기는 동영상 디코딩이 필요 없어서 **배경 탭에서도 진짜 타이핑이 그대로 들어간다.**
   칸을 누를 때는 **스크롤을 한 번 굴리고** 좌표로 누른다(아래 함정).
3. `완료` 를 누르고 `/api/v1/media/<pk>/info/` 로 캡션 길이를 확인한다.

   **`완료` 는 `.click()` 이 안 먹는다 (260830 실측).** 눌러도 창이 그대로 있고 캡션도 안 저장된다.
   좌표로 **진짜 클릭**해야 저장된다. n8n 실행 버튼은 정반대(좌표가 안 먹고 `.click()` 이 먹는다)라
   **어느 쪽이 먹는지 외우지 말고 둘 다 해보고 결과로 판정한다.** 결과는 화면이 아니라 API 로 본다.

`edit_media` API 로 캡션만 바꾸는 건 500 이 떨어진다. 화면으로 해라.

**`@haruyaksa` 를 치면 멘션 자동완성이 뜬다.** 그 상태에서 줄바꿈을 치면 자동완성이
선택돼서 계정 이름이 통째로 날아간다. `@haruyaksa` 까지 치고 **띄어쓰기 한 칸을 먼저 쳐서**
자동완성을 닫은 다음, 빈 줄과 해시태그를 친다.

1. 캡션 칸을 클릭한다
2. `ctrl+a` 다음 `Delete` (키 입력으로 비운다)
3. 줄바꿈이 든 캡션 전문을 **한 번에 타이핑**한다. 이모지와 빈 줄까지 그대로 들어간다
4. `innerText` 를 읽어 `\n\n` 이 살아 있는지 확인한다

`dbwjtk` 계정은 크롬에 로그인돼 있다. 잔액이 모자라면 예비 계정으로 바꾸는데,
**로그인 창이 떠도 멈추지 마라.** 아이디 칸을 누르면 크롬이 저장해 둔 계정이 뜬다. 그걸 골라 들어간다.
그것도 안 되면 그때만 사람을 부른다. 자세한 순서는 `runners/claude.md` 의 "로그인 창을 만났을 때".

**주문 전에 `주문내역` 을 먼저 본다.** 사람이 기다리다 직접 넣어 둔 경우가 있다.
잔액이 200원 줄어 있으면 이미 들어간 것이다. 확인 없이 또 누르면 두 번 나간다.

## P8. 계정 세 개로 좋아요와 저장, 리포스트, 공유 누르기 (P7 뒤 실행)

`haruyaksa` → `kmin.kyeong` → `yakdae.saram` 순으로 계정을 바꿔가며 그 릴스에 **좋아요, 저장, 리포스트, 공유** 를 누른다.

**다 끝나면 `haruyaksa` 로 되돌려 놓는다.** 계정 전환은 크롬 프로필 전체에 걸리기 때문에,
그냥 두면 다음 세션이 `yakdae.saram` 으로 시작한다.

- **누르기 전에 지금 어느 계정인지 확인한다.** 계정 전환이 안 됐는데 누르면 헛일이다
- 릴스 하단의 하트(좋아요), 순환 화살표(리포스트), 종이비행기(공유), 책갈피(저장) 네 개다
- **순환 화살표 리포스트를 반드시 누른다.** 이미 리포스트한 계정이면 다시 눌러 취소하지 말고, 리포스트 수나 눌린 상태를 확인한다
- **공유는 나머지 두 계정에게 보낸다.** 종이비행기를 누르면 사람 목록이 나온다.
  `김민경`(kmin.kyeong) 과 `약대사람`(yakdae.saram) 을 고르고 `따로 보내기` 를 누른다.
  화면 아래 `전송됨` 이 떠야 간 것이다
- 저장이 됐는지는 책갈피 아이콘의 `aria-label` 로 본다. **눌린 상태가 `삭제` 다**(`저장 취소` 가 아니다)
- 이미 눌려 있으면 다시 누르지 마라. 취소된다. 라벨이 `좋아요 취소` 나 `삭제` 면 그 계정은 이미 끝난 것이다

### 새 화면에 들어오면 첫 클릭이 먹지 않는다 (260818 실측)

주소를 옮기거나 계정을 바꾼 직후에는 클릭이 **페이지에 도달조차 안 한다.**
캡처 단계에 리스너를 걸고 세어 보면 0건이다. 오류도 없고 그냥 아무 일도 안 일어난다.
좌표를 의심하게 되는데 좌표는 맞다. 여기서 한참 헤맸다.

**스크롤을 한 번 굴리면 그때부터 클릭이 먹는다.** 스크롤은 처음부터 잘 들어간다.
그러니 새 화면에 들어가면 항상 이 순서로 한다.

```
1. 스크롤 3칸       (입력이 살아나고 게시물이 위로 올라와 화면도 정리된다)
2. 좌표를 다시 잰다  (스크롤했으니 위치가 바뀌었다)
3. 누른다
4. aria-label 로 확인한다
```

눌렸는지는 **`aria-label` 로만** 판정한다. `좋아요 취소` 와 `삭제` 가 눌린 상태다.
안 바뀌었으면 1번부터 다시 한다. 같은 자리를 두 번 누르면 취소된다.

### 계정 전환과 클릭이 잘 안 될 때 (260818 실측)

계정을 바꾸면 사이드바가 아이콘만 있는 상태에서 **글자까지 나오는 상태로 넓어진다.**
좌표가 통째로 밀리고, 예전 스크린샷 좌표로 누르면 엉뚱한 게 눌린다.
`더 보기` 자리를 잘못 누르면 **Threads 새 탭이 열린다.**

그래서 이 순서로 한다.

1. **버튼 위치를 화면에서 다시 잰다.** `getBoundingClientRect()` 값에
   `1568 / window.innerWidth` 를 곱하면 스크린샷 좌표가 나온다(배율이 1이 아니다)
2. 사이드바 메뉴(`더 보기` → `계정 전환`)는 좌표보다 **DOM 에서 글자로 찾아 누르는 편이 확실하다**
3. `find` 가 준 `ref` 는 화면이 다시 그려지면 어긋난다. 한 번 실패하면 다시 재서 좌표로 누른다
4. **계정을 바꾼 뒤에는 릴스 주소로 다시 들어간다.** 안 그러면 좋아요, 저장 상태가 이전 계정 것으로 남아 있다
5. **계정 전환 창이 로딩 표시에서 멈춰도 즉시 새로고침하지 않는다.** 계정 전환 직후
   새로고침하면 Instagram이 `UNAUTHORIZED`를 반환하고 기존 계정 세션을 로그인 화면으로
   되돌릴 수 있다(260821 실측). 3~5초 기다린 뒤 사이드바 프로필명과 계정 전환 창의
   체크 표시로 현재 계정을 확인한다. 로그인 화면이나 `계속해보세요`가 나타나면 작업을
   멈추고 사람에게 재로그인을 부탁한다.
6. 릴스 재생 화면(`/reels/...`)보다 **게시물 주소(`/p/<코드>/`)가 다루기 쉽다.**
   아이콘이 한 줄로 고정돼 있고 다음 릴스 것이 섞이지 않는다
7. 공유 창의 사람 목록은 **계정마다 순서가 다르다.** 얼굴 위치를 외우지 말고 이름으로 찾는다

**아이콘 줄 구성이 계정마다 다르다 (260819 실측).** 내 게시물이면 **리포스트가 끼어서**
공유하기가 오른쪽으로 밀린다. 좌표를 재활용하지 말고 **누를 때마다 `aria-label` 로 다시 재라.**

| 보는 계정 | 아이콘 줄 |
| --- | --- |
| `haruyaksa` (주인) | 좋아요, 댓글, 리포스트, 공유하기 … 저장 |
| `yakdae.saram` | 좋아요, 댓글, 리포스트, 공유하기 … 저장 |
| `kmin.kyeong` | 좋아요, 댓글, 공유하기 … 저장 (리포스트 없음) |

**리포스트 유무는 주인이냐 아니냐가 아니라 계정마다 다르다 (260829 실측).**
`kmin.kyeong` 은 게시물 화면에도 릴스 화면에도 리포스트가 없다. 없으면 없는 대로 넘어가고
보고에 적는다. 메뉴를 뒤지느라 시간을 쓰지 마라.

**공유 대상을 고른 뒤 뜨는 `전송됨` 토스트가 화면 아래를 가린다.** 그 자리에 계정 전환 창의
아래쪽 계정이 겹치면 클릭이 토스트에 먹힌다. `scrollIntoView({block:'center'})` 로 올린 뒤
`elementFromPoint` 로 그 자리에 진짜 그 계정 줄이 있는지 확인하고 누른다.

실제로 공유하기 x좌표가 계정에 따라 851 과 877 로 갈렸다.

릴스 하단 아이콘은 왼쪽부터 **좋아요, 댓글, 리포스트, 공유하기** 이고 오른쪽 끝이 **저장**이다.
리포스트와 공유가 붙어 있으니 `aria-label` 로 확인하고 누른다. 순환 화살표 리포스트도 세 계정에서 처리한다.

  `<채널> 소재/기록/업로드기록.jsonl` 에 있다
- **`업로드 준비.json` 의 status 는 올린 뒤에도 안 바뀐다.** 무엇이 남았는지는 인스타 피드로 본다
- **`visibilityState` 가 `hidden` 이라고 다 막힌 게 아니다.** 창이 최소화된 게 아니면 그냥 된다.
  판정법을 먼저 돌리고, 메타데이터가 오면 창 세우기를 건너뛴다
- **공유 창 사람 순서와 아이콘 줄이 계정마다 다르다.** 좌표를 재활용하지 말고 매번 다시 잰다
- **P8 이 끝나면 `haruyaksa` 로 되돌려 놓는다.** 계정 전환은 크롬 프로필 전체에 걸려서
  다음 세션이 `yakdae.saram` 으로 시작하게 된다
- **창이 아니라 내 탭이 배경이면 창 세우기가 안 듣는다.** 창 제목이 내 탭 제목이 아니면 그 상태다.
  같은 출처 팝업을 진짜 클릭으로 띄우고 `__pop.document` 로 만진다. P6 앞머리를 보라
- **팝업에서 캡션을 스크립트로 넣으면 캡션 없이 게시된다.** 글자 수 표시가 `588/2200` 로 정직하게
  올라가도 소용없다(260830 실측). **카운터를 증거로 쓰지 마라.** 게시는 팝업에서 캡션 없이 하고,
  캡션은 확장 탭의 수정 화면에서 진짜 타이핑으로 넣은 뒤 `/api/v1/media/<pk>/info/` 로 길이를 확인한다
- **수정 화면의 `완료` 는 `.click()` 이 안 먹는다.** 좌표로 진짜 눌러야 저장된다.
  n8n 실행 버튼은 정반대다. 어느 쪽이 먹는지 외우지 말고 둘 다 해보고 API 로 판정한다
- **팝업도 가려지면 `hidden` 이라 동영상이 안 붙는다.** 포커스를 뺏는 길은 다 막혀 있으니
  `SetWindowPos` 의 `HWND_TOPMOST` + `SWP_NOACTIVATE` 로 **가림만 푼다.** 끝나면 팝업을 닫는다
- **배경 탭이라도 스크롤 한 번 굴리면 좌표 클릭이 닿는다.** 파일 넘기기, 공유 창, 캡션 저장까지
  배경 탭에서 다 된다. 배경 탭에서 못 하는 것은 **동영상 붙이기 하나뿐이다**
- **`@haruyaksa` 뒤에 바로 줄바꿈을 치면 멘션 자동완성이 계정 이름을 먹는다.** 띄어쓰기 한 칸으로 닫고 친다
- **SNS서포터에서 조회수 상품 줄을 또 누르면 좋아요 카테고리로 되돌아간다.** 카테고리만 누르면 상품은 저절로 잡힌다
- **주문내역은 `/orders` 다.** `/mypage/orders` 는 404 다
- **리포스트 버튼은 계정마다 있고 없다.** `kmin.kyeong` 에는 없다. 없으면 넘어가고 보고에 적는다
- **`chrome.exe --new-window` 로 연 창은 확장으로 못 닫는다.** 핸들을 확인하고 `PostMessage(h, 0x0010, 0, 0)` 으로 닫는다
- **유튜브 watch 페이지는 5초 뒤 자동재생으로 넘어간다.** 그 자리에서 좋아요를 누르면 남의 영상에 들어간다.
  `pause()` 를 짧은 간격으로 반복하면서 버튼을 찾고, 누르기 전에 `location.href` 를 확인한다
- **유튜브 현재 계정을 `ownerChannelName` 으로 판정하지 마라.** 그건 영상 주인이다.
  아바타 메뉴의 `ytd-active-account-header-renderer` 를 읽는다
- **파일 넘기는 sender 탭을 열면 인스타 탭이 배경이 된다.** File 을 받은 즉시 sender 탭을 닫으면
  인스타 탭이 다시 활성이 된다. 닫기 전에 업로더를 만지면 동영상이 안 붙는다
- **인스타 공유 창의 사람 순서는 계정마다 다르다.** 260830 에 haruyaksa 는 약대사람이 1번,
  kmin.kyeong 은 약대사람 1번에 하루건강약사 3번, yakdae.saram 은 김민경 2번에 하루건강약사 4번이었다.
  자리를 외우지 말고 매번 이름으로 찾는다

## 사람에게 알려야 하는 지점

- **P2 실행 전.** KIE 잔액과 예정 편수를 숫자로 말하고 즉시 시작한다. 답을 기다리지 않는다.
- 어느 편을 올릴지 애매하고 직전 게시물과 주제가 겹치면 그 편만 건너뛰고 다음 소재를 고른다.
- 소재를 새로 써야 할 때 주제 방향이 애매하면 기존 큐에서 처리 가능한 소재를 먼저 쓴다.

### 묻지 말고 진행하는 것

여기서 멈추면 업무가 반쪽이 된다. **"쇼츠 돌려줘" 한 마디에 P8 까지 다 돈다.**

| 자리 | 어떻게 |
| --- | --- |
| P2 유튜브 공개 업로드 | 업무 이름이 그걸 뜻한다. 잔액과 편수를 한 줄 적고 돌린다 |

| P8 계정끼리 공유 | 사용자 본인 계정 셋끼리다. 제3자가 아니다 |

멈추는 건 **한도를 벗어날 때뿐**이다. KIE 잔액이 모자라 충전이 필요할 때,
