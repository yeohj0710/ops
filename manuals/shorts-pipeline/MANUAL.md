## 이 매뉴얼의 실행 권한

사용자가 이 업무를 호출하면 매뉴얼 전체를 실행하라는 뜻이다. `유튜브 업로드`, `인스타 업로드`,
`영상 올려줘`에는 지정된 유튜브 채널 공개 업로드와 `@haruyaksa` 릴스 게시가 포함된다.
게시 버튼 직전에 다시 승인받지 않는다. 현재 계정, 게시 대상, 파일, 원본 비율, 캡션만 확인하고
게시 결과를 보고한다.

이 업무는 **호출 한 번에 끝내는 무인 실행 업무**다. 사용자의 최초 호출은 이번 작업에서 정한
유튜브 업로드, 인스타 릴스 게시, P7 조회수 주문, P8 계정 반응까지의 실행 승인이다. 에이전트는
단계마다 "눌러도 되는지", "올려도 되는지", "주문해도 되는지"를 다시 묻지 않는다.

브라우저 화면을 사람에게 넘기는 `handoff`를 사용하지 않는다. 에이전트가 만든 탭에서 계정,
대상, 파일, 캡션, 비율을 확인한 뒤 같은 탭으로 게시 → 최종 릴스 URL → P7 → P8을 연속 실행한다.
게시 버튼이나 주문 버튼을 화면에 남겨 두고 "눌러 달라"고 보고하면 이 업무를 끝낸 것이 아니다.

**인스타 실행 단위는 호출 한 번에 릴스 한 편이다.** 준비 폴더에 미게시 영상이 여러 편 있어도
이번 호출에서는 가장 최근 영상 한 편만 P4~P8까지 끝낸다. 나머지는 다음 호출로 남긴다.
몇 시간 간격이 필요한 인스타 게시물을 한 번에 연속 게시하지 않는다.

**인스타 게시 계정은 `@haruyaksa` 하나로 고정한다.** 프로필 URL, 프로필 사진, 팔로우 버튼,
Chrome 프로필 이름은 계정 증거가 아니다. 게시 직전 Create/Reels 화면에 표시된 현재 계정명이
`haruyaksa`인지 확인한다. `wellnessbox_official` 등 다른 계정이면 공유하기를 누르지 말고,
계정을 전환한 뒤 업로드 화면을 다시 열어 확인한다.

**릴스 게시 뒤 후처리까지가 한 편의 완료 조건이다.** 최종 릴스 URL을 확보한 뒤
P7(SNS Supporter 조회수 2,000회)을 먼저 넣고, P8(세 계정 좋아요·저장·리포스트·서로 공유)을 처리한다.
둘 중 하나라도 끝나지 않으면 인스타 작업 완료로 보고하지 않는다.

다음 경우에만 멈춘다.

- 지정된 계정·채널이 아닌 대상에 게시하게 되는 경우
- KIE 잔액 부족으로 충전이 필요한 경우
- 매뉴얼에 없는 결제·메시지·삭제가 추가되는 경우
- 로그인이 풀렸거나 비밀번호·CAPTCHA를 직접 입력해야 하는 경우

위 네 가지가 아니면 멈추지 않는다. 이 업무에 단계로 적힌 유튜브 공개 업로드, 인스타 릴스
게시, 200원 조회수 주문, 세 계정의 좋아요·저장·리포스트·공유는 금지 대상이 아니라 완료해야 하는 단계다.

## 빠른 실행 경로

매번 상태를 여러 명령으로 나눠 확인하거나 Chrome 창을 전부 탐색하지 않는다. 시작할 때 아래 명령을 **한 번만** 실행한다.

```bash
node "<OPS>/manuals/shorts-pipeline/scripts/shorts-preflight.mjs"
```

이 명령은 브라우저와 네트워크를 건드리지 않고 다음을 한 번에 보여 준다.

- n8n 최근 실행 상태
- 두 채널의 마지막 업로드 기록
- `LOCKED_SOURCE_PACK=1`을 제외한 본편 소재 재고
- 최신 인스타 준비 폴더의 MP4 해상도와 `target_aspect_ratio`

사전 점검에서 `success`, 최근 업로드 기록, `1080,1920`, `original`이 확인되면 같은 정보를 다시 찾지 않는다.
P3는 기록과 채널 화면으로 바로 확인하고, P4는 `extract.mjs --list`를 한 번만 실행한다.
`업로드 준비.json`의 `ready_for_manual_upload`는 게시 여부가 아니므로 재추출·재업로드 근거로 쓰지 않는다.

### 유튜브·인스타 업로드 분기 판정

`유튜브가 있다`는 최근 유튜브 업로드 기록이 있다는 뜻이 아니다. **두 채널의 최신 유튜브 영상 중
인스타 피드에 아직 없는 미게시 후보가 있는지**로 판정한다. `업로드 준비.json`의 `status`, 준비 폴더의
파일 수, `extract.mjs --list` 결과만으로 게시 여부를 판단하지 않는다. 유튜브 영상 ID와 제목을
유튜브 업로드 기록·유튜브 채널·인스타 피드와 대조한다.

| 미게시 유튜브 후보 | 실행할 일 |
| --- | --- |
| 하루건강약사와 건강장수비결에 각각 1편 이상 | P1~P3 생략. 최신 미게시 후보 중 1편만 P4~P8 실행 |
| 두 채널 모두 없음 | P1 실행 후 하루건강약사 1편과 건강장수비결 1편을 각각 P2로 생성·업로드하고 P3 확인. 그중 1편만 P4~P8 실행 |
| 한 채널에만 있음 | 후보가 없는 채널만 P1~P3 실행해 1편을 보충. 양쪽을 P3로 확인한 뒤 최신 1편만 P4~P8 실행 |

즉, 유튜브 미게시 후보가 있으면 유튜브 생성은 반복하지 않고 인스타에 1편만 올린다.
두 채널 모두 미게시 후보가 없을 때만 유튜브를 채널별로 1편씩 만든 뒤 인스타 1편을 올린다.
인스타 게시 후 순서는 항상 **P7 조회수 주문 → P8 계정 반응**이다.

브라우저는 한 창·한 탭으로 처리한다. 확인 지점은 `현재 계정`, `원본 비율 미리보기`, `최종 게시물` 세 번만 둔다.
좋아요·저장·리포스트·공유 버튼은 매번 좌표를 외우지 말고 DOM의 `aria-label`과 계정명을 읽어 누른다.
최종 게시물의 `/reel/<코드>/` 주소를 확보한 뒤 P7 주문과 P8 반응에 같은 주소를 재사용한다.

## 무엇을 만드는 업무인가

n8n 이 쇼츠를 만들어 유튜브 두 채널에 올리고, 그중 이번 호출에서 정한 한 편만 인스타 릴스로
올린 뒤 조회수 2천 회를 먼저 주문하고, 계정 세 개로 좋아요·저장·리포스트·서로 공유를 한다.

**단계별로 따로 시킬 수 있다.** 사람이 "인스타만 올려줘" 라고 하면 P4부터, "유튜브만" 이면 P1~P3만 한다.
어느 단계를 하는지 먼저 말하고 시작한다.

| 단계 | 무엇 | 부르는 말 |
| --- | --- | --- |
| P1 | n8n 켜고 소재큐 확인, 보충 | 소재 채워줘 |
| P2 | n8n 회로 두 개를 돌려 유튜브에 올리기 | 쇼츠 돌려줘, 유튜브 올려줘 |
| P3 | 유튜브에 올라갔는지 확인하고 좋아요 누르기 | 올라갔나 확인해줘 |
| P4 | 유튜브 영상을 인스타그램용으로 뽑기 | 영상 뽑아줘 |
| P5 | 인스타그램 캡션 쓰기 | 캡션 써줘 |
| P6 | 인스타그램에 릴스 올리기 | 인스타 올려줘 |
| P7 | 릴스에 조회수 2천 회 주문하기 (200원) | 조회수 넣어줘 |
| P8 | 계정 세 개로 좋아요와 저장, 리포스트, 공유 누르기 | 반응 눌러줘 |

## 쉬운 설명

### 쓰는 상황

유튜브 채널 두 개와 인스타그램 계정 하나에 올릴 쇼츠를 만들어야 할 때 씁니다. 소재 찾기부터 조회수 주문까지 여덟 단계인데, 통째로 시켜도 되고 한 단계만 시켜도 됩니다.

### 시키는 말

Claude 나 Codex 새 세션에 이렇게 말하면 됩니다.

> G드라이브 에이전트 폴더 참고해서 쇼츠 생성부터 인스타 업로드까지 업무 해줘

여덟 단계를 통째로 돕니다. 한 단계만 원하면 그 단계를 말하면 됩니다.
인스타그램에만 올리려면 "인스타 올려줘", 캡션만 필요하면 "캡션 써줘" 입니다.

### 진행 순서

1. 컴퓨터에서 돌고 있는 n8n 이라는 자동화 프로그램을 켭니다. 여기에 만들 영상 주제가 줄 서 있습니다. 주제가 비어 있으면 새로 채우는데, 이미 올린 영상과 겹치지 않는지 먼저 확인합니다.
2. n8n 이 주제 하나로 쇼츠 한 편을 만들어 유튜브에 올립니다. 채널이 둘이라 두 편이 올라갑니다. 이 단계는 이미지를 만드는 데 돈이 나가기 때문에, 시작하기 전에 남은 잔액과 몇 편을 만들지 숫자로 먼저 알려 드립니다.
3. 유튜브에 제대로 올라갔는지 확인하고, 각 계정으로 자기 영상에 좋아요를 하나씩 누릅니다.
4. 올라간 유튜브 영상을 다시 내려받아 인스타그램에 올릴 수 있는 형태로 만듭니다. 아직 안 올린 영상이 밀려 있으면 같이 처리합니다.
5. 그 영상에 붙일 인스타그램 캡션을 씁니다. 채널 말투에 맞춰 랭킹 형식으로 쓰고 끝에 팔로우 유도 문구를 붙입니다.
6. 인스타그램에 릴스로 올립니다. 비율을 원본으로 맞춰야 영상이 안 잘립니다.
7. 올린 릴스에 조회수를 2천 회 주문합니다. 값은 200원입니다. 금액과 대상 링크를 화면에 적고 그대로 주문까지 마칩니다. 답을 기다리느라 멈추지 않습니다.
8. 계정 세 개로 그 릴스에 좋아요를 누르고, 저장하고, 리포스트하고, 서로에게 공유합니다.

### 결과물

유튜브 두 채널에 각각 한 편, 인스타그램에 릴스 한 편이 올라가 있습니다. 조회수 주문이 들어가 있고 계정 세 개의 좋아요·저장·리포스트·공유 반응이 붙어 있습니다. 보고 파일에 올린 링크가 정리됩니다.

### 사람이 직접 눌러야 하는 것

없습니다. "쇼츠 돌려줘" 한 마디면 조회수 주문까지 끝냅니다. 돈이 나가는 자리에서는 금액과 대상을 숫자로 적어 두니 나중에 확인하시면 됩니다.

멈추고 여쭙는 경우는 셋뿐입니다. 조회수 금액이 매뉴얼에 적힌 200원과 다를 때, 이미지 생성 잔액이 모자라 충전이 필요할 때, 인스타그램 로그인이 풀렸을 때입니다.

## P1. n8n 켜고 소재큐 확인하고 보충하기

1. **n8n 이 떠 있는지 본다 (L1)**
   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://localhost:5678
   ```
   `200` 이면 그냥 둔다. 아니면 `<DEV>/n8n-youtube-shorts-automation` 에서 띄운다.
   **`127.0.0.1:5678` 을 쓰지 마라.** 유튜브 OAuth 가 깨진다. 반드시 `localhost`.

2. **소재큐를 센다 (L1). 파일 수를 그냥 세면 틀린다** (260819 실측)
   ```bash
   node "<OPS>/manuals/shorts-pipeline/scripts/topic-count.mjs"
   ```
   본편이 **실제로 쓸 수 있는 것만** 세어 준다. 비어 있으면 채운다. 한 파일이 한 주제다.

   **왜 그냥 세면 안 되나.** 본편의 `Load Config` 노드가 파일을 열어 보고
   `LOCKED_SOURCE_PACK=1` 이 있으면 **건너뛴다.** `*-instagram_*.md` 는 전부 이게 붙어 있고,
   그건 `원본 릴스` 회로가 쓰는 소재라 본편 재고가 아니다.
   두 회로가 **같은 폴더와 같은 `사용완료/`** 를 쓰기 때문에 폴더만 봐서는 구분이 안 된다.

   | 채널 | 파일 총 | 본편이 쓸 수 있는 것 | 원본릴스 몫 |
   | --- | --- | --- | --- |
   | 하루건강약사 | 27 | **11** | 16 |
   | 건강장수비결 | 23 | **13** | 10 |

   (260819 기준. 이 표는 참고용이고 **숫자는 위 스크립트로 다시 센다.**)

   **소진 속도는 채널당 하루 한 편**이다(260801~260811 실측: 하루 11편, 장수 10편).
   본편 재고를 그 수로 나누면 남은 날짜가 나온다. **열흘 밑으로 내려가면 채운다.**

   **`topics/pending` 과 `topics-health-longevity/pending` 을 세지 마라. 둘 다 항상 0 이다.**
   살아 있는 회로가 읽는 곳이 아니다. 회로가 어디를 읽는지 확인하려면 DB 에서 꺼내 본다.


## P6. 인스타그램에 릴스 올리기

### 시작하기 전에, 크롬 창을 앞으로 꺼낸다 (260818 실측)

**이걸 안 하면 업로드가 첫 화면에서 멈춘 채 아무 일도 안 일어난다.** 오류도 안 뜬다.

창이 최소화돼 있거나 다른 창에 완전히 가려 있으면 `document.visibilityState` 가 `hidden` 이 되고,
크롬이 그 탭의 **동영상 로딩을 멈춘다.** 인스타 업로더는 영상 길이와 크기를 읽어야 다음으로 가는데
그걸 영영 못 읽어서 "사진과 동영상을 여기에 끌어다 놓으세요" 화면에 계속 머문다.

- **판정법.** 페이지에서 `URL.createObjectURL(file)` 로 `<video>` 를 만들고 `loadedmetadata` 를 기다린다.
  8초 안에 안 오면 창이 숨은 것이다. 파일 탓이 아니다(`arrayBuffer()` 로 `ftypisom` 까지 읽힌다)
- **고치는 법.** 사람을 부르지 말고 L1 으로 직접 창을 세운다. `EnumWindows` 로 클래스
  `Chrome_WidgetWin_1` 인 창을 훑어 **제목에 대상이 든 것 하나만** 골라
  `ShowWindow(h, 9)` 다음 `SetForegroundWindow(h)`. 전부 복원하면 마지막 것이 앞에 서서 헛일이 된다
- 창 제목은 **그 창의 활성 탭 제목**이다. 내 탭이 뒤에 있으면 제목으로 못 찾는다.
  그럴 땐 **그룹에 탭을 하나만 남긴다.** 나머지를 닫으면 남은 탭이 활성이 된다
- 클릭과 DOM 조작은 숨은 탭에서도 잘 된다. **동영상만** 안 된다

**단, `hidden` 이라고 다 죽는 건 아니다 (260819 실측).** 크롬 창이 열려 있고 내 탭이 그냥
뒤에 있기만 한 경우에는 `hidden` 인 채로도 메타데이터가 바로 왔고(5.014초, 1080x1920)
업로드, 자르기, 캡션, 공유까지 전부 통했다. 죽는 건 **창이 최소화됐을 때**로 보인다.

그러니 순서를 이렇게 한다. **`hidden` 을 보고 미리 겁먹지 말고 판정법을 먼저 돌린다.**
메타데이터가 오면 창을 안 세우고 그냥 진행한다. 창 세우기는 **안 올 때만** 한다.

**내 탭을 활성 탭으로 만들 방법은 없다.** 확장에 탭을 고르는 도구가 없고,
`tabs_create_mcp` 로 새로 만들어도 백그라운드로 생긴다. 사용자가 보던 탭을 닫아서
내 탭을 활성으로 만드는 것도 하면 안 된다. 정 세워야 하면 sender 탭이 자기를
`window.close()` 하게 만든다. 포커스가 opener(내 탭)로 돌아온다

1. **인스타에 들어간다 (L3).** `@haruyaksa` 로 로그인돼 있는지 먼저 확인한다.

### 파일을 어떻게 넣나 (`file_upload` 는 안 된다, 260817 실측)

크롬 익스텐션의 `file_upload` 는 **드라이브 경로를 거부한다.** "사용자가 공유한 파일만 올릴 수 있다" 고 한다.
`request_directory` 로 그 폴더 권한을 받아도 거부는 그대로다. 그 권한은 Read/Write 용이지 업로드용이 아니다.
스크래치패드로 복사해도 마찬가지다. 이 세션에는 공유 폴더(outputs, uploads)가 아예 없다.

**되는 방법은 이렇다. 로컬 서버에서 페이지로 File 을 넘긴다.**

1. mp4 를 스크래치패드로 복사하고 `127.0.0.1` 에 작은 http 서버를 띄운다.
   `/reel.mp4` 와 `/sender.html` 두 개만 있으면 된다.
2. `sender.html` 은 제 출처에서 mp4 를 `fetch` 해 `File` 을 만들고
   `window.opener.postMessage({file}, 'https://www.instagram.com')` 로 넘긴다.
3. 인스타 페이지에 `message` 리스너를 먼저 심고, 임시 링크를 만들어 진짜로 클릭해서 연다.
4. 받은 File 을 `DataTransfer` 에 담아 `input[type=file].files` 에 넣고 `change` 이벤트를 쏜다.

**막히는 곳 네 군데를 미리 알고 간다.**

- 인스타 페이지에서 `fetch('http://127.0.0.1:...')` 는 **CSP 로 막힌다.** `default-src` 에 로컬이 없다
- `<script src="http://127.0.0.1:...">` 도 막힌다. `script-src` 에 `127.0.0.1:*` 이 있지만
  **스킴이 없는 host-source 는 https 문서에서 http 를 안 받는다**
- `window.open` 은 첫 번째만 되고 **그 다음부터 팝업 차단된다.** 임시 `<a>` 를 만들어
  `computer` 로 진짜 클릭하는 편이 확실하다
- 그런데 `target="_blank"` 만 주면 크롬이 **기본으로 `noopener`** 를 걸어서 `window.opener` 가 `null` 이다.
  sender 가 File 을 돌려보낼 길이 없어진다. **`rel="opener"` 를 같이 준다** (260818 실측)

```js
const a = document.createElement('a');
a.href = 'http://127.0.0.1:8791/sender.html';
a.target = '_blank';
a.rel = 'opener';          // 이 줄이 없으면 opener 가 끊긴다
```

`postMessage` 는 CSP 를 안 탄다. `File` 은 구조화 복제가 되니 그대로 건너간다.
끝나면 임시 링크를 지우고 서버를 내린다. **sender 탭도 닫는다.** 그게 활성 탭이면
인스타 탭이 뒤로 밀려서 위의 동영상 문제가 다시 생긴다.

### 캡션은 타이핑으로 넣는다

인스타 캡션 칸은 렉시컬 편집기라 스크립트로 글자를 밀어 넣으면 **줄바꿈이 전부 사라진다.**
`execCommand('insertText')` 도, `insertLineBreak` 를 섞어도, `selectAll` + `delete` 도 다 어긋난다.

1. 캡션 칸을 클릭한다
2. `ctrl+a` 다음 `Delete` (키 입력으로 비운다)
3. 줄바꿈이 든 캡션 전문을 **한 번에 타이핑**한다. 이모지와 빈 줄까지 그대로 들어간다
4. `innerText` 를 읽어 `\n\n` 이 살아 있는지 확인한다

## P7. 릴스에 조회수 2천 회 주문하기 (200원, 인스타 게시 직후 실행)

1. https://snssupporter.com 에 들어간다 (L3). 로그인 정보는 `자격증명/계정.md`.
   크레딧이 200원도 없으면 다른 계정으로 로그인한다(둘 다 그 파일에 있다).
2. `국내서비스` → `조회수` → `실제 한국인 조회수 (0.1원)`
3. 스크롤 내려 릴스 링크를 넣고 **구매수량 2000** → 주문. **200원이다.**

**에이전트가 끝까지 한다 (260818 실측).** 예전에는 막힌다고 적혀 있었는데 아니었다.

**여기서 멈춰서 묻지 마라.** 사람이 이 업무를 시킨 것이 이 200원에 대한 승인이다.
`AGENTS.md` 의 "매뉴얼에 값이 박힌 지출은 업무 지시에 포함된 것이다" 를 따른다.

순서는 이렇다.

1. **주문 전에 `주문내역` 을 본다.** 같은 릴스에 이미 들어가 있으면 또 넣지 않는다
2. **금액을 한 줄로 적고 그대로 진행한다.** 답을 기다리지 않는다.
   "2,000회 × 0.1원 = 200원, 잔액 5,200 → 5,000, 대상은 방금 올린 릴스. 넣는다"
3. **링크 칸은 폼 채우기 도구로** 값을 넣는다
4. **수량 칸은 반드시 진짜 타이핑으로** 넣는다. 세 번 클릭해 기존 값을 잡고 `2000` 을 친다.
   폼 채우기 도구로 넣으면 값은 보이는데 **주문금액이 `₩0` 에 머문다.**
   React 상태가 안 바뀌어서 그렇고, `input` 과 `change` 이벤트를 손으로 쏴도 안 된다
5. **`주문금액` 이 `₩200` 으로 바뀐 것을 눈으로 확인하고** `주문하기` 를 누른다.
   `₩0` 이면 4번이 안 먹은 것이다. 그대로 누르지 마라
6. `주문접수가 완료되었습니다` 창에서 주문번호와 수량, 사용액, 잔액을 읽어 보고에 적는다

**타이핑이 차단되면** 그건 승인 문제다. 금액을 아직 화면에 안 적었을 때 그렇다.
2번을 먼저 하고 다시 친다. `runners/claude.md` 의 "차단됐다는 말을 들었을 때" 를 보라.

`dbwjtk` 계정은 크롬에 로그인돼 있다. 잔액이 모자라면 예비 계정으로 바꾸는데,
**로그인 창이 떠도 멈추지 마라.** 아이디 칸을 누르면 크롬이 저장해 둔 계정이 뜬다. 그걸 골라 들어간다.
그것도 안 되면 그때만 사람을 부른다. 자세한 순서는 `runners/claude.md` 의 "로그인 창을 만났을 때".

**주문 전에 `주문내역` 을 먼저 본다.** 사람이 기다리다 직접 넣어 둔 경우가 있다.
잔액이 200원 줄어 있으면 이미 들어간 것이다. 확인 없이 또 누르면 두 번 나간다.

## P8. 계정 세 개로 좋아요와 저장, 리포스트, 공유 누르기 (P7 뒤 실행)

`haruyaksa` → `kmin.kyeong` → `yakdae.saram` 순으로 계정을 바꿔가며 그 릴스에 **좋아요, 저장, 리포스트, 공유** 를 누른다.

**다 끝나면 `haruyaksa` 로 되돌려 놓는다.** 계정 전환은 크롬 프로필 전체에 걸리기 때문에,
그냥 두면 다음 세션이 `yakdae.saram` 으로 시작한다.

- **누르기 전에 지금 어느 계정인지 확인한다.** 계정 전환이 안 됐는데 누르면 헛일이다
- 릴스 하단의 하트(좋아요), 순환 화살표(리포스트), 종이비행기(공유), 책갈피(저장) 네 개다
- **순환 화살표 리포스트를 반드시 누른다.** 이미 리포스트한 계정이면 다시 눌러 취소하지 말고, 리포스트 수나 눌린 상태를 확인한다
- **공유는 나머지 두 계정에게 보낸다.** 종이비행기를 누르면 사람 목록이 나온다.
  `김민경`(kmin.kyeong) 과 `약대사람`(yakdae.saram) 을 고르고 `따로 보내기` 를 누른다.
  화면 아래 `전송됨` 이 떠야 간 것이다
- 저장이 됐는지는 책갈피 아이콘의 `aria-label` 로 본다. **눌린 상태가 `삭제` 다**(`저장 취소` 가 아니다)
- 이미 눌려 있으면 다시 누르지 마라. 취소된다. 라벨이 `좋아요 취소` 나 `삭제` 면 그 계정은 이미 끝난 것이다

### 새 화면에 들어오면 첫 클릭이 먹지 않는다 (260818 실측)

주소를 옮기거나 계정을 바꾼 직후에는 클릭이 **페이지에 도달조차 안 한다.**
캡처 단계에 리스너를 걸고 세어 보면 0건이다. 오류도 없고 그냥 아무 일도 안 일어난다.
좌표를 의심하게 되는데 좌표는 맞다. 여기서 한참 헤맸다.

**스크롤을 한 번 굴리면 그때부터 클릭이 먹는다.** 스크롤은 처음부터 잘 들어간다.
그러니 새 화면에 들어가면 항상 이 순서로 한다.

```
1. 스크롤 3칸       (입력이 살아나고 게시물이 위로 올라와 화면도 정리된다)
2. 좌표를 다시 잰다  (스크롤했으니 위치가 바뀌었다)
3. 누른다
4. aria-label 로 확인한다
```

눌렸는지는 **`aria-label` 로만** 판정한다. `좋아요 취소` 와 `삭제` 가 눌린 상태다.
안 바뀌었으면 1번부터 다시 한다. 같은 자리를 두 번 누르면 취소된다.

### 계정 전환과 클릭이 잘 안 될 때 (260818 실측)

계정을 바꾸면 사이드바가 아이콘만 있는 상태에서 **글자까지 나오는 상태로 넓어진다.**
좌표가 통째로 밀리고, 예전 스크린샷 좌표로 누르면 엉뚱한 게 눌린다.
`더 보기` 자리를 잘못 누르면 **Threads 새 탭이 열린다.**

그래서 이 순서로 한다.

1. **버튼 위치를 화면에서 다시 잰다.** `getBoundingClientRect()` 값에
   `1568 / window.innerWidth` 를 곱하면 스크린샷 좌표가 나온다(배율이 1이 아니다)
2. 사이드바 메뉴(`더 보기` → `계정 전환`)는 좌표보다 **DOM 에서 글자로 찾아 누르는 편이 확실하다**
3. `find` 가 준 `ref` 는 화면이 다시 그려지면 어긋난다. 한 번 실패하면 다시 재서 좌표로 누른다
4. **계정을 바꾼 뒤에는 릴스 주소로 다시 들어간다.** 안 그러면 좋아요, 저장 상태가 이전 계정 것으로 남아 있다
5. **계정 전환 창이 로딩 표시에서 멈춰도 즉시 새로고침하지 않는다.** 계정 전환 직후
   새로고침하면 Instagram이 `UNAUTHORIZED`를 반환하고 기존 계정 세션을 로그인 화면으로
   되돌릴 수 있다(260821 실측). 3~5초 기다린 뒤 사이드바 프로필명과 계정 전환 창의
   체크 표시로 현재 계정을 확인한다. 로그인 화면이나 `계속해보세요`가 나타나면 작업을
   멈추고 사람에게 재로그인을 부탁한다.
6. 릴스 재생 화면(`/reels/...`)보다 **게시물 주소(`/p/<코드>/`)가 다루기 쉽다.**
   아이콘이 한 줄로 고정돼 있고 다음 릴스 것이 섞이지 않는다
7. 공유 창의 사람 목록은 **계정마다 순서가 다르다.** 얼굴 위치를 외우지 말고 이름으로 찾는다

**아이콘 줄 구성이 계정마다 다르다 (260819 실측).** 내 게시물이면 **리포스트가 끼어서**
공유하기가 오른쪽으로 밀린다. 좌표를 재활용하지 말고 **누를 때마다 `aria-label` 로 다시 재라.**

| 보는 계정 | 아이콘 줄 |
| --- | --- |
| `haruyaksa` (주인) | 좋아요, 댓글, 리포스트, 공유하기 … 저장 |
| 나머지 두 계정 | 좋아요, 댓글, 공유하기 … 저장 |

실제로 공유하기 x좌표가 계정에 따라 851 과 877 로 갈렸다.

릴스 하단 아이콘은 왼쪽부터 **좋아요, 댓글, 리포스트, 공유하기** 이고 오른쪽 끝이 **저장**이다.
리포스트와 공유가 붙어 있으니 `aria-label` 로 확인하고 누른다. 순환 화살표 리포스트도 세 계정에서 처리한다.

## 알려진 함정

- **인스타 비율을 1:1 로 올리면 영상이 잘린다.** 지우고 다시 올려야 한다. 자르기 화면에서 `원본` 을 꼭 누른다
- **n8n 을 `127.0.0.1:5678` 로 열지 마라.** 유튜브 OAuth 가 깨진다. `localhost` 만 쓴다
- **n8n API 는 401 이다.** `X-N8N-API-KEY` 가 없으면 목록도 못 본다. 화면(L3)으로 한다
- **회로 JSON 을 다시 import 하지 마라.** 사람이 잡아둔 노드 배치가 날아간다. DB 에서 내보내 고친다
- **본편 회로만 돌린다.** 회로가 일곱 개인데 나머지는 소재가 다른 데서 온다
- **오래된 미업로드 영상을 거슬러 올라가지 마라.** 안 올린 이유가 있다(인스타에 안 맞아서)
- 유튜브 업로드는 화면에 바로 안 뜬다. 몇 분 기다린다
- 계정 전환 뒤에 **누르기 전에 현재 계정을 확인한다.** 엉뚱한 계정으로 누르면 헛일이다
- 소재큐가 비어 있으면 회로가 돌 것이 없다. P1 을 먼저 한다
- **`file_upload` 로는 mp4 를 못 올린다.** 드라이브도 스크래치패드도 다 거부한다. P6 의 로컬 서버 절대로 한다
- **영상이 5초라고 놀라지 마라.** 이 채널 쇼츠는 움직임 없는 정지 카드 한 장이다.
  올라간 릴스도 전부 5초다. 추출이 잘린 게 아니다
- **인스타는 호출 한 번에 한 편만 게시한다.** 준비 폴더에 여러 편이 있어도 두 번째 편을
  같은 호출에서 올리지 않는다. 한 편의 P7 조회수 주문과 P8 반응을 끝낸 뒤 다음 호출을 기다린다
- **P6 뒤 순서는 P7 → P8이다.** 인스타 게시 직후 조회수 주문을 먼저 넣고, 주문 접수 뒤 반응을 처리한다
- **Create/Reels 화면의 현재 계정명이 `haruyaksa`가 아니면 공유하지 않는다.** URL이나 프로필
  이름만 보고 게시하면 안 된다
- **크롬 창이 최소화돼 있으면 업로드가 첫 화면에서 멈춘다.** 오류가 안 나서 파일 탓으로 오해한다.
  P6 앞머리대로 창부터 세운다
- **새 화면에서 첫 클릭은 페이지에 도달하지 않는다.** 스크롤 한 번 굴리고 좌표를 다시 재서 누른다
- **`target="_blank"` 는 `window.opener` 를 끊는다.** `rel="opener"` 를 같이 줘야 File 이 건너온다
- **캡션을 스크립트로 밀어 넣으면 줄바꿈이 사라진다.** 지우기는 키로, 넣기는 타이핑으로 한다
- **SNS서포터 수량 칸을 폼 채우기 도구로 넣으면 주문금액이 `₩0` 이다.** 진짜 타이핑이어야 한다
- **결제 화면에 승인 없이 글자를 치면 차단된다.** 금액과 대상을 먼저 숫자로 보고하면 그 뒤로는 통한다
- **주문 전에 주문내역을 본다.** 사람이 먼저 넣어 뒀으면 두 번 나간다
- **KIE 잔액은 카운트업 애니메이션이다.** 열자마자 읽으면 0 이 나온다.
  값이 멈출 때까지 여러 번 재고 나서 판단한다. 이걸로 P2 를 통째로 건너뛴 적이 있다
- **탭을 쌓아 두지 마라.** 그룹에 탭이 여럿이면 내 탭이 뒤로 밀리고, 그러면 동영상이 안 붙는다
- **소재 개수를 파일 수로 세지 마라.** 본편은 `LOCKED_SOURCE_PACK=1` 이 붙은 파일을 건너뛴다.
  `*-instagram_*.md` 가 전부 그렇고 그건 `원본 릴스` 회로 몫이다. 두 회로가 같은 폴더와
  같은 `사용완료/` 를 써서 눈으로는 안 갈린다. `scripts/topic-count.mjs` 로 센다
- **`topics/pending` 은 항상 0 이다.** 회로가 읽는 곳은 `<채널> 소재/` 폴더다.
  거기만 보고 "큐가 비었다" 며 소재를 새로 쓰면 헛일이다. P1 을 보라
- **`topics/upload-log.jsonl` 은 260702 에서 멈춰 있다.** 최근 업로드는
  `<채널> 소재/기록/업로드기록.jsonl` 에 있다
- **`업로드 준비.json` 의 status 는 올린 뒤에도 안 바뀐다.** 무엇이 남았는지는 인스타 피드로 본다
- **`visibilityState` 가 `hidden` 이라고 다 막힌 게 아니다.** 창이 최소화된 게 아니면 그냥 된다.
  판정법을 먼저 돌리고, 메타데이터가 오면 창 세우기를 건너뛴다
- **공유 창 사람 순서와 아이콘 줄이 계정마다 다르다.** 좌표를 재활용하지 말고 매번 다시 잰다
- **P8 이 끝나면 `haruyaksa` 로 되돌려 놓는다.** 계정 전환은 크롬 프로필 전체에 걸려서
  다음 세션이 `yakdae.saram` 으로 시작하게 된다
