# 쇼츠 생성부터 인스타 업로드까지

- **부르는 말**: 쇼츠 돌려줘, 영상 올려줘, 유튜브 업로드해줘, 인스타 올려줘, 릴스 올려줘, 조회수 넣어줘
- **런너**: claude
- **제어층**: L1 로 시도, 화면은 L3
- **한 번에 걸리는 시간**: 전 단계 2~3시간 / 한 단계 10~30분

---

## 무엇을 만드는 업무인가

n8n 이 쇼츠를 만들어 유튜브 두 채널에 올리고, 그 영상을 다시 뽑아 인스타 릴스로 올린 뒤
조회수를 2천 회 주문하고, 계정 세 개로 좋아요와 저장, 공유를 누른다.

**단계별로 따로 시킬 수 있다.** 사람이 "인스타만 올려줘" 라고 하면 P4부터, "유튜브만" 이면 P1~P3만 한다.
어느 단계를 하는지 먼저 말하고 시작한다.

| 단계 | 무엇 | 부르는 말 |
| --- | --- | --- |
| P1 | n8n 켜고 소재큐 확인, 보충 | 소재 채워줘 |
| P2 | n8n 회로 두 개를 돌려 유튜브에 올리기 | 쇼츠 돌려줘, 유튜브 올려줘 |
| P3 | 유튜브에 올라갔는지 확인하고 좋아요 누르기 | 올라갔나 확인해줘 |
| P4 | 유튜브 영상을 인스타그램용으로 뽑기 | 영상 뽑아줘 |
| P5 | 인스타그램 캡션 쓰기 | 캡션 써줘 |
| P6 | 인스타그램에 릴스 올리기 | 인스타 올려줘 |
| P7 | 릴스에 조회수 2천 회 주문하기 (200원) | 조회수 넣어줘 |
| P8 | 계정 세 개로 좋아요와 저장, 공유 누르기 | 반응 눌러줘 |

## 쉬운 설명

### 쓰는 상황

유튜브 채널 두 개와 인스타그램 계정 하나에 올릴 쇼츠를 만들어야 할 때 씁니다. 소재 찾기부터 조회수 주문까지 여덟 단계인데, 통째로 시켜도 되고 한 단계만 시켜도 됩니다.

### 시키는 말

전부 돌리려면 "쇼츠 돌려줘" 라고 합니다. 인스타그램에만 올리려면 "인스타 올려줘", 캡션만 필요하면 "캡션 써줘" 라고 합니다.

### 진행 순서

1. 컴퓨터에서 돌고 있는 n8n 이라는 자동화 프로그램을 켭니다. 여기에 만들 영상 주제가 줄 서 있습니다. 주제가 비어 있으면 새로 채우는데, 이미 올린 영상과 겹치지 않는지 먼저 확인합니다.
2. n8n 이 주제 하나로 쇼츠 한 편을 만들어 유튜브에 올립니다. 채널이 둘이라 두 편이 올라갑니다. 이 단계는 이미지를 만드는 데 돈이 나가기 때문에, 시작하기 전에 남은 잔액과 몇 편을 만들지 숫자로 먼저 알려 드립니다.
3. 유튜브에 제대로 올라갔는지 확인하고, 각 계정으로 자기 영상에 좋아요를 하나씩 누릅니다.
4. 올라간 유튜브 영상을 다시 내려받아 인스타그램에 올릴 수 있는 형태로 만듭니다. 아직 안 올린 영상이 밀려 있으면 같이 처리합니다.
5. 그 영상에 붙일 인스타그램 캡션을 씁니다. 채널 말투에 맞춰 랭킹 형식으로 쓰고 끝에 팔로우 유도 문구를 붙입니다.
6. 인스타그램에 릴스로 올립니다. 비율을 원본으로 맞춰야 영상이 안 잘립니다.
7. 올린 릴스에 조회수를 2천 회 주문합니다. 값은 200원입니다. 금액과 대상 링크를 화면에 적고 그대로 주문까지 마칩니다. 답을 기다리느라 멈추지 않습니다.
8. 계정 세 개로 그 릴스에 좋아요를 누르고, 저장하고, 서로에게 공유합니다.

### 결과물

유튜브 두 채널에 각각 한 편, 인스타그램에 릴스 한 편이 올라가 있습니다. 조회수 주문이 들어가 있고 계정 세 개의 반응이 붙어 있습니다. 보고 파일에 올린 링크가 정리됩니다.

### 사람이 직접 눌러야 하는 것

없습니다. "쇼츠 돌려줘" 한 마디면 조회수 주문까지 끝냅니다. 돈이 나가는 자리에서는 금액과 대상을 숫자로 적어 두니 나중에 확인하시면 됩니다.

멈추고 여쭙는 경우는 셋뿐입니다. 조회수 금액이 매뉴얼에 적힌 200원과 다를 때, 이미지 생성 잔액이 모자라 충전이 필요할 때, 인스타그램 로그인이 풀렸을 때입니다.

## P1. n8n 켜고 소재큐 확인하고 보충하기

1. **n8n 이 떠 있는지 본다 (L1)**
   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://localhost:5678
   ```
   `200` 이면 그냥 둔다. 아니면 `<DEV>/n8n-youtube-shorts-automation` 에서 띄운다.
   **`127.0.0.1:5678` 을 쓰지 마라.** 유튜브 OAuth 가 깨진다. 반드시 `localhost`.

2. **소재큐를 센다 (L1)**
   ```bash
   ls "<DEV>/n8n-youtube-shorts-automation/topics/pending" | wc -l                    # 하루건강약사
   ls "<DEV>/n8n-youtube-shorts-automation/topics-health-longevity/pending" | wc -l   # 건강장수비결
   ```
   비어 있으면 채운다. 한 파일이 한 주제다.

3. **비어 있으면 그냥 새로 쓴다.** 영상 데이터가 많아서 그걸 보고 만들면 된다.
   사람에게 주제를 물어보지 말고 아래 겹침 검사만 하고 채운다.

4. **채울 때는 이미 올린 것과 겹치지 않게 한다 (L1)**
   - 완성된 소재 은행: `<DEV>/n8n-youtube-shorts-automation/건강장수비결 소재/` (27개, `final_pack` 포함)
   - 이미 쓴 것: 각 큐의 `used/` `used.jsonl` `upload-log.jsonl`
   - 채널에 올라간 것: 유튜브 채널 동영상 탭을 훑는다 (L3)
   - `topic_key` 로 겹침을 판정한다. 제목만 보고 판단하지 마라

4. **소재 파일 형식.** 대충 써도 n8n 이 랭킹 카드로 정리한다.
   ```text
   나이 들수록 아침에 피할 습관 4
   - 침대에서 벌떡 일어나기 - 어지럼 위험
   - 물 안 마시고 바로 커피 - 갈증 누적

   어른들이 바로 실천할 수 있는 건강관리 톤.
   ```
   랭킹은 **1위가 맨 위**다. 7위를 먼저 놓지 마라.

## P2. n8n 회로 두 개를 돌려 유튜브에 올리기

**시작 전에 사람에게 알린다.** 회로 한 번이 KIE 크레딧(이미지 + BGM)을 쓰고
**공개 유튜브 영상을 올린다.** 두 채널이니 두 번이다.

### KIE 크레딧

| 무엇 | 어디 |
| --- | --- |
| API 키 확인하고 복사 | https://kie.ai/api-key |
| 잔액 보고 충전 | https://kie.ai/billing |

**충전은 사람이 한다. 에이전트는 결제 화면을 건드리지 않는다.**
자동결제가 걸려 있고 5달러짜리를 눌러야 하는데 잘못 눌러 50달러가 나가면 되돌리기 어렵다.
잔액이 부족하면 **얼마나 모자란지 말하고 멈춘다.**

API 키가 필요하면 `api-key` 페이지에서 복사해 쓴다.

1. **n8n 을 연다 (L3)**
   `http://localhost:5678` 로 간다. API 는 키가 없으면 401 이라 화면으로 한다.

2. **본편 회로를 찾는다.** 다른 회로(레퍼런스 카드, 완성 이미지, 원본 릴스)는 건드리지 마라.
   | 채널 | 회로 이름 | ID |
   | --- | --- | --- |
   | 하루건강약사 | `하루건강약사 · 본편 (소재큐)`(화면에 뜨는 이름 그대로) | `mxrYb3maJS31gEYC` |
   | 건강장수비결 | `건강장수비결 · 본편 (소재큐)`(화면에 뜨는 이름 그대로) | 화면에서 이름으로 찾는다 |

3. **각각 한 번씩 수동 실행한다.** 한 채널에 하나씩만 올린다.

4. **에러가 나면 그때만 고친다.** 회로 JSON 을 고쳐야 할 수도 있다.
   고칠 때는 **먼저 로컬 DB 에서 현재 회로를 내보내 읽고** 그걸 고친다.
   `workflows/*.json` 을 다시 import 하지 마라. 사람이 잡아둔 노드 배치가 날아간다.

### credential 에러가 났을 때 (자주 난다)

유튜브 토큰이 만료되면 업로드 노드에서 인증 오류가 난다. 고치는 법은 정해져 있다.

1. **http://localhost:5678/home/credentials** 로 간다 (L3)
2. 해당 credential 을 누른다. **이름이 채널을 가른다.**
   | credential 이름 | 어느 계정으로 로그인하나 |
   | --- | --- |
   | `youtube account` | **하루건강약사** |
   | `account2` | **건강장수비결** |

   **바꿔서 로그인하면 영상이 엉뚱한 채널로 올라간다.** 누르기 전에 이름을 확인한다.
3. 구글 로그인을 다시 한다. **권한 체크박스를 전부 켜고** 확인을 누른다.
   하나라도 빠지면 업로드가 다시 실패한다.
4. 회로를 다시 실행한다.

**이 로그인 창은 팝업이라 탭 목록에 안 잡힌다.** `runners/*.md` 의 "팝업, 새 창" 절대로 처리한다.
요약하면 이렇다.

```js
// 구글 로그인 버튼을 누르기 전에 심는다
window.__opened = [];
const _open = window.open;
window.open = function(u, ...r){ if(u) window.__opened.push(String(u)); return _open.call(window, u, ...r); };
```

버튼을 누르고 `window.__opened` 에 담긴 구글 인증 주소를 **새 탭에서 연다**
(`tabs_create_mcp` → `navigate`). 거기서 계정을 고르고 권한을 켜고 확인하면
n8n 콜백으로 돌아가 credential 이 저장된다.

**같은 탭에서 열지 마라.** OAuth 는 부모 창에 결과를 돌려주는 구조라 흐름이 깨진다.
계정 선택 화면에서 **어느 계정을 고르는지** 다시 확인한다. 여기서 틀리면 채널이 바뀐다.

## P3. 유튜브에 올라갔는지 확인하고 좋아요 누르기

1. **딜레이가 있다. 기다린다 (L3)**
   업로드 직후에는 안 보인다. 몇 분 기다렸다가 채널 동영상 탭을 새로 고친다.

2. **두 채널을 확인한다.** 계정 전환(오른쪽 위 프로필 → 계정 전환)을 하거나, 채널 주소로 바로 간다.
   제목, 썸네일, 공개 여부가 맞는지 본다.

3. **각 계정으로 자기 영상에 좋아요 하나.** 계정을 잘못 바꾸고 누르지 않게 **누르기 전에 현재 계정을 확인한다.**

## P4. 유튜브 영상을 인스타그램용으로 뽑기

인스타에 올릴 영상을 유튜브에서 뽑는다. **밀린 것까지 같이 한다.**

1. **무엇이 밀렸는지 센다 (L1)**
   - 이미 준비된 폴더: `<드라이브>/영상 편집/AI 크리에이터/인스타그램 업로드용/`
     이름은 `YYMMDDHHMMSS 제목` 이다
   - 인스타에 올라간 것: https://www.instagram.com/haruyaksa/ (L3)
   - **최근 몇 개 중 안 올라간 것만** 한다. 오래전에 안 올린 건 이유가 있다(인스타에 안 맞아서).
     오래된 것까지 거슬러 올라가지 마라

2. **뽑는다 (L1). 스크립트가 다 한다.**
   ```bash
   node "<OPS>/manuals/shorts-pipeline/scripts/extract.mjs" --list        # 밀린 것 보기
   node "<OPS>/manuals/shorts-pipeline/scripts/extract.mjs" <영상ID> ...   # 뽑기
   ```
   `--list` 는 **채널별로 가장 최근 준비분 위쪽만** 골라준다. 오래된 미준비분은 알아서 뺀다.
   폴더, mp4, metadata, 업로드 준비.json, 캡션.html 을 규격대로 만든다. 캡션 내용만 P5에서 채우면 된다.

   남의 채널 영상이면 거부한다(채널 ID 두 개만 허용).
   추출기 exe 를 열 필요 없다. 같은 로직을 `yt-dlp` 로 직접 쓴다. `yt-dlp` `ffmpeg` 는 이미 깔려 있다.

3. **폴더 하나에 다섯 개를 만든다.** 기존 폴더를 그대로 본뜬다.
   | 파일 | 무엇 |
   | --- | --- |
   | `<이름>.mp4` | 영상 |
   | `<이름> metadata.json` | 제목, 채널, 채널ID, 원본 URL, 영상 ID |
   | `<이름> caption.txt` | 유튜브용 캡션 (끝이 구독 유도) |
   | `캡션.html` | 인스타용 캡션 (P5에서 만든다) |
   | `업로드 준비.json` | 상태, 원본 URL, 대상 계정, 비율 |

   `업로드 준비.json` 의 `target_aspect_ratio` 는 반드시 `original`.
   `source_ownership.allowed_channel_ids` 에 두 채널 ID 를 넣어 남의 영상을 안 올리게 막는다.

그걸 영영 못 읽어서 "사진과 동영상을 여기에 끌어다 놓으세요" 화면에 계속 머문다.

- **판정법.** 페이지에서 `URL.createObjectURL(file)` 로 `<video>` 를 만들고 `loadedmetadata` 를 기다린다.
  8초 안에 안 오면 창이 숨은 것이다. 파일 탓이 아니다(`arrayBuffer()` 로 `ftypisom` 까지 읽힌다)
- **고치는 법.** 사람을 부르지 말고 L1 으로 직접 창을 세운다. `EnumWindows` 로 클래스
  `Chrome_WidgetWin_1` 인 창을 훑어 **제목에 대상이 든 것 하나만** 골라
  `ShowWindow(h, 9)` 다음 `SetForegroundWindow(h)`. 전부 복원하면 마지막 것이 앞에 서서 헛일이 된다
- 창 제목은 **그 창의 활성 탭 제목**이다. 내 탭이 뒤에 있으면 제목으로 못 찾는다.
  그럴 땐 **그룹에 탭을 하나만 남긴다.** 나머지를 닫으면 남은 탭이 활성이 된다
- 클릭과 DOM 조작은 숨은 탭에서도 잘 된다. **동영상만** 안 된다

1. **인스타에 들어간다 (L3).** `@haruyaksa` 로 로그인돼 있는지 먼저 확인한다.

### 파일을 어떻게 넣나 (`file_upload` 는 안 된다, 260817 실측)

크롬 익스텐션의 `file_upload` 는 **드라이브 경로를 거부한다.** "사용자가 공유한 파일만 올릴 수 있다" 고 한다.
`request_directory` 로 그 폴더 권한을 받아도 거부는 그대로다. 그 권한은 Read/Write 용이지 업로드용이 아니다.
스크래치패드로 복사해도 마찬가지다. 이 세션에는 공유 폴더(outputs, uploads)가 아예 없다.

**되는 방법은 이렇다. 로컬 서버에서 페이지로 File 을 넘긴다.**

1. mp4 를 스크래치패드로 복사하고 `127.0.0.1` 에 작은 http 서버를 띄운다.
   `/reel.mp4` 와 `/sender.html` 두 개만 있으면 된다.
2. `sender.html` 은 제 출처에서 mp4 를 `fetch` 해 `File` 을 만들고
   `window.opener.postMessage({file}, 'https://www.instagram.com')` 로 넘긴다.
3. 인스타 페이지에 `message` 리스너를 먼저 심고, 임시 링크를 만들어 진짜로 클릭해서 연다.
4. 받은 File 을 `DataTransfer` 에 담아 `input[type=file].files` 에 넣고 `change` 이벤트를 쏜다.

**막히는 곳 네 군데를 미리 알고 간다.**

- 인스타 페이지에서 `fetch('http://127.0.0.1:...')` 는 **CSP 로 막힌다.** `default-src` 에 로컬이 없다
- `<script src="http://127.0.0.1:...">` 도 막힌다. `script-src` 에 `127.0.0.1:*` 이 있지만
  **스킴이 없는 host-source 는 https 문서에서 http 를 안 받는다**
- `window.open` 은 첫 번째만 되고 **그 다음부터 팝업 차단된다.** 임시 `<a>` 를 만들어
  `computer` 로 진짜 클릭하는 편이 확실하다
- 그런데 `target="_blank"` 만 주면 크롬이 **기본으로 `noopener`** 를 걸어서 `window.opener` 가 `null` 이다.
  sender 가 File 을 돌려보낼 길이 없어진다. **`rel="opener"` 를 같이 준다** (260818 실측)

```js
const a = document.createElement('a');
a.href = 'http://127.0.0.1:8791/sender.html';
a.target = '_blank';
a.rel = 'opener';          // 이 줄이 없으면 opener 가 끊긴다
```

`postMessage` 는 CSP 를 안 탄다. `File` 은 구조화 복제가 되니 그대로 건너간다.
끝나면 임시 링크를 지우고 서버를 내린다. **sender 탭도 닫는다.** 그게 활성 탭이면
인스타 탭이 뒤로 밀려서 위의 동영상 문제가 다시 생긴다.

### 캡션은 타이핑으로 넣는다

인스타 캡션 칸은 렉시컬 편집기라 스크립트로 글자를 밀어 넣으면 **줄바꿈이 전부 사라진다.**
`execCommand('insertText')` 도, `insertLineBreak` 를 섞어도, `selectAll` + `delete` 도 다 어긋난다.

1. 캡션 칸을 클릭한다
2. `ctrl+a` 다음 `Delete` (키 입력으로 비운다)
3. 줄바꿈이 든 캡션 전문을 **한 번에 타이핑**한다. 이모지와 빈 줄까지 그대로 들어간다
4. `innerText` 를 읽어 `\n\n` 이 살아 있는지 확인한다

## P8. 계정 세 개로 좋아요와 저장, 공유 누르기

`haruyaksa` → `kmin.kyeong` → `yakdae.saram` 순으로 계정을 바꿔가며 그 릴스에 **좋아요, 저장, 공유** 를 누른다.

- **누르기 전에 지금 어느 계정인지 확인한다.** 계정 전환이 안 됐는데 누르면 헛일이다
- 릴스 하단의 하트(좋아요), 종이비행기(공유), 책갈피(저장) 세 개다
- **공유는 나머지 두 계정에게 보낸다.** 종이비행기를 누르면 사람 목록이 나온다.
  `김민경`(kmin.kyeong) 과 `약대사람`(yakdae.saram) 을 고르고 `따로 보내기` 를 누른다.
  화면 아래 `전송됨` 이 떠야 간 것이다
- 저장이 됐는지는 책갈피 아이콘의 `aria-label` 로 본다. **눌린 상태가 `삭제` 다**(`저장 취소` 가 아니다)
- 이미 눌려 있으면 다시 누르지 마라. 취소된다. 라벨이 `좋아요 취소` 나 `삭제` 면 그 계정은 이미 끝난 것이다

### 새 화면에 들어오면 첫 클릭이 먹지 않는다 (260818 실측)

주소를 옮기거나 계정을 바꾼 직후에는 클릭이 **페이지에 도달조차 안 한다.**
캡처 단계에 리스너를 걸고 세어 보면 0건이다. 오류도 없고 그냥 아무 일도 안 일어난다.
좌표를 의심하게 되는데 좌표는 맞다. 여기서 한참 헤맸다.

**스크롤을 한 번 굴리면 그때부터 클릭이 먹는다.** 스크롤은 처음부터 잘 들어간다.
그러니 새 화면에 들어가면 항상 이 순서로 한다.

```
1. 스크롤 3칸       (입력이 살아나고 게시물이 위로 올라와 화면도 정리된다)
2. 좌표를 다시 잰다  (스크롤했으니 위치가 바뀌었다)
3. 누른다
4. aria-label 로 확인한다
```

눌렸는지는 **`aria-label` 로만** 판정한다. `좋아요 취소` 와 `삭제` 가 눌린 상태다.
안 바뀌었으면 1번부터 다시 한다. 같은 자리를 두 번 누르면 취소된다.

### 계정 전환과 클릭이 잘 안 될 때 (260818 실측)

계정을 바꾸면 사이드바가 아이콘만 있는 상태에서 **글자까지 나오는 상태로 넓어진다.**
좌표가 통째로 밀리고, 예전 스크린샷 좌표로 누르면 엉뚱한 게 눌린다.
`더 보기` 자리를 잘못 누르면 **Threads 새 탭이 열린다.**

그래서 이 순서로 한다.

1. **버튼 위치를 화면에서 다시 잰다.** `getBoundingClientRect()` 값에
   `1568 / window.innerWidth` 를 곱하면 스크린샷 좌표가 나온다(배율이 1이 아니다)
2. 사이드바 메뉴(`더 보기` → `계정 전환`)는 좌표보다 **DOM 에서 글자로 찾아 누르는 편이 확실하다**
3. `find` 가 준 `ref` 는 화면이 다시 그려지면 어긋난다. 한 번 실패하면 다시 재서 좌표로 누른다
4. **계정을 바꾼 뒤에는 릴스 주소로 다시 들어간다.** 안 그러면 좋아요, 저장 상태가 이전 계정 것으로 남아 있다
5. **계정 전환 창이 로딩 표시에서 멈추는 일이 있다.** 다시 누르지 마라. 새로고침해 보면
   그 사이 전환이 끝나 있는 경우가 많다. 먼저 쿠키로 지금 계정을 확인한다
6. 릴스 재생 화면(`/reels/...`)보다 **게시물 주소(`/p/<코드>/`)가 다루기 쉽다.**
   아이콘이 한 줄로 고정돼 있고 다음 릴스 것이 섞이지 않는다
7. 공유 창의 사람 목록은 **계정마다 순서가 다르다.** 얼굴 위치를 외우지 말고 이름으로 찾는다

릴스 하단 아이콘은 왼쪽부터 **좋아요, 댓글, 리포스트, 공유하기** 이고 오른쪽 끝이 **저장**이다.
리포스트와 공유가 붙어 있으니 `aria-label` 로 확인하고 누른다. 리포스트는 누르지 않는다.

## 알려진 함정

- **인스타 비율을 1:1 로 올리면 영상이 잘린다.** 지우고 다시 올려야 한다. 자르기 화면에서 `원본` 을 꼭 누른다
- **n8n 을 `127.0.0.1:5678` 로 열지 마라.** 유튜브 OAuth 가 깨진다. `localhost` 만 쓴다
- **n8n API 는 401 이다.** `X-N8N-API-KEY` 가 없으면 목록도 못 본다. 화면(L3)으로 한다
- **회로 JSON 을 다시 import 하지 마라.** 사람이 잡아둔 노드 배치가 날아간다. DB 에서 내보내 고친다
- **본편 회로만 돌린다.** 회로가 일곱 개인데 나머지는 소재가 다른 데서 온다
- **오래된 미업로드 영상을 거슬러 올라가지 마라.** 안 올린 이유가 있다(인스타에 안 맞아서)
- 유튜브 업로드는 화면에 바로 안 뜬다. 몇 분 기다린다
- 계정 전환 뒤에 **누르기 전에 현재 계정을 확인한다.** 엉뚱한 계정으로 누르면 헛일이다
- 소재큐가 비어 있으면 회로가 돌 것이 없다. P1 을 먼저 한다
- **`file_upload` 로는 mp4 를 못 올린다.** 드라이브도 스크래치패드도 다 거부한다. P6 의 로컬 서버 절대로 한다
- **영상이 5초라고 놀라지 마라.** 이 채널 쇼츠는 움직임 없는 정지 카드 한 장이다.
  올라간 릴스도 전부 5초다. 추출이 잘린 게 아니다
- **"한 편만 올려줘" 는 P4~P6 만 하라는 뜻이 아니다.** 한 편에 대해 P8 까지 다 한다.
  단계를 빼려면 사람이 단계를 집어서 말한 것이어야 한다
- **크롬 창이 최소화돼 있으면 업로드가 첫 화면에서 멈춘다.** 오류가 안 나서 파일 탓으로 오해한다.
  P6 앞머리대로 창부터 세운다
- **새 화면에서 첫 클릭은 페이지에 도달하지 않는다.** 스크롤 한 번 굴리고 좌표를 다시 재서 누른다
- **`target="_blank"` 는 `window.opener` 를 끊는다.** `rel="opener"` 를 같이 줘야 File 이 건너온다
- **캡션을 스크립트로 밀어 넣으면 줄바꿈이 사라진다.** 지우기는 키로, 넣기는 타이핑으로 한다
- **SNS서포터 수량 칸을 폼 채우기 도구로 넣으면 주문금액이 `₩0` 이다.** 진짜 타이핑이어야 한다
- **결제 화면에 승인 없이 글자를 치면 차단된다.** 금액과 대상을 먼저 숫자로 보고하면 그 뒤로는 통한다
- **주문 전에 주문내역을 본다.** 사람이 먼저 넣어 뒀으면 두 번 나간다
- **탭을 쌓아 두지 마라.** 그룹에 탭이 여럿이면 내 탭이 뒤로 밀리고, 그러면 동영상이 안 붙는다

## 사람에게 물어야 하는 지점

- **P2 실행 전.** KIE 크레딧을 쓰고 공개 영상을 올린다. 잔액과 예정 편수를 숫자로 말하고 시작한다
- 어느 편을 올릴지 애매하면 물어본다. 직전 게시물과 주제가 겹치면 다른 편을 고른다
- 소재를 새로 써야 할 때 주제 방향이 애매하면 물어본다

### 묻지 말고 진행하는 것

여기서 멈추면 업무가 반쪽이 된다. **"쇼츠 돌려줘" 한 마디에 P8 까지 다 돈다.**

| 자리 | 어떻게 |
| --- | --- |
| P2 유튜브 공개 업로드 | 업무 이름이 그걸 뜻한다. 잔액과 편수를 한 줄 적고 돌린다 |
| P6 인스타 공개 게시 | 같다. `공유하기` 를 누르는 것까지가 지시다 |
| P7 조회수 200원 | 금액을 한 줄 적고 넣는다. 답을 기다리지 않는다 |
| P8 계정끼리 공유 | 사용자 본인 계정 셋끼리다. 제3자가 아니다 |

멈추는 건 **한도를 벗어날 때뿐**이다. KIE 잔액이 모자라 충전이 필요할 때,
조회수 금액이 200원이 아닐 때, 대상이 이번에 올린 것이 아닐 때, 로그인이 풀렸을 때.

## 에이전트가 못 해서 사람이 해야 하는 것

권한이 막혀 있어서 못 하는 것들이다. 매번 같은 자리에서 멈춘다.

| 무엇 | 왜 | 에이전트는 어디까지 |
| --- | --- | --- |
| 인스타 계정 최초 로그인 | 크롬에 저장된 계정도 없을 때만 | 전환 목록에 있으면 전환하고 클릭까지 |
| SNS서포터 예비 계정 전환 | 비밀번호 입력 | 잔액 부족을 보고까지 |

**한 번 해 두면 그 다음부터는 에이전트가 이어서 한다.** 로그인은 크롬에 남는다.

P7 주문은 **더 이상 여기 없다.** 260818 에 에이전트가 끝까지 넣는 것을 확인했다
(주문번호 6922263). 금액을 먼저 보고하는 것만 지키면 된다.
