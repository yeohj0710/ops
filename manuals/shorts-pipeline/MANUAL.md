## P1. n8n 켜고 소재큐 확인하고 보충하기

1. **n8n 이 떠 있는지 본다 (L1)**
   ```bash
   curl -s -o /dev/null -w "%{http_code}" http://localhost:5678
   ```
   `200` 이면 그냥 둔다. 아니면 `<DEV>/n8n-youtube-shorts-automation` 에서 띄운다.
   **`127.0.0.1:5678` 을 쓰지 마라.** 유튜브 OAuth 가 깨진다. 반드시 `localhost`.

2. **소재큐를 센다 (L1)**
   ```bash
   ls "<DEV>/n8n-youtube-shorts-automation/topics/pending" | wc -l                    # 하루건강약사
   ls "<DEV>/n8n-youtube-shorts-automation/topics-health-longevity/pending" | wc -l   # 건강장수비결
   ```
   비어 있으면 채운다. 한 파일이 한 주제다.

3. **비어 있으면 그냥 새로 쓴다.** 영상 데이터가 많아서 그걸 보고 만들면 된다.
   사람에게 주제를 물어보지 말고 아래 겹침 검사만 하고 채운다.

4. **채울 때는 이미 올린 것과 겹치지 않게 한다 (L1)**
   - 완성된 소재 은행: `<DEV>/n8n-youtube-shorts-automation/건강장수비결 소재/` (27개, `final_pack` 포함)
   - 이미 쓴 것: 각 큐의 `used/` `used.jsonl` `upload-log.jsonl`
   - 채널에 올라간 것: 유튜브 채널 동영상 탭을 훑는다 (L3)
   - `topic_key` 로 겹침을 판정한다. 제목만 보고 판단하지 마라

4. **소재 파일 형식.** 대충 써도 n8n 이 랭킹 카드로 정리한다.

### credential 에러가 났을 때 (자주 난다)

유튜브 토큰이 만료되면 업로드 노드에서 인증 오류가 난다. 고치는 법은 정해져 있다.

1. **http://localhost:5678/home/credentials** 로 간다 (L3)
2. 해당 credential 을 누른다. **이름이 채널을 가른다.**
   | credential 이름 | 어느 계정으로 로그인하나 |
   | --- | --- |
   | `youtube account` | **하루건강약사** |
   | `account2` | **건강장수비결** |

   **바꿔서 로그인하면 영상이 엉뚱한 채널로 올라간다.** 누르기 전에 이름을 확인한다.
3. 구글 로그인을 다시 한다. **권한 체크박스를 전부 켜고** 확인을 누른다.
   하나라도 빠지면 업로드가 다시 실패한다.
4. 회로를 다시 실행한다.

**이 로그인 창은 팝업이라 탭 목록에 안 잡힌다.** `runners/*.md` 의 "팝업, 새 창" 절대로 처리한다.
요약하면 이렇다.

```js
// 구글 로그인 버튼을 누르기 전에 심는다
window.__opened = [];
const _open = window.open;
window.open = function(u, ...r){ if(u) window.__opened.push(String(u)); return _open.call(window, u, ...r); };
```

버튼을 누르고 `window.__opened` 에 담긴 구글 인증 주소를 **새 탭에서 연다**
(`tabs_create_mcp` → `navigate`). 거기서 계정을 고르고 권한을 켜고 확인하면
n8n 콜백으로 돌아가 credential 이 저장된다.

**같은 탭에서 열지 마라.** OAuth 는 부모 창에 결과를 돌려주는 구조라 흐름이 깨진다.
계정 선택 화면에서 **어느 계정을 고르는지** 다시 확인한다. 여기서 틀리면 채널이 바뀐다.

   - **최근 몇 개 중 안 올라간 것만** 한다. 오래전에 안 올린 건 이유가 있다(인스타에 안 맞아서).
     오래된 것까지 거슬러 올라가지 마라

2. **뽑는다 (L1). 스크립트가 다 한다.**
   ```bash
   node "<OPS>/manuals/shorts-pipeline/scripts/extract.mjs" --list        # 밀린 것 보기
   node "<OPS>/manuals/shorts-pipeline/scripts/extract.mjs" <영상ID> ...   # 뽑기
   ```
   `--list` 는 **채널별로 가장 최근 준비분 위쪽만** 골라준다. 오래된 미준비분은 알아서 뺀다.
   폴더, mp4, metadata, 업로드 준비.json, 캡션.html 을 규격대로 만든다. 캡션 내용만 P5에서 채우면 된다.

   남의 채널 영상이면 거부한다(채널 ID 두 개만 허용).
   추출기 exe 를 열 필요 없다. 같은 로직을 `yt-dlp` 로 직접 쓴다. `yt-dlp` `ffmpeg` 는 이미 깔려 있다.

3. **폴더 하나에 다섯 개를 만든다.** 기존 폴더를 그대로 본뜬다.
   | 파일 | 무엇 |
   | --- | --- |
   | `<이름>.mp4` | 영상 |
   | `<이름> metadata.json` | 제목, 채널, 채널ID, 원본 URL, 영상 ID |
   | `<이름> caption.txt` | 유튜브용 캡션 (끝이 구독 유도) |
   | `캡션.html` | 인스타용 캡션 (P5에서 만든다) |

   `업로드 준비.json` 의 `target_aspect_ratio` 는 반드시 `original`.

### 파일을 어떻게 넣나 (`file_upload` 는 안 된다, 260817 실측)

크롬 익스텐션의 `file_upload` 는 **드라이브 경로를 거부한다.** "사용자가 공유한 파일만 올릴 수 있다" 고 한다.
`request_directory` 로 그 폴더 권한을 받아도 거부는 그대로다. 그 권한은 Read/Write 용이지 업로드용이 아니다.
스크래치패드로 복사해도 마찬가지다. 이 세션에는 공유 폴더(outputs, uploads)가 아예 없다.

**되는 방법은 이렇다. 로컬 서버에서 페이지로 File 을 넘긴다.**

1. mp4 를 스크래치패드로 복사하고 `127.0.0.1` 에 작은 http 서버를 띄운다.
   `/reel.mp4` 와 `/sender.html` 두 개만 있으면 된다.
2. `sender.html` 은 제 출처에서 mp4 를 `fetch` 해 `File` 을 만들고
   `window.opener.postMessage({file}, 'https://www.instagram.com')` 로 넘긴다.
3. 인스타 페이지에 `message` 리스너를 먼저 심고, `window.open('http://127.0.0.1:PORT/sender.html')` 로 연다.
4. 받은 File 을 `DataTransfer` 에 담아 `input[type=file].files` 에 넣고 `change` 이벤트를 쏜다.

**막히는 곳 세 군데를 미리 알고 간다.**

- 인스타 페이지에서 `fetch('http://127.0.0.1:...')` 는 **CSP 로 막힌다.** `default-src` 에 로컬이 없다
- `<script src="http://127.0.0.1:...">` 도 막힌다. `script-src` 에 `127.0.0.1:*` 이 있지만
  **스킴이 없는 host-source 는 https 문서에서 http 를 안 받는다**
- `window.open` 은 **사용자 동작이 없으면 팝업 차단된다.** 페이지에 임시 버튼을 하나 만들어
  `computer` 로 진짜 클릭을 하고, 그 핸들러 안에서 `window.open` 을 부른다

`postMessage` 는 CSP 를 안 탄다. `File` 은 구조화 복제가 되니 그대로 건너간다.
끝나면 임시 버튼을 지우고 서버를 내린다.

- 이미 눌려 있으면 다시 누르지 마라. 취소된다. 라벨이 `좋아요 취소` 나 `삭제` 면 그 계정은 이미 끝난 것이다

### 계정 전환과 클릭이 잘 안 될 때 (260818 실측)

계정을 바꾸면 사이드바가 아이콘만 있는 상태에서 **글자까지 나오는 상태로 넓어진다.**
좌표가 통째로 밀리고, 예전 스크린샷 좌표로 누르면 엉뚱한 게 눌린다.
`더 보기` 자리를 잘못 누르면 **Threads 새 탭이 열린다.**

그래서 이 순서로 한다.

1. **버튼 위치를 화면에서 다시 잰다.** `getBoundingClientRect()` 값에
   `1568 / window.innerWidth` 를 곱하면 스크린샷 좌표가 나온다(배율이 1이 아니다)
2. 사이드바 메뉴(`더 보기` → `계정 전환`)는 좌표보다 **DOM 에서 글자로 찾아 누르는 편이 확실하다**
3. `find` 가 준 `ref` 는 화면이 다시 그려지면 어긋난다. 한 번 실패하면 다시 재서 좌표로 누른다
4. **계정을 바꾼 뒤에는 릴스 주소로 다시 들어간다.** 안 그러면 좋아요, 저장 상태가 이전 계정 것으로 남아 있다

릴스 하단 아이콘은 왼쪽부터 **좋아요, 댓글, 리포스트, 공유하기** 이고 오른쪽 끝이 **저장**이다.
리포스트와 공유가 붙어 있으니 `aria-label` 로 확인하고 누른다. 리포스트는 누르지 않는다.

## 알려진 함정

- **인스타 비율을 1:1 로 올리면 영상이 잘린다.** 지우고 다시 올려야 한다. 자르기 화면에서 `원본` 을 꼭 누른다
- **n8n 을 `127.0.0.1:5678` 로 열지 마라.** 유튜브 OAuth 가 깨진다. `localhost` 만 쓴다
- **n8n API 는 401 이다.** `X-N8N-API-KEY` 가 없으면 목록도 못 본다. 화면(L3)으로 한다
- **회로 JSON 을 다시 import 하지 마라.** 사람이 잡아둔 노드 배치가 날아간다. DB 에서 내보내 고친다
- **본편 회로만 돌린다.** 회로가 일곱 개인데 나머지는 소재가 다른 데서 온다
- **오래된 미업로드 영상을 거슬러 올라가지 마라.** 안 올린 이유가 있다(인스타에 안 맞아서)
- 유튜브 업로드는 화면에 바로 안 뜬다. 몇 분 기다린다
- 계정 전환 뒤에 **누르기 전에 현재 계정을 확인한다.** 엉뚱한 계정으로 누르면 헛일이다
- 소재큐가 비어 있으면 회로가 돌 것이 없다. P1 을 먼저 한다
- **`file_upload` 로는 mp4 를 못 올린다.** 드라이브도 스크래치패드도 다 거부한다. P6 의 로컬 서버 절대로 한다
- **영상이 5초라고 놀라지 마라.** 이 채널 쇼츠는 움직임 없는 정지 카드 한 장이다.
