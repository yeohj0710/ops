# 영상 프롬프트 설계

대상과 목적이 정해지면 에이전트가 자료 조사, 이야기, 컷 구성, 카메라, 음향을 설계한다. 장소·제품·브랜드·설명 영상·행사·창작 영상에 공통으로 쓴다. **브랜드, 세로 화면, 무인 연출, 5초 길이를 모든 요청의 기본값으로 두지 않는다.**

참고 자료는 사용자가 제공한 [Artlist X Astra Prompt](https://paperlogy.notion.site/Artlist-X-Astra-Prompt-3e50f4883e0c80ac9a92f9cf84aa7a36)와 같은 내용의 첨부문이다. 2026-09-26 연결된 Chrome에서 본문을 확인했다. 자료를 찾고 장면·움직임·소리를 설계하는 구조를 참고했다. 특정 서비스·모델과 정해진 컷 수는 그대로 고정하지 않는다.

## 요청을 제작 기준으로 바꾸기

아래 여섯 가지를 먼저 정한다. 사용자가 이미 말한 내용은 다시 묻지 않는다. 용도에서 분명한 조건은 채우고, 결과를 크게 바꿀 선택만 짧게 확인한다. 조사와 파일 점검은 그동안 진행한다.

| 항목 | 정할 내용 |
| --- | --- |
| 대상 | 무엇을 보여 주나. 실제 장소라면 정확한 지점·주소, 제품이라면 정확한 모델·포장 |
| 목적과 관객 | 누가 보고 무엇을 느끼거나 하길 바라나 |
| 전달할 한 문장 | 그 대상만의 매력이나 설명할 핵심. 이름만 바꿔도 통하는 문장은 다시 쓴다 |
| 납품 | 게시 위치, 길이, 비율, 해상도, 음향·내레이션·자막, 결과 수량 |
| 유지할 것 | 실제 구조, 제품 모양, 로고, 인물, 색상, 확인된 사실 |
| 제작 범위 | 실사 자료의 활용, AI로 만들 부분, 편집할 부분, 예산 상한 |

`templates/creative-brief.md`에 정리한다. 장소를 몰라도 되는 설정 업무에서 임의의 실제 장소를 골라 생성하지 않는다. 실제 제작 요청에서 동명 지점 때문에 자료가 섞일 때만 대상부터 확인한다.

## 목적별 출발점

아래 값은 **제안**이다. 사용자 지시, 납품 채널, 확보한 자료, 모델 사양이 우선한다.

| 목적 | 이야기와 화면 | 길이·비율 제안 | 소리 제안 |
| --- | --- | --- | --- |
| 장소 홍보 | 대표 모습 → 실제 경험 → 장소의 정체성. 외관·내부·대표 활동을 구분 | 별도 조건이 없으면 20초·16:9·1080p | 음악 한 곡과 화면에 맞는 효과음. 말소리는 기본 제외 |
| 제품 광고 | 전체 모습 → 차별점·사용 맥락 → 기억할 제품. 모양과 라벨 유지 | SNS용이면 6~15초·9:16, 가로 광고면 16:9 | 음악·질감 효과음. 설명이 필요할 때만 음성 |
| 브랜드·서비스 | 고객 상황 → 실제 제공 가치 → 다음 행동 | 사용처에 맞춰 길이·비율 결정 | 분위기와 메시지를 정한 뒤 음악·내레이션 선택 |
| 설명·교육·시연 | 질문 → 작동·변화 → 결과. 순서와 원인·결과를 보여 줌 | 설명이 끝나는 길이, 본편과 숏폼을 구분 | 전달력이 필요한 음성·자막 우선 |
| 행사·현장 분위기 | 공간 → 참여·반응 → 핵심 순간 | 행사 소개·예고·기록 목적에 맞춤 | 현장감, 음악, 필요한 말소리의 비중 결정 |
| 창작·서사 | 인물·세계의 규칙 → 변화 → 끝맺음 | 이야기와 승인 예산에 맞춤 | 인물·사건·장면 전환과 함께 설계 |

특정 브랜드의 자료와 제약은 해당 브랜드를 요청했을 때만 적용한다. 예를 들어 한 브랜드의 인물 없는 제작 원칙을 다른 장소 홍보에 자동 적용하지 않는다. 앞선 영상의 색감·악기·카메라·컷 순서를 다음 대상에 기계적으로 복사하지 않는다.

## 조사와 참조 자료

1. 사용자 첨부와 보유 원본을 먼저 본다. 실제 장소의 정식 이름·지점·주요 공간은 공식 자료로 확인하고, 방문자 사진으로 현재 모습을 보완한다.
2. 장소에서는 이름을 알아볼 대표 모습과 방문 이유가 되는 경험을 고른다. 20초 장소 홍보라면 상징 2~3개와 서로 다른 시각적 경험을 우선 찾는다. 작은 가게는 외관·공간·조리·대표 메뉴처럼 구분하고 숫자를 맞추려고 없는 공간을 만들지 않는다.
3. 참조마다 ID, 원본 주소 또는 파일, 출처 페이지, 확인한 특징, 사용 범위를 기록한다. 조사용 사진과 생성에 넣을 수 있는 원본을 구분한다. 로고가 흐리거나 워터마크가 있으면 정식 원본부터 확보한다.
4. 실제 사진, 이미 연출된 광고 이미지, 설계 시안, AI 합성본을 표시한다. 사진에 없는 뒷면·실내·창밖을 사실처럼 채우지 않는다. 실제 자료가 없으면 설명 가능한 범위의 구도로 바꾸거나 가상의 연출로 표시한다.
5. 공식 로고·간판은 원본의 형태와 위치를 보존한다. 정확한 문자가 핵심이면 고정 원본이나 편집 합성을 우선 검토한다. '글자를 정확히 유지'라는 문장만으로 성공을 보장하지 않는다.

## 이야기와 컷표

관객이 처음 이해할 것, 중간에 발견할 것, 끝에 기억할 것을 한 줄씩 정한다. 각 컷에는 **보여 줄 이유 하나와 핵심 동작 하나**를 둔다. 컷마다 더 많은 명령을 얹기 전에 불필요한 대상을 뺀다.

장소 홍보 20초는 대략 8~12컷, 1~3초의 리듬을 출발점으로 삼을 수 있다. 다만 여백이 중요한 장소, 설명이 필요한 동작, 참조가 적은 대상은 컷 수를 줄인다. 같은 사진의 확대·크롭을 새로운 공간으로 세지 않는다. 제품 한 개를 정확히 보여 주는 요청에 이 컷 수를 적용하지 않는다.

컷표에는 다음 열을 둔다.

| 컷 | 최종 시작~끝 | 참조 ID | 장소·대상 | 필요한 이유 | 동작 | 카메라·새로 드러날 것 | 다음 컷 연결 | 음향 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| S01 등 | 초 단위 | R01 등 | 실제로 확인한 내용 | 이야기에서 하는 역할 | 주동작 하나 | 방향·속도·시작과 끝 | 시선·방향·동작·색·소리 중 근거 | 음악 흐름·효과음 시점 |

끝 시각의 합이 아니라 **타임라인 전체가 빈틈·겹침 없이 목표 길이**가 되는지 확인한다. 의도한 겹침 전환이 있으면 최종 편집 길이와 전환 길이를 따로 설계한다. 현재 점검 양식의 타임라인은 겹치지 않는 최종 구간으로 적는다.

## 일관성과 자연스러운 움직임

작품 전체에서 유지할 기준을 먼저 짧게 적는다. 시간대·광원 방향·색감·재료의 질감·카메라 높이·주요 인물의 외모와 옷·제품 개수와 배치가 기준이다. 변하는 항목은 그 이유와 변화 시점을 적는다.

- 카메라는 한 컷에 주된 움직임 하나를 둔다. 정지, 접근, 후퇴, 옆 이동, 추적, 상승, 회전 중 무엇이 장면을 설명하는지 고른다. 모든 컷을 움직이거나 다섯 종류를 채울 필요는 없다.
- 움직이는 컷은 방향·속도·경로·새로 보일 대상을 적는다. 앞·뒤 물체의 위치 변화로 깊이를 만들되 참조에서 확인하지 못한 공간을 크게 드러내지 않는다.
- 로고·제품 라벨이 중요하면 큰 회전과 급격한 접근을 줄인다. 실제 자료가 보장하는 각도 안에서 설계하고, 필요한 경우 고정 촬영과 후반 편집을 선택한다.
- 사람의 수와 동작은 실제 사용 맥락에 맞춘다. 장소를 가리지 않는 거리에서 자연스럽게 걷고 머무르게 한다. 시선의 대상, 손과 물건의 접촉, 몸과 의자·기구의 연결을 구체화한다.
- 손·얼굴·빠른 동작이 핵심이면 무조건 지우지 않는다. 동작을 단순화하거나 구도를 넓히고 짧게 나눈다. 필요한 인물을 제거해 다른 영상으로 만들지 않는다.
- 빛은 화면의 광원과 그림자·반사에 맞춘다. 피부·목재·금속을 같은 광택으로 만들지 않는다. '영화 같게'만 적지 말고 시간대·광원·대비·질감을 정한다.

## 모델에 전달할 프롬프트

작업 지시서 전체를 생성 칸에 붙이지 않는다. **연출 의도 → 유지 조건 → 컷별 문장 → 제외할 오류 → 소리**로 필요한 내용만 정리한다. 한국어로 기획하되 모델이 요구하는 언어와 입력 형식에 맞춰 최종 문안을 별도로 만든다.

이미지 준비가 필요한 컷의 양식:

```text
목적: [이 컷이 전달할 순간].
참조: [R01의 실제 공간/제품과 R02의 로고 등, 각 역할].
유지: [구조·배치·비례·개수·실제 글자와 심벌].
화면: [주대상·거리·높이·프레이밍·안전 여백].
활동: [누가 어디서 무엇을 하는지, 시선과 접촉].
빛과 재료: [광원 방향·시간대·피부/재료·색감].
변경: [원본에서 바꿀 수 있는 항목만].
제외: [이번 장면에서 생기기 쉬운 오류 3~5개].
```

컷별 영상 양식:

```text
참조 [R01]. [주대상]이 [공간]에서 [동작 하나]를 한다.
카메라는 [높이·거리]에서 [방향·속도·경로]로 움직인다/고정된다.
처음에는 [시작 구도], 끝에는 [끝 구도와 새로 드러날 대상].
[원본 구조·제품·인물·빛·글자]를 유지한다.
배경 움직임은 [실제로 있을 움직임]. 다음 컷은 [편집 연결].
효과음은 [화면 속 원인·시점·거리]. 피할 오류는 [선별 목록].
```

여러 컷을 한 번에 받는 모델은 전체 의도와 컷표를 묶는다. 한 컷씩 받는 모델은 공통 유지 기준과 해당 컷만 보낸다. 다른 컷의 참조와 카메라 명령을 섞지 않는다. 참조 번호는 실제 업로드 순서와 다시 대조한다. 모델이 별도 negative prompt 칸을 지원하지 않으면 중요한 제외 조건만 본문에 자연스럽게 합친다.

## 음악·효과음·음성

음악은 장르·주악기·빠르기·정서·구간별 전개·끝맺음을 정한다. 효과음은 실제 화면의 원인과 시점, 거리감을 정한다. 내레이션과 대사, 주변 사람 소리는 각각 필요 여부를 정한다. '소리 있음' 하나로 모두 맡기지 않는다.

장소 홍보 프리셋은 기본적으로 연주곡 한 곡과 장면 효과음을 쓰고 말소리를 빼되, 다른 목적의 음성까지 금지하지 않는다. 여러 클립을 따로 생성하면 클립마다 새 음악을 만들게 하지 않는다. 전체 길이의 음악 한 곡과 클립 효과음을 후반 편집에서 맞추는 방식을 검토한다. 영상 모델이 오디오를 지원하지 않으면 별도 음향 제작·라이선스·편집 비용을 견적에 넣는다.

참고문의 -14 LUFS와 -1 dB는 모든 납품의 규정으로 고정하지 않는다. 필요할 때 평균 체감 음량 -14 LUFS, 실제 최대 피크 -1 dBTP를 게시용 사본의 제안값으로 두고 대상 채널에 맞춰 결정한다. 실제 파일을 측정·청취하고 음악 끊김, 말소리 혼입, 효과음 과장을 검수한다. 프롬프트에 숫자를 적는 것으로 음량 검사를 대신하지 않는다.

## 모델 사양과 견적 연결

1. 현재 모델의 입력 방식, 최대 참조 수, 길이 선택 단위, 해상도·비율, 여러 컷 지원, 오디오 지원, 프롬프트 제한을 확인한다. 참고문에 나온 Artlist 모델명을 Higgsfield의 같은 사양으로 가정하지 않는다.
2. 완성 영상 20초를 요청했다고 한 번에 20초를 생성할 수 있다고 가정하지 않는다. 지원하면 단일 요청, 아니면 컷별 생성과 편집 계획을 세운다. 컷 시간표가 정확히 재현될지도 별도로 검수한다.
3. **편집에 쓸 길이와 과금되는 생성 길이를 나눈다.** 예를 들어 2초 컷 10개를 만들 때 모델의 최소 생성 길이가 4초라면 완성본은 20초여도 생성 분량은 40초다. 모델에 그런 제한이 확인됐을 때만 적용하는 계산 예시다.
4. 영상 전에 이미지 5장 생성, 영상 10개 생성, 음악 1개 생성, 편집처럼 실제 요청 목록을 만든다. 필요한 유료 이미지 준비를 '전처리 0원'에 숨기지 않는다.
5. `templates/shot-plan.json`을 채워 아래 점검을 실행한 뒤 `WORKFLOW.md`의 크레딧·충전 기준 비용 견적에 연결한다. 점검 성공은 사양·타임라인의 형식 검사이며 연출 품질이나 사실성의 보증이 아니다.

```text
node "<매뉴얼>/scripts/plan-check.mjs" "<작업>/etc/shot-plan.json" "<작업>/etc/plan-check.json"
```

## 생성 전 검토와 납품

생성 전에 에이전트가 컷표를 읽고 다음을 고친다. 대상의 정체성이 빠졌는지, 비슷한 컷만 반복하는지, 한 컷에 동작이 과한지, 글자와 기하가 무너질 구도인지, 모델이 지원하지 않는 지시가 있는지, 음악이 편집 도중 끊길지 확인한다. 미리보기용 자료와 숫자 견적을 준비한 뒤 필요한 승인만 받는다.

결과에는 영상, 실제 사용 참조와 출처, 최종 프롬프트 전문, 모델·옵션, 작업 ID, 검수 결과, 실제 차감액을 남긴다. 정체성·형태·동작·카메라·컷 연결·소리를 실제 재생으로 확인한다. 실패 원인을 입력 자료, 프롬프트, 모델 제약, 편집 문제로 나누고 해당 부분을 먼저 고친다. 승인 없이 유료 재생성을 반복하지 않는다.

## 이번 반영 범위

공통 프롬프트 절차와 장소 홍보용 제안, 목적별 선택 기준, 타임라인·요청 수 점검을 설정했다. AI 이미지·영상·음향은 생성하지 않았다. 실제 생성 품질과 특정 모델의 20초 출력은 미검증이다. 문장 구성은 기존 Toss 쉬운 설명 자료를 참고했다.
