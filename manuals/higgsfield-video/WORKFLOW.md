# 힉스필드 견적과 영상 제작

사용자는 만들 영상만 설명하면 된다. 에이전트가 자료를 찾고, 원본을 점검하고, 장면과 프롬프트를 정한다. **돈을 쓰기 전에는 숫자가 있는 견적을 보여준다.** 생성 요청은 준비 작업을 시작하는 지시다. 비용 상한이나 견적 승인이 없으면 결제와 생성 제출은 보류한다.

## 새 세션의 첫 작업

1. `MANUAL.md`, `<에이전트>/기억/SNS 계정 운영/시작.md`, 해당 브랜드의 제품 목록, `힉스필드 영상 제작.md`를 읽는다. 브랜드가 지정돼 있으면 그대로 따르고, 이번 샵인샵 흐름의 기본 브랜드는 어라운드팜이다.
2. 기존 작업 폴더와 작업 ID를 확인한다. 생성 중이거나 완료된 결과가 있으면 이어서 처리한다. 같은 영상을 중복 주문하지 않는다.
3. 현재 MCP 연결과 계정, 모델 사용 자격, 잔액을 읽는다. 저장된 잔액·할인·모델 목록은 현재 값으로 보지 않는다.
4. 영상 용도와 장면을 정한다. 별도 조건이 없으면 세로 9:16, 짧은 단일 장면 1개를 제안한다. 실제 지원 길이·해상도·오디오·참조 수는 현재 모델에서 확정한다.
5. 자료가 부족해도 가능한 기획·무료 전처리·견적은 먼저 끝낸다. 매장 실사가 없으면 '가상의 진열 예시'로 명시한다. 실제 지점을 만들어내지 않는다.

## 무료 전처리

원본은 그대로 둔다. 작업 폴더의 `etc/`에 입력 점검, 프롬프트, 견적, 원본 해시를 저장한다. 외부 편집자에게 공유된 폴더라면 내부 작업물을 먼저 넣지 말고 기존 공유 범위와 비공개 작업 위치를 확인한다. 에이전트 기억 폴더에는 반복 절차와 참조 경로를 둔다.

| 단계 | 할 일 | 통과 기준 |
| --- | --- | --- |
| 원본 점검 | 파일 존재·해시·가로세로·용량·형식·색상 프로필·EXIF 회전을 확인 | 제품과 라벨을 직접 보고 현재 모델의 업로드 조건에 맞음 |
| 구도 | 9:16 또는 모델 지원 비율로 최종 프레임 결정 | 제품·라벨·뚜껑·접지 그림자가 잘리지 않음 |
| 이미지 정리 | 필요하면 로컬에서 회전 보정, sRGB 변환, 축소, 메타데이터 제거 | 원본 보존. 최종 파일을 다시 열어 색·글자·크기 확인 |
| 여백·배경 | 원본 비율이 다르면 제품이 잘리는 자동 중앙 자르기를 하지 않음 | 적합한 세로 사진 또는 합성 구도를 먼저 확정. 단색 여백도 시각 검수 |
| 영상 참조 | ffprobe 등으로 길이·해상도·코덱·오디오 확인 후 필요한 구간만 로컬 추출 | 인물·브랜드·권리·음성 공유 조건 확인. 무조건 전체 업로드하지 않음 |
| 프롬프트 | 피사체·공간·빛·카메라 움직임·유지할 항목을 한 장면에 정리 | 큰 회전, 손 동작, 복잡한 반사, 글자 재생성을 첫 시도에서 줄임 |
| 업로드 | 모델 규격을 확인한 최종 파일만 선택 | 외부 전송 권한을 확인하고 생성·공개 옵션을 별도로 점검 |

로컬 점검 도구는 파일을 바꾸거나 업로드하지 않는다. Pillow가 필요하며 없는 PC에서는 번들 Python 또는 기존 이미지 점검 도구를 쓴다.

```text
python "<매뉴얼>/scripts/preflight.py" "<원본 이미지>" --width 1080 --height 1920 --out "<작업>/etc/input-check.json"
```

`padding_needed`나 `upscale_needed`가 참이면 자동으로 준비 완료로 처리하지 않는다. `ready_for_upload=false`는 시각 검수와 모델 규격 확인을 남겼다는 뜻이다. **AI 배경 생성·AI 보정·업스케일은 무료 전처리에 섞지 않고 별도 비용 단계로 적는다.**

## 매번 보여줄 견적

전처리 파일과 프롬프트를 정한 다음, 생성 버튼을 누르기 전에 현재 모델의 견적을 읽는다. 견적 조회 자체가 유료 작업을 제출하는 도구라면 호출하지 말고 모델 설명 또는 공식 웹의 제출 전 표시를 쓴다. 참고 가격표만 있으면 '참고 견적'으로 표시하고 실제 제출은 미룬다.

견적에는 다음을 함께 적는다.

- 모델, 영상 길이, 화면 비율, 해상도, 오디오, 참조 방식, 수량.
- 이미지 준비·영상·업스케일·오디오 등 단계별 최초 크레딧과 합계. 로컬 작업은 0이다. 하지 않는 유료 단계도 '미사용'으로 적는다.
- 재시도를 포함한 상한. 기본은 1회다. 예비 횟수를 적었다고 자동 재시도 권한이 생기지 않는다.
- **사용분의 충전 기준 가치**: 사용 크레딧 × 선택한 패키지 가격 ÷ 패키지 크레딧.
- **추가 충전에 필요한 현금**: 현재 잔액으로 부족한 크레딧을 채우는 패키지 결제액. 잔액이 충분하면 $0이며, 사용분의 환산 가치가 0이라는 뜻은 아니다.
- 기준 패키지, 가격 확인 시각·출처, USD/KRW 환율과 기준일, 세금·해외결제 수수료 포함 여부.

충전 단가는 **현재 로그인한 계정의 '크레딧 충전' 화면**에서 읽는다. 기본 비교 기준은 가장 작은 구매 가능 패키지다. 사용자가 기준 패키지를 지정하면 그것을 쓴다. 실제 충전 영수증이 제공된 경우에만 실제 매입 단가를 별도로 표시한다. 월 구독료를 월 크레딧으로 나눈 값을 충전 단가로 바꾸어 쓰지 않는다. 반올림된 'US$1 = 16크레딧' 문구 대신 **패키지 실제 가격/실제 크레딧**으로 계산한다.

원화는 현재 확인 가능한 공신력 있는 기준환율로 계산한다. 당일 고시가 없으면 직전 영업일과 날짜를 표시한다. 카드 청구액은 확정하지 않는다. 환율 조회에 실패하면 USD 금액을 유지하고 원화는 '환율 미확인'으로 쓴다. 세금이나 수수료를 모르는데 임의로 10% 등을 더하지 않는다.

```text
node "<매뉴얼>/scripts/refresh-fx.mjs" "<작업>/etc/fx.json"
node "<매뉴얼>/scripts/quote.mjs" "<작업>/etc/요청.json" "<작업>/etc/충전가격.json" "<작업>/etc/견적.json"
```

두 스크립트는 기존 출력 파일을 덮어쓰지 않는다. 갱신할 때는 기존 파일을 `etc/` 안의 백업 위치에 보존하고 정본 이름으로 다시 저장한다. 환율 파일을 확인한 뒤 충전가격 JSON의 `fx`에 넣는다. 이번 요청에서 가격을 다시 읽었을 때만 `verified_for_request_id`를 요청 ID와 맞춘다. 계산기의 `quote_usable=true`는 입력 견적이 갖춰졌다는 뜻일 뿐 **사용자 승인 증거가 아니다**.

요청·가격 양식은 `templates/`에 있다. 계정별 최신 확인 기록은 `<에이전트>/기억/SNS 계정 운영/힉스필드/충전 단가.json`에 둔다. 저장 기록에는 기본적으로 `verified_for_request_id=null`을 둔다. 오래된 할인을 다음 작업에 그대로 적용하지 않는다.

보고 예시(실제 생성 견적 아님):

> 영상 1개, 첫 시도 30크레딧. 100크레딧 $6.25 충전 기준으로 $1.875입니다. 표시액은 $1.88, 환율 1달러=1,355.0469원 기준 약 2,541원입니다. 세금·해외결제 수수료는 제외했습니다. 잔액이 100이라면 추가 충전은 $0입니다. 재생성·업스케일·음성은 포함하지 않았습니다.

## 승인과 실행

| 현재 지시 | 진행 범위 |
| --- | --- |
| '세팅해줘', '견적만', '크레딧 쓰지 마' | 자료·무료 전처리·견적만. 생성·충전 0 |
| '○○ 영상 생성해줘', 비용 한도 없음 | 준비와 견적까지 끝내고 그 견적을 한 번 확인 |
| '○○ 1개, 최대 40크레딧 사용해서 생성해줘' | 제출 전 예상 크레딧·환산액을 알리고, 이미 승인된 40크레딧과 수량 안에서 진행 |
| 표시된 견적에 '그 금액으로 진행' | 그 모델·옵션·입력·수량·상한에만 적용. 바뀌면 재견적 |
| 잔액 부족, 새 충전·구독·체험 필요 | 부족분과 실제 결제액을 보여주고 별도 지시를 기다림 |

이 매뉴얼은 기존 비용 금지나 사용량 초기화 금지보다 우선하지 않는다. 새 세션이 '생성해줘' 한 문장으로 무제한 지출 권한을 얻는 것도 아니다. 명시한 현재 한도나 해당 견적 승인이 있으면 동일한 승인을 반복해서 요구하지 않는다.

현재 PC의 MCP 허용 목록은 조회 전용이다. **기존에 노출된 생성 도구가 있고 이번 지출을 승인받았다면** 도구 사양에 따라 제출한다. 생성 도구가 없으면 같은 계정의 공식 웹에서 입력과 견적을 확인하고 실행한다. 설정을 통째로 풀거나 별도 API 키·타 서비스의 결제 경로로 바꾸지 않는다. 웹에서도 생성이 불가능하면 이유를 기록한다. 연결 성공을 생성 성공으로 보고하지 않는다.

## 중복·실패 방지와 납품

1. 제출 직전에 견적과 최종 설정을 대조한다. 비용·수량이 상한 안인지, 자동 공개가 꺼져 있는지 확인한다. 충전 페이지의 '구매'는 누르지 않는다.
2. 요청 ID, 입력 파일 해시, 프롬프트, 모델·옵션, 견적, 사용자 승인 문장과 범위를 작업 폴더에 저장한다. JSON의 승인 플래그만 보고 지출하지 않는다.
3. 제출 후 서버 작업 ID를 바로 기록한다. 응답이 끊겨도 생성 내역에서 먼저 찾는다. 이미 들어간 요청을 또 제출하지 않는다.
4. 진행 상태는 서버가 안내한 간격으로 조회한다. 재시도·다른 모델·업스케일은 승인된 작업 범위와 남은 상한 안에서만 검토한다. 자동 재시도는 기본으로 끈다.
5. 결과를 내려받아 시작·중간·끝 프레임과 재생을 확인한다. 라벨, 용기, 개수, 선반 수직선, 바닥 접촉, 그림자, 깜박임, 카메라 흔들림, 소리를 본다. 이상이 있으면 실패 이유를 적고 바로 추가 결제하지 않는다.
6. 최종 영상은 해당 브랜드의 요청된 작업 폴더에 저장한다. 견적·작업 ID·실제 차감·환급·원본 결과·검수 기록은 `etc/`에 보존한다. SNS 게시와 외부 공유는 생성 요청에 자동 포함되지 않는다.
7. 최종 보고에는 결과 위치, 최초 견적, 실제 순차감, 충전 기준 USD·원화 환산, 추가 결제 여부를 쓴다. 실제 비용은 작업 ID별 거래를 우선한다. 동시 작업 때문에 잔액 차이만으로 분리할 수 없으면 '정산 미확인'으로 남긴다.
