# 인스타 지표 채우기

- **부르는 말**: 인스타 지표 뽑아줘, 릴스 조회수 측정해줘, 인플루언서 지표 실측, 미측정 채워줘, 팔로워 조회수 채워줘, 빈칸 채워줘, 공개 연락처 채워줘, 좋아요 중앙값 채워줘
- **미리 허가**: 인스타 내부 API 읽기, 통합 원장과 유입 탭의 지표 열 쓰기
- **런너**: codex (계정이 수백 개다). 수십 개면 claude 도 된다
- **제어층**: L3 (로그인된 크롬의 instagram.com 탭 안에서 fetch) → L1 (시트 쓰기)
- **한 번에 걸리는 시간**: 계정 100개당 약 4분. 700개면 25분 안팎

빈칸이면 `예상 조회수` 수식이 팔로워 곱하기 구간 계수로 추정하는데, 실측과 몇 배씩 벌어진다.

**정확할 필요는 없다. 빠르게 몇 편만 보고 대충 맞으면 된다.** 릴스 한 편만 보여도 그 값을 쓴다.

## 지난 런이 왜 실패했나

260829 에 원인 셋을 다 잡았다. 같은 실수를 반복하지 마라.

1. **숫자 열에 글자를 적었다.** 릴스가 없거나 오류가 나면 `릴스없음`, `비공개`, `오류400` 을
   릴스 중앙 조회수 칸에 적게 돼 있었다. 그러면 수식이 죽고 사람 눈에는 "비공개래" 로 보인다.
   **숫자 열에는 숫자만 쓴다.** 사유는 `조회수 근거` 나 `계정 상태` 에 적는다
2. **인스타가 400 을 내는데 계정이 없는 줄 알았다.** `web_profile_info` 가 일부 계정에서
   `Asset asset://laser.provider/ig_business_category_subvertical has been deleted` 라는 400 을 낸다.
   **인스타 응답 스키마가 깨진 것이지 계정 문제가 아니다.** 260829 표본 17개 중 3개(18%)가 그랬다.
   다시 돌려도 같은 계정이 또 400 이라 "재시도해도 또 비공개" 로 보였다.
   **우회 경로가 있다.** `topsearch` 로 pk 를 찾아 `users/{pk}/info/` 를 부르면 멀쩡히 나온다
3. **한 계정마다 에이전트가 한 번씩 돌았다.** 계정당 왕복이 생겨서 수백 개면 몇 시간이 걸린다.
   **수집은 브라우저 안에서 떼어 놓고 돌리고, 에이전트는 가끔 진행률만 본다**

## 채우는 규칙

**이 표가 이 업무의 전부다.** 여기서 벗어나지 마라.

| 시트 열 | 넣는 값 | 값이 없으면 |
| --- | --- | --- |
| 릴스 중앙 조회수 | 릴스 중 조회수가 보이는 것들의 **중앙값**. 한 편만 보여도 그 값을 쓴다 | **빈칸으로 둔다.** 글자를 쓰지 마라 |
| 좋아요 중앙값 | 좋아요가 보이는 글의 중앙값 | 빈칸으로 둔다 |
| 팔로워 | 실측 팔로워 수 (콤마 없이) | 빈칸으로 둔다 |
| 공개 연락처 | 이메일, 전화, 외부 링크를 `; ` 로 잇고 끝에 `Instagram DM` | `Instagram DM` 만 적는다 |
| 조회수 근거 | `릴스 N편 실측` | `릴스 없음`, `비공개 계정`, `조회수 숨김` |

**릴스가 없다고 좋아요로 조회수를 추정하지 마라.** 260829 에 17개 계정에서 재 봤더니
조회수 나누기 좋아요가 14.6 에서 4,284 까지 벌어졌다(중앙 55). 293배 차이라 추정으로 못 쓴다.
**릴스 중앙 조회수를 비워 두면 `예상 조회수` 수식이 팔로워 구간 계수로 알아서 추정한다.**
그게 이미 만들어진 길이고, 빈칸이 그 길을 여는 신호다.

**"비공개" 는 API 의 `is_private` 가 true 일 때만 쓴다.** 그것도 숫자 열이 아니라 근거 열에 쓴다.
시트에 이미 적혀 있는 `미측정`, `미확인`, `비공개` 는 지난 런이 못 본 것이니 **덮어쓴다.**

**사람이 손으로 넣은 열은 건드리지 마라.** 진행 상태, 합의 단가, 협상 메모, 확정, 방문 예정일,
배정 건이다. 그리고 **값이 이미 들어 있는 지표 칸도 건드리지 마라.** 빈칸만 채운다.

## 절차

1. **채울 대상을 뽑는다 (L1)**

   두 탭을 gviz CSV(`headers=2`)로 받아 `<OPS>/work/<taskId>/before/` 에 저장한다.
   **열은 머리글 이름으로 찾는다.** 열 문자를 외워 쓰지 마라.

   그다음 **빈칸인 행만** 골라 핸들 목록을 만든다. 플랫폼이 인스타그램인 행만 대상이다.
   목록을 `targets.json` 에 `[{i, 행, 계정}]` 로 저장한다. `i` 는 0부터 세는 순번이고
   수집기가 이 번호로 결과를 돌려준다.

2. **instagram.com 탭을 하나 연다 (L3)**

   아무 페이지나 좋다. 프로필을 열 필요가 없다. 로그인 화면이 뜨면 준비물로 돌아간다.
   **fetch 는 반드시 이 탭 안에서 부른다.** 다른 출처에서 부르면 CORS 로 막힌다.

3. **수집기를 심고 떼어 놓고 돌린다 (L3)**

   `scripts/harvest.js` 를 통째로 붙여넣는다. 그다음 목록을 넘긴다.

   ```js
   IGM.start(["handle1", "handle2", "..."], { reset: true, gap: 1200 })
   ```

   **바로 반환한다.** 수집은 뒤에서 계속 돈다.

   `이게 보이면 성공`: `{받음: N, 총: N, 시작index: 0}` 이 온다.

4. **가끔 진행률만 본다 (L3)**

   ```js
   IGM.status()
   ```

   **폴링에 `sleep` 을 넣지 마라.** 브라우저 도구의 JS 호출은 45초에서 끊긴다.
   기다리는 코드를 넣으면 호출이 죽는다. 기다려야 하면 에이전트 쪽에서 쉬고 다시 부른다.

   `멈춤사유` 에 `차단 401` 이나 `차단 429` 가 들어오면 **거기서 끝낸다.** 재시도하지 마라.
   그때까지 모은 것을 저장하고, 몇 개까지 했는지 적어 보고한다.

5. **결과를 받아 저장한다 (L3)**

   ```js
   IGM.take(0, 200)   // 그다음 IGM.take(200, 200) ...
   ```

   **한 번에 200개를 넘기지 마라.** 응답이 잘린다.
   받은 것을 `<OPS>/work/<taskId>/harvest.json` 에 합쳐 저장한다.

   돌아오는 열쇠는 이렇다. 계정 이름은 안 온다. `i` 로 `targets.json` 과 맞춘다.

   | 열쇠 | 뜻 |
   | --- | --- |
   | `i` | 넘긴 목록의 순번 |
   | `f` | 팔로워 |
   | `rm` | 릴스 중앙 조회수. **null 이면 시트를 비워 둔다** |
   | `vn` | 조회수가 보인 릴스 편 수. 근거 문구에 쓴다 |
   | `rn` | 릴스 편 수 |
   | `lm` | 좋아요 중앙값 |
   | `c` | 연락처 배열 (이메일, 전화, 링크) |
   | `last` | 최근 게시일 |
   | `st` | `측정`, `릴스없음`, `조회수숨김`, `비공개`, `계정없음`, `차단NNN` |
   | `via` | 1 이면 400 우회 경로로 받았다 |

6. **쓰기 계획을 만들고 검사를 통과시킨다 (L1)**

   `write-plan.json` 에 탭, 열쇠 열, 채울 열, 보호 열, 연산을 적는다.
   **`operations` 에는 지금 빈칸인 칸만 넣는다.** 값이 있는 칸을 넣으면 안 된다.

   ```text
   node "<OPS>/manuals/influencer-seeding/scripts/validate-write-plan.mjs" \
     "<OPS>/work/<taskId>/write-plan.json" \
     --out "<OPS>/work/<taskId>/write-plan.validated.json"
   ```

7. **열 단위로 쓰고 다시 읽는다 (L1)**

   한 요청에 **한 열의 연속 구간**만 쓴다. 여러 열을 한 번에 붙여넣지 마라.
   폭이 한 칸 어긋나면 옆 열을 통째로 덮는다.

   쓰기 직전에 계정 열을 다시 읽어 순서가 그대로인지 확인한다. 다르면 멈춘다.
   구간을 하나 쓸 때마다 그 구간과 좌우 인접 열을 다시 읽는다.

   **`updateCells` 의 `rows[].values` 사이에 `{}` 를 끼우지 마라.** 건너뛰기가 아니라 그 칸을 지운다.

8. **대조하고 보고한다 (L1)**

   `after/` 에 다시 받아 `sheet-diff.mjs` 로 대조한다.

   ```text
   node "<OPS>/manuals/influencer-seeding/scripts/sheet-diff.mjs" \
     --before "<OPS>/work/<taskId>/before" --after "<OPS>/work/<taskId>/after" \
     --allow "<OPS>/work/<taskId>/write-plan.validated.json" \
     --out "<OPS>/work/<taskId>/diff.json"
   ```

   보고에는 이걸 넣는다. 탭별 채운 행 수, `st` 분포, 릴스 중앙 조회수의 최소와 중앙값과 최대,
   **팔로워 추정치와 실측이 3배 이상 벌어진 계정 목록**(단가를 다시 봐야 한다),
   그리고 기준일. 같은 계정을 다시 부르면 조회수가 조금씩 오르니 날짜를 적는다.

9. **열어 둔 탭을 닫는다 (L3)**

## 알려진 함정

- **`web_profile_info` 400 은 계정 문제가 아니다.** `ig_business_category_subvertical` 스키마가
  깨져서 나는 인스타 쪽 오류다. 260829 표본 17개 중 3개가 그랬고 재시도해도 똑같이 400 이 난다.
  `topsearch` 로 pk 를 찾고 `users/{pk}/info/` 로 우회하면 팔로워, 바이오, 비공개 여부가 다 나온다.
  `harvest.js` 가 이미 이 우회를 한다. **400 을 보고 계정없음으로 적지 마라**
- **릴스가 하나만 보여도 그 값을 쓴다.** 아홉 편이나 열두 편을 다 봐야 한다는 규칙은 없다.
  그 규칙 때문에 601행이 빈칸으로 남았다
- **좋아요로 조회수를 추정하지 마라.** 배수가 14.6 에서 4,284 까지 벌어진다. 중국어권 계정은
  조회수가 정상인데 좋아요만 한 자리인 경우가 흔하다
- **`like_count` 는 좋아요를 숨긴 글에서 `-1` 이나 `0` 으로 온다.** 그대로 중앙값을 내면 3 같은
  숫자가 나온다. **`> 0` 인 것만 세라**
- **브라우저 도구의 JS 호출은 45초에서 끊긴다.** 계정을 열몇 개만 넣어도 한 호출 안에서
  기다리면 죽는다. 수집기를 떼어 놓고 돌리고 폴링은 즉시 반환하게 한다
- **결과에 계정 이름을 담아 돌려주면 지워진다.** 점이 든 핸들(`wander.with.zoey`)을
  돌려주면 도구가 토큰으로 오인해 `[BLOCKED: JWT token]` 으로 바꾼다.
  쿼리스트링이 붙은 URL 도 같다. **순번(`i`)으로 돌려받고 URL 은 경로까지만 남긴다**
- **게시물(격자) 탭 DOM 에는 조회수가 아예 없다.** 릴스 탭은 지연 로딩이라 안 붙는 계정이 많다.
  **DOM 을 읽지 마라.** 이 업무는 API 로만 한다
- **`web_profile_info` 의 `edge_owner_to_timeline_media.edges` 는 빈 배열로 온다.**
  게시물은 `feed/user/{pk}` 로 받는다. `.count` 는 정상이다
- **`feed/user` 는 `count=33` 을 줘도 한 번에 12개쯤만 준다.** 릴스가 그 안에 없으면
  `next_max_id` 로 한 페이지 더 간다. 두 페이지까지만 하고 없으면 릴스 없는 계정으로 본다
- **피드 앞쪽은 고정 게시물이라 날짜순이 아니다.** 최근 게시일은 `taken_at` 최대값으로 구한다
- **`/api/v1/clips/user/` (릴스 전용 POST) 는 HTML 을 돌려준다.** 막혔으니 쓰지 마라
- **API `play_count` 와 릴스 탭 화면 표기가 5% 안팎 다르다.** 한 산출물에 섞지 마라. 이 업무는 API 값이다
- **401 이나 429 가 뜨면 즉시 멈춘다.** 재시도를 반복하면 계정이 잠기고 다음 런까지 막힌다.
  그 계정은 섭외 DM 을 보내는 계정이라 잠기면 업무가 통째로 선다
- **간격을 1초 밑으로 내리지 마라.** 260829 에 1.1초로 700회 가까이 돌려도 차단이 없었다. 그 선을 지킨다
- **다른 세션이 같은 시트를 동시에 만진다.** 열 번호가 어긋날 수 있으니 절차 1번을 건너뛰지 마라

## 묻지 말고 이렇게 한다

- **릴스가 없으면** 그 칸을 비우고 근거에 `릴스 없음` 을 적는다. 추정하지 않는다
- **연락처가 하나도 없으면** `Instagram DM` 만 적는다
- **400 이 나면** 우회 경로로 한 번 더 간다. 그래도 안 되면 `계정없음` 으로 근거에만 적는다
- **팔로워가 시트 값과 다르면** 실측으로 덮는다. 사람이 손으로 넣는 열이 아니다
- **차단되면** 그때까지 모은 것을 쓰고 몇 번째까지 했는지 적어 보고한다. 다시 시도하지 않는다

## 사람에게 물어야 하는 지점

- 계정이 잠겨서 로그인을 다시 해야 할 때. 비밀번호는 사람이 넣는다
- 대상 시트가 매뉴얼에 없는 것일 때
- 비공개 계정에 팔로우 요청을 보내야 할 것 같을 때. **보내지 마라.** 상호작용은 이 업무 밖이다
- 실측이 팔로워 추정과 몇 배씩 벌어져 이미 부른 금액을 다시 봐야 할 때
