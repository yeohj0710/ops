# 어라운드팜 인스타그램 운영

- **부르는 말**: 어라운드팜 운영해줘, 어라운드팜 인스타 운영, 어라운드팜 오늘 할 일, 어라운드팜 편성표 짜줘, 어라운드팜 다음 달 계획표, 어라운드팜 기획안 써줘, 어라운드팜 카드뉴스 만들어줘, 어라운드팜 릴스 캡션 써줘, 어라운드팜 올려줘, 어라운드팜 게시해줘, 어라운드팜 댓글 봐줘, 어라운드팜 DM 봐줘, 어라운드팜 주간 리포트, 어라운드팜 월간 리포트, 바로팜 인스타 운영
- **미리 허가**: 어라운드팜 인스타 계정에 릴스와 카드뉴스 공개 게시, 정보성 댓글 답글 게시, 노션 기획안 DB 쓰기, 드라이브 운영 폴더 쓰기. 슬랙 게시와 DM 답장, 악플 삭제는 초안과 목록만 만들고 사람이 한다
- **런너**: claude
- **제어층**: L1 (드라이브 파일, 노션 MCP, 피그마 MCP, 지표 수집 스크립트) → L3 (인스타 게시, 댓글, 인사이트, 레퍼런스 캡처)
- **한 번에 걸리는 시간**: 갈래마다 다르다. 오늘 할 일 판정 10분, 편성표 20~30분, 기획안 한 편 15~20분, 카드뉴스 한 벌 40~60분, 게시 한 편 10~15분, 주간 리포트 30~40분

## 무엇을 만드는 업무인가

바로팜이 운영하는 뷰티 약국 브랜드 **어라운드팜**의 인스타그램 4개 계정(한국어 본계정, 영어, 중국어, 일본어)을
**기획안대로 굴린다.** 기획, 제작, 발행, 댓글과 DM 관리, 주간과 월간 리포트가 전부 이 매뉴얼 하나에 있다.
사람은 "어라운드팜 올려줘" 처럼 계정 이름과 갈래만 말한다.

기획안 원본은 `<드라이브>/[운영] 어라운드팜 인스타그램/` 의 PDF 31장인데 **PDF 텍스트 추출이 깨진다**(피그마 서브셋 폰트).
그래서 같은 폴더의 **`기획안.md`** 에 31장 전부와 260901 미팅 결정을 글로 옮겨 뒀다. 기획안이 필요하면 그 파일을 읽는다.
PDF 를 다시 뜯지 마라.

**약사 개인 계정(하루건강약사, 오약 등)의 카드뉴스는 이 매뉴얼이 아니다.** 그건 `manuals/card-news` 다.
계정 이름 없이 "카드뉴스 만들어줘" 라고만 했으면 그쪽이다.

## 쉬운 설명

### 쓰는 상황

바로팜과 계약한 어라운드팜 인스타그램을 매주 굴려야 합니다. 월수금은 카드뉴스, 화목토는 릴스가 나가고,
매주 월요일에 주간 리포트, 매달 말에 월간 리포트와 다음 달 편성표를 바로팜에 보냅니다.

### 시키는 말

> G드라이브 에이전트 폴더 참고해서 어라운드팜 인스타그램 운영 업무 해줘

세팅이 끝난 컴퓨터에서는 "어라운드팜 올려줘", "어라운드팜 주간 리포트" 처럼 갈래를 붙여 줄여 말해도 됩니다.
갈래 없이 "어라운드팜 운영해줘" 라고 하면 오늘 날짜로 할 일을 스스로 정해서 합니다.

### 진행 순서

1. 드라이브 운영 폴더의 편성표와 노션 기획안 목록을 보고 오늘 무엇이 밀렸는지 봅니다.
2. 밀린 것부터 합니다. 기획안이 없으면 쓰고, 카드뉴스가 없으면 만들고, 만든 것이 있으면 올립니다.
3. 올린 뒤에는 노션 상태를 바꾸고 드라이브 폴더를 `업로드 완료` 로 옮깁니다.
4. 월요일이면 주간 리포트, 25일 이후면 다음 달 편성표와 월간 리포트를 씁니다.
5. 슬랙에 올릴 글은 초안까지만 씁니다. 사람이 올립니다.

### 결과물

드라이브 `[운영] 어라운드팜 인스타그램/` 안의 `콘텐츠/`, `편성표/`, `리포트/` 폴더와 노션 기획안 DB 상태,
그리고 인스타에 올라간 게시물입니다.

## 실행 계약

사용자가 이 업무를 호출하면 해당 갈래의 절차와 완료 검사를 한 번에 실행한다. 게시 직전에 다시 승인받지 않는다.
계정, 파일, 캡션, 비율만 확인하고 올린다. 중간 산출물만 남기고 멈추지 않는다.

멈추는 것은 넷이다. **슬랙과 DM 으로 남에게 보내는 것**(초안만), **댓글 삭제**(목록만), **매뉴얼 밖 지출**(올리브영 제품 구매 포함),
**언어 계정 핸들이 확인 안 된 상태에서 그 계정에 올리는 것**(본계정만 올리고 보고).

### 콘텐츠 형식

릴스 네 형식을 월 3편씩, 카드뉴스는 홍익약국 형식 하나로 간다. 9월과 10월은 이 넷을 그대로 돌리고 지표 하위 형식을 교체한다.

| 형식 | 무엇 | 화자 | 첫 화면과 요령 |
| --- | --- | --- | --- |
| A 약국 방문 인터뷰 | 약국을 방문한 분께 어떤 제품을 샀는지 묻는다 | 방문 손님(섭외한 분도 가능) | 홍익약국 앞이나 안. 변형은 **약국 퀴즈** (OX 3문항, 전 문항 정답 시 제품 증정. 참여만 해도 샘플). 이번 달 고정 콘텐츠 |
| B 약사 출연 | 올리브영 베스트와 약국 베스트를 소개하며 등급을 매긴다 | 약사 | 변형 4종: 점수제(10점 만점 큰 숫자), 역순 배치(S급부터 아쉬운 제품까지), 다음 편 예고(마지막 컷에 다음 제품), 올리브영 베스트 대 약국 베스트(같은 선크림 비교) |

- **제품 범위를 넓힌다.** 약국 제품만으로는 외국 유저 모수가 좁다. 올리브영 제품을 섞고, 샵인샵이 아닌 레디영과 홍익약국도 노출한다 (260901)
- 샵인샵 제품 25종과 소비자가는 `기획안.md` 의 제품 표에 있다. **제품 정보는 지어내지 마라.** 브랜드 공식 자료와 `G:/공유 드라이브/샵인샵자료/` (QR모음, 동영상, 이미지, 편집본)에서 옮긴다
- 조회 잘 나온 편의 첫 화면은 매장 간판, 약사 얼굴, 면세 가격표, 역 출구 표지판 중 하나였다. **제품 단독 컷으로 시작한 편은 상위에 없다** (260828 실측). 조회 10만 넘은 편 중앙 57초. 짧게 치지 말고 길게 설명한다
- 교체 후보 E 약사 인플루언서 동반 출연, F 바로팜 팀원과 인턴 출연, G 크리에이터 공동 게시. 두 달 연속 지표 하위면 그 형식을 빼고 후보를 3편 시험한다

### 출연진

앵커 약사 한 분(편당 단가 별도, 3개월째부터 월 12편 중 3~4편), 약사 인플루언서(초반에 번갈아, 조회수 좋은 분께 주 1편 고정 요청), 바로팜 팀원과 인턴(카드뉴스와 제품 소개, 얼굴을 내세우지 않음), 손님과 배우.
앵커 약사는 양측이 찾는다. 아직 없다.

### 하이라이트와 링크

- 하이라이트 6구획: 신제품 NEW IN, 이벤트 EVENT, 인기 순위 BEST, 약사 추천 PICK, 계절템 SEASON, 사용법 HOW TO. **약국 찾기와 입점 문의는 빼고 링크 페이지로** (업자 계정으로 보이면 댓글과 공유가 준다). 커버 타입(타이포형, 그래픽형, 제품 실사형)은 채널명과 같이 정한다. 웰니스박스는 그래픽형을 권했다
- 링크 페이지(인포크링크 구성안): 상단 배너(신제품 또는 진행 중 이벤트) / 지금 진행 중(최근 릴스에 나온 제품, 이달 매대 신제품) / 콘텐츠 모음(조회 상위 릴스와 이달 카드뉴스) / **팔로워 2만 이후 추가**(약국 찾기, 어라운드팜 앱 설치, 브랜드 입점 문의)

| 언어 | 한국어, 영어, 중국어, 일본어. 같은 소재를 시장별로 따로 만들지 않는다. 발행 시각만 현지 시간대로 분리하고 지표는 계정별로 나눠 집계 |
| 초기 | 완성본 30편 선확보. 편집이 외주라 어떤 편이 먼저 나올지 통제가 어려워 미리 쌓는다 |
| 9월 | 9/1~9/9 준비, 9/7~8 첫 촬영, 9/10 카드뉴스 발행 시작, 9/15 부터 릴스 화목토. 10/1~3 10월 편성 |
| 제작 순서 | 기획(형식 표에서 소재, 대본, 촬영 목록) → 촬영(약국 한 번 방문에 5~6편 몰아 찍기) → 편집(외주, 자막과 배지 규칙 전달) → 검수(서체, 색, 링크 네 자리) → 발행(예약, 네 계정 차례로) |
| 편집 실비 | 편당 1만 5천 원 안팎이 운영비와 별도로 나간다 (바로팜에 참고 사항으로 전달함) |

**발행량은 계약상 확약이 아니다.** 주 6편은 기준이다. 260828 실측으로는 어라운드팜이 주 4.4편으로 이미 발행량 1위였는데 24편 조회 합계가 7.2만이었다. 편수보다 구성(릴스 비중, 길이, 공동 게시)이 갈랐다. 편수를 채우려고 질을 떨어뜨리지 마라.

### P0. 오늘 할 일을 정한다 (L1)

갈래 없이 시켰을 때 한다. 갈래를 말했으면 그 절차로 바로 간다.

1. 폴더를 확인하고 없으면 만든다.
   ```bash
   node "<OPS>/manuals/aroundpharm-sns/checks.mjs"
   ```
2. `편성표/<이번 달>.md` 를 연다. 없으면 P1 부터다.
3. 오늘 요일의 슬롯을 본다. 월수금 카드뉴스, 화목토 릴스.
4. 노션 기획안 DB 두 개를 상태별로 센다 (`notion-query-data-sources`, SQL 로 `상태` 집계).

5. `콘텐츠/` 에서 `업로드 완료` 밖에 있는 폴더를 센다. 미게시가 있으면 오늘 슬롯에 맞는 것을 P5 로 올린다.
6. 오늘 슬롯에 올릴 것이 없으면 P3 (카드뉴스 슬롯) 또는 P4 (릴스 슬롯, 편집본이 있을 때) 로 만든다.
7. 월요일이면 P7 주간, 25일 이후면 P1 다음 달 편성표와 P7 월간을 뒤에 붙인다.
8. 끝에 무엇을 했고 무엇이 막혔는지 한 번에 보고한다.

### P1. 다음 달 편성표를 짠다 (L1)

매달 25일 이후에 한다. 결과는 `편성표/YYYY-MM.md` 다.

1. 지난달 편성표와 노션 DB 를 보고 이월할 소재를 뽑는다.
2. 요일 고정으로 깐다. 화목토 릴스에 A, B, C, D 를 3편씩 돌려 넣고, 월수금 카드뉴스는 그 주 릴스 소재를 같은 틀로 재구성한 것을 넣는다.
   형식 교체 규칙(두 달 연속 하위 형식 제외, 후보 E F G 투입)은 월간 리포트의 형식별 지표를 보고 반영한다.
3. 촬영일을 넣는다. 약국 한 번 방문에 5~6편을 몰아 찍으니 릴스 4편당 촬영 1회 꼴이다.
4. 표 형식은 이렇다. 칸에는 형식만 적는다. 소재까지 박으면 조정이 안 된다.

   ```
   | 날짜 | 요일 | 슬롯 | 형식 | 상태 |
   | 10/01 | 목 | 릴스 | A | 예정 |
   ```
5. 슬랙에 올릴 안내 초안을 `편성표/YYYY-MM 안내 초안.md` 로 둔다. 다음 달 계획표는 월간 리포트와 함께 나간다 (P7).

### P2. 기획안을 쓴다 (L1, 레퍼런스 볼 때 L3)

편성표의 빈 슬롯 하나를 골라 노션 기획안 DB 에 새 페이지로 쓴다. **DB 가 이미 사람 손으로 채워지고 있다** (260907 기준 릴스 5건, 카드뉴스 16건). 같은 소재가 있는지 먼저 본다.

1. 형식 표에서 소재를 고른다. 샵인샵 제품(`기획안.md` 표), 올리브영 제품, 환절기 소재 순으로 폭을 넓힌다.
2. 레퍼런스를 찾는다. 콘텐츠 제작 Tip 기준으로 **팔로워는 적은데 조회수가 큰 편**(팔로워 3만에 조회 100만 같은 것)을 찾고, 1년 넘은 편은 피한다. 주제와 포맷이 둘 다 겹치면 카피다. 성공 요인만 가져온다.
3. DB 템플릿 구조 그대로 쓴다. `notion-create-pages` 에 `parent` 로 data source 를 준다.
   - 릴스: `## 요약` 한 줄 / `## 장면 구성` 표(장면 설명, 대사와 자막) / `## 배경 음악` / `# 편집자 노트` (데드존 피하기, 대사 끊김 없이). 템플릿의 체크리스트 토글은 그대로 두고 아래 항목만 채운다
   - 카드뉴스: `## 요약` (형식 레퍼런스 링크) / `## 카드뉴스 구성` 표(페이지, 내용 구성. 첫 행이 썸네일) / `# 편집자 노트`
   - 속성: `이름` 은 제목, `상태` 는 `작성 완료(검토 대기)`, `업로드 예정일` 은 편성표 날짜(글자). `사람` 은 비운다
4. 제목은 명사구. 대사는 입으로 하는 말. 의약품 효능을 단정하는 문장, 약국 확인 없는 가격은 넣지 않는다.
5. 쓴 뒤 `notion-fetch` 로 다시 읽어 한글이 안 깨졌는지 본다.

상태 값 13개는 `작성 중, 작성 완료(검토 대기), 반려됨, 수정 필요, 채택됨, 녹화 확정, 녹화 완료, 편집 중, 편집 완료, 업로드 예정, 업로드 완료, 보류됨, 기획안 보류` 다. 다른 글자를 넣지 마라.

### P4. 릴스 캡션과 자막을 쓴다 (L1)

편집본이 `콘텐츠/<YYMMDDhhmm 제목 (릴스 A) (aroundpharm_official)>/` 에 mp4 로 와 있을 때 한다. 편집자가 다른 곳에 두면 여기로 옮기고 편성표에 적는다.

1. 영상을 1초에 한 장씩 잘라 직접 본다 (`manuals/caption-gen` 의 방법). 화면의 제품 이름, 성분, 말하는 순서가 재료다.
2. 캡션은 브랜드 계정 톤이다. 첫 줄 후킹 한 줄, 본문 두세 문단, 저장이나 공유 유도 한 줄, 해시태그 3개 안팎(주제를 알고리즘에 알리는 용도), 링크는 "프로필 링크" 로 안내. 다음 게시물을 예고하는 문장은 넣지 않는다.
3. 자막 규칙 검수: 제목 위, 설명 아래, Pretendard, 배지 하나, 데드존 회피. 어긋나면 편집자에게 돌려보낼 메모를 `편집 비고` 에 적는다.
4. `캡션.txt` 와 `캡션.html` 을 폴더에 둔다. 영어 캡션은 `캡션.en.txt`. 중국어와 일본어는 `번역 요청.md`.
5. 고정 댓글 문안을 `고정댓글.txt` 로 둔다. 링크 페이지 주소와 그 편 제품 이름이 들어간다.
6. 노션 상태 `업로드 예정`.

1. 로그인된 탭에서 본계정 피드를 받아 저장한다. 계정 숫자 id 는 프로필 HTML 의 `"profile_id":"(\d+)"` 다.
   ```js
   const r = await fetch("/api/v1/feed/user/<id>/?count=30", { headers: { "x-ig-app-id": "936619743392459" } }).then(r => r.json());
   JSON.stringify((r.items||[]).map(i => ({ code: i.code, taken: i.taken_at, cap: (i.caption?.text||"").split("\n")[0] })))
   ```
2. 올릴 한 편을 스크립트가 정한다. **가장 오래된 미게시 한 편**이다.
   ```bash
   node "<OPS>/manuals/card-news/scripts/cardnews-next.mjs" "<피드.json>" --root "<드라이브>/[운영] 어라운드팜 인스타그램/콘텐츠" --account aroundpharm_official
   ```
   mp4 가 든 폴더는 릴스로, png 만 든 폴더는 카드뉴스로 판정한다. 후보가 없으면 종료 코드 3 이고 이번 호출에서는 올리지 않는다.
3. **게시 화면의 계정명을 확인한다.** 쿠키 `ds_user_id` 로 `/api/v1/users/<id>/info/` 를 불러 `username` 이 `aroundpharm_official` 인지 본다. 아니면 계정 전환(좌표 말고 DOM 글자로 `.click()`) 뒤 다시 연다.
4. 파일을 넘긴다.
   ```bash
   node "<OPS>/manuals/shorts-pipeline/scripts/insta-file-server.mjs" "<고른 폴더>"
   ```
   카드뉴스는 `card-news` U3~U4 (배경 탭에서도 붙는다, 자르기 `4:5`), 릴스는 `shorts-pipeline` P6 (크롬 창을 앞으로, 자르기 `9:16`) 그대로.
5. **캡션은 게시 뒤 수정 화면에서 넣는다.** 게시 화면에서 넣으면 빈 채로 나간다 (card-news U4-1). 넣은 뒤 `/api/v1/media/<pk>/info/` 의 `caption.text` 길이로 확인한다.
6. 고정 댓글을 단다. `고정댓글.txt` 를 댓글로 쓰고 고정한다.
7. 게시를 API 로 확인한 뒤에 옮긴다.
   ```bash
   node "<OPS>/manuals/card-news/scripts/cardnews-done.mjs" "<고른 폴더>" --root "<드라이브>/[운영] 어라운드팜 인스타그램/콘텐츠" --url https://www.instagram.com/p/<코드>/
   ```
8. 노션 상태 `업로드 완료`, `편집 진행도 연결` 에 게시물 주소. 편성표의 그 슬롯 상태를 `게시` 로 바꾼다.
9. 언어 계정 핸들이 확인돼 있으면 같은 편의 영어판을 같은 방법으로 올린다. 발행 시각은 현지 사람이 많은 시간대로 예약한다. 중국어와 일본어판은 담당자가 올린다. 확인 전이면 본계정만 올리고 보고에 적는다.

### P6. 댓글과 DM 을 본다 (L3)

1. 최근 게시물 전체의 댓글을 훑는다. 답이 정보가 되는 질문(성분, 사용법, 어느 약국에 있는지)에 답글을 단다. 언어 계정의 댓글은 그 언어로 답한다. 중국어와 일본어는 담당자 몫이라 목록만 넘긴다.
2. **답하지 않는 것**: 의약품 효능을 단정하는 표현, 약국 확인 없는 가격과 할인, 처방약 상담. 이런 질문은 "약국에 문의" 로 돌린다.
3. 비방과 잘못된 정보는 지우지 말고 `리포트/악플 목록 YYYY-MM-DD.md` 에 주소와 내용을 적는다. 삭제는 사람이 한다.
4. DM 은 `abilities/인스타그램.md` 의 규칙대로 **열기 전에 안 읽은 방 목록을 먼저 적고, 다 읽고 나서 전부 안 읽음으로 되돌린다.** 입점과 제휴 문의는 슬랙 전달 초안, 제품 문의는 답장 초안을 `리포트/DM 초안 YYYY-MM-DD.md` 에 둔다. 보내지 않는다.

### P7. 리포트를 쓴다 (L1 수집, L3 인사이트)

**주간**은 매주 월요일, **월간**은 매월 말에 다음 달 편성표와 함께다. 결과는 `리포트/YYYY-MM-DD 주간.md`, `리포트/YYYY-MM 월간.md` 와 슬랙에 붙일 초안 `... 슬랙 초안.md`.

1. 편별 공개 지표(조회, 좋아요, 댓글, 팔로워)는 로그인 없이 수집기로 뽑는다. 조사 트래픽을 발송 계정에 쌓지 않기 위해서다.
   ```bash
   node "<OPS>/manuals/insta-metrics/scripts/ig-harvest.mjs" --check
   ```
   쓰는 법은 `manuals/insta-metrics/MANUAL.md`.
2. 저장, 공유, 도달 계정 수, 프로필 방문, 팔로워 순증은 로그인된 본계정의 인사이트 화면(게시물별 인사이트, 프로페셔널 대시보드)에서 읽는다 (L3). 화면 숫자는 스크린샷이 아니라 `get_page_text` 로 옮긴다.
3. 주간 리포트 다섯 칸: 발행 목록(편별 링크, 형식, 길이, 올린 시각) / 편별 지표(조회, 좋아요, 댓글, 저장, 공유, 팔로워 순증) / 링크 유입(편별 링크 클릭과 앱 도달. 앱 쪽 파라미터 수신은 바로팜 개발 협조가 필요해 안 잡히면 "미집계" 로 적는다) / 다음 주 편성(형식 배정과 촬영 일정) / 특이 사항(악플 처리 내역, 지연 사유).
4. 월간 리포트 다섯 칸: 형식별 누적(네 형식의 편수와 먼저 보는 지표 합계) / 성장 지표(팔로워 순증, 도달 계정 수, 프로필 방문) / 잘 된 편 분석(상위 3편 공통점과 다음 달에 쓸 지점) / 바꿀 형식(내릴 형식과 새로 넣을 형식) / 다음 달 계획표(주차별 형식 배정과 촬영 일정). **조회수 대비 팔로워 유입률 상위 편**을 반드시 적는다. 광고 집행 판단 근거다.
5. 4개 계정은 합친 것과 계정별로 나눈 것을 같이 적는다.
6. 숫자에 출처(수집기 `play_count` 인지 화면 표기인지)를 한 줄 적는다. 둘은 5% 안팎 다르다.

## 알려진 함정

- **기획안 PDF 의 텍스트를 뽑으면 전부 깨진다.** 피그마 내보내기가 서브셋 폰트에 ToUnicode 를 안 넣는다. `기획안.md` 를 읽거나, 정 필요하면 PyMuPDF 로 페이지를 그림으로 렌더해서 본다. 피그마 `OmcoQi8GrKDyLS4rCprjf1` 에서 읽는 것도 된다
- **파일명은 260901 인데 내용은 260902 개정본 31장이다.** 27장짜리 260901 발표본과 헷갈리지 마라. 개정본에 성장 단계(04), 출연진(22), 전담 인력(30), 슬랙(31)이 추가됐다
- **언어 계정 핸들이 아직 없다.** 노션 운영 페이지에도 없다 (260907). 슬랙에서 바로팜이 준 권한을 확인하기 전에는 본계정만 올린다. 지어내지 마라
- **채널명과 브랜드 컬러 정확한 값이 미정이다.** 컬러는 로고 실측 `#09B9B9` 로 만들되 바로팜 디자인팀 값이 오면 바꾼다. 채널명 후보 제안은 액션 아이템으로 남아 있다
- **하이라이트 6구획에서 약국 찾기와 입점 문의를 빼라는 결정**(260901)을 되돌리지 마라. 업자 계정으로 보이면 댓글과 공유가 준다
- **기획안 DB 는 사람이 채우는 중이다.** 같은 소재를 또 만들지 말고, `작성 완료(검토 대기)` 는 검토 전이라 만들지 않는다
- 카드뉴스와 릴스 게시의 함정(캡션이 빈 채로 나감, 배경 탭, 팝업, zoom 으로 뷰포트 굳음, G: 에서 재귀 fs 호출 죽음)은 `card-news` 와 `shorts-pipeline` 매뉴얼의 알려진 함정 절에 다 있다. 거기 것을 그대로 지킨다
- 인스타 `web_profile_info` 는 비즈니스 계정에서 400 이 난다. 프로필 HTML 의 `profile_id` 로 간다
- `feed/user` 는 count 를 크게 줘도 12편만 준다. `next_max_id` 로 넘긴다
- 조사 트래픽을 발송 계정에 쌓지 마라. 지표 수집은 로그인 없는 수집기로 한다
