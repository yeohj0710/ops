# OpenAI API 크레딧 충전분 RCMS 사용등록

- **부르는 말**: OpenAI 충전분 RCMS 등록해줘, OpenAI 결제 RCMS 등록해줘, 오픈AI 크레딧 충전 등록해줘, OpenAI API 결제 처리해줘, TIPS OpenAI 등록, 오픈AI 충전 건 RCMS 올려줘
- **미리 허가**: RCMS 사용등록 제출
- **런너**: claude
- **제어층**: L1 → L3
- **한 번에 걸리는 시간**: 15~20분

`<드라이브>` 는 `<OPS>/machine.json` 의 `drive_root` 다. 보통 `G:/내 드라이브`.
이 업무의 서류 폴더는 `<드라이브>/여형준님/10 TIPS/연구비 집행 서류/260824 OpenAI API 크레딧 충전` 이다.
아래에서 `<폴더>` 라고 쓰면 이 경로다.

클로드 구독 건(`tips-claude-rcms`)과 화면 조작은 같다. 다른 것은 셋이다.
정액 구독이 아니라 **충전 회차마다** 등록한다. 증빙이 회차 폴더에 있다. 거래처 값이 OpenAI 것이다.

## 무엇을 만드는 업무인가

OpenAI API 선불 크레딧을 법인 연구비카드로 충전하면 그 승인 건을 TIPS 과제 연구비로
RCMS에 사용등록한다. 끝났을 때 세 가지가 남아 있어야 한다.

- `<폴더>/etc/회차별 증빙/YYMMDD 충전/` 에 그 회차 인보이스와 결제 영수증 PDF 두 개
- RCMS 카드사용 내역에서 그 승인 건이 **노란색, 사용등록여부 "등록"** 으로 바뀐 상태
- `<폴더>/etc/회차별 증빙/00 회차별 저장방법.txt` 누적표에 승인번호, 원화 승인액, 등록일이 채워진 줄

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차, 후속 작업, 완료 검사를 한 번에 실행한다.
증빙만 챙기고 멈추지 않는다. RCMS 등록 버튼까지 누르는 것이 이 업무다.
사용등록은 돈이 나가는 행위가 아니라 이미 나간 카드 승인 건을 과제에 붙이는 행위다.
**충전 자체는 이 업무가 아니다.** 충전은 `<폴더>/00 충전 및 RCMS 등록 방법.txt` 대로 사람이 한다.

## 준비물

  로그인이 안 되어 있으면 여기서 멈추고 사람을 부른다. 비밀번호를 대신 치지 않는다.
  사람이 열어둔 RCMS 탭은 익스텐션 그룹 밖이라 못 잡는다. 새 탭을 만들어
  `www.rcms.go.kr/main.do` 로 가면 로그인 세션이 그대로 살아 있다
- 그 회차 인보이스와 영수증 PDF. OpenAI 계정(`wellnessbox.gpt@gmail.com`)의
  platform.openai.com → Settings → Billing → Billing history 에서 받는다. 260824 회차는
  충전 당일에 사람이 받아 두었다
- 공통서류 4종이 `<폴더>` 루트에 이미 있다. 계정, 1회 충전액, 결제카드가 안 바뀌었으면 그대로 재사용한다
  - `01 내부결재문서.pdf` / `02 구매의뢰서.pdf` / `03 연구개발비 집행 사유서.pdf` / `04 검수(설치)완료확인서.pdf`
  - 바뀌었으면 `<폴더>/etc/작업 스크립트/build_documents.py` 상단 상수를 고쳐 다시 만든다.
    클로드 건과 달리 이 폴더의 스크립트는 재실행해도 된다. 만든 뒤 `verify_deliverables.py` 로 4종 1페이지를 확인한다

## 절차

1. **회차 증빙을 확인한다 (L1)**
   `<폴더>/etc/회차별 증빙/YYMMDD 충전/` 에 두 파일이 있는지 본다. 없으면 준비물대로 받아 넣는다.
   - `01 OpenAI 인보이스.pdf`
   - `02 OpenAI 결제 영수증.pdf`

   PDF 텍스트를 뽑아 네 가지를 확인한다. **하나라도 어긋나면 멈추고 사람에게 알린다.**
   - Bill to 에 `주식회사 웰니스박스` 와 `KR BRN 728 88 03267`
   - 공급자 `OpenAI OpCo, LLC`, 주소 `1455 3rd Street, San Francisco, California 94158`
   - 품목 `OpenAI API usage credit - Manual purchase`, Subtotal = Total (세액 줄이 없다)
   - 영수증의 결제수단 끝 네 자리(`Mastercard - 9970`)가 RCMS 카드목록의 끝자리와 같은지

   업로드용으로 스크래치패드에 복사해 둔다. 파일명은 `YYYY-MM-DD OpenAI 인보이스.pdf`,
   `YYYY-MM-DD OpenAI 결제 영수증.pdf` 로 바꾼다. 공통서류 4종도 같이 복사한다.

2. **RCMS에서 그 회차 카드 승인 건을 찾는다 (L3)**
   새 탭에서 `www.rcms.go.kr/main.do` → 상단 `연구비사용` → `연구비사용등록`.
   과제선택에 `25465584` 가 이미 떠 있다. `증빙우선등록` 탭의 `증빙선택` 을 **`카드`** 로 고른다.
   이 셀렉트는 DIV 라 form_input 이 안 먹는다. 눌러서 펼친 뒤 `카드` 를 누른다.
   `카드사용 내역 조회` 창이 뜨면 카드목록 라디오(IBK기업 BC카드, 끝자리 9970)를 누르고
   `1개월` 을 누른 뒤 `조회`. 창 안을 아래로 스크롤해야 목록이 보인다.

   **이게 보이면 성공**: 가맹점명 `O P E N A I`, 사용구분 `해외`, 그 회차 승인 건이
   흰색(미등록)으로 보인다. 노란색이면 이미 등록된 것이니 8번으로 간다.
   결제 당일에는 안 뜬다. 승인 다음날 매입으로 잡힌다.

3. **금액을 확정한다 (L3)**
   승인 건 라디오를 누르고 창 아래 `적용`. `카드사용 부가세 수정` 창이 뜬다.
   - `수정 공급금액` 은 기본값(= 사용금액 전액) 그대로 둔다. `원 공급금액` 이 아니다
   - `수정 부가세액` `0`, `봉사료` `0`
   - 부가세액 라디오를 **`0%`** 로 고른다
   `저장` → `선택된 증빙[카드승인(매입)내역]건을 등록하시겠습니까?` → `예`.
   창이 닫히고 등록 폼에 한 줄이 생긴다. 사용금액과 공급금액이 같고 부가세가 0이면 맞다.

4. **행을 채운다 (L3)**
   - 항목: `연구활동비`
   - 세부항목: `소프트웨어 활용비`
   - 품목: `OpenAI API 연구개발용 사용료 크레딧 충전(YYYY.MM.DD)`. 괄호 안은 카드 승인일
   - 이월금 사용여부: 미체크
   항목과 세부항목은 그리드 안 드롭다운이다. 눌러서 펼친 뒤 값을 누른다.
   품목은 셀을 누르고 타이핑한 뒤 Tab 으로 빠져나온다. `input` 값에 `OpenAI` 가 들어갔는지 스크립트로 한 번 본다.

5. **거래처를 채운다 (L3)**
   `거래처 및 계좌정보` 버튼이 빨간색이면 눌러서 채운다. 거래구분 `해외거래`, 기관명 `OPENAI`,
   사업자등록번호 `9999999999` 는 이미 들어 있고 두 칸만 비어 있다.
   - 대표자: `Sam Altman`
   - 사업자주소: `1455 3rd Street, San Francisco, California 94158, United States`
   `입력확인` 을 누르면 버튼이 파란색으로 바뀐다.

6. **증빙을 첨부한다 (L3)**
   행의 `증빙자료첨부` 칸에서 `등록하기`. 슬롯은 여덟 개고 필수는 넷이다.
   각 슬롯 오른쪽 `+` 를 눌러 `파일추가` 창을 띄우고 아래 "파일 올리는 법" 대로 넣는다.

   | 슬롯 | 넣을 파일 |
   | --- | --- |
   | 내부결재문서(필수) | `01 내부결재문서.pdf`, `03 연구개발비 집행 사유서.pdf` |
   | 구매의뢰서(필수) | `02 구매의뢰서.pdf` |
   | 거래명세서(필수) | `YYYY-MM-DD OpenAI 인보이스.pdf` |
   | 세금계산서(선택필수) | 비움 |
   | 카드매출전표(선택필수) | `YYYY-MM-DD OpenAI 결제 영수증.pdf` |
   | 계약서 | 비움 |
   | 검수(설치)완료확인서(필수) | `04 검수(설치)완료확인서.pdf` |
   | 기타 | 비움 |

   **카드사에서 뽑는 전표는 필요 없다.** 카드매출전표 칸에 OpenAI 결제 영수증을 넣는 것으로 통과한다.
   다 넣고 `저장` → `저장이 완료되었습니다` → `확인`. 창이 닫히고 행의 증빙자료첨부가 `등록완료` 로 바뀐다.

7. **등록한다 (L3)**
   오른쪽 아래 `등록` → `입력하신 연구비 사용등록 정보를 저장하시겠습니까?` → `예`.
   **이게 보이면 성공**: `성공적으로 저장되었습니다`. 등록 폼이 빈 줄로 돌아간다.

8. **확인하고 기록한다 (L3 → L1)**
   2번 화면을 다시 열어 그 승인 건이 노란색이고 `사용등록여부 등록`, `과제등록건수 1`,
   `등록금액` 이 승인액과 같은지 본다. `닫기` 로 창을 닫고 탭을 닫는다.
   `<폴더>/etc/회차별 증빙/00 회차별 저장방법.txt` 누적표의 그 회차 줄에
   승인번호, 원화 승인액, RCMS 등록일을 채운다. 아래 메모에 등록 내용을 한 줄 남긴다.

## 파일 올리는 법 (이 업무의 핵심 우회)

RCMS `파일추가` 창은 파일 선택 버튼을 누르면 **OS 파일 선택창**이 떠서 에이전트가 못 만진다.
누르지 말고 아래로 한다. 창 안에는 file input 이 두 개 있고, 실제로 동작하는 것은
Kendo 위젯이 붙은 쪽인데 **find 로 잡히는 것은 동작하지 않는 쪽**이다. 그래서 두 단계로 한다.

1. `파일추가` 창의 file input 을 find 로 잡아 L3 의 파일 업로드로 로컬 경로를 넣는다.
   스크래치패드에 복사해 둔 경로가 확실히 먹는다. 창을 열 때마다 ref 가 바뀌니 매번 find 한다
2. 그 다음 페이지 스크립트로 Kendo 쪽 input 에 옮겨 담고 change 를 쏜다. 창은 저절로 닫힌다

```js
const $ = window.jQuery;
const ins = [...document.querySelectorAll('input[type=file]')];
const src = ins.find(i => i.files && i.files.length && !$(i).data('kendoUpload'));
const target = ins.find(i => $(i).data('kendoUpload'));
const dt = new DataTransfer(); [...src.files].forEach(f => dt.items.add(f));
target.files = dt.files;
target.dispatchEvent(new Event('change', {bubbles:true}));
```

한 슬롯에 두 개를 넣을 때는 업로드 한 번에 경로 두 개를 같이 준다. 위 코드가 둘 다 옮긴다.
파일이 한 줄씩 늘 때마다 아래 슬롯의 `+` 가 한 줄(약 21px)씩 내려간다. 슬롯마다 화면을 다시 본다.
넣은 뒤에는 화면을 믿지 말고 아래 함정의 "그리드가 아래를 안 그린다" 로 확인한다.

## 알려진 함정

- **연구비 사용 내역에 안 뜬다고 실패가 아니다** → 그 화면은 카드대금 이체가 끝난 건만
  보여준다. 등록 직후에는 안 나온다. → 확인은 카드사용 내역 조회 화면의 색과 `사용등록여부` 로 한다
- **그리드가 아래를 안 그린다** → 증빙파일 목록은 보이는 줄만 DOM에 만든다. 화면 아래로
  밀린 줄은 스크린샷에도 `querySelectorAll` 에도 안 잡혀서 "안 올라갔다" 로 오해한다.
  → 부모 줄의 `▲` 를 눌러 접어서 아래 줄을 화면 안으로 끌어올려 확인한다. 휠 스크롤은 안 먹는다
- **금액은 카드 승인액 전액을 넣는다** → USD 100 이 원화 141,317원으로 승인됐고 RCMS 원공급금액은
  141,066원이다. 차액 251원은 해외 결제 수수료다. `사용금액` 전액을 공급금액으로 넣는다
- **부가세는 0** → 인보이스에 세액 줄이 없다. 사업자등록번호를 등록해 둔 덕이다. 임의로 10%를 넣지 않는다
- **재원은 계속비로 잡힌다** → 본예산이 아니다. 화면 아래 사용한도에서 계속비 잔액이
  141,317원 줄어드는지로 확인한다
- **세부항목 목록에 `클라우드컴퓨팅서비스 활용비` 가 따로 있다** → RCMS 드롭다운에는 있지만
  서류 4종과 사유서가 소프트웨어 활용비 기준으로 쓰여 있다. 그대로 소프트웨어 활용비로 간다.
  바꾸려면 서류부터 다시 만들어야 하니 사람이 정한다
- **RCMS 탭이 얼어붙는다** → WebSquare가 네이티브 대화상자를 띄우면 스크립트 주입이
  타임아웃 나고 스크린샷도 안 된다. 260904 에는 첫 슬롯에 파일 두 개를 넣은 직후 다음 슬롯
  `+` 를 누르자 굳었다. → 되살리려 하지 말고 그 탭을 닫고 새 탭에서 `www.rcms.go.kr/main.do`
  부터 다시 간다. 세션은 살아 있고 카드 승인 건도 그대로다. 대신 폼 입력은 부가세 수정까지
  전부 날아가니 3번부터 다시 한다. 같은 순서로 다시 하니 두 번째는 안 굳었다
- **메뉴 클릭이 한 번에 안 먹는다** → 상단 메뉴는 눌러서 펼친 뒤 하위 링크를 다시 눌러야 이동한다.
  find 로 `연구비사용` 과 `연구비사용등록` 링크 ref 를 받아 차례로 누르면 된다
- **저장 순서를 뒤집으면 첨부가 날아간다** → 파일을 올린 뒤 `저장` 을 누르기 전에 다른
  화면을 갔다 오면 방금 올린 것이 목록에서 빠질 수 있다. 슬롯을 다 채우고 바로 저장한다
- **`변경된 내역이 없습니다` 가 떠도 놀라지 마라** → 이미 서버에 반영된 상태다. `아니오` 를
  누르고 목록을 다시 확인한다

## 사람에게 물어야 하는 지점

- RCMS 로그인이 안 되어 있을 때. 비밀번호는 사람이 친다
- 인보이스 Bill to 에 법인명이나 사업자등록번호가 안 찍혀 있을 때. 그 회차 인보이스는
  소급 수정이 안 되므로 그대로 올릴지 정해야 한다
- 1회 충전액, 계정, 결제카드가 바뀌었을 때. 공통서류 4종을 다시 만들어야 한다
- 카드 승인 건이 조회에 아예 안 나올 때. 카드사 매입 반영 전일 수 있다
- 세부항목을 클라우드컴퓨팅서비스 활용비로 바꿀지. 서류 재작성이 따라오니 사람이 정한다
