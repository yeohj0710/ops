# 릴스 기획안 생성

- **부르는 말**: 릴스 기획안 만들어줘, AI 기획안 작성해줘, 내용 레퍼런스와 형식 레퍼런스 조합해줘, 릴스 기획안 자동화
- **미리 허가**: 기존 릴스 자료와 업로드 완료 기획안을 읽고, 지정한 노션 AI 기획안 목록에 검토용 초안을 추가한다. 실행 자료와 검증 기록을 에이전트 보고 폴더에 저장한다.
- **런너**: either
- **제어층**: L1 → L2/L3
- **한 번에 걸리는 시간**: 기존 자료로 3편 작성 시 약 20~40분. 신규 영상 확인 시간은 별도다.

## 결과와 호출

서로 맞는 내용 영상과 형식 영상을 골라 촬영 기획안을 만든다. 이미 업로드한 기획안의 첫 장면, 대사 밀도, 촬영 지시를 기준으로 검토한다. 노션의 AI 에이전트 테스트 기획안 목록 안 콘텐츠 기획안 목록에 작성 완료(검토 대기)로 저장하고 다시 읽어 확인한다.

호출 예: `G드라이브 에이전트 폴더 참고해서 김제조 릴스 기획안 3편 만들어서 노션 AI 기획안 목록에 넣어줘.`

계정이나 편수를 지정하지 않으면 기존 설정의 계정과 3편을 사용한다. 사용자가 붙인 새 릴스 주소도 같은 검사를 거친다. 이 업무는 호출할 때 에이전트가 작성부터 등록까지 실행한다. 별도 주기 수집기나 유료 생성 API를 자동으로 켜지 않는다.

## 실행 위치

`<DEV>`와 `<DRIVE>`는 `<OPS>/machine.json`에서 읽는다. `<MANUAL>`은 이 파일이 있는 폴더다. 저장소가 없으면 드라이브 사본의 스크립트를 그대로 실행한다. Node 22 이상이 필요하다.

| 구분 | 위치 |
| --- | --- |
| 실행 도구 | `<MANUAL>/scripts/pipeline.mjs` |
| 설정과 게시 기준 | `<DRIVE>/에이전트/보고/릴스 기획안/설정.json`, `기준 기획안.json` |
| 원본 대사와 형식 | `<DEV>/jev-lab/api/_plan-data.json`, `<DEV>/reels-corpus/data/beats.csv` |
| 후보 점수 | `<DEV>/jev-lab/public/data/reels.json` |
| 보정 자료 | 보고 폴더의 `원본 보정.json`과 설정의 `externalReferences` |
| 실행 기록 | 보고 폴더의 `etc/실행/`, 기존 검증 기록은 `etc/검증/` |

원본 저장소는 읽기만 한다. 설정, 원문 스냅샷, 생성 대사, 인증된 노션 응답은 공개 ops 저장소에 넣지 않는다. 기존 파일을 바꾸면 `etc/backup/`에 원본을 보존한다. 스크립트는 내용 해시별 백업을 자동으로 만든다.

## 실행 계약

등록과 읽기 검증까지 이 업무에 포함된다. 노션의 채택, 녹화 확정, SNS 게시, 편집자 메시지 전송은 포함하지 않는다. 별도 생성 API를 쓰려면 먼저 예상 비용을 숫자로 알리고 현재 사용자 승인과 비용 설정을 확인한다. 기본 경로는 현재 호스트 에이전트가 대본을 작성하며 추가 유료 API 호출은 없다. 사용량 리셋 크레딧은 어떤 단계에서도 자동 사용하지 않는다.

## 절차

### 1. 기준 기획안과 목적지 확인

현재 연결된 노션 워크스페이스를 확인한다. 대상 계정에서 업로드 완료인 실제 기획안 2~3개를 읽고 상태, 페이지 주소, 본문, 조회일을 기준 파일에 보존한다. 영상 자체를 재생하지 않았으면 `videoViewed:false`로 적는다. 첫 장면, 형식 유지, 구어체, 촬영 가능성, 사실 근거를 구체적인 장면과 연결한다. 업로드 상태만으로 조회수 성과나 의료적 정확성이 입증됐다고 해석하지 않는다.

목적지의 실제 data source와 속성 스키마를 읽고 설정에 저장한다. 기본 속성은 이름, 상태, 편집 비고다. 편집 비고에는 중복 방지 식별자를 저장한다. 사람, 편집자, 업로드 날짜는 임의로 배정하지 않는다.

`node "<MANUAL>/scripts/schema.mjs"`로 전체 JSON 계약을 확인한다. 가상 예제를 실제 원본이나 검토 증거로 복사하지 않는다. 설정에 비밀키를 넣지 않는다.

### 2. 후보 준비와 조합 선택

설정의 asOf를 이번 실행 날짜로 갱신한다. 기본 후보는 조회수 50만 이상, 게시일이 최근 달력 3개월 이내, 해당 축 점수 0.7 이상이다. 조회수 측정일도 보존하며 오래된 값을 실시간 수치로 부르지 않는다. 광고 여부가 불명이거나 대사와 형식 근거가 없으면 자동 선택에서 제외한다.

```text
node "<MANUAL>/scripts/pipeline.mjs" prepare --config "<설정.json>" --run-dir "<실행 폴더>"
```

prepared.json의 pairRanking과 source-ledger.jsonl을 읽는다. 같은 영상이나 같은 대사를 두 축에 쓰지 않는다. 항목 수, 길이, 순서, 대사 유형이 맞는 쌍을 우선 검토한다. 기계 점수는 검토 순서이며 의미상 적합도 합격 판정이 아니다.

내용 원본의 주장과 사례, 형식 원본의 도입과 반복, 반전, 끝맺음을 직접 대응시킨다. 원본 프레임의 구도, 자막 위치, 손동작과 실제 시간도 확인한다. 선택한 쌍은 selection.pairs에 이유, 검토자, 검토일을 적고 prepare를 다시 실행한다.

기준 미달 예외가 필요한 검증 초안은 eligibilityException에 조건과 사용 범위를 적고 본문에도 공개한다. 예외를 다음 실행 기본 설정에 남기지 않는다. 같은 계정과 내용이 이미 쓰인 경우 이전 실행 원장과 노션을 확인하고 다음 후보를 고른다.

### 3. 신규 릴스와 원본 보정

주소만으로 대사를 만들지 않는다. 기존 DB에 있으면 그 자료부터 읽는다. 없으면 원본 게시일, 조회수와 측정일, 광고 여부, 시간별 대사와 화면을 확보한다. 대사 파일과 프레임 파일의 SHA-256 해시를 보존한다.

외부 자료는 version:1과 references 배열을 갖는다. 각 원본에 id, url, title, topic, posted, measured, views, ad, contentScore, formatScore, lines, beats, provenance를 채운다. 정확한 구조는 scripts/data.mjs의 validateExternal을 따른다. 점수의 평가자와 근거도 보존한다. 인증이나 원본 확보가 막히면 그 항목만 보류하고 다음 후보를 진행한다.

```text
node "<MANUAL>/scripts/pipeline.mjs" ingest --config "<설정.json>" --run-dir "<실행 폴더>" --file "<신규 레퍼런스.json>"
```

통과한 경로를 externalReferences에 추가한다. 오역과 잘못된 화면 설명은 referenceOverlays로 보정한다. 대사를 바꾸면 transcriptCorrectionReason을 남긴다. 원본 파일을 고치지 않는다. prepare를 다시 실행하여 보정 파일의 해시도 준비 기록에 포함한다.

### 4. 촬영 대본 작성

packets/<id>.json을 읽고 plans/<id>.json을 채운다. 장면 수를 8~11개로 고정하지 않는다. 원본 비트와 필요한 항목 수에 맞춘다.

각 장면에 시간, 역할, 실제 대사, 자막, 손동작과 소품, 카메라, 편집, 내용 대사 ID, 형식 비트 ID를 적는다. formatComparison은 모든 원본 비트에서 유지한 점, 바꾼 점과 이유를 설명한다. 생략한 비트도 기록한다. 생성 대사와 자막의 브랜드를 빼고 필요한 경우 성분으로 쓴다. 원문 제목은 출처로 보존한다. 새 글에는 줄표와 가운뎃점을 쓰지 않는다.

의학적 효과, 용량, 위험, 순위와 수치는 공식 자료로 확인하고 claims와 evidence에 연결한다. 확인되지 않은 주장은 excluded-pending-verification으로 기록하고 대사에서 제외한다. 사실 확인을 이유로 원본 주제를 새 주제로 바꾸지 않는다. 개별 치료나 임의 복용 중단으로 확대하지 않는다.

대사는 실제로 말할 때의 속도로 검토한다. 초당 글자 수 검사는 보조 수단이다. 녹음 길이를 측정하지 않았으면 측정했다고 쓰지 않는다.

### 5. 독립 검토와 재작성

작성과 다른 에이전트 세션 또는 검토자가 기준 기획안과 새 대본을 함께 읽는다. 훅, 형식 유지, 구어체, 촬영 가능성, 사실 근거, 브랜드 제외를 검토한다. 기준 장면과 이번 장면 ID, 판단 근거를 남긴다. 작성자가 이름만 바꿔 독립 검토를 만들지 않는다. 검토자가 없으면 로컬 초안을 보존하고 노션 등록 조건 미충족으로 기록한다.

한 항목이라도 미달이면 고친 뒤 다시 검토한다. review-hash가 준 대본 해시와 패킷 해시를 reviewedPlanHash와 reviewedPacketHash에 저장한다. 대본이나 원본을 수정한 뒤에는 오래된 검토 해시가 무효다.

```text
node "<MANUAL>/scripts/pipeline.mjs" review-hash --plan "<대본.json>" --packet "<packets/id.json>"
node "<MANUAL>/scripts/pipeline.mjs" lint --config "<설정.json>" --run-dir "<실행 폴더>" --plan "<대본.json>"
node "<MANUAL>/scripts/pipeline.mjs" render --config "<설정.json>" --run-dir "<실행 폴더>" --plan "<대본.json>"
```

lint-report.json의 오류를 해결한다. 생성한 기획안.md의 장면 설명/대사 2열 표, 편집자 노트, 원본 주소와 검토 근거를 확인한다.

### 6. 노션 등록과 재조회

render가 만든 notion-dedupe-request.json의 요청을 현재 호스트의 인증된 연결로 실행한다. 원본 응답을 `{tool, arguments, fetchedAt, response}` 봉투로 저장한다. 결과가 있으면 새로 만들지 않고 기존 페이지를 읽는다. 조회가 실패하거나 불완전하면 생성하지 않는다.

```text
node "<MANUAL>/scripts/pipeline.mjs" publish --config "<설정.json>" --run-dir "<실행 폴더>" --plan "<대본.json>" --dedupe "<중복 조회 응답.json>"
```

publish는 요청 파일을 만들고 awaiting-notion으로 기록한다. 명령 자체는 노션에 쓰지 않는다. 에이전트가 notion-create-request.json의 요청을 인증된 연결로 실행한다. 그 페이지를 다시 조회하여 실제 부모, 제목, 상태, 식별자와 본문을 확인한다.

```text
node "<MANUAL>/scripts/pipeline.mjs" receipt --config "<설정.json>" --run-dir "<실행 폴더>" --plan "<대본.json>" --evidence "<노션 재조회 응답.json>"
node "<MANUAL>/scripts/pipeline.mjs" check --config "<설정.json>" --run-dir "<실행 폴더>"
```

생성 결과가 불명확하면 중복 조회부터 다시 한다. 본문 차이가 있으면 누락과 노션 정규화를 구분한다. 증거를 요청값으로 바꾸거나 해시 검사를 끄지 않는다. 렌더링된 노션 화면에서 제목, 표와 줄바꿈을 확인한다. 브라우저 규칙을 지키고 자신이 연 탭을 닫는다. 이후 공용 설정이 바뀌어도 이 실행은 config.snapshot.json으로 검사한다.

### 7. 결과 전달

노션 링크, 계정과 제목, 미확인 조건, 실제 유료 호출 비용을 짧게 보고한다. ledger.json에 완료 영수증이 있고 check가 통과한 수만 완료로 센다. 초안 등록 완료는 촬영 승인이나 성과 보장이 아니다.

## 알려진 함정

- 미확인은 실제 값이 아니다. 대사나 화면이 빠진 자료를 점수만으로 통과시키지 않는다.
- 자동 번역이 kidneys를 근육으로 바꾼 사례가 있었다. 원문 자막과 공식 근거를 함께 확인한다.
- 범용 형식 템플릿과 실제 원본의 항목 수, 시간, 소품이 달랐다. 프레임과 시간별 받아쓰기를 우선한다.
- 기획안 보류 상태만으로 보류 이유를 추정하지 않는다. 업로드 완료 기준과 구분한다.
- 목적지 보기에서 이름에 예시가 들어간 페이지가 숨겨질 수 있다. 실제 제목을 쓴다.
- 광고 판정 불명을 비광고로 바꾸지 않는다. 예외는 공개하고 다음 실행으로 넘기지 않는다.
- 원본이 바뀌면 준비 해시가 달라져 검사가 멈춘다. 확인 후 prepare부터 다시 한다.
- 완료한 조합을 반복 생성하지 않는다. 기존 식별자를 조회하고 영수증을 복구한다.
- 노션은 내부 페이지 링크를 페이지 멘션으로 바꿔 저장한다. 비교할 때 같은 페이지 ID인지 확인한다. 다른 주소나 빠진 대사를 표시 방식 차이로 무시하지 않는다.
- 빈칸 자막의 밑줄은 마크다운에서 서식으로 해석될 수 있다. 렌더러가 밑줄을 이스케이프한 뒤 실제 재조회 값과 화면에서 빈칸이 남았는지 확인한다.
