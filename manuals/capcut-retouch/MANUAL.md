# CapCut 인물 영상 보정

- **부르는 말**: 영상 보정해줘, 캡컷 보정해줘, 인물 보정해줘, 영상 미용 보정
- **미리 허가**: 지정한 영상의 백업과 별도 보정본을 만든다. 원본과 기존 프로젝트를 보존한다.
- **런너**: codex
- **제어층**: L1 백업·검수 → L4 CapCut Retouch·내보내기
- **한 번에 걸리는 시간**: 영상 길이와 인물 수, 컴퓨터 성능에 따라 달라짐

## 무엇을 만드는 업무인가

CapCut 데스크톱의 Video → Retouch로 얼굴을 보정한다. 피부결과 잡티를 정리하고 얼굴형은 사람마다 맞춘다. 예쁘고 잘생기게 보이는 결과를 우선하되, 말하거나 고개를 돌릴 때 얼굴이 찌그러지는 강도는 피한다.

## 쉬운 설명

2026-09-19 Windows CapCut 9.5.0.4050에서 네이티브 보정과 4K·30/60fps, 1080p·30fps 출력에 성공했다. 일반 화면 조작은 창을 앞으로 가져오므로 사용자의 컴퓨터 작업과 동시에 실행하지 않는다. 해당 세션에서 화면 사용을 승인했다면 다시 묻지 않는다.

2026-09-26 같은 버전의 본체를 숨긴 Windows 데스크톱에서 실행하고, 화면 캡처·새 프로젝트 열기·원본 한 편 가져오기·영상 미리보기에 성공했다. 사용자 입력 데스크톱을 전환하지 않고 대상 창에 Windows 메시지를 보냈다. 드래그로 타임라인에 놓는 방법은 성공하지 못했지만, 기존 네이티브 프로젝트의 복사본을 열어 타임라인·Retouch 수치를 읽는 방법은 성공했다. Export를 누른 뒤 나타난 별도 창은 검게 캡처됐고 접근성 정보에도 조작 항목이 없었다. 이 창의 용도와 원인은 미확인이다. 새 보정 적용과 파일 출력은 미검증이므로 일괄 보정에 사용하지 않는다. 아래 백그라운드 도구는 준비·파일 대조만 수행한다.

유료 API, 별도 결제, 유료 크레딧은 쓰지 않는다. 사용자가 확인한 조건은 Pro 전용 Retouch를 구독 안에서 횟수 제한 없이 사용하는 것이다. 2026-09-26 사용자가 제공한 Creator Center 화면에서 Pro를 확인했다. 같은 계정의 로그인·구독 확인이나 동의를 반복해서 요청하지 않는다. 숨김 창의 Sign in 표시만으로 계정 전체가 로그아웃됐다고 판단하지 않는다. 계정이 실제로 바뀌거나 구독이 만료됐다는 근거가 있을 때만 다시 확인한다. 결제나 크레딧 사용 화면이 나타나면 실행하지 않는다. Pro 표시만으로 모든 AI 기능이 무료라고 판단하지 않는다.

## 묻지 말고 이렇게 한다

새 세션에 `에이전트 폴더 매뉴얼대로 "<폴더 절대경로>" 캡컷 보정해줘`라고 말한다. 계정이나 대상 폴더를 이전 대화에서 추측하지 않는다. 다른 컴퓨터는 ops 설치와 CapCut 로그인이 필요하다.

백그라운드만 요청했다면 일반 화면 조작으로 임의 전환하지 않는다. 준비와 파일 대조를 먼저 실행하고, 숨김 창 방식은 실제 보정·출력 검증을 마친 뒤에만 일괄 작업에 사용한다.

## P1. 준비

1. 현재 존재하는 사용자 폴더를 <입력>으로 정한다. 폴더가 이동됐다면 현재 경로를 찾고 예전 경로를 다시 만들지 않는다. 로그·백업·검토 이미지는 <입력>/etc/capcut-retouch에 둔다. etc/capcut-replacement/state.json이 있으면 아래 백그라운드 check부터 실행한다. 교체 완료 파일은 새 원본이 아니므로 재보정하지 않는다.
2. node "<OPS>/manuals/capcut-retouch/scripts/prepare.mjs" "<입력 절대경로>" [대표 영상 파일명]으로 목록과 SHA-256, 길이, 해상도, 회전, 프레임률, 오디오를 수집한다. 파일명을 생략하면 모든 MOV를 백업한다. 파일명을 여러 개 지정하면 해당 파일만 먼저 백업한다. 전체 처리 전에 대상 모두를 backup/sources에 복사하고 해시를 확인한다.
3. sources.json은 최초 기록으로 보존한다. 원본 폴더가 이동되거나 파일명이 바뀌면 현재 경로를 찾아 해시로 대조한다. 예전 위치로 옮겨 되돌리지 않는다. 원본이 달라지면 해당 파일을 건너뛰고 기록한다.
4. 기존 프로젝트를 백업한 뒤 전용 프로젝트를 만든다. 준비 명령에 --project "프로젝트 이름"을 추가해 해당 기존 프로젝트를 백업한다. 여러 개면 옵션을 반복한다. 프로젝트 이름을 지정하지 않으면 프로젝트를 자동으로 백업하지 않으므로 L4 편집 전에 별도로 백업한다. 계정 인증 파일은 복제하지 않는다.
5. state.json과 보정 완료 폴더를 읽어 이미 저장한 파일을 제외한다. 출력 도중 중단됐다면 먼저 해당 결과의 완전성을 검사한다. 같은 영상을 중복 출력하지 않는다.

## P2. 인물 보정

1. 검증한 백업 사본을 Import → From device로 불러온다. 파일 선택창에서 먼저 폴더로 이동한 뒤 같은 폴더의 짧은 파일명을 따옴표로 묶어 여러 개 선택한다.
2. 한 편만 타임라인에 놓고 전체 길이를 확인한다. 새 클립마다 Video → Retouch → Single face를 확인한다. 여러 얼굴이 중심인 영상은 각각 적용 여부를 따로 확인한다.
3. Face presets를 시작점으로 쓰되 다른 사람의 값을 그대로 확정하지 않는다. Face → Skin과 Face 항목에서 밝기·피부결·얼굴형을 조절한다. 얼굴 선택 테두리와 실제 변화를 확인한다.
4. Save as preset으로 인물별 설정을 저장한다. 자동 이름은 생성 순서에 따라 달라지므로 이름과 수치를 함께 profiles.json에 적는다. 사진은 작업 안에서 인물을 구분하는 용도로만 쓴다.
5. 같은 사람도 조명·촬영 거리가 다르면 다시 확인한다. 얼굴이 없는 외관·보행 영상은 보정 제외 사유를 적고 원본을 유지한다.

검증한 시작 범위는 Smooth 50~60, Whitening 5~15, Clear blemishes 45, Dewrinkle 15~35, Facelift 10~20, Slim 11~20이다. 모든 사람의 정답은 아니다. 실제 수치는 작업별 profiles.json을 우선한다. 사용하지 않은 Auto styles·체형·메이크업 등은 임의로 켜지 않는다.

## P3. 내보내기

1. 원본이 약60fps면 프로젝트와 출력을60fps로, 약30fps면30fps로 맞춘다. 변동 프레임률의 평균 수치를 그대로 입력하지 않는다.
2. Export에서 <입력>/보정 완료/<원본 이름>_보정.mp4로 저장한다. 기존 파일은 덮어쓰지 않는다. 이번 작업에서 만든 잘못된 출력만 수정할 때는 먼저 백업과 해시 확인을 마친 뒤 교체한다.
3. 원본 표시 해상도에 맞춘다. 1080p 원본은1080p로 저장하며, 직전4K 설정을 그대로 쓰지 않는다. 4K 세로 소스의 검증 설정은 4K, Higher, H.264, mp4, 원본에 맞는 프레임률이다. Optical flow와 Sync exported videos to space는 끈다. SDR 소스는 Rec.709 SDR을 유지하고 HDR 소스는 별도 확인한다.
4. Video is saved가 나타나면 Close로 닫는다. Share·TikTok·YouTube 게시를 누르지 않는다.
5. 파일 생성과 길이를 확인한 뒤 해당 클립의 타임라인 배치만 해제한다. 미디어나 원본 파일은 지우지 않는다. 다음 영상을 한 편씩 같은 순서로 처리한다.

## P4. 검수와 완료

- 시작·중간·끝의 얼굴을 원본과 비교한다. 말하기, 웃기, 고개 돌리기 구간에서 눈·입·턱선이 튀는지, 머리카락과 배경 선반이 휘는지 확인한다.
- 표시 해상도와 방향, 전체 길이,30/60fps, 오디오 유무를 대조한다. 회전 정보가 있는 원본은 저장 폭·높이만 비교하지 않는다.
- 파일 전체를 디코딩해 손상 여부를 검사한다. 음성은 앞·중간·끝 구간을 원본과 비교해 누락과 시간 차이를 확인한다. 파일 헤더가 읽힌다는 이유만으로 검수 통과로 적지 않는다.
- 원본과 사용한 백업의 SHA-256을 최초 기록과 대조한다.
- 모든 파일에 결과 또는 제외 사유가 있어야 한다. state.json, profiles.json, 검수 결과, 출력 목록을 저장하고 작업용 프로젝트도 백업한다.
- 완료 보고에는 실제 저장 수, 제외 사유, 출력 폴더, 미검증 사항만 적는다. 화면 조작이 필요했던 작업을 백그라운드 성공으로 보고하지 않는다.

## P5. 검수 명령

Node.js와 FFmpeg·ffprobe가 필요하다. 현재 도우미는 MOV 원본과 IMG_숫자 파일명을 대상으로 검증했다. 다른 이름·형식은 목록 연결과 검사 스크립트를 먼저 조정한다. 명령은 보정을 수행하지 않으며, L4에서 저장한 결과만 검사한다.

```text
node "<OPS>/manuals/capcut-retouch/scripts/verify-native.mjs" "<입력>"
node "<OPS>/manuals/capcut-retouch/scripts/verify-audio.mjs" "<입력>" <출력한 원본 ID 전부, 확장자 제외>
node "<OPS>/manuals/capcut-retouch/scripts/verify-current-originals.mjs" "<입력>"
node "<OPS>/manuals/capcut-retouch/scripts/review-endpoints.mjs" "<입력>" <출력한 원본 ID 전부>
node "<OPS>/manuals/capcut-retouch/scripts/review-motion-frames.mjs" "<입력>" <출력한 원본 ID 전부>
node "<OPS>/manuals/capcut-retouch/scripts/check-completion.mjs" "<입력>"
```

비교 이미지는 위쪽이 원본, 아래쪽이 출력이며 각 열은 시작·중간·끝이다. 연속 프레임 이미지는0.5초 간격6장이다. 실제로 검토한 뒤에만 state.json의 visualSampleReviewed·motionSampleReviewed를 true로 적는다. 표본 검토를 영상 전체 육안 검수로 보고하지 않는다. 음성 도우미는 결과 파일을 교체하므로 최종 검사에는 출력한 ID 전부를 전달한다.

완료 검사는 모든 원본의 출력 또는 제외 사유, 원본·백업 해시, 출력 데이터, 음성 구간별 비교, 인물 설정 기록, 화면 검토 기록을 확인한다. 음성 판정은 상관계수0.85 이상·시간 차이50ms 이하이며, 값은 검수 기록에 남긴다. 무음 구간은 이 기준으로 판정할 수 없으므로 따로 확인한다.

## P6. 백그라운드 실행

다음 명령은 별도 Node.js 프로세스로 실행한다. CapCut이나 터미널 창을 앞으로 가져오지 않는다. 같은 입력 폴더의 실행 잠금으로 중복 작업을 막는다.

```text
node "<OPS>/manuals/capcut-retouch/scripts/background.mjs" start "<입력>" check
node "<OPS>/manuals/capcut-retouch/scripts/background.mjs" status "<입력>"
node "<OPS>/manuals/capcut-retouch/scripts/background.mjs" start "<새 입력 폴더>" prepare [영상 파일명]
```

- `check`: 교체 계획의 이전 기준 경로를 현재 입력 폴더에 대응시키고, 교체 파일·교체 전 백업·최초 원본 백업의 SHA-256을 대조한다. 내부 폴더까지 이동했다면 etc와 링크를 제외한 현재 입력 폴더에서 같은 파일명 후보를 찾고, 해시가 같은 단일 파일만 인정한다. 여러 사본이 일치하면 임의 선택하지 않는다. 누락·내용 변경·여러 사본을 구분해 기록한다. 원본이나 보정본을 변경하지 않는다. 교체 이력이 있는 폴더 전체에 prepare를 다시 실행하면 차단한다.
- `prepare`: 기존 준비 도구로 MOV 목록·백업·기본 정보를 만든다. 성공 상태 `ready-for-desktop`은 준비 완료이며, 보정 완료가 아니다.
- 결과는 `<입력>/etc/capcut-retouch/background/state.json`, `report.json`, `runner.log`에 저장한다. `needs-review`나 `failed`면 불일치나 오류부터 확인한다. 상태 조회의 `completed`는 해당 준비·대조 작업만 끝났다는 뜻이다.
- 실행 중에는 `next_check_at`을 따른다. 기다리는 일만 남으면 15분 이상 간격의 기존 모니터를 사용하고, 변동 없는 조회를 반복하지 않는다. 프로세스를 중복 실행하지 않는다.

숨김 창 시험 기록은 이 컴퓨터의 에이전트 폴더 `etc/capcut-background`에 있다. 시험 도구는 기존 CapCut이 실행 중이면 멈추며, 시험 프로세스만 종료한다. 프로젝트와 목록을 백업한 뒤 실행하고, 사용자 화면으로 전환하는 호출과 전역 마우스·키보드 입력은 사용하지 않는다. 기록된 창 번호나 좌표는 다음 실행에 재사용하지 않는다. 새 화면을 읽고 입력 대상을 다시 확인한다.

확인한 범위는 숨김 실행·캡처·새 프로젝트 열기·원본 가져오기·영상 미리보기·복사한 프로젝트의 타임라인과 Retouch 설정 읽기다. 새 영상의 인물별 Retouch 적용, 같은 길이·해상도·프레임률·음성으로 저장, 결과 검수까지 모두 통과해야 백그라운드 보정 완료로 승격한다. 사용자 계정의 Pro 확인과 숨김 실행기의 조작 성공 여부를 혼동하지 않는다. 시험 후 전용 프로젝트는 에이전트 폴더의 etc로 보관했고, 기존 프로젝트 파일221개의 해시가 바뀌지 않았음을 확인했다.

## 산출물

보정 완료 폴더의 MP4, etc/capcut-retouch의 원본 목록·백업·인물 설정·검수 기록·작업 프로젝트 백업. 큐 입력에는 input.root로 원본 폴더의 절대경로를 전달한다. checks.mjs는 이 폴더의 실제 검수 기록을 대조한다.

## 알려진 함정

- AI Lab 시험에서는 공급자가 개별 Retouch 미지원과30fps 고정 출력을 인정했다. 단일 HD II 필터를 얼굴 보정 결과로 납품하지 않는다. 기존 실패 요청을 재인증·재업로드·재렌더링하지 않는다.
- Windows VEHelper의 확인된 진입점은 로그 전송용이었다. macOS 렌더러 사례를 Windows에 그대로 적용하지 않는다.
- 숨긴 데스크톱에서 보조 프로그램이 실행됐다는 사실은 CapCut 보정 출력 성공을 뜻하지 않는다. 다른 로컬 엔진의 결과도 CapCut 결과로 쓰지 않는다.
- 숨김 시험에서 From device 메뉴는 폭100px이었다. 작은 창을 검사에서 제외하면 정상적으로 열린 메뉴를 놓친다. 클릭·파일 선택은 작동했으나 메시지로 보낸 드래그·더블클릭은 타임라인 배치로 이어지지 않았다. 같은 좌표 입력을 반복하지 않는다.
- 기존 프로젝트를 복제해 시험할 때는 별도 이름·프로젝트 ID·폴더를 만들고, 이동된 소스 경로를 백업 위치로 연결한다. 실제 CapCut에서 복사본 이름과 Retouch 수치를 확인한다. 검게 보이는 Export 후속 창을 좌표 추측으로 누르거나, 원인 확인 없이 로그인 요청을 반복하지 않는다.
- 공개 CapCut CLI의 프로젝트 편집과 네이티브 영상 렌더링은 다르다. 별도 렌더러가 필요한 macOS 예제를 Windows용 완성 도구로 안내하지 않는다.
- Export selected clips 우클릭 메뉴는 포커스 전환으로 사라진 사례가 있다. 반복해서 누르지 말고 한 편씩 타임라인 전체를 내보낸다.
- 내보내기 창과 완료 창은 크기·위치가 다르다. 새 창 자체의 화면을 확인해 입력한다. 창 전환 직후 화면이 잠시 이전 상태일 수 있다.
- 입력 지점에 다른 프로그램이 있다는 오류가 나오면 입력을 멈추고 CapCut을 다시 확인한다. 사용자가 컴퓨터를 쓰는 중이면 화면을 다투지 않는다.
- 리셋 크레딧은 자동으로 사용하지 않는다.
