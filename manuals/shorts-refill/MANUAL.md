# 쇼츠 소재 리필

- **부르는 말**: 소재 채워줘, 쇼츠 소재 리필, 소재 보충해줘, 소재큐 채워줘, 잘된 거 보고 소재 만들어줘, 재고 확인해줘
- **런너**: claude
- **제어층**: L1 (재고, 중복검사, 검증), L3 (인스타 실측 한 번)
- **한 번에 걸리는 시간**: 실측 5분, 팩 쓰기 채널당 25분 안팎

---

## 무엇을 만드는 업무인가

`shorts-pipeline` 이 하루 한 편씩 먹어 치우는 소재 재고를 다시 채운다.
끝나면 `<채널> 소재/` 폴더에 새 팩 JSON 이 들어가 있고 검증 스크립트가 그 팩들을 통과시킨다.

**감으로 뽑지 않는다.** 인스타 @haruyaksa 재생수를 전수로 재서 이긴 프레임과 죽은 프레임을
먼저 뽑고, 그 결과로 주제를 고른다. 실측을 안 보면 죽은 프레임을 계속 다시 쓴다.
실제로 260808 에 넓힌 생활민원 갈래(환급금, 구직)가 전부 5천 회 밑으로 죽었는데
재고에는 같은 갈래가 아직 남아 있었다.

## 쉬운 설명

### 쓰는 상황

쇼츠 업로드는 매일 도는데 소재는 유한합니다. 재고가 열흘치 밑으로 내려가면 채워야 합니다.
채울 때 아무거나 쓰면 조회수가 죽으니, 지금까지 올린 것 중 잘된 것을 먼저 확인하고 씁니다.

### 시키는 말

"소재 채워줘" 한 마디면 됩니다. 채널을 정해 주려면 "하루건강약사 소재 채워줘" 라고 합니다.
재고만 궁금하면 "재고 확인해줘" 라고 하면 세기만 하고 멈춥니다.

### 진행 순서

재고를 세고, 인스타에 올라간 릴스 조회수를 전부 긁어서 뭐가 잘됐는지 뽑고,
잘된 갈래에서 새 주제를 잡고, 이미 올린 것과 겹치는지 검사하고, 팩을 써서 넣고, 검사를 돌립니다.

### 결과물

`하루건강약사 소재/` `건강장수비결 소재/` 폴더에 새 소재 파일이 들어갑니다.
그리고 이번에 무엇이 잘됐고 무엇이 죽었는지 정리한 실측표가 작업 폴더에 남습니다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차와 완료 검사를 한 번에 실행한다.
재고를 세고 끝내지 마라. **재고가 기준 밑이면 채우는 것까지가 이 업무다.**
주제를 사람에게 물어보지 않는다. 실측과 겹침 검사로 정하고, 무엇을 왜 골랐는지 보고에 적는다.

이 업무는 돈을 쓰지 않는다. 유료 호출은 `shorts-pipeline` 이 팩을 소비할 때 일어난다.
여기서는 파일만 만든다. 그래서 되돌리기가 쉽고, 멈출 이유가 거의 없다.

## 준비물

- 로그인된 크롬. 인스타 계정은 아무거나 상관없다. **보는 것만 한다**
- `<DEV>/n8n-youtube-shorts-automation` 저장소. n8n 서버는 안 떠 있어도 된다
- 규격은 그 저장소의 `AGENTS.md` 가 원본이다. **여기에 자릿수를 옮겨 적지 마라.**
  바뀌면 저쪽만 고치기 때문에, 옮겨 적은 숫자는 반드시 낡는다

## 절차

### P1. 재고를 센다 (L1)

```bash
node "<OPS>/manuals/shorts-pipeline/scripts/topic-count.mjs"
```

**소진 속도는 채널당 하루 한 편이다.** 나온 수가 곧 남은 날짜다.
**열흘 밑으로 내려간 채널을 채운다.** 두 채널 다 밑이면 둘 다 채운다.

파일 수를 그냥 세지 마라. `LOCKED_SOURCE_PACK=1` 이 붙은 파일은 본편이 안 쓴다.
이유는 `shorts-pipeline` 매뉴얼 P1 에 있다.

### P2. 인스타 재생수를 전수로 긁는다 (L3)

로그인된 크롬에서 `instagram.com/haruyaksa` 를 연다. 그 탭 안에서 아래를 실행한다.
**계정은 아무거나 된다. 남의 계정으로 봐도 숫자는 같다.**

```js
const csrf = (document.cookie.match(/csrftoken=([^;]+)/) || [])[1];
async function page(maxId) {
  const body = new URLSearchParams();
  body.set('target_user_id', '15272270790');
  body.set('page_size', '50');
  if (maxId) body.set('max_id', maxId);
  const r = await fetch('/api/v1/clips/user/', {
    method: 'POST',
    headers: { 'X-IG-App-ID': '936619743392459', 'X-CSRFToken': csrf,
               'Content-Type': 'application/x-www-form-urlencoded' },
    body: body.toString(),
  });
  if (!r.ok) throw new Error(r.status + ' ' + (await r.text()).slice(0, 200));
  return r.json();
}
const all = [];
let maxId = null;
for (let i = 0; i < 10; i++) {
  const j = await page(maxId);
  all.push(...(j.items || []).map(x => x.media || x));
  if (!j.paging_info || !j.paging_info.more_available) break;
  maxId = j.paging_info.max_id;
}
window.__reels = all.map(m => ({
  code: m.code,
  date: new Date(m.taken_at * 1000).toISOString().slice(0, 10),
  plays: m.play_count ?? m.ig_play_count ?? null,
  likes: m.like_count,
  caption: (m.caption && m.caption.text ? m.caption.text : '').split('\n')[0].slice(0, 60),
})).sort((a, b) => b.plays - a.plays);
window.__reels.length
```

**`X-CSRFToken` 을 빼면 403 `CSRF token missing or incorrect` 가 난다.** 오류 메시지가
로그인 문제처럼 보이지만 로그인은 멀쩡하다. 쿠키 `csrftoken` 을 헤더로 다시 넣어 주면 된다.

숫자가 나오면 `<OPS>/work/<taskId>/insta-plays.tsv` 로 옮긴다. 한 줄이 한 편이다.
아래를 `slice(0,15)`, `slice(15,30)` 처럼 끊어서 네 번 부른다.

```js
window.__reels.slice(0, 15).map(r => [r.date, r.plays, r.likes, r.code, r.caption].join('\t')).join('\n')
```

**한 번에 다 꺼내려 하지 마라.** 도구가 응답을 잘라서 중간 편이 통째로 사라진다.
15편씩 끊는 게 실제로 되는 방법이다. 마지막에 줄 수가 맞는지 센다.

프로필 그리드 DOM 에는 재생수가 없고, 릴스 탭은 브라우저 패널이 안 떠 있으면 렌더링이 안 된다.
그래서 화면을 읽지 않고 이 경로로 긁는다.

### P3. 무엇이 이겼는지 뽑는다 (L1)

```bash
node "<OPS>/manuals/shorts-refill/scripts/analyze-performance.mjs" "<OPS>/work/<taskId>/insta-plays.tsv"
```

나오는 것 여섯 가지다.

| 절 | 무엇에 쓰나 |
| --- | --- |
| 먼저 치울 것 | `research/queue` 에 남은 발행분. **있으면 지우고 시작한다** |
| 이긴 것과 죽은 것 | 상하위 25%. 프레임을 여기서 읽는다 |
| 판정 못 하는 것 | 나흘 미만. 낮다고 죽었다고 보지 마라 |
| 최근 발행 12편의 영역 | **여기 있는 영역은 이번 배치에서 피한다** |
| 지금 재고의 영역 | 재고가 한쪽으로 쏠렸는지 |
| 영역별 성적 | 승패. 0승 여러 패인 영역은 안 쓴다 |

**인스타 재생수를 유튜브 조회수와 절대값으로 비교하지 마라.** 재생수는 반복 재생을 센다.
순위만 쓴다.

### P4. 주제를 잡는다

순서를 지킨다. **생활에서 주제를 먼저 잡고, 중복검사를 통과시키고, 그 다음에 내용을 채운다.**
근거를 찾으러 가지 마라. 논문에서 주제가 나오면 접근성이 폭락한다.

거르는 기준 셋.

1. **P3 의 죽은 영역은 안 쓴다.** 0승 여러 패인 영역은 이번 배치에서 뺀다
2. **최근 12편에 있는 영역은 피한다.** 한 영역에 두 개 이상 쏠리면 좁아진 것이다
3. **행마다 가져갈 것이 있어야 한다.** 55세가 읽고 "그건 나도 알지" 하면 그 주제는 버린다

이긴 프레임과 죽은 프레임의 실측 목록은 아래 "실측이 말해 주는 것" 절에 있다.
**회차마다 갱신한다.** 매뉴얼에 박아 둔 규칙이 아니라 이번 달 성적표다.

### P5. 제목 중복검사를 먼저 통과시킨다 (L1)

내용을 채우기 전에 제목만으로 먼저 건다.

```bash
node ./scripts/check-topic-title-availability.mjs "제목 1" "제목 2"
```

**걸렸다고 제목을 비틀어 통과시키지 마라.** 제목은 항목 목록을 그대로 설명해야 한다.
검사에 걸리면 주제를 바꾼다.

이 검사는 제목만 본다. 같은 이야기를 다른 제목으로 쓰면 못 잡는다. 그건 P6 이 잡는다.

### P6. 팩을 쓰고 검사를 통과시킨다 (L1)

규격은 `<DEV>/n8n-youtube-shorts-automation/AGENTS.md` 의 `New-Pack Staging Checklist` 를
**그 자리에서 읽고** 따른다. 자릿수와 문장꼴이 거기 있다.

팩 파일은 `<채널> 소재/<번호>-<영문키>.json` 으로 넣는다. 번호는 그 폴더에서 안 쓴 다음 번호다.
`research/queue/<채널>/` 에도 같은 파일을 넣는다. 검증 스크립트가 그쪽을 본다.

```bash
node ./scripts/verify-queued-packs-pass-gate.mjs
```

```bash
node ./scripts/verify-queued-topics-are-fresh.mjs
```

앞엣것은 살아 있는 결정적 게이트에 팩을 그대로 통과시켜 본다. **유료 실행 전에 여기서 막힌다.**
뒤엣것은 행 내용이 이미 발행한 편과 겹치는지 본다. 제목이 안 겹쳐도 같은 이야기면 잡힌다.

걸리면 고쳐서 다시 돌린다. **검사를 건너뛰고 완료라고 말하지 마라.**

### P7. 실측표를 매뉴얼에 반영하고 커밋한다

P3 결과가 지난 회차와 달라졌으면 아래 "실측이 말해 주는 것" 을 고쳐 쓴다.
그리고 커밋하고 push 한다. 소재 팩은 n8n 저장소, 실측표는 ops 저장소다.

## 알려진 함정

- **`X-CSRFToken` 없이 클립 API 를 부르면 403 이 난다.** 메시지가 `CSRF token missing or
  incorrect` 라 로그인이 풀린 것처럼 보인다. 쿠키 `csrftoken` 을 헤더에 넣으면 그냥 된다
- **실측을 한 번에 다 꺼내면 도구가 잘라서 중간 편이 사라진다.** 15편씩 네 번 나눠 꺼내고
  마지막에 줄 수를 센다. 260825 에 이걸로 두 번 다시 꺼냈다
- **인스타 캡션은 제목이 아니다.** 올릴 때 다시 쓴다.
  발행 제목 `혈압약 드시면 꼭 피해야 하는 음식 4` 가 캡션에서는
  `혈압약 드실 때, 음식도 같이 살펴보셔야 해요` 다. 그래서 분석기는 앞글자가 아니라
  내용어 겹침으로 붙이고, 날짜가 맞는 것만 후보로 본다.
  날짜를 안 보면 7월 릴스가 8월 팩에 붙는다(실측으로 겪었다)
- **`research/queue` 를 재고로 세지 마라.** 거기는 사본이고, 발행하고 안 지운 팩이 쌓인다.
  260825 에 실제 재고 15건이 26건으로 부풀어 보였다. 원장은 `<채널> 소재/` 폴더다
- **발행된 팩을 `research/queue` 에 두면 검증이 상시 빨갛다.**
  `verify-stockpile-titles-unpublished` 가 잡는다. 리필 시작할 때 먼저 치운다
- **인스타 @haruyaksa 하나에 두 채널 영상이 다 올라간다.** 실측 한 판으로 두 채널을 같이 본다.
  대신 어느 채널 것인지는 캡션이 아니라 아카이브 팩의 `lane` 으로 가린다
- **게이트가 `사이` 를 주격조사로 읽는다.** `card_name` 이 `사이` 로 이어지고 `기` 로 끝나면
  `broken_nominalization` 으로 반려한다. 검사식이 `[가-힣](이|가) ... 기$` 라 `사이 ` 의 `이` 가
  걸리는데, 예외 목록에 `없이 같이 높이 많이 깊이` 만 있고 `사이` 가 없다.
  `나이` `차이` `아이` 도 같은 꼴이다. 260825 에 `발가락 사이 건너뛰기` 가 여기 걸려
  `발가락 틈 건너뛰기` 로 바꿔 나갔다. **문장이 멀쩡하면 게이트 탓이니 말을 바꿔 우회한다.**
  예외 목록을 고치려면 `install-shared-content-quality-gate.mjs` 세 군데를 같이 고치고
  `simplify-legacy-editorial-flow.mjs` 를 반드시 뒤에 다시 돌려야 한다. 리필하다 하지 마라
- **다른 세션이 같은 시간에 파이프라인을 돌린다.** 260825 에 검사 도중 에어컨 편이 발행돼
  큐 사본이 새로 고아가 됐다. **검사가 갑자기 걸리면 P3 을 다시 돌려 치울 것을 다시 본다**
- **거부된 팩을 `사용완료` 로 옮기지 마라.** 중복검사가 발행된 것으로 보고 제목을 영영 막는다.
  `보류` 폴더로 옮긴다
- 나흘 안 된 편은 재생수가 계속 오른다. 낮다고 죽었다고 판정하지 마라
