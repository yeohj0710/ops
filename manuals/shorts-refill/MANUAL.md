# 쇼츠 소재 리필

- **부르는 말**: 소재 채워줘, 쇼츠 소재 리필, 소재 보충해줘, 소재큐 채워줘, 잘된 거 보고 소재 만들어줘, 재고 확인해줘
- **미리 허가**: 없음. 소재 파일만 만들고 돈을 안 쓴다
- **런너**: claude
- **제어층**: L1 만 쓴다. 로그인도 화면 조작도 필요 없다
- **한 번에 걸리는 시간**: 전략 뽑기 2분, 이긴 카드 읽기 5분, 팩 쓰기 채널당 25분 안팎

---

## 무엇을 만드는 업무인가

`shorts-pipeline` 이 하루 한 편씩 먹어 치우는 소재 재고를 다시 채운다.
끝나면 `<채널> 소재/` 폴더에 새 팩 JSON 이 들어가 있고 검사 다섯 개가 그 팩들을 통과시킨다.

**판정은 팔로우로 한다.** 조회수로 고르면 정반대 결론이 나온다. 실측으로 확인했다.

| 편 | 조회 | 팔로우 | 전환 |
| --- | --- | --- | --- |
| 안약 넣을 때 대부분 잘못하고 있는 것 4 | 62.8만 | 86 | 0.014% |
| 무릎 허리 깎아먹는 생활 습관 7가지 | 21.6만 | 115 | 0.053% |

조회수 3분의 1인 편이 팔로우는 더 데려왔다. 채널을 키우는 것은 팔로우다.
조회수는 그날 하루 숫자고 팔로우는 다음 편의 시작 조회수다.

## 쉬운 설명

### 쓰는 상황

쇼츠 업로드는 매일 도는데 소재는 유한합니다. 재고가 열흘치 밑으로 내려가면 채워야 합니다.
채울 때 아무거나 쓰면 조회수는 나와도 팔로워가 안 늘어서, 지금까지 올린 것 중
**팔로우를 실제로 데려온 것**을 먼저 확인하고 씁니다.

### 시키는 말

"소재 채워줘" 한 마디면 됩니다. 채널을 정해 주려면 "하루건강약사 소재 채워줘" 라고 합니다.
재고만 궁금하면 "재고 확인해줘" 라고 하면 세기만 하고 멈춥니다.

### 진행 순서

재고를 세고, 어떤 영상이 팔로워를 데려왔는지 뽑고, **잘된 카드를 직접 열어 뭐라고 썼는지 읽고**,
그 결대로 새 주제를 잡고, 이미 올린 것과 겹치는지 보고, 팩을 써서 넣고, 검사 다섯 개를 돌립니다.

숫자만 보면 안 됩니다. 팔로워를 제일 많이 데려온 영상이 "김치찌개에 케첩 넣기" 같은
뜻밖의 내용이었는데, 숫자만 봐서는 그걸 알 수가 없습니다. 그래서 카드 그림을 받아서 읽습니다.

### 결과물

`하루건강약사 소재/` `건강장수비결 소재/` 폴더에 새 소재 파일이 들어갑니다.
그리고 무엇이 팔로워를 데려왔는지 정리한 전략표가 작업 폴더에 남습니다.

## 실행 계약

사용자가 이 업무를 호출하면 이 매뉴얼의 절차와 완료 검사를 한 번에 실행한다.
재고를 세고 끝내지 마라. **재고가 기준 밑이면 채우는 것까지가 이 업무다.**
주제를 사람에게 물어보지 않는다. 실측과 겹침 검사로 정하고, 무엇을 왜 골랐는지 보고에 적는다.

이 업무는 돈을 쓰지 않는다. 유료 호출은 `shorts-pipeline` 이 팩을 소비할 때 일어난다.
여기서는 파일만 만든다. 그래서 되돌리기가 쉽고, 멈출 이유가 거의 없다.

## 준비물

- 인터넷. 로그인은 필요 없다. 지표도 카드 그림도 공개 주소로 받는다
- **그림을 볼 수 있는 세션.** P2.5 에서 카드를 눈으로 읽는다. 못 보면 그 단계가 무의미하다
- `<DEV>/n8n-youtube-shorts-automation` 저장소. n8n 서버는 안 떠 있어도 된다
- 규격은 그 저장소의 `AGENTS.md` 가 원본이다. **여기에 자릿수를 옮겨 적지 마라.**
  바뀌면 저쪽만 고치기 때문에, 옮겨 적은 숫자는 반드시 낡는다

## 절차

### P1. 재고를 센다 (L1)

```bash
node "<OPS>/manuals/shorts-pipeline/scripts/topic-count.mjs"
```

**소진 속도는 채널당 하루 한 편이다.** 나온 수가 곧 남은 날짜다.
**열흘 밑으로 내려간 채널을 채운다.** 두 채널 다 밑이면 둘 다 채운다.

파일 수를 그냥 세지 마라. `LOCKED_SOURCE_PACK=1` 이 붙은 파일은 본편이 안 쓴다.
이유는 `shorts-pipeline` 매뉴얼 P1 에 있다.

### P2. 팔로우 전환 전략을 뽑는다 (L1)

```bash
node "<OPS>/manuals/shorts-refill/scripts/follow-strategy.mjs" --out "<OPS>/work/<taskId>/전략.md"
```

릴스 인사이트 랩이 화면 녹화를 데이터화해 둔 공개 JSON 을 받아 한 장으로 줄인다.
**로그인도 브라우저도 필요 없다.** 인스타를 긁던 옛 절차는 조회수밖에 못 줘서 버렸다.

나온 `전략.md` 를 읽는다. **1.5MB 짜리 원본 JSON 을 읽지 마라.** 이 파일이 그걸 줄인 것이다.

읽을 것 다섯이다.

| 절 | 무엇에 쓰나 |
| --- | --- |
| 무엇이 팔로우 수를 흔드는가 | 조회수와 전환율 중 어느 쪽이 지배하는지 |
| 팔로우를 많이 데려온 편 | **여기 있는 결을 따라간다** |
| 조회수는 벌어 놓고 전환에서 흘린 편 | 제일 아까운 자리. 같은 주제를 프레임만 바꿔 다시 쓴다 |
| 아무것도 못 벌어온 편 | 조회수도 전환도 낮았던 것 |
| 회로별과 항목 수별 | 얽혀 있으니 단정하지 마라 |

**다른 계정 표는 기본으로 안 나온다.** 자료에 실제 약사 계정이 같이 들어 있지만
하루건강약사는 AI 크리에이터라 그쪽 소재가 옮겨지지 않는다. 아래 "공략점" 을 보라.

**전략표는 숫자만 준다. 행은 P2.5 에서 본다.** 여기서 멈추면 260825 처럼 된다.

### P2.5. 이긴 카드의 행을 실물로 읽는다 (L1)

**이 단계를 건너뛰지 마라. 260825 에 팩 22장을 쓰고 통째로 반려된 자리가 여기다.**
전략표는 "무엇이 이겼나" 를 제목과 숫자로만 준다. 이긴 카드가 **행에 무엇을 썼는지**는
어디에도 없어서, 대상 폭과 프레임을 다 맞추고도 행이 전부 뻔한 팩이 나왔다.

```bash
node "<OPS>/manuals/shorts-refill/scripts/collect-winning-cards.mjs" --worst
```

팔로우 상위 12편과 바닥 4편의 **카드 그림**을 `references/이긴카드/` 에 받는다.
이 계정 릴스는 정지 카드 한 장이라 **썸네일이 곧 카드 전체**다. 행이 다 읽힌다.

**그림을 직접 열어라.** `references/수집목록.md` 에 순위와 숫자가 붙은 표가 있으니
위에서부터 열고, 바닥 4편도 같이 본다. 이긴 것만 보면 무엇이 없어서 졌는지를 못 본다.

**그리고 이번 회차가 본 것을 `<OPS>/work/<taskId>/카드읽기.md` 에 네 말로 적는다.**
옛 회차의 메모를 베끼지 마라. 무엇이 눈에 띄었고 이번 배치에 무엇을 가져갈지 적는다.
이게 P4 의 잣대가 된다.

`references/이긴카드.md` 는 그때 그림을 옮겨 적어 둔 **사본**이다. 그림을 못 받을 때 쓴다.
거기 달린 메모는 260825 회차가 본 것이지 규칙이 아니다. 그대로 따르면 그때와 같은 것만 나온다.

**인스타를 직접 열지 마라.** 인스타 화면에는 편별 팔로우 수가 안 나와서 어느 카드가
이겼는지로 줄을 못 세운다. 대시보드 지표와 붙여야 순위가 나오고, 이 스크립트가 그걸 한다.
로그인도 필요 없다.

`이긴카드.md` 가 한 달 넘게 낡았거나 상위 편이 바뀌었으면 그림을 다시 받아 옮겨 적고
그 파일을 고쳐 쓴다. 옮겨 적는 것은 에이전트가 한다. 스크립트는 무엇을 볼지만 정한다.

### P3. 재고와 큐 위생을 본다 (L1)

```bash
node "<OPS>/manuals/shorts-refill/scripts/analyze-performance.mjs" "<OPS>/work/<taskId>/insta-plays.tsv"
```

실측 TSV 가 없으면 이 단계는 건너뛰어도 된다. **다만 아래 하나는 반드시 확인한다.**

```bash
node "<OPS>/manuals/shorts-refill/scripts/analyze-performance.mjs" --stock-only
```

`research/queue` 에 발행하고 안 지운 팩이 남아 있으면 지운다.
두면 `verify-stockpile-titles-unpublished` 가 상시 실패한다.

### P4. 주제를 잡는다

순서를 지킨다. **생활에서 주제를 먼저 잡고, 중복검사를 통과시키고, 그 다음에 내용을 채운다.**
근거를 찾으러 논문에 가지 마라. 논문에서 주제가 나오면 접근성이 폭락한다.
근거는 주제를 고른 **다음에**, 위험한 행만 확인한다(P6).

거르는 기준 다섯이다. 아래 "공략점" 절이 이 기준의 지금 값이고,
`references/이긴카드.md` 가 실물이다. **둘 다 읽고 시작한다.**

1. **대상 폭을 먼저 본다.** 조건이 붙을수록 조회수가 깎이고, 조회수가 팔로우 수를 지배한다
2. **얻는 프레임으로 쓴다.** 잃는 프레임은 조회수만 오고 팔로우가 안 붙는다
3. **재고와 최근 발행에 있는 영역은 피한다.** 한 영역에 두 개 이상 쏠리면 좁아진 것이다
4. **행마다 이름을 대고, 그 이름이 뻔하지 않아야 한다.** 이름만으로는 모자라다.
   진 카드에도 소금통, 밥공기, 국물이 다 나오는데 팔로우가 0명이다.
   써 놓은 행을 소리 내 읽고 "그건 나도 알지" 가 나오면 그 행을 버린다
5. **틀리면 사람이 다치는 주제는 교과서 표준만 쓴다.** 확인이 안 되면 그 행을 버린다

**팩을 다 쓰고 나서 마지막으로 이 검사를 한다.** 내가 쓴 카드 한 장과 P2.5 에서 본
**1위 카드 그림**을 나란히 놓는다. 그 옆에서 내 카드가 읽을 만한가.
밀리면 검사를 다 통과했어도 그 팩은 버린다.
**기계 검사는 자수와 겹침만 본다. 뻔함은 어느 검사도 못 잡는다.**

**"이 결은 죽었다" 고 단정하기 전에 같은 소재의 다른 편을 찾아본다.**
결만 보고 가르면 틀린다. 같은 소재로 이긴 편과 진 편이 다 있고, 갈린 자리는 대개
대상 폭이나 프레임이지 소재가 아니다. 공략점 절의 짝 비교가 그 실측이다

### P5. 제목 중복검사를 먼저 통과시킨다 (L1)

내용을 채우기 전에 제목만으로 먼저 건다.

```bash
node ./scripts/check-topic-title-availability.mjs "제목 1" "제목 2"
```

**걸렸다고 제목을 비틀어 통과시키지 마라.** 제목은 항목 목록을 그대로 설명해야 한다.
검사에 걸리면 주제를 바꾼다.

**통과한 제목을 소리 내 읽어 무슨 영상인지 바로 떠오르는지 본다.** 검사는 겹침만 보지
알아듣기 쉬운지는 안 본다. 기준은 위 공략점의 "제목은 한 번에 이해돼야 한다" 절에 있다.

이 검사는 제목만 본다. 같은 이야기를 다른 제목으로 쓰면 못 잡는다. 그건 P6 이 잡는다.

### P6. 팩을 쓰고 검사 다섯 개를 통과시킨다 (L1)

규격은 `<DEV>/n8n-youtube-shorts-automation/AGENTS.md` 의 `New-Pack Staging Checklist` 를
**그 자리에서 읽고** 따른다. 자릿수와 문장꼴이 거기 있다.

팩 파일은 `<채널> 소재/<번호>-<영문키>.json` 으로 넣는다. 번호는 그 폴더에서 안 쓴 다음 번호다.
`research/queue/<채널>/` 에도 같은 파일을 넣는다. 검증 스크립트가 그쪽을 본다.

**`notes` 에 두 가지를 적는다.** 왜 이 주제를 골랐는지(전략 근거), 그리고
위험한 행이 무엇에 기대어 쓴 것인지(사실 근거). 아래 검사가 뒤엣것을 본다.

```bash
node ./scripts/verify-queued-packs-pass-gate.mjs
```

```bash
node ./scripts/verify-queued-topics-are-fresh.mjs
```

```bash
node ./scripts/verify-stockpile-titles-unpublished.mjs
```

```bash
node "<OPS>/manuals/shorts-refill/scripts/check-claims.mjs"
```

앞 셋은 모양과 겹침을 본다. 넷째가 **틀리면 사람이 다치는 주장**을 골라 근거를 적었는지 본다.
약 이름, 병 이름, 용량, 응급, 기관 이름, 숫자가 붙은 행이 걸린다.

마지막으로 P4 의 "1위 카드 옆에 놓기" 를 빈칸으로 강제한다. 팩마다 **뜻밖인 행 하나**를
그대로 옮겨 적어야 하고, 못 적으면 그 팩을 버린다. 260825 2차 회차부터 쓴다.

```bash
node "<OPS>/manuals/shorts-refill/scripts/compare-with-winners.mjs" --out "<OPS>/work/<taskId>/견주기.md"
node "<OPS>/manuals/shorts-refill/scripts/compare-with-winners.mjs" --check "<OPS>/work/<taskId>/견주기.md"
```

**근거를 못 대면 그 행을 버린다.** 숫자를 지어내지 마라. 항목이 모자라면 주제를 바꾼다.
이 검사는 근거를 적었는지만 본다. 내용이 맞는지는 마지막에 사람이 통독해서 본다.

### P7. 공략점과 실측을 매뉴얼에 반영하고 커밋한다

`전략.md` 가 지난 회차와 달라졌으면 아래 "공략점" 을 고쳐 쓴다.
**상위 편이 바뀌었으면 `references/이긴카드.md` 도 새 그림을 보고 다시 쓴다.**
표만 갈아 끼우고 옛 메모를 그대로 두지 마라. 그러면 다음 회차가 옛 결론을 읽는다.

그리고 커밋하고 push 한다. 소재 팩은 n8n 저장소, 매뉴얼은 ops 저장소다.
카드 그림은 git 에 안 올라간다. 다음 세션은 스크립트로 다시 받는다.

**push 뒤에 `node "<OPS>/ops.mjs" sync` 를 돌린다.** 드라이브 매뉴얼 사본이 그때 갱신된다.
안 돌리면 드라이브만 보고 일하는 세션이 낡은 절차를 읽는다. 260825 에 실제로 7줄이 뒤처져 있었다.
sync 는 카드 그림도 같이 옮겨서, 저장소가 없는 컴에서도 P2.5 를 할 수 있게 해 준다.

## 공략점

### 목표는 전환율이 아니라 팔로우 수다

```
팔로우 수 = 조회수 × 전환율
```

| 견줄 것 | 로그 표준편차 | 팔로우 수와 상관 |
| --- | --- | --- |
| 조회수 | 1.29 | 0.92 |
| 전환율 | 0.59 | 0.52 |

**조회수가 지배한다.** 안약 편은 전환율 0.014% 로 바닥인데 62.9만 조회로 팔로우 86명,
전체 5위다. 전환율만 보면 이 편을 버리는 판단을 하게 된다. 실제로 260825 에 그렇게 적었다가 고쳤다.

**다만 조회수와 전환율은 서로 상관 0.15 로 거의 무관하다.**
트레이드오프가 아니다. 조회수를 깎아 전환율을 올릴 필요가 없고, 전환율이 바닥인 결을
그냥 두면 벌어 놓은 조회수를 흘린다. 아침 신호 편은 90.5만을 벌고 0.014% 라 75명을 흘렸다.

**상위 10편이 전체 팔로우의 69% 를 만들었다.** 골고루 잘하는 게임이 아니라 터뜨리는 게임이다.

### 위 조건을 다 맞춰도 실용이 없으면 안 된다

260825 에 견본 6편이 위 다섯 질문을 다 통과하고 반려됐다. 이유는 하나다.
**다 읽고 나도 새로 알게 된 것이 없었다.**

반려된 행들이다.

| 반려된 행 | 왜 걸리나 |
| --- | --- |
| 원료명 뒤 괄호 안에 적힌 것이 실제로 들어간 원료예요 | 어디를 보라고만 하고 보고 나서 뭘 알아야 하는지는 안 준다 |
| 다리를 꼬는 습관 때문에 한쪽 무릎에만 몸이 실려요 | 다 아는 말이다 |
| 쪼그려 앉으면 무릎 안쪽이 서로 눌려서 제일 부담돼요 | 다 아는 말이다 |
| 봉지째 먹는데 표시는 반 봉지 기준일 때가 많아요 | 사실은 맞는데 그래서 뭘 사라는 건지가 없다 |

공통점은 **행이 "무엇을 하라" 로만 되어 있다는 것**이다. 보세요, 바꾸세요, 견주세요.
시청자는 시킴을 받고 아무것도 못 들고 나간다.

이긴 편의 행은 전부 **명단**이다. 이름을 대고 어느 쪽인지 갈라 준다.

| 이긴 행 | 무엇을 주나 |
| --- | --- |
| 감자와 양파는 냉장고에 넣으면 맛이 되레 나빠져요 | 대상이 콕 집힌다 |
| 냉동실에 넣으면 오히려 맛있어지는 음식 | 어느 음식인지 이름을 준다 |
| 매일 먹어도 되는 것과 안 되는 것 | 갖고 있는 것을 두 칸으로 갈라 준다 |

**검사는 하나다. 영상을 끄고 나서 옆사람한테 한 문장으로 옮겨 말할 수 있나.**
"라벨 뒷면 보래" 는 옮길 말이 없다. "감자는 냉장고 넣으면 안 된대" 는 옮겨진다.
옮길 것이 없으면 저장도 공유도 팔로우도 안 나온다.

**행을 쓸 때 이름을 대라.** 음식이면 음식 이름, 시간이면 몇 시, 자리면 어느 칸,
사람이면 어떤 사람. "어떤 것들" 이나 "잘 보고" 로 뭉갠 행은 버린 행이다.

**"틀린 말은 안 넣었다" 는 통과 기준이 아니다.** 안전하게 쓰려다 아무 말도 안 하게 되는 것이
이 계정에서 제일 흔한 실패다. 확인이 안 되는 숫자는 빼되, 뺀 자리를 두루뭉술한 말로
메우지 말고 **확인되는 다른 명단으로 채운다.**

### 소재 영역에 스스로 울타리를 치지 마라

**이 계정에서 제일 크게 이긴 편은 건강 이야기가 한 줄도 없는 요리 꿀팁이다.**
1위 집밥 한 끗(팔로우 391, 조회 95.6만)은 김치찌개에 케첩, 불고기에 콜라다.
약도 몸도 안 나온다. 그런데 haruyaksa 계정 편이다.

260825 2차에서 이걸 놓쳤다. 1위 카드의 **행 문법**(아는 재료 둘의 뜻밖의 짝)은 가져다 썼는데
**영역 자체**(요리가 맛있어지는 것)는 안 가져왔다. 부엌 팩 넷을 전부 보관과 안전으로 채웠다.
"약사 채널에 요리 맛 내는 법이 맞나" 라는 스스로의 판단이 이유였는데, 1위가 바로 그 계정
것이라 근거가 없는 걱정이었다. 제목 검사를 돌려 보니 요리 제목은 겹침 0으로 그냥 통과했다.
**길이 막혀 있던 게 아니라 안 간 것이다.**

보관과 안전은 잘해 봐야 **안 나빠지는** 것이라 얻은 게 눈에 안 보인다.
요리는 오늘 저녁에 해보고 결과가 그 자리에서 나오고 옆사람한테 그대로 옮겨진다.
그래서 조회수와 전환율이 동시에 터진 유일한 자리가 거기다.

**주인이 정한 경계는 하나뿐이다.** 채널 정체성과 100% 반대로만 가지 않으면 된다.
겹침은 느슨해도 된다. 그 안에서는 좁히지 말고 넓게 잡아라.
막히는지는 검사를 돌려서 확인하지, 안 될 것 같다는 짐작으로 접지 마라.

**뜻을 짐작해야 하는 제목은 후킹이 아니라 장벽이다.** 260825 2차에서 여덟 개를 다시 썼다.

제목을 고치면 행과 방향이 어긋날 수 있다. 260825 2차에서 제목을 "뜨거운 음식에 닿으면
안 되는 것" 으로 바꾸자 영수증 행이 뜨거움과 무관해져서 그 행을 배달 용기로 갈았다.
**제목을 고쳤으면 네 행이 다 그 약속 안에 있는지 다시 본다.**

### 주제를 잡을 때 순서대로 묻는 것

1. **다 보고 나면 무엇을 새로 알게 되나.** 한 문장으로 옮겨 말할 것이 없으면 여기서 버린다
2. **몇 명이 자기 얘기라고 느끼나.** 조건이 붙을수록 조회수가 깎인다. 이게 제일 크다
3. **제목이 약속한 결과를 사람들이 이미 겪고 있나.** 못 느끼는 위험은 안 본다
4. **얻는 이야기인가 잃는 이야기인가.** 잃는 쪽은 조회수만 오고 팔로우가 안 붙는다
5. **물건 이야기인가 내 삶의 방식 이야기인가.** 물건은 사고 나면 끝이다
6. **사람이 있어야 성립하는 말이 들어갔나.** 들어갔으면 뺀다

### 형식은 원인이 아니다

| 갈래 | 편 | 합산 전환 | 중앙 전환 |

| 본편 카드 4항목 | 24 | 0.020% | 0.018% |

숫자만 보면 항목을 늘리면 될 것 같지만 **아니다.**
7개짜리 `자기 전에 무심코 반복하는 밤 습관 7` 이 팔로우 2명이고,
4개짜리 냉동실 편이 45명이다. **결이 정하지 항목 수가 정하지 않는다.**

본편이 4개인 것은 세로 공간 때문이다. 늘리려면 카드 레이아웃을 먼저 고쳐야 하고
발행 회로 일곱 개가 같이 바뀐다. **그건 사람이 정할 일이다.** 지금은 4개를 지킨다.

## 알려진 함정

- **전략표의 숫자만 보고 팩을 쓰면 뻔한 카드가 나온다. 260825 에 22장이 통째로 반려됐다.**
  대상 폭, 얻는 프레임, 중복, 게이트 다섯 개, 근거 검사를 전부 통과했는데도 그랬다.
  이유는 하나다. 이긴 편이 **행에 무엇을 썼는지**를 안 보고 공략점의 요약 문장
  ("넓음, 얻음, 내 삶")만 보고 썼다. 요약을 잣대로 쓰면 요약을 만족하는 뻔한 행이 나온다.
  **그래서 P2.5 를 만들었다. 카드 그림을 받아 직접 읽고 시작해라**
- **이 매뉴얼의 관찰을 규칙으로 읽지 마라.** 공략점 절과 `이긴카드.md` 의 메모는
  그 회차가 본 것이다. 그대로 따르면 회차마다 비슷한 것만 나오고 소재가 굳는다.
  **매번 그림을 다시 보고 이번 회차가 본 것을 `work/<taskId>/카드읽기.md` 에 새로 적는다**
- **"행마다 이름을 댔다" 는 통과 기준이 아니다.** 진 카드에도 이름은 다 있다.
  꼴찌 저녁 식탁 편에 밥공기, 국물, 소금통이 다 나오는데 팔로우 0명이다.
  이름은 최소 조건이고 기준은 **뜻밖인가**다. 260825 에 이 둘을 헷갈려서
  "이름을 다 댔으니 통과" 라고 보고했다
- **1위와 꼴찌가 같은 소재다.** 집밥 살리는 한 끗(391명)과 저녁 식탁 순서(0명)는
  둘 다 저녁 밥상 이야기다. 391 대 0 을 가른 것은 소재가 아니라 행이다.
  **소재로 판단하지 말고 행으로 판단해라**
- **다른 계정 표를 보고 전략을 세우면 못 지킬 약속을 하게 된다.** 260825 에 한 번 그렇게 썼다가
  되돌렸다. 자료에 실제 약사 계정 넷이 같이 들어 있고 전환율이 4배에서 11배 높은데,
  그쪽이 이기는 소재는 "내가 써봤다", "우리 약국에서" 처럼 **사람이 있어야 성립하는 것**이다.
  하루건강약사는 AI 크리에이터라 그 말을 쓸 수 없다. `follow-strategy.mjs` 는 그래서
  계정 표를 기본으로 안 낸다. 굳이 보려면 `--compare-accounts` 를 붙이되 전략에는 쓰지 마라
- **전환율로 판정하면 틀린 결론이 나온다.** 260825 에 전환율로 한 번 뽑았다가 두 번 고쳤다.
  안약 편은 전환율 0.014% 로 밑에서 세 번째지만 62.9만 조회로 팔로우 86명, **전체 5위**다.
  목표는 팔로우 수고 조회수가 그걸 지배한다(상관 0.92). 전환율만 보면 상위 편을 버린다
- **"이 결은 죽었다" 를 상하위 목록만 보고 적지 마라.** 같은 소재가 양쪽에 다 있다.
  자기 전 습관은 팔로우 164명과 2명이 같이 있고, 신호형도 130명과 1명이 같이 있다.
  갈린 자리는 대개 대상 폭이나 프레임이지 소재가 아니다. **짝을 지어 무엇이 달랐는지 봐야 한다**
- **지표는 화면 녹화를 데이터화한 것이라 새 편이 바로 안 들어온다.** 최근에 올린 편은
  전략표에 없다. 없다고 성적이 나쁜 게 아니다. 자료를 다시 만들어야 들어온다
- **한 릴스가 두 화면으로 두 번 잡힌다.** 릴스 인사이트와 게시물 인사이트다.
  합칠 때 팔로우가 큰 쪽을 남긴다. 작은 쪽은 화면을 덜 내린 컷이다
- **`research/queue` 를 재고로 세지 마라.** 거기는 사본이고, 발행하고 안 지운 팩이 쌓인다.
  260825 에 실제 재고 15건이 26건으로 부풀어 보였다. 원본은 `<채널> 소재/` 폴더다
- **P5 의 제목 검사는 이번 배치 후보끼리는 비교하지 않는다.** 원본과 기존 큐만 본다.
  후보 여럿을 같은 배치로 넣으면 `verify-stockpile-titles-unpublished` 에서야 후보끼리 충돌이
  드러나고, 검사 순서상 뒤 번호 파일이 걸린 것으로 나온다. 260825 에 "빨리 ~하는 순서" 와
  "이렇게 ~요" 꼬리가 배치 안에서 부딪혀 세 번 고쳤다. 흔한 동사 하나로도 걸린다.
  "잠 잘 오는 방 만드는 법" 이 원본의 "더부룩 만드는 식사 습관" 과 `만드는` 세 글자 조각으로
  걸렸다. 배치 제목들은 꼬리말과 흔한 동사를 서로 다르게 쓰고, 다 넣은 뒤 이 verify 를 돌려
  후보끼리 충돌까지 확인하고 끝내라
- **게이트가 `사이` 를 주격조사로 읽는다.** `card_name` 이 `사이` 로 이어지고 `기` 로 끝나면
  `broken_nominalization` 으로 반려한다. 검사식이 `[가-힣](이|가) ... 기$` 라 `사이 ` 의 `이` 가
  걸리는데, 예외 목록에 `없이 같이 높이 많이 깊이` 만 있고 `사이` 가 없다.
  `나이` `차이` `아이` 도 같은 꼴이다. **문장이 멀쩡하면 게이트 탓이니 말을 바꿔 우회한다.**
  예외 목록을 고치려면 `install-shared-content-quality-gate.mjs` 세 군데를 같이 고치고
  `simplify-legacy-editorial-flow.mjs` 를 반드시 뒤에 다시 돌려야 한다. 리필하다 하지 마라
- **다른 세션이 같은 시간에 파이프라인을 돌린다.** 260825 에 검사 도중 에어컨 편이 발행돼
  큐 사본이 새로 고아가 됐다. **검사가 갑자기 걸리면 P3 을 다시 돌려 치울 것을 다시 본다**
- **조건을 다 맞춰도 실용이 없으면 반려된다.** 260825 에 견본 6편이 대상 폭, 프레임, 중복,
  게이트 다섯 개를 전부 통과하고 반려됐다. 행이 "라벨 뒷면을 보세요", "다리를 꼬지 마세요" 처럼
  **시킴만 있고 명단이 없었다.** 검사 항목을 통과하는 것과 볼 만한 것은 다른 문제다.
  공략점의 "위 조건을 다 맞춰도 실용이 없으면 안 된다" 절을 팩 쓰기 직전에 다시 읽어라
- **거부된 팩을 `사용완료` 로 옮기지 마라.** 중복검사가 발행된 것으로 보고 제목을 영영 막는다.
  `보류` 폴더로 옮긴다
- **`보류` 의 `재발행예정-*` 팩은 어느 기계 검사도 안 본다.** 신선도 검사는 큐와 `사용완료` 만
  견주기 때문에, 새 팩이 재발행 예정 팩과 같은 행(우유·자몽과 약 같은 것)을 써도 통과한다.
  나중에 그 팩을 재발행할 때 이쪽이 막힌다. **주제를 잡기 전에 두 채널 `보류` 폴더에서
  `재발행예정` 파일 제목을 눈으로 훑어라.** 260825 2차에서 약+음료 팩과 겹칠 뻔했다
- **제목 검사가 통과여도 `nearest_published` 를 읽어라.** 260825 2차에서 소비기한 주제가
  검사는 통과했는데 nearest 에 `유통기한 지났다고 바로 버리면 손해 보는 것 7` 이 떠서
  이미 발행된 주제임을 알았다. 통과 여부만 보면 같은 주제를 다시 쓴다
