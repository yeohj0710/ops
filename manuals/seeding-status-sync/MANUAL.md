- **부르는 말**: 시딩 상황 파악해줘, 시딩 진행표 갱신해줘, 섭외 DM 확인하고 시트 갱신해줘, 인플루언서 회신 정리해줘, 진행상황 동기화해줘, 미모미 시딩 상황 파악해줘
- **미리 허가**: 인스타 DM·샤오홍슈 쪽지·지메일 회신 읽기, 해외 섭외 진행표 시트 쓰기, 노션 데스크 현황 숫자 갱신

- **제어층**: L3 (DM·메일 읽기, 시트 쓰기) → L1 (gviz 대조, 기록 파일)

## 무엇을 만드는 업무인가

섭외 DM 을 뿌려 둔 채널 세 곳(인스타 DM, 샤오홍슈 쪽지, 지메일)을 훑어 새 회신을 읽고,
**해외 섭외 진행표를 실제 상황에 맞게 고친다.** 끝나면 시트가 받은함과 같은 이야기를 하고,
사람이 결정해야 하는 건만 따로 모여 있다.

기록이 곧 업무다. 시트가 안 맞으면 누가 어디까지 갔는지 아무도 모르고, 같은 사람에게
같은 금액을 두 번 부르게 된다.

**이 업무는 `mimomi-seeding-sync` 를 대체한다.** 미모미약국이 260822 에 진행을 접었고
260825 에 확정 16명이 동대문 미미라인으로 배정됐다. 대상 건이 넷으로 늘어서 새로 짰다.

## 실행 계약

사용자가 이 업무를 호출하면 점검, 읽기, 시트 갱신, 안 읽음 복원, 완료 검사, 기록을 한 번에 실행한다.

## 절차

1. **먼저 시트를 읽어 원장을 만든다 (L1)**

   **DM 을 열기 전에 시트부터 읽는다.** 무엇이 이미 반영돼 있는지 모르면 같은 회신을 두 번 적는다.

   로그인된 탭에서 탭마다 gviz CSV 로 통째로 받는다. 화면을 훑지 마라.

   ```js
   const u = "https://docs.google.com/spreadsheets/d/" + ID
     + "/gviz/tq?tqx=out:csv&headers=2&sheet=" + encodeURIComponent(탭이름);
   const t = await (await fetch(u, { credentials: "include" })).text();
   ```

   `headers=2` 를 반드시 준다. `headers=0` 이면 숫자 열과 체크박스 열의 헤더 글자가 조용히 사라진다.

   `<OPS>/work/<taskId>/before.json` 에 탭별로 저장한다. 계정 키, 진행 상태, 응답, 메모,
   합의 단가, 확정, 배정 건, 마지막 데이터 행 번호.

2. **2행 헤더를 다시 읽어 열을 매핑한다 (L1)**

   **이 표의 열 문자를 그대로 믿지 마라.** 여러 세션이 같은 시트를 만진다.
   260826 기준 배치는 이렇고, 다르면 헤더 이름으로 다시 매핑하고 그 사실을 기록한다.

   | 탭 | 상태 | 계정 키 | 제안 금액 | 진행 단계 12칸 |
   | --- | --- | --- | --- | --- |
   | 중국 진행표 | B | C | I:K | N:Y |
   | 직접 탐색 후보 | B | C | I:K | N:Y |
   | 일본 진행표 | B | C | I:K | N:Y |
   | 일본 직접 탐색 후보 | B | C | I:K | N:Y |
   | 샤오홍슈 진행표 | D | E | K:M | P:AA |
   | 샤오홍슈 직접 탐색 후보 | D | E | K:M | P:AA |
   | 시딩 현황 | 자동 집계 | 없음 | 없음 | 손대지 마라 |

   진행 단계 12칸의 뜻은 차례대로 `DM 발송, 응답, 협상 메모, 합의 단가, 확정, 방문 예정일,
   가이드 전달, 촬영, 초안 검수, 업로드, 정산자료, 지급` 이다.

   **이 업무에서 손대는 것은 상태, 응답, 협상 메모, 합의 단가, 확정, 배정 건뿐이다.**
   제안 금액 세 칸은 팔로워를 보고 수식이 계산한다. 손으로 덮지 마라.

3. **읽기 전에 안 읽은 방을 적어 둔다 (L3)**

   **이 단계를 건너뛰면 되돌릴 수가 없다. 이 업무에서 제일 잘 나는 사고다.**
   방을 하나라도 열기 전에 목록부터 만든다.

   `https://www.instagram.com/direct/inbox/` 를 열고 목록만 읽는다. 누르지 마라.

   ```js
   [...document.querySelectorAll('div[role="listitem"], a[href^="/direct/t/"]')]
     .map(function (n) {
       return {
         방: (n.innerText || "").split("\n")[0],
         링크: (n.querySelector('a[href^="/direct/t/"]') || n).href,
         안읽음: /Unread|읽지 않음/.test(n.getAttribute("aria-label") || "")
           || !!n.querySelector('[aria-label*="읽지 않음"], [aria-label*="Unread"]')
       };
     })
     .filter(function (x) { return x.링크; })
   ```

   **DM 목록은 가상 스크롤이다.** 화면에 보이는 방만 DOM 에 있다. 아래로 내리면서 모아야 전체가 나온다.
   표시가 안 잡히면 화면을 캡처해 파란 점이 붙은 방 이름을 눈으로 적는다.

   지메일도 같다. 안 읽은 메일의 목록을 먼저 적는다. 샤오홍슈 쪽지도 같다.

   세 채널의 목록을 `<OPS>/work/<taskId>/unread-before.json` 에 저장한다.
   **저장을 확인하고 나서 첫 방을 연다.**

4. **회신을 읽고 갈래를 나눈다 (L3)**

   지난번 실행 이후에 온 것만 보면 된다. 그 날짜는 드라이브 `에이전트/보고/` 의 마지막 보고에 있다.

   | 갈래 | 무엇 | 시트에 어떻게 |
   | --- | --- | --- |
   | 수락 | 하겠다, 조건 좋다 | 응답 TRUE, 합의 단가 채움, 확정 TRUE, 상태 `확정` |
   | 금액 협상 | 더 달라, 얼마냐 | 응답 TRUE, 메모에 요구 금액 원문 그대로, 상태 `협상중` |
   | 질문 | 제품이 뭐냐, 언제냐, 배송은 안 되냐 | 응답 TRUE, 메모에 질문 원문 그대로, 상태 `협상중` |
   | 일정만 안 맞음 | 하고는 싶은데 그때 한국에 없다 | 응답 TRUE, 메모에 시기, 상태 `일정 보류` |
   | 거절 | 안 한다, 광고 안 받는다, 한국에 없다 | 응답 TRUE, 메모에 사유, 상태 `거절` |
   | 무응답 | 읽고 답이 없다 | 상태를 발송 단계 그대로 둔다 |

   **중국어와 일본어는 원문을 그대로 옮기고 옆에 한국어 뜻을 단다.** 요약해서 뜻을 바꾸지 마라.

   확정 16명이 답을 준 경우는 갈래가 둘 더 있다.

   | 갈래 | 무엇 | 시트에 어떻게 |
   | --- | --- | --- |
   | 배정 수락 | 미미라인으로 옮긴 것을 받아들임 | 배정 건 `미미라인`, 메모에 방문 날짜 |
   | 배정 거절 | 동대문은 못 간다 | 배정 건 비움, 상태 `일정 보류`, 메모에 사유 |

5. **시트를 고친다 (L3)**

   계정 키 열에서 행을 찾는다. 인스타는 `@핸들`, 샤오홍슈는 샤오홍슈 ID 로 찾는다.

   **DM 방 이름은 표시 이름이지 핸들이 아니다.** 방을 열어 프로필을 눌러 핸들을 확인하고 나서 시트를 뒤진다.

   시트에 없는 계정이 답장했으면 맨 아래에 줄을 만들고 계정, 이름, 팔로워, 상태, DM 발송,
   응답, 메모까지만 채운다. 컨택 점수와 근거 URL 같은 참고 열은 비워 둔다. 그건 후보 조사에서 오는 값이다.

   범위 선택은 이름 상자를 쓰지 말고 **주소로 한다.** `?gid=<gid>&range=I3` 을 붙여 새로 연다.
   이름 상자를 JS 로 `focus()` 하면 렌더러가 45초 얼어붙는 일이 있다.

   **이미 그 gid 에 떠 있는 탭에서는 range 가 안 먹는다.** 새로 이동해야 한다.

6. **안 읽음으로 되돌린다 (L3)**

   3단계에서 적어 둔 방을 **전부** 되돌린다. 하나도 빠뜨리지 마라.

   인스타는 방 목록에서 그 방을 오른쪽 클릭하면 "읽지 않음으로 표시" 가 나온다.
   메뉴가 안 뜨면 방 줄 오른쪽 끝의 점 세 개 버튼을 눌러도 같은 메뉴가 나온다.
   지메일은 메일을 골라 "읽지 않음으로 표시" 를 누른다.

   되돌린 뒤 **목록을 다시 읽어 개수가 원래대로 돌아왔는지 확인한다.**
   결과를 `<OPS>/work/<taskId>/unread-after.json` 에 저장한다.

7. **시트를 다시 읽어 대조한다 (L1)**

   1단계와 같은 방법으로 다시 받아 `<OPS>/work/<taskId>/result.json` 에 저장한다.

   - 탭별 `rowCountBefore`, `rowCountAfter`
   - `statusCountsBefore`, `statusCountsAfter`
   - `touchedRows` — 이번에 고친 행 목록 (계정 키, 바뀐 열, 이전 값, 새 값)
   - `newRows` — 이번에 새로 만든 줄
   - `formulaErrors` (`#REF!`, `#VALUE!`, `#N/A`, `#DIV/0!`, `#NAME?`, `#NUM!`)
   - `agreedPricesChangedUnexpectedly` — 손대지 않은 행의 합의 단가가 바뀌었는가

   행 수는 새로 만든 줄만큼만 늘어야 한다. 손대지 않은 합의 단가는 그대로여야 한다.

8. **완료 검사를 돌린다 (L1)**

   ```text
   node "<OPS>/manuals/seeding-status-sync/checks.mjs" "<진행 중인 task JSON 경로>"
   ```

   통과하지 못하면 그 자리에서 고친다. 특히 안 읽음 복원이 하나라도 빠지면 여기서 걸린다.

9. **노션 데스크 숫자를 맞춘다 (L3)**

   중화권 데스크 `3. 지금 명단 상태` 표와 `1. 이번 주에 할 일` 의 1군, 2군, 3군 인원이
   시트와 어긋나면 고친다. 일본 데스크와 국내 데스크의 명단 상태도 같다.

   **`notion-update-page` 의 `update_content` 는 매칭 안 된 편집을 조용히 버린다.**
   앵커를 한 줄로 짧게 끊고, 끝나고 반드시 다시 읽어 확인한다.

   **한글 겹받침이 보내는 쪽에서도 깨진다.** `늦었` 이 `늘었` 으로, `썸네일` 이 `썬네일` 로 바뀌어
   맞는 앵커가 안 맞는 일이 있다. 그런 낱말은 앵커로 쓰지 말고 다른 구간을 잡는다.

10. **보고하고 기록한다 (L1)**

    채팅에 표로 찍는다. 계정, 갈래, 요구 금액, 원문 한 줄.
    같은 내용을 드라이브 `에이전트/보고/<날짜>-시딩상황.md` 에 남긴다.
    다음 세션이 "어디까지 읽었나" 를 여기서 찾는다.

    `<OPS>/work/<taskId>/기록.md` 에 이번에 헤맨 것과 뚫은 법을 적는다.

11. **열어 둔 탭을 닫는다 (L3)**

    이번 업무에서 연 탭만 닫는다. 원래 떠 있던 탭은 사람이 보던 것일 수 있으니 그대로 둔다.

## 단가는 조회수로 정한다

팔로워가 아니라 **예상 조회수**가 기준이다. 팔로워는 사기도 하고 죽은 계정도 많다.

| 상황 | 예상 조회수 구하는 법 |
| --- | --- |
| 인스타, 조회수가 보임 | 최근 릴스 9~12개 조회수의 **중앙값** |
| 인스타, 조회수 비공개 | 최근 릴스 좋아요 중앙값 **곱하기 40** |
| 샤오홍슈 | 최근 노트 좋아요 중앙값 **곱하기 50** |
| 틱톡 | 조회수가 그대로 보인다. 그 중앙값 |
| 아무것도 안 보임 | 팔로워 수를 쓰고 메모에 "추정". **한 칸 낮게 부른다** |

**평균 말고 중앙값이다.** 하나가 터지면 평균이 두 배로 뛰어서 단가를 잘못 부른다.

| 예상 조회수 | 1차 제안 | 2차 상향 | 3차 상향(상한) |
| --- | ---: | ---: | ---: |
| 5천 미만 | 제품 협찬만 | 30,000 | 50,000 |
| 5천~1만 | 30,000 | 50,000 | 70,000 |
| 1만~2만 | 50,000 | 70,000 | 100,000 |
| 2만~4만 | 100,000 | 150,000 | 200,000 |
| 4만~8만 | 150,000 | 200,000 | 300,000 |
| 8만 이상 | 200,000 | 300,000 | 대표에게 물어본다 |

**약국에 방문하는 건은 위 금액에 50,000원을 더한다.** 촬영에 출연하는 것도 같다.
집에서 찍는 배송 리뷰는 위 금액 그대로다.

**다음에 부를 금액은 상태 열이 정한다.** 금액 칸을 비워서 단계를 표시하지 않는다.

| 상태 | 다음에 부를 금액 |
| --- | --- |
| 미접촉 | 1차 |
| 1차 발송 | 2차 |
| 2차 발송 | 3차 |
| 3차 발송 | 없다. 안 되면 거절로 바꾼다 |
| 거절, 일정 보류 | 보내지 않는다 |

**확정된 사람의 합의 단가는 옛 기준으로 맺은 값이다. 새 사다리로 덮어쓰지 마라.**
3만원부터 30만원까지 제각각인데 그대로 간다. 깎으면 그 사람은 다시 안 온다.

## 알려진 함정

- **읽기 전에 안 읽은 방을 안 적으면 되돌릴 수가 없다.** 이 업무에서 제일 잘 나는 사고다.
  방을 하나라도 열기 전에 목록부터 저장하고, 저장을 확인하고 나서 연다
- **DM 을 먼저 읽고 시트를 나중에 읽으면 같은 회신을 두 번 적는다.** 시트가 먼저다
- **인스타 DM 목록은 가상 스크롤이다.** 화면에 보이는 방만 DOM 에 있다. 내리면서 모은다
- **DM 방 이름은 표시 이름이지 핸들이 아니다.** 방을 열어 프로필에서 핸들을 확인하고 시트를 뒤진다
- **계정 전환을 하지 마라.** 로그인이 크롬 프로필 단위라 전환하면 같은 크롬을 쓰는 다른 세션도 같이 바뀐다.
  전환이 아니라 프로필을 옮긴다. `list_connected_browsers` → `select_browser`
- **샤오홍슈 회신은 발송 프로필에서만 읽는다.** 조사 부계(`Profile 9`)에는 보낸 적이 없어서 받은 것도 없다
- **샤오홍슈 진행표는 아직 샤오홍슈 명단이 아니다.** 297행 중 291행이 중국 진행표와 같은 인스타 계정이다.
  같은 사람이 양쪽에 있으면 **인스타로 답장이 왔을 때 인스타 탭만 고치고**, 샤오홍슈 탭에는
  메모에 "인스타로 회신함" 만 남긴다
- **DM 발송이 양쪽 탭에 중복 계상된다.** 총 발송을 셀 때 205가 아니라 고유 173으로 본다
- **일부 행은 열이 밀려 있다.** 메모 칸에 `FALSE` 가 들어간 행이 다섯 개 있다. 옆 칸까지 확인하고 쓴다
- **`headers=0` 으로 gviz 를 받으면 숫자 열 헤더가 조용히 사라진다.** 팔로워나 금액 열 헤더만
  빈칸으로 나오면 이 문제다. 값은 멀쩡해서 더 헷갈린다. `headers=2` 를 준다
- **이름 상자를 JS 로 `focus()` 하면 렌더러가 45초 얼어붙는다** (260819 실측). 범위는 주소로 잡는다
- **이미 그 gid 에 떠 있는 탭에서는 `range=` 가 안 먹는다.** 새로 이동해야 한다
- **시트 행 수를 넘는 범위를 지정하면 오류가 난다.** `I3:K1000` 이 그랬다.
  범위를 좁게 잡고, 남은 값이 있으면 먼저 지우고 넣는다
- **한 번에 여러 탭을 처리하면 브라우저 연결이 시간 초과된다.** 탭 하나씩 끝내고 저장을 확인한다
- **노션 `update_content` 가 편집을 조용히 버린다.** 앵커를 짧게 끊고 끝나고 다시 읽어 확인한다.
  한글 겹받침은 보내는 쪽에서도 깨져서 맞는 앵커가 안 맞을 수 있다
- **사람이 노션 화면에서 같은 페이지를 고치는 중일 수 있다.** `replace_content` 로 통째로 덮으면
  그 수정이 지워진다. 쓰기 직전에 한 번 더 읽어 최신 상태를 확인한다
- **미모미약국 이름을 대외 문서에 올리지 마라.** 비밀 유지 요청이 있다.
  섭외 상대에게는 "성수 약국" 까지만 말하고 왜 접었는지는 말하지 않는다
- **답장을 보내지 마라.** 이 업무는 읽고 적는 것까지다

## 묻지 말고 이렇게 한다

- **새 회신이 없으면** "새 회신 없음" 으로 보고하고 끝낸다. 그것도 결과다
- **갈래가 애매하면** 가장 가까운 것으로 넣고 메모에 원문을 그대로 남긴다
- **시트에 없는 계정이 답장했으면** 줄을 새로 만든다. 물어보지 않는다
- **팔로워나 조회수가 비어 있으면** 프로필에서 보고 채운다
- **중국어나 일본어를 못 읽겠으면** 원문을 그대로 옮기고 "번역 확인 필요" 를 붙인다
- **한 채널이 막히면** 나머지 두 채널은 계속한다. 막힌 채널만 사유와 함께 적는다
